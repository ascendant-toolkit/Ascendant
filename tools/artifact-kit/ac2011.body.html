Programming Paradigms: Low-level and Imperative

Coursebook: Chapter 20 · Further programming, section 20.1 Programming paradigms

What a programming paradigm is, low-level programming and the five addressing modes, imperative (procedural) programming, step-by-step animations, labs and the real past paper questions on paradigms.

This page in five sentences

A programming paradigm is a style of programming, a way of thinking about how a program is built. Low-level programs work with the processor's own instruction set and give direct control of registers and memory, and the way an instruction finds its data is the addressing mode: immediate, direct, indirect, indexed or relative. Imperative (procedural) programs are an ordered list of commands that change the program's state, organised into procedures and functions. Object-oriented programs are built from classes and objects, and declarative programs state facts and rules and ask a question. This page covers the first two paradigms; the next pages take the other two.

1 · What is a programming paradigm?

A paradigm is a way of organising a program. The same problem can be solved in more than one paradigm, and a paradigm suits some problems better than others. Many languages support more than one: Python can be written in an imperative, an object-oriented or a (partly) functional style.

2 · Low-level programming

Low-level code is written close to the hardware. Machine code is binary the processor runs directly; assembly language uses short readable mnemonics (LDD, ADD) that an assembler translates into machine code. Each assembly instruction is usually one machine instruction, and every processor family has its own instruction set.

BenefitsDrawbacks
Direct control of registers, memory and hardware; small, fast programs; no hidden overheadsHard to write, read, debug and maintain; many lines for one simple task
Used where speed or size matters: device drivers, embedded systems, parts of an operating systemNot portable: the code is written for one processor, so it must be rewritten for another

3 · Addressing modes

An instruction has an opcode (what to do) and an operand (the data, or where to find it). The addressing mode is the way the operand is used to find the data. The exam gives the instruction set, so learn the idea behind each mode rather than the mnemonics.

ModeHow the operand is usedExample (ACC after)
ImmediateThe operand is the valueLDM #500: ACC = 500
DirectThe operand is the address that holds the valueLDD 500: ACC = the contents of address 500
IndirectThe operand is the address of a location that holds another address, and the value is at that second addressLDI 500: read address 500, use what it holds as an address, load from there
IndexedThe address used is the operand plus the contents of the index register (IX)LDX 200 with IX = 3: load from address 203
RelativeThe address used is found by adding an offset (the operand) to the address of the current instructionA relative jump of +4 from address 1050 continues at 1054
Worked example (May/June 2022)Address 500 holds 100 and address 100 holds 20. LDM #500 loads 500 (immediate). LDD 500 loads 100 (direct: the contents of address 500). LDI 500 loads 20 (indirect: address 500 holds 100, so go to address 100). Same operand, three different answers.

Why indexed addressing exists: arrays. Store the first element at address 200, then set IX to 0, 1, 2... and the same instruction LDX 200 reads each element in turn. Why relative addressing exists: the code works wherever it is placed in memory, because jumps are measured from where they are, not from a fixed address.

4 · Writing a low-level program

The May/June 2022 question asked for code to add the constant 20 to the value stored at the address held in variable Y, and store the result in Z. The steps are always the same: load, calculate, store, then declare the data after the code with labels.

LDM #20       // load the constantSTO Twenty    // the constant must be stored somewhere so it can be addedLDI Y         // indirect: Y holds an address, load the value at that addressADD Twenty    // add the constantSTO Z         // store the answerENDTwenty: #0Y:      #0Z:      #0

Only ACC can be added to, and ADD works on an address, not a number. That is why the constant is stored first. Labels for data go after the program code.

5 · Imperative (procedural) programming

An imperative program is a sequence of commands, run in the order written, where each command changes something: a variable, an output, a file. Procedural code is imperative code organised into procedures and functions, so a task can be named, reused and tested on its own. You already write this: every Paper 4 program is imperative.

  • Variables hold the state, and assignment changes it.
  • Constructs: sequence, selection (IF, CASE) and iteration (FOR, WHILE, REPEAT).
  • Procedures do a job; functions return a value. Parameters pass data in.
  • Structured programming (AS 11.3): modules with one entry and one exit, top-down design, no unstructured jumps.
total = 0for i in range(1, 5):    total = total + i      # each pass changes the state of totalprint(total)               # 10

6 · Common ways to lose marks

  • Describing imperative code as "code that uses loops". The mark is for the sequence of commands that change the program state, in the order written.
  • Calling LDD 500 "immediate" because the number is written in the instruction. Immediate has the #: the number is the data.
  • Stopping one step early on indirect addressing. Indirect needs two reads: the address, then the value.
  • Forgetting to store a constant at an address before using ADD, or putting the labelled data in the middle of the program.
  • Writing "declarative means no loops". Say it states the result wanted using facts and rules, not how to get it.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A washing machine controller

The program in a simple appliance often runs on a small microcontroller with very little memory. It can be written in assembly or very close to it so it fits and responds instantly.

Exam use: low-level code is chosen for tiny devices where speed and size matter, at the cost of portability.

Device drivers and boot code

The first instructions that run when a computer starts, and the code that talks to a graphics card or a disk, need exact control of registers and memory addresses, so parts of them are low-level.

Exam use: low-level gives direct hardware control that a high-level language hides.

A spreadsheet macro or a Python script

A list of commands such as read the file, loop through the rows, add the total, print the result is imperative: each step changes the state and the order matters.

Exam use: imperative means a sequence of commands that change the program state, in the order written.

Arrays and indexed addressing

When a program reads item after item from a list, the processor adds an index to the start address of the list. That is indexed addressing, one instruction used over and over with a changing index.

Exam use: indexed addressing is the answer when a question mentions arrays or tables of data.

Position-independent code

Code that uses relative addresses can be loaded anywhere in memory without changing its jumps, which is why shared libraries use it.

Exam use: relative addressing measures from the current instruction, not from a fixed address.

Describing and identifying paradigms

M/J 2021 · 9618/31, 32, 33 · Q9(a), (b) Describe 2 + 2 marks (a) Describe what is meant by an imperative (procedural) programming language. (b) Describe what is meant by a declarative programming language.
ReminderTwo marks each. (a) is about a sequence of commands that change the state. (b) is about stating what is wanted, using facts and rules.

(a) The statements form a sequence of commands for the computer to perform in the order written, and each line of code changes something in the program state.

(b) It states what needs to be done instead of how to do it, using facts and rules that are queried to satisfy a goal.

Common mistakeDefining imperative as "uses loops and IF statements". That describes constructs, not the paradigm.

ReminderLook for the giveaway: facts ending in a full stop, a counted loop, mnemonics with a label, the word class.

Descriptions: (A) programs using the instruction set of a processor; (B) programs based on events such as user actions or sensor outputs; (C) programs using the concepts of class, inheritance, encapsulation and polymorphism; (D) programs with an explicit sequence of commands that update the program state, with or without procedure calls; (E) programs that specify the desired result rather than how to get to it.
ReminderFour paradigms, five descriptions: one description is a distractor.

Low-level matches (A) the processor's instruction set Object-oriented matches (C) class, inheritance, encapsulation, polymorphism Imperative matches (D) a sequence of commands that update the state Declarative matches (E) the desired result, not how to get it

Description (B) is the odd one out: it describes event-driven programming, which is not one of the four paradigms.

Common mistakeMatching imperative to "specify the desired result". That is declarative: imperative gives the steps.

Addressing modes and writing assembly

M/J 2022 · 9618/31, 33 · Q9(a) State 3 marks A processor has one general purpose register, the accumulator (ACC). The table shows part of its instruction set. The address 500 contains the value 100 and the address 100 contains the value 20. State the addressing mode and the contents of ACC after each instruction has been executed: LDM #500, LDD 500, LDI 500.
InstructionExplanation
LDM #nLoad the number n to ACC
LDD <address>Load the contents of the given address to ACC
LDI <address>The address to be used is at the given address. Load the contents of this second address to ACC
ADD <address>Add the contents of the given address to the ACC
STO <address>Store the contents of the ACC at the given address
<label>: <data>Gives a symbolic address to the memory location holding the data; the label can be used in place of an address. # denotes a denary number
ReminderOne mark per instruction, and the mode and the ACC value must both be right. Indirect needs two reads.

Common mistakeAnswering 100 for LDI. That stops after the first read. Indirect follows the address once more.

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Distinguish 2 marks Distinguish between immediate and direct addressing.
ReminderOne mark each: what the operand is in each mode. Give an example instruction if you can.

Immediate: the operand is the value to use, e.g. LDM #25 loads 25. Direct: the operand is the address that holds the value, e.g. LDD 25 loads the contents of address 25.

Common mistakeSaying direct uses the value in the instruction. That is immediate.
Explain 3 marks A program reads each element of an array stored from address 300 onwards. Explain why indexed addressing suits this task.
ReminderSay what the effective address is, and what changes between elements.

In indexed addressing the address used is the operand plus the contents of the index register. The operand can be the start address of the array (300) and stay the same. Adding one to the index register each time moves to the next element, so one instruction can read every element in a loop.

ReminderAdd the operand and IX first.

Complete 3 marks ACC holds 12. Address 50 holds 8 and address 8 holds 30. Give the value in ACC after each instruction, run one after another: ADD 50, then LDI 50, then LDM #50.
ReminderRun them in order and track ACC. Each load replaces ACC; ADD adds to it.

Top tips

  • Name the paradigm by its giveaway. Facts and rules: declarative. Class: object-oriented. Opcodes and labels: low-level. Assignments in loops: imperative.
  • Write the full definition. Imperative: a sequence of commands, in order, that change the program state. Declarative: say what is wanted, using facts and rules, not how.
  • Count the reads. Immediate zero, direct one, indirect two. Write each address you visit.
  • Track ACC line by line. Load replaces ACC. ADD changes it. STO does not change ACC.
  • Store the constant first. There is no immediate ADD in the exam instruction set.
  • Data labels go last. Place labelled data after the program code and before nothing else in the answer.
