Data Security, Privacy and Integrity

Coursebook: Chapter 6 · Security, privacy and data integrity · section 6.1 Data security

Data security, privacy and integrity defined, and the security measures: passwords, biometrics, firewalls, anti-malware, encryption, digital signatures and back-ups, with animations, labs and the real Paper 1 questions from 2021 to 2026.

This page in five sentences

Data security is protecting data from loss, corruption and unauthorised access. Data privacy means data can only be accessed by or disclosed to authorised people. Data integrity means the data is accurate, complete, consistent and up to date. Security and privacy are protected by user accounts and passwords, access rights, biometrics, firewalls, anti-malware, encryption, digital signatures and back-ups; integrity is protected by validation and verification (and back-ups). A good answer always says how the measure works, not only its name. Do not mix security measures (firewall, password) with integrity measures (double entry, presence check): matching them is a regular question.

1 · Security, privacy and integrity

TermMeaningWhy it matters
Data securityProtecting data from loss, corruption, being amended or deleted, and from unauthorised accessData needs protecting from someone amending, deleting or taking it; the computer system needs protecting from someone installing malware or damaging it; and data must be recoverable
Data privacyEnsuring data can only be accessed by or disclosed to authorised personsPersonal data about staff and students must not be seen by people who should not see it
Data integrityThe accuracy, completeness and consistency of data (and that it is up to date), during and after processingWrong data gives wrong decisions

Security against privacy: security protects the data against loss or damage; privacy protects it against unauthorised access. Security against integrity: security protects data from loss or corruption; integrity is the accuracy and consistency of the data.

2 · Security measures

MeasureHow it works
User account and strong passwordThe user must log in to prove their identity; a strong password is long and mixes upper and lower case letters, digits and symbols, and is not related to the user
Biometrics / two-factor authenticationUses a feature of the individual (fingerprint, face) that is unique and almost impossible to duplicate; two-factor needs a second form of verification, such as an authenticator app code
Access rights (permissions)Each user can only open, edit or delete the files they have been given permission for
FirewallMonitors incoming and outgoing packets, checks them against a set of rules (allow or deny list of addresses, ports), blocks those that do not meet the rules and lets the others through
Anti-virus / anti-malwareScans files, downloads and devices, compares against a database of known malware, and quarantines, deletes or alerts the user if a match is found; its definitions must be kept up to date
EncryptionConverts the data (plain text) into cipher text using a key, so that if it is intercepted it cannot be understood without the decryption key
Digital signatureProves the sender (authenticity) and that the data has not been changed (see section 3)
Back-upRegular copies so lost or corrupted data can be recovered

3 · Digital signatures

  1. The sender puts the message through a hashing algorithm to produce a digest.
  2. The digest is encrypted with the sender's private key: this is the digital signature.
  3. The message and the signature are sent to the receiver.
  4. The receiver decrypts the signature with the sender's public key to reproduce the digest. This proves who sent it, because only the sender's private key could produce a signature the matching public key can decrypt.
  5. The receiver applies the same hashing algorithm to the message received and compares the two digests. If they are the same the message has not changed.

Common ways to lose marks

  • Saying security "stops hackers" and privacy "stops hackers". Security protects from loss and corruption; privacy is about unauthorised access.
  • Naming a measure without how it works, such as "use a firewall". Say it checks packets against rules and blocks those that do not meet them.
  • Saying encryption "stops hackers from getting the data". It does not stop interception: the intercepted data cannot be understood without the key.
  • Listing a validation or verification check as a security measure. They protect integrity.
  • Describing a digital signature as an image of a signature. It is an encrypted digest.

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Your phone's face unlock

A feature unique to you replaces a password: this is biometric authentication.

Exam use: biometrics.

The padlock in a web address

Data between your browser and the site is encrypted, so someone intercepting it sees only cipher text.

Exam use: encryption in transit.

School data access

A teacher can edit grades for their own class but a student cannot: the OS applies access rights.

Exam use: access rights.

A signed software update

Your computer checks the digital signature of an update, so it knows who published it and that nobody has changed it on the way.

Exam use: digital signature.

A back-up after ransomware

A school restores yesterday's copy of its files instead of paying: that is why back-ups protect security.

Exam use: back-up.

M/J 2025 · 9618/11 · Q7(a)(b) Identify / Explain 3 + 5 marks A banker transfers confidential data across the internet. (a) Identify and describe one method of restricting the risks posed by an unauthorised person intercepting the data. (b) The data includes a digital signature. Explain how a digital signature can make sure the data has not been changed during transmission.
ReminderEncryption. Hash, digest, private key, compare.

(a) Method: encryption Data is encoded or scrambled using a key to create cipher text If intercepted it cannot be understood without being decrypted using a key

(b) Any five: The sender hashes the document to produce a digest The sender encrypts the digest to create the digital signature The message and the signature are sent to the receiver The receiver decrypts the signature to reproduce the digest The receiver uses the same hashing algorithm on the document received to produce a second digest The receiver compares this digest with the one from the digital signature If they are the same the document has not changed

Common mistakeDescribing a digital signature as an image or as encrypting the whole message.

ReminderSecond form of verification.

Explain 2 marks Explain why a company keeps back-ups even though it has a firewall.
ReminderRecovery.

A firewall cannot prevent all loss or corruption (for example hardware failure or malware) back-ups allow the data to be recovered

Top tips

  • Security: loss. Privacy: access. Integrity: accuracy.
  • Name it and say how it works. Firewall: rules on packets.
  • Encryption: cipher text. Useless without the key.
  • Digital signature: hash, private key. Receiver compares two digests.
  • Checks protect integrity. Not security.
  • Back-up for recovery. It does not prevent loss.
