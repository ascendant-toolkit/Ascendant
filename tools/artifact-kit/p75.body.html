Test Data

Normal, abnormal, extreme and boundary test data, and how they are used in a test plan.

The big idea

Test data is chosen in four types: normal, abnormal, extreme and boundary. Each has an expected result, and the edges of the range are where many errors hide.

7.5 Test data

In the testing stage, a program is run with test data: values chosen in advance, with the expected result for each worked out beforehand. If the actual result differs from the expected one, there is an error. To test properly you need four types of test data.

TypeMeaningShould be…
NormalTypical, valid data that the program should handle.Accepted
AbnormalData that the program should not accept: the wrong data type, or outside the allowed range.Rejected
ExtremeThe largest and smallest acceptable values.Accepted
BoundaryThe largest and smallest acceptable values and the corresponding smallest and largest rejected values, the ones either side of each limit.The acceptable ones accepted, the others rejected

Example 1: a mark from 0 to 100

TypeTest dataExpected result
Normal56Accepted
Extreme0 and 100Accepted
Boundary0 and −1 (lower limit), 100 and 101 (upper limit)0 and 100 accepted; −1 and 101 rejected
Abnormal−5, 150, "abc"Rejected

Example 2: an age from 18 to 65

TypeTest dataExpected result
Normal40Accepted
Extreme18 and 65Accepted
Boundary17, 18 and 65, 6618, 65 accepted; 17, 66 rejected
Abnormal"twenty", −3, 200Rejected
Extreme against boundaryThe extreme values are the acceptable edges (18 and 65). The boundary values are those and the nearest rejected values (17 and 66). That is why both are useful.

Why boundary and extreme values matter

A very common mistake is to write > instead of >=, or < instead of <=. A normal value such as 40 will never find it, because 40 passes both versions. Only testing 18 and 65 exposes the error.

A test plan

Test data is recorded in a test plan: the test data, its type, the expected result, the actual result, and whether the test passed. When a test fails, the code is corrected and the tests are run again.

Testing a speed limit sign reader

A car's sign reader is tested with ordinary signs (normal), the lowest and highest speeds (extreme), and damaged or unreadable signs (abnormal).

Exam use: all four test data types in a vehicle example.

An online age check

A site for 18 to 65-year-olds must accept 18 and 65 but reject 17 and 66. Developers test exactly those four values.

Exam use: extreme and boundary data around a range.

A hotel booking system

Booking 1 night (smallest), 30 nights (largest) and 31 nights (just outside) are standard tests, plus an entry like "two" (abnormal).

Exam use: extreme, boundary and abnormal values.

A lift weight limit

A lift rated for 1000 kg is tested at normal loads, exactly 1000 kg and 1001 kg.

Exam use: boundary testing: the point where behaviour should change.

Password length rules

A rule of 8 to 12 characters is tested with 8 and 12 characters (extreme), 7 and 13 (boundary, rejected) and an empty password (abnormal).

Exam use: turning a validation rule into test data.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 State 4 marks State the four types of test data.
ReminderOne word each.
Normal Abnormal Extreme Boundary
Common mistakeWriting "valid" and "invalid". Those are not the four types.
Q2 Explain 3 marks A program accepts a whole number from 1 to 50. Explain the difference between extreme data and boundary data, using examples.
ReminderExtreme = acceptable edges. Boundary = those + nearest rejected.
Extreme data is the largest and smallest acceptable value, for example 1 and 50. Boundary data is the largest and smallest acceptable values and the corresponding smallest and largest rejected values, for example 0 and 1, 50 and 51. Extreme data is accepted, but boundary data includes values that should be rejected (0 and 51).
Common mistakeSaying they are the same. Boundary also includes the rejected neighbours.
Q3 Give 4 marks A program accepts ages from 18 to 65. Give one example of each type of test data.
ReminderFour values that fit the definitions.
Normal: any age between 19 and 64, for example 40. Abnormal: for example "abc" or −5 or 200. Extreme: 18 or 65. Boundary: 17 or 66 (the nearest rejected values), or 18 or 65.
Common mistakeChoosing the same value twice, or choosing a normal value for extreme.
Q4 Explain 2 marks Explain why a program is tested with test data.
ReminderCheck it works.
To check that the program gives the expected results (works correctly). To find errors so that they can be corrected.
Common mistakeWriting "to see if it is good". Link to expected results and errors.
Q5 Explain 2 marks Explain why abnormal test data is used.
ReminderThe program should reject it.
To check the program rejects (or handles) data that it should not accept, so it does not crash or give wrong results.
Common mistakeSaying abnormal data is "wrong data that is used by mistake". It is chosen on purpose.
Q6 Give 4 marks A password must be from 8 to 12 characters. State the extreme data and the boundary data (lengths).
ReminderExtreme: 8 and 12. Boundary: 7, 8, 12, 13.
Extreme: 8 characters Extreme: 12 characters Boundary rejected: 7 characters Boundary rejected: 13 characters
Common mistakeGiving only the extremes. Boundary needs the rejected values too.
Q7 Explain 2 marks A programmer writes IF Age > 18 instead of IF Age >= 18. Explain which test data would find this error.
ReminderWhich value does the wrong operator reject?
Test data of 18 (an extreme / boundary value) is accepted by the correct code but rejected by IF Age > 18.
Common mistakeChoosing 40. A normal value passes both versions.
Q8 State 2 marks A program accepts marks from 0 to 100. State the expected result for (a) 100 and (b) 101.
ReminderOne accepted, one rejected.
(a) 100 is accepted (it is the largest acceptable value). (b) 101 is rejected (it is just outside the range).
Common mistakeStating "valid" and "invalid" without saying what the program does with them.

Top tips

  • Four types: normal, abnormal, extreme, boundary.
  • Extreme: the biggest and smallest acceptable values.
  • Boundary: those and the nearest values just outside (rejected).
  • State the expected result for each test: accepted or rejected.
  • Boundary tests find > and >= mistakes. A normal value never will.
