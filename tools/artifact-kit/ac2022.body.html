Exception Handling: try and except

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

What an exception is, its causes, why and when to use exception handling, try, except and finally in Python, the patterns the exam uses with files and input; animations, labs and the real Paper 3 and Paper 4 questions.

This page in five sentences

An exception is an unexpected event that happens while a program is running and disrupts its normal flow, and unless something responds to it the program halts. Exception handling is the process of responding to the unwanted event so the program does not stop unexpectedly: the risky statements go in a try block and the response goes in an except block. Exceptions have three common causes: programming errors (dividing by zero, an index outside an array), user errors (typing text where a number is expected, a wrong file name) and hardware failure (a disk crash, a lost connection to a printer). Use exception handling when something outside the program's control could go wrong, especially opening and reading files and converting user input. Paper 3 asks you to define and describe it; Paper 4 awards marks for writing it round a file.

1 · What an exception is

CauseExamplePython exception
Programming errorDivide by zero; read an array element that does not exist; a variable of the wrong typeZeroDivisionError, IndexError, TypeError
User errorTyping abc when a number is asked for; giving a file name that does not existValueError, FileNotFoundError
Hardware or system failureA disk crash; the file is on a device that has been unplugged; the disk is full; a printer is disconnectedOSError (which IOError is an alias of)

Without handling, Python stops at the line where it happened and prints an error message. Statements after it never run, and files may be left open.

2 · Why use exception handling?

  • To trap runtime errors and stop the program halting unexpectedly.
  • To show a meaningful message to the user instead of a system error.
  • To let the program recover or carry on: ask again, use a default, or close down safely.

The mark scheme's wording: exception handling is a process that responds to unwanted or unexpected events when a program runs, to prevent the program or computer from stopping unexpectedly.

3 · try and except in Python

try:    File = open("Data.txt", "r")          # might fail: file missing    for Line in File:        Numbers.append(int(Line))         # might fail: a line is not a number    File.close()except IOError:                           # the response when the file cannot be opened    print("Could not find the file")except ValueError:                        # the response when int() fails    print("The file contains something that is not a number")
  1. Python runs the statements in the try block.
  2. If one of them causes an exception, the rest of the block is skipped and the matching except block runs.
  3. If nothing goes wrong, the except blocks are skipped.
  4. The program then carries on after the whole try statement.
PartUse
try:The statements that might cause the exception
except IOError: / except:What to do if it happens. Naming the exception is best; a bare except: catches everything and is accepted in the exam
else:Runs only if no exception happened
finally:Runs whether or not an exception happened, for example to close a file

The syllabus pseudocode form is the same idea:

TRY
   OPENFILE "Data.txt" FOR READ
   READFILE "Data.txt", Line
EXCEPT
   OUTPUT "File not found"
FINALLY
   CLOSEFILE "Data.txt"
ENDTRY

4 · When to use it

Use exception handling forUse ordinary checks (IF, validation) for
Opening, reading and writing filesA value that must be in a range: IF Age < 0 THEN
Converting user input: int(input())A list index you can test with IF Index < len(List)
Network, printer or disk problemsMenu choices from a known set
Division where the divisor comes from the userLogic errors in your own algorithm (fix the code)

Use it where the problem comes from outside the program and cannot be ruled out in advance. It does not replace validation, and it does not fix a logic error.

The mark scheme awards separate marks for: the try structure, the except (catch) block, an appropriate output message, and for the file work inside it (open, loop, read, close).

6 · Common ways to lose marks

  • Defining an exception as "an error". Say it is an unexpected event during execution that can make the program halt.
  • Listing a cause that is not an exception cause (for example "the program is slow"). Use programming errors, user errors or hardware failure.
  • Writing try without except, or an except with no message or action.
  • Putting try round the wrong lines: the file opening and reading must be inside it.
  • Describing validation (an IF check) as exception handling.
  • In Paper 4, leaving out the exception handling when the question says "use exception handling". It is usually worth a mark or two.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A web form that asks for a quantity

If a customer types ten instead of 10, converting it to a number would normally crash the page. The code catches the error and shows 'Please enter a whole number'.

Exam use: user error handled by an exception handler with a helpful message.

A spreadsheet opening a missing file

When a linked file has been moved or deleted, the program says it cannot find the file and offers to browse for it instead of closing.

Exam use: file not found: caught so the program can carry on.

A game saving to a full disk

If there is no space left, the save fails. The game reports it and keeps running so the player does not lose their progress in memory.

Exam use: hardware or system failure: the response protects the data.

A banking program dividing by a count

An average is total divided by the number of transactions. With no transactions that would divide by zero, so the program handles it and reports 'no transactions'.

Exam use: a programming error that can be caught (or checked first with IF).

An app losing its network connection

A download stops when the Wi-Fi drops. The app catches the connection error, tells the user, and lets them retry.

Exam use: failure outside the program's control, reported rather than crashing.

Top tips

  • Define it fully. An exception is an unexpected event during execution that disrupts normal flow and can make the program halt. Exception handling responds to it so the program does not stop unexpectedly.
  • Give causes in three groups. Programming errors, user errors, hardware failure. Name one example of each.
  • Put the risky code inside try. File opening, reading and converting input all go in the try block.
  • Always add a message. An except block that does nothing gets no mark. Output an appropriate message.
  • Handle what is outside your control. Files, input, devices. Use IF for ranges and logic.
  • Read the question for 'use exception handling'. It is a separate mark in Paper 4 file questions.
