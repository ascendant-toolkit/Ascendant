Polymorphism: One Call, Many Behaviours

Coursebook: Chapter 20 · Further programming, section 20.1 Programming paradigms

What polymorphism means, how it follows from overriding, how one loop handles a list of different objects, and how it looks in Python and exam pseudocode; animations, labs and review questions.

This page in five sentences

Polymorphism means "many forms". Several classes have a method with the same name, and each class gives it its own behaviour. The code that calls the method does not need to know which class the object belongs to: it makes the same call and the object responds in its own way. It is built on inheritance, with a child overriding a method of its parent. The advantage is that one loop can handle a whole list of different objects.

1 · One method name, different results

Python

class Animal:    def __init__(self, pName):        self.__Name = pName    def GetName(self):        return self.__Name    def Description(self):        return self.__Name + " is an animal" class Parrot(Animal):    def Description(self):        return self.GetName() + " is a parrot that squawks" class Dog(Animal):    def Description(self):        return self.GetName() + " is a dog that barks" Zoo = [Animal("Generic"), Parrot("Polly"), Dog("Rex")]for Item in Zoo:    print(Item.Description())

Pseudocode (exam style)

CLASS Animal  PRIVATE Name : STRING  PUBLIC FUNCTION GetName() RETURNS STRING    RETURN Name  ENDFUNCTION  PUBLIC FUNCTION Description() RETURNS STRING    RETURN Name & " is an animal"  ENDFUNCTIONENDCLASS CLASS Parrot INHERITS Animal  PUBLIC FUNCTION Description() RETURNS STRING    RETURN GetName() & " is a parrot that squawks"  ENDFUNCTIONENDCLASS CLASS Dog INHERITS Animal  PUBLIC FUNCTION Description() RETURNS STRING    RETURN GetName() & " is a dog that barks"  ENDFUNCTIONENDCLASS
Generic is an animalPolly is a parrot that squawksRex is a dog that barks

The loop calls Item.Description() every time. It never tests what kind of animal it has. Each object runs the version from its own class.

2 · Polymorphism and overriding: how they fit

TermWhat it is
OverridingThe mechanism: a child class redefines a parent's method, keeping the name.
PolymorphismThe effect: the same call behaves differently depending on the object it is made on.

3 · Why it helps

No chains of IF

Without it the loop would need a test for each kind of animal and a different call for each.

New classes cost nothing

Add a Cat class with its own Description(). The loop does not change at all.

4 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A drawing program

Every shape has Draw(). A Circle draws a circle and a Square draws a square. The program loops over the shapes and calls Draw() on each.

Exam use: same call, different drawing.

Payments

Card, Cash and Voucher each have Pay(amount). The till calls Pay() without needing to know which type the customer used.

Exam use: new payment types can be added later.

A game with enemies

Every enemy has Attack(). A Goblin hits, a Dragon breathes fire. The game loop calls Attack() on each enemy.

Exam use: one loop, many behaviours.

Sound on a phone

Play() works the same for a song, a podcast and a video. Each type plays itself in its own way.

Exam use: common name, different behaviour.

Common mistakeCalling the method CatDescription instead of Description.
Explain 2 marks Give one advantage of polymorphism.
ReminderBe specific.
The same code (a loop) can be used for objects of different classes so new classes can be added without changing the code that calls the method

Top tips

  • Same name, different behaviour. Both halves are needed.
  • Overriding is the how. Polymorphism is the result.
  • Use the example. Name Description() in Animal, Parrot and Dog when you explain.
  • Say 'depending on the object'. The class of the object decides.
  • Don't mix it up. Not inheritance, not encapsulation, not containment.
