Exception Handling When Using Files

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

What can go wrong with a file, where the try block goes, catching a bad line as well as a missing file, and closing with finally; pseudocode and Python side by side, with line-by-line animations.

This page in five sentences

Files are the most common place for an exception, because the program depends on something outside itself: the file may not exist, may be unreadable, or may contain data in the wrong form. In Paper 4, a question that says use exception handling awards a mark or two for a try block round the file work and an except block with an appropriate message. The whole of the open, read or write, and close goes inside the try, so a problem at any stage is caught. A named except IOError catches file problems only, so a bad line such as abc (a ValueError) needs a bare except or a second block. A finally block can close the file whatever happened.

2 · Reading a file into an array

The file Data.txt holds whole numbers, one per line. The array is filled inside the try.

Python

DataArray = []try:    DataFile = open("Data.txt", "r")    for Line in DataFile:        DataArray.append(int(Line))    DataFile.close()except IOError:    print("Could not find file")

Pseudocode (exam style)

Index <- 0TRY   OPENFILE "Data.txt" FOR READ   WHILE NOT EOF("Data.txt")      READFILE "Data.txt", Line      DataArray[Index] <- STR_TO_NUM(Line)      Index <- Index + 1   ENDWHILE   CLOSEFILE "Data.txt"EXCEPT   OUTPUT "Could not find file"ENDTRY

3 · Where the try goes

PlacementResult
try round the whole open, loop and closeA problem at any stage is caught. This is the mark-scheme pattern
try round only the openA bad line while reading is not caught, so the program can still halt
No try at allThe program halts with a system message and the exception-handling marks are lost

4 · Writing a file

Python

try:    File = open("Tree.txt", "w")    File.write("-1,20,1\n")    File.close()except IOError:    print("Cannot write to file")

Pseudocode (exam style)

TRY   OPENFILE "Tree.txt" FOR WRITE   WRITEFILE "Tree.txt", "-1,20,1"   CLOSEFILE "Tree.txt"EXCEPT   OUTPUT "Cannot write to file"ENDTRY

5 · Catching a bad line as well

With except IOError, a line containing abc raises a ValueError, which does not match, so the program halts. Catch it too:

try:    DataFile = open("Data.txt", "r")    for Line in DataFile:        DataArray.append(int(Line))    DataFile.close()except (IOError, ValueError):         # or a bare:  except:    print("Problem reading the file")

6 · Closing the file with finally

If an exception is raised part-way through reading, the line that closes the file is skipped. A finally block always runs, so it can close the file whatever happened. Python needs to check the file was opened first.

Python

DataFile = Nonetry:    DataFile = open("Data.txt", "r")    Line = DataFile.readline()except IOError:    print("Problem with the file")finally:    if DataFile is not None:        DataFile.close()

Pseudocode (exam style)

TRY   OPENFILE "Data.txt" FOR READ   READFILE "Data.txt", LineEXCEPT   OUTPUT "Problem with the file"FINALLY   CLOSEFILE "Data.txt"ENDTRY

8 · Common ways to lose marks

  • A try round only the open, leaving the reading unprotected.
  • An except with no message.
  • Closing the file outside the structure, so it is skipped when an exception is raised.
  • Using except IOError and expecting it to catch int(Line) failing.
  • Forgetting int(), so the array holds strings.
  • Leaving out the exception handling when the question says to use it.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A save game that cannot be found

When a player presses Load and the save file has been deleted, the game says it cannot find the save and returns to the menu instead of closing.

Exam use: file not found caught, with a message.

A spreadsheet import with a bad row

A column of numbers has a text entry in row 40. The import stops at that row, reports it, and keeps the 39 rows already read.

Exam use: a ValueError during reading needs handling as well as the open.

A log written to a full disk

A write fails when there is no space. The program reports the failure and carries on instead of crashing.

Exam use: hardware or system failure while writing.

A database connection

Whether the query worked or not, the connection is closed afterwards so it does not stay open.

Exam use: finally closes the resource whatever happened.

A school mark file

A teacher's program reads marks from a file. If the file is missing it asks for another file name rather than stopping.

Exam use: except with a recovery action.

Top tips

  • Whole file work inside. Open, loop and close all go inside the try.
  • Add a message. An except with no message or action loses the mark.
  • Match the exception. IOError for files, ValueError for int(). Or use a bare except.
  • Convert each line. int(Line) before storing numbers.
  • Close properly. Inside the try, or in finally.
  • Read the question. If it says use exception handling, it is a mark point.
