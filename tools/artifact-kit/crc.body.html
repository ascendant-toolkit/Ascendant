Cyclic Redundancy Checks

How a packet's trailer lets the receiving computer check the payload: count the 1-bits, store the total as a hex value, recount on arrival, and compare.

The big idea

A cyclic redundancy check (CRC) is an error checking method used to check data packets. The sending computer works out a number from the payload and stores it in the trailer. The receiving computer works out the same number from the payload it received and compares the two. Same: no transmission error. Different: the packet is sent again.

Where it sits in a packet

A packet has three parts. The header holds things like the destination and the packet number. The payload is the actual data being sent. The trailer marks the end of the packet and holds the error check value.

Headeraddresses, packet no.
Payloadthe data (bits)
TrailerCRC value (hex)

The method, step by step

Sending computer

  1. Add up all the 1-bits in the payload.
  2. Write that total as a hex value.
  3. Store the hex value in the trailer and send the packet.

Receiving computer

  1. When the packet arrives, recalculate the number of 1-bits in the payload.
  2. Check this value against the one sent in the trailer.
  3. If the two values match, no transmission errors have occurred. Otherwise the packet needs to be re-sent.

Worked example

The payload is 4 bytes: 11110110 01111011 10111101 11111111

Total26

26 in hex is 1A (26 = 1 × 16 + 10, and 10 is A). The trailer stores 1A.

On arrival the receiver counts again. If it gets 26, it writes 1A, which matches the trailer, so no error. If a bit was damaged and it counts 25 (hex 19), then 19 ≠ 1A, so the packet is re-sent.

Counting to hex

Hex (base 16) uses the digits 0 to 9 then A to F, where A = 10, B = 11, C = 12, D = 13, E = 14, F = 15. To convert a decimal total to hex, divide by 16. The whole number is the left digit and the remainder is the right digit.

Total of 1-bitsWorkingHex
90 × 16 + 99 (or 09)
130 × 16 + 13 (D)D (or 0D)

Why bother with hex?

A total like 26 would need 5 bits. Hex is a compact way of writing the number, and it is easy to convert to and from binary. It keeps the trailer short, whatever the size of the payload.

What the check can and cannot show

It can

  • Spot a packet where the number of 1-bits has changed, such as a single 1 turning into a 0.
  • Trigger a re-send, because a mismatch tells the receiving computer something went wrong (this works with the ARQ process).

It cannot

  • Say which bit is wrong. It only says the packet is wrong.
  • Spot every error. If one 1 becomes a 0 and one 0 becomes a 1, the count is unchanged, so the values match and the error is missed. Try it in the Explore tab.

Loading a web page

The page reaches you as many packets. Each packet carries a check value in its trailer. A packet that fails the check is thrown away and requested again, so you rarely see a broken page.

Downloading a file

A large download is split into packets. If one packet is damaged on the way, only that packet is re-sent, not the whole file.

Radio signals suffer interference, so some packets arrive damaged. The receiving device finds this with the check and asks for the packet again.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 State 2 marks State what a cyclic redundancy check (CRC) is used for, and which part of a packet stores the check value.
ReminderPurpose, then location.
It is used to check data packets for transmission errors. The check value is stored in the trailer.
Common mistakeSaying the header. The header holds addresses and packet numbers.
Q2 Describe 4 marks Describe how a CRC is used to check for errors in a data packet.
ReminderSender adds up and stores; receiver recalculates and compares; say what happens in each case.
The sending computer adds up all the 1-bits in the payload and stores the total as a hex value in the trailer before the packet is sent. When the packet arrives, the receiving computer recalculates the number of 1-bits in the payload. It checks this value against the one sent in the trailer. If the two values match, no transmission errors have occurred; otherwise the packet needs to be re-sent.
Common mistakeCounting the 1-bits in the whole packet. It is the payload only.
Q3 Calculate 3 marks A payload contains three bytes: 10110010 01101110 11010001. Work out the value stored in the trailer.
ReminderCount the 1-bits in each byte, add them, then convert to hex.
10110010  →  4
01101110  →  5
11010001  →  4
total        13   → hex D (or 0D)
Counts the 1-bits in each byte: 4, 5 and 4. Total = 13. Hex value = D (accept 0D).
Common mistakeWriting 13 in the trailer. The value is stored as hex, so 13 becomes D.
Q4 Explain 3 marks A packet arrives with the payload 11110110 01111011 10111101 11111011 and the trailer value 1A. Explain what the receiving computer does and what the result will be.
ReminderRecount, convert, compare, then say what the result means.
It counts the 1-bits in the payload: 6 + 6 + 6 + 7 = 25. 25 in hex is 19, which it compares with the trailer value 1A. The values do not match, so the packet has an error and needs to be re-sent.
Common mistakeComparing 25 with 1A. Convert to hex first, or convert 1A to 26.
Q5 Explain 2 marks A packet is corrupted, but the receiving computer finds that the values match. Explain how this could happen.
ReminderThink about what is being counted.
Two (or more) bits may have changed, for example one 1 became 0 and one 0 became 1. The number of 1-bits is therefore the same, so the recalculated value matches the trailer and the error is not found.
Common mistake"The check is always right". It only compares the count of 1-bits.
Q6 Describe 2 marks State what happens when the receiving computer finds that the two values do not match.
ReminderTwo things: the packet is not accepted, and the sender is involved.
The receiving computer knows an error occurred in transmission. The packet needs to be re-sent (the sender is asked to send it again).
Common mistakeSaying the receiver corrects the packet. It cannot tell which bit is wrong.
Q7 Calculate 2 marks (a) Convert 27 to hex. (b) Convert hex 2C to decimal.
ReminderHex digits are worth 16 and 1.
(a) 27 = 1 × 16 + 11, so 1B. (b) 2C = 2 × 16 + 12 = 44.
Common mistakeForgetting that B = 11 and C = 12.
Q8 Explain 2 marks Explain why the CRC value is stored in the trailer as a hex value.
ReminderIt is about size and convenience.
Hex is a compact way to write a number, so the trailer stays short. It is also easy to convert to and from binary.
Common mistakeSaying hex is "more secure". It is only a different way to write the number.

Top tips

  • Count 1-bits in the payload only, not the header or trailer.
  • Count the 1s, never the 0s.
  • Store it as hex. Convert the total before you write it in the trailer.
  • Two calculations. Sender counts and stores; receiver counts again and compares.
  • Match means no error found. No match means re-send.
  • Know the weakness. Two changes that cancel out (a 1 to 0 and a 0 to 1) keep the count the same, so the error is missed.
  • Show your counting byte by byte. Method marks are available.
  • Link it up: a mismatch leads to a negative acknowledgement and a re-send (ARQ).
