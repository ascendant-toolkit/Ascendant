Single-Table Databases

Tables, fields and records, defining a single-table database from storage requirements, and validation of data.

The big idea

A database stores data in a table: each record is a row and each field is a column. Designing a table means choosing fields, data types, validation and a key.

9.1 Single-table databases

A database is an organised collection of data that can be searched, sorted and updated easily. In IGCSE Computer Science you work with a single-table database: all the data is stored in one table.

Table

The whole collection of data, laid out in rows and columns.

Field

A column: one type of data about every item, such as Name or Year. Each field has a field name, shown at the top of the column.

Record

A row: all the data about one item, such as one student.

Data item

A single value where a record and a field meet, such as "Ana Lee".

Defining a database from storage requirements

Given a description of the data a system must store, you design the table in these steps:

  1. Decide what each record is about: one student, one book, one pet.
  2. List the fields: one piece of data per field. Split data that you may want to search or sort separately (for example FirstName and Surname, rather than one Name field).
  3. Choose a clear field name for each field.
  4. Choose a suitable data type for each field (see 9.2).
  5. Choose the validation each field needs.
  6. Choose a primary key, a field that is unique for every record (see 9.2).

Validation in a database

Validation checks stop impossible data being stored. The checks are the ones from 7.4: range, length, type, presence, format and check digit. They check that data is reasonable, not that it is correct: Year 12 passes a range check even if the student is in Year 9.

Why use a database?

  • Records can be searched and sorted quickly.
  • Data can be validated as it is entered.
  • It takes less space than paper and is easier to update.
  • Several people can use the same data.

Exam-style questions

Q1 Define 3 marks Define the terms (a) table, (b) record and (c) field.
ReminderRows and columns.
(a) A table is a collection of data stored in rows and columns. (b) A record is a row: all the data about one item. (c) A field is a column: one type of data about each item.
Common mistakeMixing up rows and columns. A record is a row, a field is a column.
Q2 State 4 marks A library stores the title, author, year of publication and whether each book is on loan. Suggest a suitable field name for each of four fields.
ReminderClear field names.
Title Author YearPublished OnLoan (or similar)
Common mistakeUsing vague names such as "Info".
Q3 Explain 2 marks A database stores the name of each customer in one field. Explain why it may be better to use separate fields for first name and surname.
ReminderSearch and sort.
So that records can be sorted (or searched) by surname or first name separately. Each field then holds one piece of data.
Common mistakeSaying "to save space".
Q4 Name 3 marks A field called Year must contain a whole number from 7 to 13. Name the validation check and describe a type check on the same field.
ReminderRange, then type.
Range check The range check ensures the number is between 7 and 13. A type check ensures the value entered is an integer (not text).
Common mistakeDescribing verification checks.
Q5 Explain 2 marks Explain why a validation check does not guarantee that the data in a record is correct.
ReminderValid is not the same as correct.
Validation only checks data is reasonable (allowed). A wrong value, such as Year 12 for a Year 9 student, would still pass.
Common mistakeSaying validation is "never" useful.
Q6 Describe 3 marks A school wants a database of its students. Describe the steps in defining the table.
ReminderFields, types, validation, key.
Decide the fields needed (for example name, year, form). Choose a data type and validation for each field. Choose a primary key (such as a StudentID) that is unique for each record.
Common mistakeDescribing how to use the finished database.
Q7 State 2 marks A table has 30 records and 6 fields. State how many field names it has and how many records.
ReminderCount.
6 field names (one for each field) 30 records
Common mistakeGiving the number of data items (180) instead.

Top tips

  • Record = row. Field = column.
  • One piece of data per field: separate first name and surname.
  • Choose field names, data types and validation for each field.
  • Validation checks that data is reasonable, not that it is correct.
  • Every table needs a primary key. It is unique for each record.
