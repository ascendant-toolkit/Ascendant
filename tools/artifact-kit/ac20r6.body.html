Containment: Objects Inside Objects

Coursebook: Chapter 20 · Further programming, section 20.1 Programming paradigms

What containment (aggregation) is, how a Hand holds Cards, the order objects are created in, how to chain calls through a contained object, and how it differs from inheritance; animations, labs and review questions.

This page in five sentences

Containment (also called aggregation) is when one class has an attribute that is an object of another class, or an array of them. It is a "has a" relationship: a Hand has Cards. The contained objects are created first and passed to the container's constructor. The container reaches them through its own methods, and a call can be chained: MyHand.GetCard(2).GetNumber(). Containment is different from inheritance, which is "is a".

1 · A Hand that contains Cards

Python

class Card:    # Number : INTEGER    # Colour : STRING    def __init__(self, NewNumber, NewColour):        self.__Number = NewNumber        self.__Colour = NewColour    def GetNumber(self):        return self.__Number    def GetColour(self):        return self.__Colour class Hand:    # Cards : ARRAY[0:4] OF Card    def __init__(self, Card1, Card2, Card3, Card4, Card5):        self.__Cards = [Card1, Card2, Card3, Card4, Card5]    def GetCard(self, Position):        return self.__Cards[Position]

2 · Creating them in the right order

C1 = Card(4, "Red")C2 = Card(9, "Blue")C3 = Card(2, "Red")C4 = Card(7, "Green")C5 = Card(1, "Blue")MyHand = Hand(C1, C2, C3, C4, C5)

The Hand needs the Cards to exist before its constructor runs, because they are passed in as arguments. Creating the Hand first would leave nothing to pass.

3 · Reaching a contained object

ThirdCard = MyHand.GetCard(2)         # a Card objectprint(ThirdCard.GetNumber())          # 2print(MyHand.GetCard(2).GetNumber())  # the same, chained

Read the chain left to right: the Hand returns a Card, then that Card is asked for its number. The Hand never needs to know how a Card stores its number.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Cards, hands and a deck

A Hand holds five Cards and asks each one for its number and colour. A Deck holds many Cards. The Cards know nothing about the Hand.

Exam use: classic containment: objects working through their methods.

A school and its classes

A School object holds Class objects and each Class holds Student objects. A report asks the School, then the Class, then the Student.

Exam use: objects inside objects, with a chain of calls.

A car and its parts

A Car has an Engine, four Wheels and a Radio. Each part is its own class with its own methods.

Exam use: 'has a' for each part.

A linked list

A LinkedList holds Node objects, and each Node holds data and a pointer to the next Node.

Exam use: data structures are often built from containment.

Top tips

  • Say has a. A Hand has Cards. Use that wording in your answer.
  • Contained objects first. Create them, then the container.
  • Chain left to right. MyHand.GetCard(2).GetNumber(): Hand first, then Card.
  • Count from 0. The last of five is position 4.
  • Don't use inheritance. A Hand is not a Card.
