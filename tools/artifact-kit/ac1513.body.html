Virtual Machines

Coursebook: Chapter 15 · Hardware and virtual machines, section 15.1 Processors, parallel processing and virtual machines

What a virtual machine is, the host and guest operating systems and the hypervisor, benefits and limitations with reasons; animations, a resource-sharing lab and the real Paper 3 questions from 2022 to 2026.

This page in five sentences

A virtual machine (VM) is a software emulation of a computer system: a standalone environment, with all the components of a real computer, that runs on a physical host computer and behaves like a different machine. The host's operating system controls the real hardware, and a hypervisor (VM software) runs between the host and the guest operating system, creating the virtual machines and sharing the host's RAM, processor time and storage between them. Benefits include running software for a different system, trying software safely (a crash or virus is contained), and saving the cost of extra hardware. Limitations include poorer performance than a real machine, the complexity of setting up and maintaining it, and that some hardware cannot be emulated. The exam asks you to describe a VM, give benefits and limitations, and explain the roles of the host and guest operating systems.

1 · What a virtual machine is

  • The emulation of a computer system (hardware and/or software) using a host computer.
  • It is a standalone environment running on a physical computer; it is not a physical machine, but it contains all the components of one (processor, memory, storage, devices), all simulated.
  • A guest operating system runs inside the virtual machine. Several virtual machines, with different guest operating systems, can run on one host.
  • The host provides the real resources (RAM, processor, storage) and shares them between the virtual machines.
Layer (from the bottom)Role
Physical hardwareThe real processor, RAM and storage
Host operating systemThe normal operating system of the host computer. It has control of all the resources of the host and can access its physical hardware. It also provides a user interface to operate the VM software and runs the VM software
Hypervisor / VM softwareRuns between the host and guest operating systems; creates and runs the virtual machines and allocates host resources to them
Virtual machine (guest OS)The guest operating system runs within the virtual machine, under the control of the host. It controls the virtual hardware during the emulation, reaches the real hardware through the VM and the host OS, and gives the emulated system its own user interface
ApplicationsPrograms running inside the guest

2 · Benefits

BenefitExplanation
CompatibilitySoftware or legacy applications that do not run on the host can run in a guest operating system that they do work on; different instruction set architectures can be emulated on one computer; software can be tried on different operating systems on the same hardware
ProtectionThe guest operating system can crash without affecting the host or other VMs, so a new or suspicious program can be tested safely: if it has a virus it only infects the VM. Easier recovery
CostNo need to buy extra computers or hardware to test or run another system: several VMs run on the same hardware
FlexibilityMore than one operating system can coexist on a single computer; a new system can be tried before the hardware is bought

3 · Limitations

LimitationExplanation
PerformanceA VM is less efficient than a real machine: there is extra code to run, it accesses hardware indirectly through the host, and the resources (RAM, processor time) are shared. Many VMs on a weak host slow each other down. Response times cannot be measured accurately on a VM
Complexity / maintenanceSetting up and maintaining a VM is complex and can be expensive: both the host and the VM need to be maintained and updated
Hardware / software issuesSome hardware cannot be emulated (especially new hardware), or the host's hardware cannot be accessed directly. A VM depends on the features of the host and can be affected by its weaknesses

4 · Common ways to lose marks

  • Saying a VM is "a computer in the cloud" or "a copy of a computer". It is an emulation by software on a host.
  • Giving "it is slower" without a reason: extra code, indirect access to hardware, shared resources.
  • Giving "it is cheaper" with no explanation. Say no extra hardware has to be bought.
  • Mixing up the host and guest operating systems: the host controls the real hardware; the guest runs inside the VM.
  • Stating a benefit and a limitation that are the same point twice.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Running Windows software on a Mac

A VM runs Windows as a guest on a Mac. A program that only works on Windows can be used without buying a second computer.

Exam use: benefit: runs software not compatible with the host, and saves the cost of extra hardware.

Testing a suspicious download

A security analyst opens a file inside a VM. If it contains malware, it can only infect the VM, which is then deleted. The host is untouched.

Exam use: benefit: the guest can crash or be infected without affecting the host.

Cloud servers

A cloud provider runs many customers' virtual servers on the same physical machines. Each customer sees a separate computer.

Exam use: several VMs share one host; the hypervisor allocates resources.

Running an old game or old program

Old software that needs an old operating system can run in a VM with that system as the guest, even though the host has a modern one.

Exam use: legacy applications run in a compatible guest operating system.

A slow virtual desktop

If ten virtual desktops share a host with too little RAM, each becomes slow, because they share the host's resources and every action goes through the VM software.

Exam use: limitation: reduced performance from shared resources and extra code.

Benefits and limitations

M/J 2022 · 9618/31, 33 · Q6 Describe 6 marks A virtual machine is used to emulate a new computer system. Describe two benefits and one limitation of using a virtual machine for this purpose.
ReminderTwo marks for each described benefit and two for the limitation: a point and its reason.

Benefits (2 marks each, max 4): The new system can be tried on different virtual hardware, without needing to buy the hardware It is easier to recover if the software emulating the new computer causes a crash, as the VM protects other software Programs for the new system that are not compatible with the host can be emulated using the guest operating system More than one new system can be emulated, so multiple operating systems can coexist on one computer Limitation (2 marks, max 2): A VM may not be able to emulate the new hardware, because that hardware may have been developed since the VM was written Extra code is executed, and resources such as RAM and processor time are shared, so performance is degraded Using a VM increases maintenance overheads, because both the host and the VM must be maintained

Common mistakeNaming a benefit without the second mark, which is the reason. Each benefit needs a point and why.

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Explain 2 marks Explain why a virtual machine is slower than running the same program on a real computer.
ReminderExtra layers and sharing.

Extra code (the VM software and guest OS) has to be run, and the hardware is accessed indirectly through the host. The resources, RAM and processor time, are shared with the host and other VMs.

Describe 3 marks A company wants to test new software for a different operating system. Describe how a virtual machine helps.
ReminderCompatibility, protection, cost.

A guest OS that the software works on is installed in a VM, so it can run on the existing computer. If the software crashes or has a fault, only the VM is affected, not the host. No extra computer has to be bought.

State 2 marks State two resources that the host shares with its virtual machines.
ReminderWhat a VM needs to run.

RAM / memory Processor time (also storage)

Distinguish 2 marks Distinguish between the host operating system and the guest operating system.
ReminderWhich controls the real hardware?

The host OS is the normal OS of the physical computer and controls all its resources. The guest OS runs inside the virtual machine, under the control of the host, and controls the virtual hardware.

Explain 3 marks Explain why running ten virtual machines on a small host might not be a good idea.
ReminderShared RAM and processor time.

Each VM needs RAM and processor time from the host. A small host may not have enough for all ten, so they compete. Every VM runs slowly, so performance is degraded.

Top tips

  • Benefit plus reason. 'Protection: a crash or virus stays in the VM and cannot affect the host.'
  • Limitation plus reason. 'Slower: extra code and shared resources.'
  • Know the layers. Hardware, host OS, hypervisor, virtual machine with guest OS.
  • Host and guest. Host controls the real resources; guest runs inside the VM.
  • Describe 'emulate'. A VM emulates a computer system in software.
  • Do not repeat a point. Give two different benefits and two different limitations.
