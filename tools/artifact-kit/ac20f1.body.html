Storing Records in a Serial or Sequential File

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

Turning a record into a line, appending to a serial file, sorting before writing a sequential file, and reading the records back; pseudocode and Python side by side, with step-by-step animations.

This page in five sentences

A record is a group of related fields (a student's ID, name and mark), and a file keeps many records after the program has ended. In a text file each record is stored as one line, made by joining the fields into a string with a separator such as a comma. A serial file stores the records in the order they arrive, so a new record is appended to the end with FOR APPEND. A sequential file stores them in order of a key field, so the records must be sorted by the key before they are written. Either file is read back from the start, one record after another, until EOF.

1 · A record in a program

Before a record can be stored it has to exist in the program. A record type groups the fields; one variable of that type holds one record.

Python

class TStudent:    def __init__(self, StudentID, Name, Mark):        self.StudentID = StudentID        self.Name = Name        self.Mark = Mark S = TStudent(104, "Aria", 72)

Pseudocode (exam style)

TYPE TStudent   DECLARE StudentID : INTEGER   DECLARE Name : STRING   DECLARE Mark : INTEGERENDTYPE DECLARE S : TStudentS.StudentID <- 104S.Name <- "Aria"S.Mark <- 72

2 · Turning a record into one line of text

A text file can only hold strings. Convert each number to a string (str() in Python, NUM_TO_STR() in pseudocode) and join the fields with a comma. The comma is the separator: it is what lets the fields be cut apart again when the line is read back.

Python

Line = str(S.StudentID) + "," + S.Name + "," + str(S.Mark)# Line is now "104,Aria,72"

Pseudocode (exam style)

Line <- NUM_TO_STR(S.StudentID) & "," & S.Name & "," & NUM_TO_STR(S.Mark)// Line is now "104,Aria,72"
Keep the format fixedEvery record must use the same fields, in the same order, with the same separator. If a name could contain a comma, choose a different separator, otherwise the line cannot be cut apart correctly.

3 · Storing a record in a serial file

Open the file for append, write the line, close the file. Append keeps every record already in the file and adds the new one after the last. If the file does not exist yet, append creates it.

Python

File = open("Students.txt", "a")File.write(Line + "\n")File.close()

Pseudocode (exam style)

OPENFILE "Students.txt" FOR APPENDWRITEFILE "Students.txt", LineCLOSEFILE "Students.txt"

write() does not add a new line by itself, so the "\n" ends the record. Without it the next record would run on to the same line.

4 · Storing records in a sequential file

The line format is exactly the same. What changes is the order: the records are sorted on the key field (StudentID) first, then written from the start of a new file, so each key is larger than the one before. Opening with FOR WRITE is right here because the whole file is being created.

Python

Students.sort(key=lambda Student: Student.StudentID)File = open("Students.txt", "w")for Student in Students:    File.write(str(Student.StudentID) + "," + Student.Name + "," + str(Student.Mark) + "\n")File.close()

Pseudocode (exam style)

// sort Students[1:Count] into StudentID order (for example a bubble sort)OPENFILE "Students.txt" FOR WRITEFOR Index <- 1 TO Count   Line <- NUM_TO_STR(Students[Index].StudentID) & "," & Students[Index].Name & "," & NUM_TO_STR(Students[Index].Mark)   WRITEFILE "Students.txt", LineNEXT IndexCLOSEFILE "Students.txt"

Adding one record to a file that is already in key order is a different job, because the new record has to go in the right place. That is on the next page, Adding a Record to a Sequential File.

6 · Reading the stored records back

Both kinds are read the same way: open for read, repeat until the end of the file, close. Each line is cut into fields and converted back to the right data types.

Python

File = open("Students.txt", "r")for Line in File:    Parts = Line.strip().split(",")    S = TStudent(int(Parts[0]), Parts[1], int(Parts[2]))File.close()

Pseudocode (exam style)

OPENFILE "Students.txt" FOR READWHILE NOT EOF("Students.txt")   READFILE "Students.txt", Line   S.StudentID <- STR_TO_NUM(LEFT(Line, 3))   // IDs are always 3 digits   // Name and Mark are cut out of Line with MID in the same wayENDWHILECLOSEFILE "Students.txt"

strip() removes the new line at the end of each line, and int() turns the text back into a number.

7 · Common ways to lose marks

  • Using FOR WRITE to add one record. It deletes every record already in the file. Use FOR APPEND.
  • Forgetting NUM_TO_STR or str() when joining a number to a string.
  • Forgetting the separator or the new line, so the fields run together.
  • Describing a serial file as "in order". Serial means the order added, not sorted.
  • Not closing the file.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A shop's till log

Every sale is added as a new line at the end of the day's file as it happens. Nothing is sorted, so recording is quick and no earlier sale is touched.

Exam use: serial file: records in the order they happened, added with APPEND.

A payroll file

Staff records are held in order of employee number. A program reads the file from the top once a month and produces payslips in that order.

Exam use: sequential file: sorted on the key field, processed from start to end.

Data logging from a sensor

A weather station writes a temperature line every minute. The file simply grows, and an analysis program reads it from the start later.

Exam use: serial file used for data logging.

A temporary transaction file

During the day orders are collected in a file in the order they arrive. Overnight they are sorted and merged into the main file, which is kept in order of customer number.

Exam use: serial for collecting, sequential for the master file.

Top tips

  • Name the order. Serial: the order added. Sequential: the order of a key field. Never swap them.
  • Say where a new record goes. Serial: the end of the file. Sequential: in its key position.
  • APPEND adds, WRITE replaces. Using WRITE to add a record loses the rest of the file.
  • One record, one line. Join the fields with a separator and end with a new line.
  • Convert numbers. str() or NUM_TO_STR() before joining; int() or STR_TO_NUM() after reading.
  • Always close. CLOSEFILE once the writing or reading is finished.
