Writing a Binary Tree with Classes

Coursebook: Chapter 20 · Further programming, section 20.1 Programming paradigms

A Node class and a Tree class: constructors, private pointers with getters and setters, containment, a CountTree child class and polymorphism; insert, search and in-order traversal with animations, a tree-building lab and review questions.

This page in five sentences

A binary tree is a structure where each item, a node, can point to at most two others: a left child and a right child. In a binary search tree every value in the left part is smaller than the node and every value in the right part is larger or equal, so searching can ignore half the tree at each step. In an object-oriented program it is written as two classes: a Node that holds one value and two pointers, and a Tree that holds the root node. Writing it uses every idea from the earlier pages: a constructor, private data, getters and setters, containment, and, for a variation, inheritance.

1 · Words to know

TermMeaning
NodeOne item in the tree: a value and two pointers
RootThe top node; the only one nothing points to
Left / right pointerWhere the left and right child are, or None (NULL in pseudocode) if there is none
LeafA node with no children: both pointers are empty
SubtreeA node and everything below it

The rule used on this page: a new value smaller than the node goes left; a value equal or larger goes right.

2 · Which concept does what

ConceptWhere it appears in the tree
ConstructorNode(NewData) sets the value and starts both pointers empty. Tree() starts with no root
EncapsulationData and pointers are private. Other code uses the methods
Getters and settersGetData, GetLeft, GetRight, SetLeft, SetRight
ContainmentThe Tree has a root Node, and each Node has a left and right Node
InheritanceA CountTree is a Tree that also counts its insertions
PolymorphismInsert() is called the same way on a Tree or a CountTree, and each does its own version

3 · The Node class

Python

class Node:    # Data : INTEGER    # LeftPointer : Node    # RightPointer : Node    def __init__(self, NewData):        self.__Data = NewData        self.__LeftPointer = None        self.__RightPointer = None     def GetData(self):        return self.__Data    def GetLeft(self):        return self.__LeftPointer    def GetRight(self):        return self.__RightPointer    def SetLeft(self, NewLeft):        self.__LeftPointer = NewLeft    def SetRight(self, NewRight):        self.__RightPointer = NewRight

Pseudocode (exam style)

CLASS Node  PRIVATE Data : INTEGER  PRIVATE LeftPointer : Node  PRIVATE RightPointer : Node  PUBLIC PROCEDURE NEW(NewData : INTEGER)    Data <- NewData    LeftPointer <- NULL    RightPointer <- NULL  ENDPROCEDURE  PUBLIC FUNCTION GetData() RETURNS INTEGER    RETURN Data  ENDFUNCTION  PUBLIC FUNCTION GetLeft() RETURNS Node    RETURN LeftPointer  ENDFUNCTION  PUBLIC FUNCTION GetRight() RETURNS Node    RETURN RightPointer  ENDFUNCTION  PUBLIC PROCEDURE SetLeft(NewLeft : Node)    LeftPointer <- NewLeft  ENDPROCEDURE  PUBLIC PROCEDURE SetRight(NewRight : Node)    RightPointer <- NewRight  ENDPROCEDUREENDCLASS

The constructor takes only the value. The two pointers are fixed starting values: a new node has no children yet. The setters exist so the Tree can attach children later, because the Node's pointers are private.

4 · The Tree class: constructor and Insert

Python

class Tree:    # Root : Node    def __init__(self):        self.__Root = None     def Insert(self, NewData):        NewNode = Node(NewData)        if self.__Root is None:            self.__Root = NewNode        else:            Current = self.__Root            Placed = False            while not Placed:                if NewData < Current.GetData():                    if Current.GetLeft() is None:                        Current.SetLeft(NewNode)                        Placed = True                    else:                        Current = Current.GetLeft()                else:                    if Current.GetRight() is None:                        Current.SetRight(NewNode)                        Placed = True                    else:                        Current = Current.GetRight()

Pseudocode (exam style)

CLASS Tree  PRIVATE Root : Node  PUBLIC PROCEDURE NEW()    Root <- NULL  ENDPROCEDURE  PUBLIC PROCEDURE Insert(NewData : INTEGER)    NewNode <- NEW Node(NewData)    IF Root = NULL      THEN        Root <- NewNode      ELSE        Current <- Root        Placed <- FALSE        WHILE Placed = FALSE          IF NewData < Current.GetData()            THEN              IF Current.GetLeft() = NULL                THEN                  Current.SetLeft(NewNode)                  Placed <- TRUE                ELSE                  Current <- Current.GetLeft()              ENDIF            ELSE              IF Current.GetRight() = NULL                THEN                  Current.SetRight(NewNode)                  Placed <- TRUE                ELSE                  Current <- Current.GetRight()              ENDIF          ENDIF        ENDWHILE    ENDIF  ENDPROCEDUREENDCLASS

Notice what the Tree never does: it never touches __Data or a pointer directly. It calls GetData(), GetLeft() and SetLeft(). That is encapsulation at work. The new node is created before it is attached, as in containment.

5 · Search and in-order traversal

Python

    def Search(self, Target):        Current = self.__Root        while Current is not None:            if Target == Current.GetData():                return True            elif Target < Current.GetData():                Current = Current.GetLeft()            else:                Current = Current.GetRight()        return False     def InOrder(self):        self.__TraverseFrom(self.__Root)     def __TraverseFrom(self, ThisNode):        if ThisNode is not None:            self.__TraverseFrom(ThisNode.GetLeft())            print(ThisNode.GetData())            self.__TraverseFrom(ThisNode.GetRight())

Pseudocode (exam style)

  PUBLIC FUNCTION Search(Target : INTEGER) RETURNS BOOLEAN    Current <- Root    WHILE Current <> NULL      IF Target = Current.GetData()        THEN          RETURN TRUE        ELSE          IF Target < Current.GetData()            THEN              Current <- Current.GetLeft()            ELSE              Current <- Current.GetRight()          ENDIF      ENDIF    ENDWHILE    RETURN FALSE  ENDFUNCTION   PUBLIC PROCEDURE InOrder()    CALL TraverseFrom(Root)  ENDPROCEDURE   PRIVATE PROCEDURE TraverseFrom(ThisNode : Node)    IF ThisNode <> NULL      THEN        CALL TraverseFrom(ThisNode.GetLeft())        OUTPUT ThisNode.GetData()        CALL TraverseFrom(ThisNode.GetRight())    ENDIF  ENDPROCEDURE

These two methods belong inside Tree. In-order visits the left subtree, then the node, then the right subtree, so a search tree prints in sorted order. The helper is private: outside code calls InOrder(), and the recursion inside is hidden.

7 · A child class: CountTree

A tree that also counts how many values have been inserted. It inherits everything and overrides Insert, calling the parent's version first.

Python

class CountTree(Tree):    # Count : INTEGER    def __init__(self):        super().__init__()        self.__Count = 0     def Insert(self, NewData):        super().Insert(NewData)        self.__Count = self.__Count + 1     def GetCount(self):        return self.__Count

Pseudocode (exam style)

CLASS CountTree INHERITS Tree  PRIVATE Count : INTEGER  PUBLIC PROCEDURE NEW()    SUPER.NEW()    Count <- 0  ENDPROCEDURE  PUBLIC PROCEDURE Insert(NewData : INTEGER)    SUPER.Insert(NewData)    Count <- Count + 1  ENDPROCEDURE  PUBLIC FUNCTION GetCount() RETURNS INTEGER    RETURN Count  ENDFUNCTIONENDCLASS

The child's constructor calls the parent's first (so the root is set up), then sets its own attribute. Because both classes have Insert, code that holds a list of trees can call Insert on each without checking which kind it is: polymorphism.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A sorted contact list

A phone stores names in a tree so searching does not have to check every contact. Each step of a search throws away about half of the remaining names.

Exam use: search follows one path down the tree.

A database index

A database keeps an index so it can find a record without reading the whole table. Many indexes use tree structures like this one.

Exam use: trees keep data in order for fast searching.

A game's decision tree

A computer opponent asks a yes or no question at each node, then follows the left or right branch to the next question.

Exam use: left and right pointers as two choices.

A file system

Folders contain folders and files, so a folder object holds other objects. A binary tree is the same idea with at most two children.

Exam use: containment: objects inside objects.

Top tips

  • Create the node first. Make the Node from the value, then find where to attach it.
  • Never touch the pointers directly. From Tree, always use GetLeft, GetRight, SetLeft and SetRight.
  • Check for empty first. An empty tree has Root = None. Handle it before looping.
  • Smaller left, larger or equal right. State the rule you are using in a comment.
  • Pointers start empty. A new Node's two pointers are None, not parameters.
  • Child tree: parent first. super().__init__() then your own attributes.
