Errors, Detection and Solutions Compared

Three questions every exam answer on this topic comes back to: what went wrong, how did the receiver find out, and what happens next. Compare the types of error, the checks that find them and the ways they are fixed.

The big idea

Treat every error as a chain of three links. The type of error decides which check can find it, and the check decides which solution is available. Most checks can only say "something is wrong". The usual solution is then to send the data again. Only a parity block can fix a bit by itself, and only a check digit protects against typing mistakes.

1 · The error

Corrupted, lost, gained, out of step, or mistyped.

2 · The detection

Parity, parity block, checksum, CRC, echo check, check digit.

3 · The solution

Re-send on request, re-send after a timeout, correct the bit, or re-enter the data.

1 · Types of error compared

Transmission errors

These happen on the way. The data was right when it was sent.

These happen before sending, when a person types a code or a scanner reads it wrongly.

The key contrastA transmission check asks "did the data arrive as it was sent?" It never asks "was it right in the first place?". A mistyped number that travels perfectly passes every transmission check. That is why data entry needs its own check, the check digit.

Contrasts worth learning

Parity bit v parity block

A parity bit says "this byte has an error". A parity block checks rows and columns, so it says "the error is here". The price is an extra parity byte for every block.

Parity v checksum v CRC

All three work out a small value from the data. They differ in the amount of data covered: parity covers one byte, a checksum covers a block, and a CRC covers a packet's payload and lives in its trailer.

Echo check v ARQ

An echo check sends all the data back. ARQ only sends a short acknowledgement. ARQ also copes with lost data through its timeout, which an echo check cannot do.

Transmission check v check digit

Parity, checksums, CRCs and echo checks compare the data received with the data sent. A check digit tests whether a number is valid, before anything is sent.

3 · Solutions compared

Finding an error is only half the job. These are the ways of dealing with it.

SolutionUsed whenHow it worksCost
Re-send on request (negative acknowledgement)A check such as a CRC, checksum or parity failsThe receiver tells the sender the data had an error and the sender sends it againExtra time and traffic
Re-send after a timeoutThe data, or the acknowledgement, never arrivesThe sender waits a set time; with no reply it re-sends automatically, up to a limitWaiting time
Correct the bitA parity block finds one bad bitThe wrong row and wrong column cross at the bad bit, so the receiver flips it backExtra parity data on every block
Re-enter or re-scanA check digit does not matchThe system rejects the number and the user types or scans it againUser time
Re-send after an echo mismatchThe returned copy differs from the originalThe sender sends the data againDouble traffic every time
ARQ is not a detection methodARQ does not find errors itself. It uses a detection code (such as a CRC) and then decides what to do: a positive acknowledgement means carry on, a negative acknowledgement or a timeout means re-send.

7 · Multiple choice

Descriptions are kept general. Real systems use more advanced calculations, but the ideas are the ones in the textbook.

Scanning shopping at the till

A scanner can misread a barcode. The last digit of the code is a check digit, so a misread fails the check and the till beeps for a re-scan instead of charging for the wrong item.

Exam use: a data entry check, and the solution is to re-scan.

Downloading a file

The file is split into packets, each with a check value. A damaged packet fails its check and only that packet is asked for again. A packet that never arrives is re-requested after a timeout.

Exam use: contrasts a failed check (negative acknowledgement) with a lost packet (timeout).

A video call

Live calls cannot wait for re-sends, so a lost packet often just becomes a glitch. Speed matters more than a perfect picture.

Exam use: a reminder that re-sending has a cost in time, which is why it is not always the answer.

Space probes and satellites

When a signal takes minutes or hours to arrive, waiting for a re-send is painful. These links add extra data that lets the receiver fix errors itself, which is the same idea as a parity block but much stronger.

Exam use: beyond the syllabus, but it shows why correction exists as well as detection.

Ordering a book online

An ISBN typed into a shop is checked using its final digit. A swapped pair of digits usually fails the check, so you are asked to look again before the order is made.

Exam use: transposition is one of the errors a check digit can usually detect.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 State 2 marks State two causes of errors when data is transmitted.
ReminderOne cause per mark. Any two from the list below.
Interference (on a cable or radio link) corrupting or losing data. Packets lost or gained during packet switching / skew in parallel transmission, where bits arrive out of step.
Common mistakeWriting "a virus" or "a hacker". Those are security threats, not transmission errors.
Q2 Explain 3 marks A user types the code 5037 instead of 5307. The data is then sent over a network and a checksum is used. Explain why the checksum does not find the mistake.
ReminderWhat does a transmission check actually compare?
The checksum checks that the data received is the same as the data sent. The mistake was made before the data was sent, so 5037 was already wrong when the checksum was calculated. 5037 arrives unchanged, so the checksums match and no error is found. A check digit would be needed at data entry.
Common mistakeSaying the checksum "does not work on numbers". It works fine; it is just answering a different question.
Q3 Compare 4 marks Compare the use of a parity bit in each byte with the use of a parity block.
ReminderCompare means similarities and differences. Put both methods in each point.
Both use an agreed parity (even or odd) so each byte has the right number of 1-bits. Both can detect a single changed bit. A parity bit only shows which byte has the error, whereas a parity block checks rows and columns so it can find the position of the bad bit. A parity block needs an extra parity byte for each block, whereas a parity bit alone needs no extra byte.
Common mistakeDescribing each method separately and never linking them with "whereas" or "both".
Q4 Compare 4 marks Compare an echo check with an automatic repeat request (ARQ).
ReminderThink about what travels back to the sender, and what happens if data is lost.
Both involve the receiver sending something back to the sender, and both lead to the data being sent again if an error is found. An echo check sends a copy of all the data back, whereas ARQ sends only a short acknowledgement. An echo check therefore doubles the amount of data sent, whereas ARQ uses little extra traffic. ARQ uses a timeout so it can re-send data that was lost, whereas an echo check cannot tell whether the error happened on the way there or the way back.
Common mistakeSaying ARQ detects the error. It relies on a code such as a CRC to do that.
Q5 Explain 3 marks A whole packet is lost on its way to the receiver. Explain why a CRC does not find this and how the sender finds out.
ReminderWhat would the receiver need in order to run the check?
The CRC is checked on the packet that arrives, and a lost packet never arrives, so there is nothing to recount or compare. The sender does not receive an acknowledgement. When the timeout runs out, the sender re-sends the packet automatically.
Common mistakeSaying the receiver sends a negative acknowledgement. It cannot reply about a packet it never saw.
Q6 Describe 3 marks Describe how a parity block can correct a single changed bit without the data being sent again.
ReminderRows, columns, then the fix.
Each byte has a parity bit (row check) and an extra parity byte holds the column checks. When one bit changes, one row and one column have the wrong parity, and the bad bit is where they cross. The receiver changes that bit back (0 to 1 or 1 to 0).
Common mistakeClaiming it can fix two or more bits. With more errors, the crossing points are ambiguous.
Q7 Suggest 4 marks A librarian types ISBNs into a system, and the system sends the day's records to a central server. Suggest a suitable error check for each task and give a reason.
ReminderOne check and one reason for each task. Match entry to entry, transmission to transmission.
Typing the ISBNs: a check digit. It is recalculated on entry and finds mistakes such as a wrong, swapped or missing digit. Sending the records: a checksum (or CRC) with ARQ. The server recalculates the value and, if it does not match, asks for the data to be sent again.
Common mistakeSuggesting a parity bit for the typing task. Parity checks bytes in transit, not typed codes.
Q8 Identify 3 marks A block of four bytes was sent with even parity. The fourth line is the parity byte (column check). One bit changed in transit. Identify which bit changed and what it should be.
byte 1   0 1 1 0 1 1 1 1
byte 2   1 1 1 0 0 1 0 0
byte 3   0 1 0 1 1 0 1 1
byte 4   1 0 1 1 1 0 1 1
parity   0 1 1 0 0 0 1 1
ReminderFind the row with the wrong parity, then the column.
byte 1: six 1s   OK        byte 3: five 1s  WRONG
byte 2: four 1s  OK        byte 4: six 1s   OK
column 5: 1+0+1+1 = 3 (odd) but parity byte says 0  WRONG
Byte 3 has an odd number of 1-bits, so the error is in byte 3. Column 5 (the fifth bit from the left) has the wrong parity. The bit at byte 3, column 5 should be 0 (it was changed from 0 to 1).
Common mistakeFinding only the row. The row says which byte; you need the column too.
Q9 Explain 2 marks Explain why a sender using ARQ needs a timeout.
ReminderWhat if neither acknowledgement ever arrives?
The data, or the acknowledgement, could be lost, so the sender would wait forever without a timeout. When the timeout expires with no acknowledgement, the sender re-sends the data automatically.
Common mistakeSaying the timeout is how long the receiver waits. The sender does the waiting.

Top tips

  • Work down the chain: error, then check, then solution. Name all three when a question asks "what happens".
  • Detect is not correct. Almost every check only detects. The fix is a re-send.
  • Only a parity block can pinpoint and fix a bit (one error, row and column cross).
  • Lost data needs the timeout. Checks only examine what arrives.
  • Check digits are for typing and scanning; parity, checksum, CRC and echo are for transmission.
  • Compare = both sides in every point. Use whereas, both, while.
  • Name the weakness. A parity bit misses an even number of flips; a CRC misses a swapped 1 and 0; an echo check cannot say which journey failed.
  • Do not say a method "prevents" errors. It finds them after they happen.
