This page in five sentences

Structured programming breaks a program into named, self-contained subroutines (also called modules): a procedure does a task, and a function does a task and returns a value. Data is passed in through parameters; the values supplied when the subroutine is called are the arguments. A local variable exists only inside its subroutine, while a global variable can be used anywhere. Subroutines mean a repeated or separate task is written once, tested on its own and reused, so the program is shorter and easier to understand, test and maintain. A program is also easier to read when it uses meaningful names, indentation and white space, capitalised keywords and comments.

Use a function when the subroutine produces a single result (a check, a calculation). Use a procedure when it performs an action (output, write to a file, change several values).

2 · Parameters

  • In the header the names are parameters, each with a data type: PROCEDURE MyProc(Count : INTEGER, Message : STRING). Parameters pass values into the subroutine; this makes it reusable with different data.
  • By value (BYVAL, the default): the subroutine gets a copy, so changing it does not change the caller's variable.
  • By reference (BYREF): the subroutine works on the caller's variable itself, so a change is seen by the caller. It is how a procedure can send back more than one value: PROCEDURE Mod_X(T4 : INTEGER, BYREF P3 : REAL).
  • The arguments in the call must match the parameters in number, order and type.

3 · Local and global variables

  • Local: declared inside the subroutine; it exists only while it runs, cannot be changed by other subroutines, and its name can be reused elsewhere. This is the better choice.
  • Global: declared outside any subroutine; any part of the program can use or change it, so it is harder to test and a fault can appear in any subroutine that touches it. A global is sometimes used for data shared by many parts (a list of settings).
  • A fault with a global variable is exposed by testing different paths, for example data that does and does not cause the assignment to happen.

4 · Why use subroutines (and library routines)?

  • A task repeated or reused in several places is written once.
  • Each subroutine does one specific job: the program is simpler, and each part is easier to test, debug and maintain.
  • Different programmers can write different subroutines at the same time.
  • Library routines are ready-made subroutines: they are tried and tested, do things you may not be able to program yourself (encryption), and save development time.

5 · Writing readable programs

Meaningful identifier names, indentation and blank lines (white space), capital letters for keywords, and comments that explain why. These make the code easier to read, understand, debug and maintain.

6 · Reading code in the exam

Questions give a numbered listing and ask for: a line with an initialisation (a variable set before a loop, such as OutString ← ""), the start of a repeating block (the FOR or WHILE line), a logic operation (AND, OR, NOT), the number of parameters a function takes (MID takes three), the type of loop, and what could be simplified. NOT((c < 'a') OR (c > 'z')) simplifies to (c >= 'a') AND (c <= 'z').

Common ways to lose marks

  • Writing "function" for a module that does not return a value, or the other way round.
  • Saying a parameter and an argument are the same without the context: parameters are in the header, arguments in the call.
  • Forgetting RETURNS and the type in a function header, or the RETURN statement itself.
  • Using a global variable when a parameter or a local variable would do.

Top tips

  • Function = returns. Write RETURNS and the type, and a RETURN statement.
  • Parameter or argument. Header or call.
  • BYREF changes the original. BYVAL works on a copy.
  • Prefer local. Pass values in with parameters.
  • Read the listing. Initialise before the loop; the loop line starts the repeating block.
  • Library routines. Tested, hard to write, quick to use.
