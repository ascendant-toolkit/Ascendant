Data Types and Records

Coursebook: Chapter 10 · Data types and structures · section 10.1 Data types and records

The six data types, records declared with TYPE and ENDTYPE, arrays of records and dot notation, unused elements, and procedures that loop through records, with animations, an attendance lab and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

Pseudocode has six basic data types: INTEGER (whole numbers), REAL (numbers with a decimal point), CHAR (one character, in single quotes), STRING (text in double quotes), BOOLEAN (TRUE or FALSE) and DATE. A record is a user-defined composite data type that stores items of different data types under one identifier; you declare it with TYPE ... ENDTYPE, and access a field with dot notation, Staff[Index].Attendance. A 1D array of records stores many records, each reached by an index, so a loop can process every record. Unused array elements are marked with a standard impossible value (for example EmployeeNumber = −1 or an empty string) so they can be skipped when processing. Exam questions ask you to declare the record and the array, state the benefits of an array of records, and write a procedure or function that loops through the array.

2 · Records

TYPE Employee   DECLARE EmployeeNumber : INTEGER   DECLARE Name : STRING   DECLARE Department : STRING   DECLARE Born : DATE   DECLARE Attendance : REALENDTYPE DECLARE Staff : ARRAY [1:500] OF EmployeeStaff[3].Attendance ← 92.5OUTPUT Staff[3].Name

Benefits of an array of records: different data types are held for each item under a single identifier; a loop can go through every record (iteration) and an index gives direct access to one record; the code is simpler, with less duplication, so it is easier to write, understand, test and maintain.

Unused elements. If the array is bigger than the number of records, mark unused elements in a standard way: give a field an impossible value (an EmployeeNumber less than 1, an empty string for the name, a weight of zero or less). It is good practice because unused elements can then be recognised when processing or searching; otherwise they may contain old or unexpected data.

3 · Processing an array of records

The standard pattern: declare a loop counter, loop through every element, skip unused records, test the field with dot notation, and output or count.

PROCEDURE Absentees()   DECLARE Index : INTEGER   FOR Index ← 1 TO 500      IF Staff[Index].EmployeeNumber <> -1 THEN         IF Staff[Index].Attendance <= 90 THEN            OUTPUT Staff[Index].EmployeeNumber            OUTPUT Staff[Index].Name         ENDIF      ENDIF   NEXT IndexENDPROCEDURE

Common ways to lose marks

  • Declaring a numeric ID like "AB1234" as INTEGER, or a percentage as INTEGER instead of REAL.
  • Writing Staff.Attendance or Staff[Attendance]. The record is the array element: Staff[Index].Attendance.
  • Forgetting ENDTYPE, or declaring the array without the record type: ARRAY [1:500] OF Employee.
  • Not skipping unused records, or not saying how they are indicated.
  • Looping to the wrong limit: loop to the declared size of the array.

Top tips

  • Type from the example and comment. ID with letters: STRING.
  • TYPE ... ENDTYPE. Then DECLARE the array OF the type.
  • Dot notation. Array[Index].Field
  • Skip unused records. Say how they are marked.
  • Loop to the array size. FOR Index ← 1 TO 500.
  • Three benefits. Mixed types, loops, simpler code.
