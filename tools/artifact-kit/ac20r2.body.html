Encapsulation: Hiding the Data

Coursebook: Chapter 20 · Further programming, section 20.1 Programming paradigms

What encapsulation means, private and public in Python and pseudocode, how outside code gets at hidden data, and why hiding it is useful; animations, labs and review questions.

This page in five sentences

Encapsulation means two things at once: the attributes and the methods are bundled together in one class, and the data is hidden so it can only be reached through the class's own methods. The attributes are declared private; the methods that other code is allowed to use are public. Outside code has to ask the object, using a getter, rather than reaching in and taking the value. The class can check values on the way in, so the object stays valid. The inside of the class can later change without breaking the code that uses it.

1 · Private and public

Python

class Pet:    # PetName : STRING    # Age : INTEGER    def __init__(self, NewName, NewAge):        self.__PetName = NewName    # private        self.__Age = NewAge         # private     def GetAge(self):               # public        return self.__Age    def SetAge(self, NewAge):       # public        if NewAge >= 0 and NewAge <= 40:            self.__Age = NewAge

Pseudocode (exam style)

CLASS Pet  PRIVATE PetName : STRING  PRIVATE Age : INTEGER  PUBLIC PROCEDURE NEW(NewName : STRING, NewAge : INTEGER)    PetName <- NewName    Age <- NewAge  ENDPROCEDURE  PUBLIC FUNCTION GetAge() RETURNS INTEGER    RETURN Age  ENDFUNCTION  PUBLIC PROCEDURE SetAge(NewAge : INTEGER)    IF NewAge >= 0 AND NewAge <= 40      THEN        Age <- NewAge    ENDIF  ENDPROCEDUREENDCLASS

2 · Reaching a private attribute

MyPet = Pet("Rex", 3)print(MyPet.__Age)       # AttributeError: not reachable from outsideprint(MyPet.GetAge())    # 3: ask the object through its public method

Python does not lock the attribute: the double underscore renames it behind the scenes. For the exam, treat a double-underscore attribute as private and always go through a method.

3 · Why hide the data?

Protect the data

No code can set an age of -5 by accident, because the only way in is SetAge, which checks the value.

Change the inside safely

If Age is later stored as a birth year, only the class changes. Code that calls GetAge() keeps working.

One place to look

Everything that can change a Pet is written in the Pet class, so bugs are easier to find.

Simple to use

The rest of the program only needs to know the public methods, not how the data is stored.

Encapsulation is about the data hiding. Getters and setters are the controlled doorway; they have their own page.

4 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A bank account

The balance is private. You cannot set it to any figure; you can only call deposit and withdraw, which check the amount.

Exam use: private data with checking methods.

A car's speedometer

You read the speed through the dial. You do not reach into the engine to take the value, and the engine design can change without changing the dial.

Exam use: hidden inside, simple public interface.

A game score

A game keeps the score private so no other part of the program can cheat by setting it directly. Only AddPoints() changes it.

Exam use: only the class's methods change the data.

A school record

A student's grades are private. A getter reports them and a setter checks they are between 0 and 100 before storing.

Exam use: validation in a setter.

Top tips

  • Two parts. Bundling attributes and methods, and hiding the data. Say both.
  • Attributes private, methods public. Unless the question says otherwise.
  • Name the benefit. Protects the data, allows validation, lets the inside change.
  • Never print a private attribute. Call its getter.
  • Don't confuse the three. Encapsulation hides, inheritance reuses, polymorphism gives one name many behaviours.
