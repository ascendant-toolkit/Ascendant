Coursebook: Chapter 8 · Databases · section 8.1 Database concepts

File-based against relational databases, entities, tables, records, fields, primary, foreign, candidate and secondary keys, the three kinds of relationship and referential integrity, with animations, an SQL lab and the real Paper 1 questions from 2021 to 2026.

This page in five sentences

A file-based approach stores data in separate files for each application, which causes data redundancy (the same data stored many times), data inconsistency, program-data dependence and poor privacy; a relational database stores each item of data once in linked tables, which addresses these limitations. A table holds data about one entity; each record (tuple) is a row and each field (attribute) a column. A primary key uniquely identifies each record; a foreign key is a field in one table that links to the primary key in another, which creates a relationship (one-to-one, one-to-many or many-to-many). Referential integrity keeps the links valid: every foreign key has a matching primary key, so there are no orphaned records. You must be able to define each term and give an example from the database in the question.

1 · File-based against relational

Limitation of a file-based approachHow a relational database addresses it
Data redundancy: the same data is stored many timesSeparate linked tables; each item of data is stored once
Data inconsistency and poor integrity: duplicated data may be stored differently or not updated everywhereData changed once in one place updates everywhere; linked data cannot be entered differently in two tables; referential integrity can be enforced
Program-data dependence: a change to the structure of the data means the programs must be rewrittenThe DBMS manages the structure; queries are not dependent on how the data is stored, so changes to the data do not require programs to be rewritten
Complex searches are hard: a new program has to be written each timeComplex queries are easier to run (using SQL)
Lack of privacy: user views cannot easily be set upDifferent views can be provided so users see only specific aspects of the data
Poor support for several users at onceMultiple concurrent access is possible through record locking

3 · Relationships

  • One-to-one (1:1): a customer has one set of login details. Implemented by making the primary key of one table the foreign key in the other.
  • One-to-many (1:M): one customer places many orders. The primary key of the "one" table (CustomerID) becomes a foreign key in the "many" table (SHOP_ORDER).
  • Many-to-many (M:M): an order contains many products and a product is in many orders. This cannot be directly implemented in a normalised relational database: a linking table (ORDER_ITEM) holds the primary keys of both as foreign keys, turning it into two one-to-many relationships.

To describe a relationship in an exam answer, name the tables, the type (for example 1:M), the primary key and the matching foreign key: "ShipID is the primary key in SHIP and a foreign key in CONTAINER; one ship carries many containers, and each container is on one ship".

Common ways to lose marks

  • Defining a foreign key as "a key from another table" without saying it links to that table's primary key.
  • Describing a relationship without naming the keys when the question says to refer to them.
  • Saying a many-to-many relationship "is not possible". It is implemented with a linking table.
  • Stating the advantage of a relational database without the reason (less redundancy because each item is stored once).
  • Confusing field and record: the field is a column, the record is a row.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A school's student list on paper and in a spreadsheet

A student's address appears in the sports list, the library list and the register. When they move, it is changed in one place and not the others: redundancy and inconsistency.

Exam use: a relational database stores it once.

Online shopping

Your customer details are stored once; each order links to your customer number, so you can have many orders but one customer record.

Exam use: one-to-many with a foreign key.

Deleting a customer

If the shop removes a customer but their orders stay, the orders point at nobody: an orphaned record, which referential integrity prevents.

Exam use: referential integrity.

Students and clubs

A student joins many clubs and a club has many students: a many-to-many relationship, held in a membership table.

Exam use: linking table.

A booking system

Each seat is identified by its own key; each booking uses that key as a foreign key.

Exam use: primary and foreign keys.

Top tips

  • A point and its reason. Redundancy because each item is stored once.
  • Field: column. Record: row. Entity: the object.
  • Name both keys. Primary in one table, foreign in the other.
  • Many-to-many: linking table. Two foreign keys.
  • Referential integrity: no orphans. Every foreign key has a primary key.
  • Use the example asked for. From the database in the question.
