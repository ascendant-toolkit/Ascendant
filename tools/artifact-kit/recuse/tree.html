Recursion in Action: Binary Tree Traversal

A binary tree is built from smaller binary trees, so recursion is the natural way to walk it. See in-order, pre-order and post-order traversal run call by call, watch a recursive search, and learn why the output order changes with one line moved.

A tree is a node with two smaller trees

A binary tree is made of nodes. Each node holds a value and up to two children: a left child and a right child. Each child is the root of its own smaller binary tree (a subtree), and an empty subtree is a tree with no nodes.

That is a recursive definition: a tree is a node plus a left tree plus a right tree. Any algorithm that must visit every node can be written the same way: do something with this node, then do the same for the left subtree and for the right subtree. The base case is the empty tree.

How the tree is stored

In 9618 a binary tree is usually stored in arrays: one for the data and one each for the left and right pointers. A pointer holds the array index of the child, and a special value means “no child”. Here that value is 0, and the arrays start at index 1. Always check which null value a question uses; some papers use −1 or another value.

The root is at index 1 (RootPointer = 1). Node 3 (70) has a left child (index 6) but no right child, so its right pointer is 0.

Three ways to visit every node

A traversal visits each node exactly once. The three standard orders differ only in when the node’s own value is output, compared with the two recursive calls.

In-order

left · node · right

Left subtree first, then the node, then the right subtree. For a binary search tree this outputs the values in ascending order.

Pre-order

node · left · right

The node first, then its subtrees. The root always comes out first. Useful for copying a tree.

Post-order

left · right · node

Both subtrees before the node. The root always comes out last. Useful for deleting a tree, or evaluating an expression tree.

The procedure, line by line

This is in-order traversal. Choose Pseudocode or Python. The base case is Node = 0: the empty tree, where nothing happens.

  1. IF Node <> 0. If the pointer is 0 the subtree is empty. The procedure ends without doing anything. This is the base case.
  2. CALL InOrder(LeftPointer[Node]). Visit the whole left subtree before anything else. The argument is a pointer to a smaller tree, so each call moves towards an empty tree.
  3. OUTPUT Data[Node]. Only now is this node’s own value output.
  4. CALL InOrder(RightPointer[Node]). Then the whole right subtree.
One line moves, the order changesFor pre-order, move the OUTPUT line above both calls. For post-order, move it below both calls. Nothing else changes.

Recursive search and insert

The syllabus asks you to find and insert items in a binary tree. In a binary search tree, smaller values go left and larger values go right, so a search only follows one branch at each node: it is recursion with a single call, like a chain. The base case is either an empty subtree (not found) or a matching value (found).

Insert works the same way. Go left or right as the search would; where the pointer is 0, there is a free place for the new node.

def insert(node, item):
    if item < data[node]:
        if left[node] == 0:
            left[node] = new_node(item)      # free slot found: base case
        else:
            insert(left[node], item)
    else:
        if right[node] == 0:
            right[node] = new_node(item)
        else:
            insert(right[node], item)

Stack depth and the shape of the tree

The stack holds one branch at a time, so the deepest the stack gets is the height of the tree (plus one for the final empty call). A well-balanced tree of 1 000 nodes is about 10 levels deep. A tree that is really a long chain (for example values inserted already in order) is as deep as it has nodes, and a very long chain could overflow the stack. The Explore tab lets you compare.

Quick quiz

Flashcards

General descriptions of where tree traversal appears. These are illustrations of the idea, not code from any particular program.

Folders on a computer

A folder contains files and other folders, which contain files and other folders. Listing everything under a folder, or adding up its size, is a recursive walk of a tree: handle this folder, then do the same for each folder inside it.

Exam use: a clear example of a structure that is defined in terms of smaller copies of itself.

Sorted output from a binary search tree

If values are stored so that smaller ones go left and larger ones go right, an in-order traversal outputs them in ascending order without any separate sort.

Exam use: state what in-order gives for a binary search tree: the values in order.

Evaluating a calculation

An expression such as (3 + 4) × 5 can be stored as a tree with the operator at the node and the numbers as leaves. A post-order walk handles both operands before the operator, which is exactly the order a stack-based calculator needs (reverse Polish notation).

Exam use: shows why post-order exists. It links to the stack work in 19.1.

Copying or deleting a tree

To copy a tree, create the node first and then copy its subtrees (pre-order). To delete a tree safely, free the children before the node that points to them (post-order).

Exam use: a reason for choosing pre-order or post-order when asked “when would each be used?”.

Web pages

The elements of a web page are nested inside each other, forming a tree. Code that finds, styles or counts elements walks that tree, and often does it recursively.

Exam use: another example for “give an example of a recursive application”.

Why not always use recursion for trees?

It is the shortest and clearest way, but the stack grows with the height of the tree. For a very deep, unbalanced tree an iterative version using your own stack can avoid a stack overflow.

Exam use: supports a “discuss” answer on when recursion is and is not suitable.

Q2 Explain 3 marks Explain why recursion is suitable for traversing a binary tree.
ReminderLink the structure of the tree to the structure of the code.
Each subtree of a binary tree is itself a binary tree, so the same procedure can be applied to the left and right subtrees. An empty subtree (a null pointer) gives a natural base case, where the procedure stops. The code is short, and the call stack automatically remembers where to come back to after a subtree is finished.
Common mistakeSaying “because trees are complicated”. Name the self-similar structure and the base case.

Q4 Write 6 marks Write a recursive function Find(Node, Item) for a binary search tree stored in the same arrays. It returns the index of the item, or 0 if it is not in the tree.
ReminderTwo base cases: an empty subtree, and a match. Otherwise choose one side only.
Function header with two parameters, returning an integer. If the pointer is 0, return 0. If Data[Node] equals Item, return Node. If Item is less than Data[Node], call recursively on the left pointer. Otherwise call recursively on the right pointer. The recursive result is returned (RETURN in front of each recursive call). 
def find(node, item):
    if node == 0:
        return 0
    elif data[node] == item:
        return node
    elif item < data[node]:
        return find(left[node], item)
    else:
        return find(right[node], item)
Common mistakeWriting find(left[node], item) without return. The answer is found but never passed back up.
Q5 Describe 2 marks A binary search tree is built by inserting the values 10, 20, 30, 40, 50 in that order. Describe the problem this causes for a recursive search.
ReminderDraw the tree: each value is larger than the last, so it goes to the right.
The tree becomes a chain (all nodes on one side), so its height equals the number of nodes. A search may need as many calls as there are nodes, so it is no faster than a linear search, and the stack could grow very deep.
Common mistakeSaying the tree “is wrong”. It is still a valid tree; it is just unbalanced, which removes the benefit of halving the search.

Top tips

  • The base case is the empty tree. The pointer is the null value (0 in these examples), and the procedure does nothing.
  • One line decides the order. Output before the calls: pre-order. Between them: in-order. After both: post-order.
  • Finish a whole subtree before moving on. In-order of Tree A outputs everything under 30 before 50.
  • In-order of a binary search tree is sorted. If your answer isn’t ascending, you have made a slip.
  • Pre-order starts with the root; post-order ends with it. A quick check on your answer.
  • Count the calls. A tree with n nodes causes 2n + 1 calls to the traversal procedure: one per node and one per empty pointer.
  • The stack is as deep as the height. Not the number of nodes, unless the tree is a chain.
  • Use RETURN on recursive calls in a function. RETURN Find(…), not just Find(…).
  • Check the question’s null pointer. It may be 0, −1 or something else, and the arrays may start at 0 or 1.
  • Say “subtree”, “frame”, “return address” and “base case” in any explanation.
