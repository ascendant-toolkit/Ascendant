Recursion in Action: Binary Search

Search a sorted array by looking at the middle and throwing half of it away, again and again. See the range shrink call by call, trace the function, count how many calls it needs, and practise the Paper 4 question that asked for it.

The problem

You have a sorted array and want the position of a value in it. A linear search checks the items one at a time, which could mean checking all of them. A binary search uses the order: look at the middle item. If it is the one you want, stop. If the middle item is too big, the value can only be in the lower half. If it is too small, only the upper half. Either way, half of the array has been ruled out in one step.

Searching the remaining half is the same problem on a smaller array. That is recursion: search this range = check the middle, then search a smaller range.

Two base cases and two general cases

Base cases

found · or · range empty

Found: DataArray[Middle] = DataToFind, so return Middle. Not found: Upper < Lower, so no items are left to look at: return −1.

General cases

search the lower half · or · the upper half

If the middle value is greater than the target, search Lower to Middle − 1. If it is less, search Middle + 1 to Upper. The middle is excluded because it has just been checked.

The array must be sortedThe whole idea depends on knowing that everything on one side of the middle is smaller and everything on the other is larger. On an unsorted array a binary search can give the wrong answer.

The function, line by line

This is the function from the past paper question (O/N 2025, Paper 4). Switch between Pseudocode and Python.

  1. Header. Four parameters: the array, the Lower and Upper index of the part still to search, and the value to find. It RETURNS an index, or −1.
  2. IF Upper >= Lower. There is at least one item left. If this is false the range is empty, which is the “not found” base case at the bottom.
  3. Middle ← Lower + (Upper − Lower) DIV 2. The integer middle of the range. With indexes 0 to 10, Middle = 5.
  4. Compare. Equal: return Middle (found). Greater: recurse on Lower … Middle − 1. Otherwise: recurse on Middle + 1 … Upper. Each recursive call has a range at least one item smaller, so it must end.
  5. RETURN in front of each recursive call. The answer from the smaller search is passed straight back up. Nothing is added or calculated on the way up.

How many calls?

Each call halves the range, so the number of calls is about log₂ of the array size. 1 000 items need at most 10 calls; a million items need at most 20. A linear search could need a million.

The same job with a loop

Binary search is also easy to write with a loop: keep Lower and Upper as variables and move them instead of passing new values to a new call. It uses no stack.

def binary_search(data_array, data_to_find):
    lower, upper = 0, len(data_array) - 1
    while upper >= lower:
        middle = lower + (upper - lower) // 2
        if data_array[middle] == data_to_find:
            return middle
        elif data_array[middle] > data_to_find:
            upper = middle - 1
        else:
            lower = middle + 1
    return -1
The two versions make the same comparisons. The loop avoids the stack frames; the recursive version matches the idea more directly.

Quick quiz

Flashcards

General descriptions of where the halving idea is used. Numbers are illustrative only.

Looking up a word in a dictionary

You open the book near the middle, see whether your word comes before or after the page you landed on, and repeat with the remaining half. That is binary search done by hand, and it only works because the words are in alphabetical order.

Exam use: a clear example of why the data must be sorted.

The guessing game

In “I’m thinking of a number between 1 and 100”, guessing the middle each time and being told higher or lower finds the number in at most 7 guesses.

Exam use: shows the number of calls grows with log₂ of the size, not with the size itself.

Finding a fault in a long list of changes

If a program worked last month and is broken now, testing the middle version tells you which half contains the change that broke it. Repeating this finds the problem in a handful of tests, even among thousands of changes. Developer tools can automate it.

Exam use: a non-obvious use of the same idea, good for “give an example”.

Database indexes

Databases keep an ordered index of a column so that a record can be located without reading every row. Many indexes are tree structures that work on the same halving principle, as you see on the binary tree page.

Exam use: links searching to databases and to binary trees.

The cost of sorting first

If the data arrives unsorted, it has to be sorted before a binary search can be used, and sorting costs time. Binary search pays off when the same data will be searched many times.

Exam use: supports a “discuss” answer comparing binary and linear search.

Recursion or a loop?

Because the answer is passed straight back with no calculation, binary search is just as easy with a loop, and the loop avoids stack frames. The recursive version is shorter to explain; a real program would often use the loop.

Exam use: for “when is recursion beneficial?” the honest answer is: when the problem splits into smaller copies, and the code is clearer; not always when it is fastest.

Q1 State 2 marks State the two base cases of a recursive binary search.
ReminderOne where the value is found, one where it cannot be.
The value at the middle index equals the value being searched for (found, so return the index). The upper bound is less than the lower bound / there are no items left to search (not found, so return −1).
Common mistakeForgetting the not-found case. Without it, searching for a missing value would keep calling forever or index outside the array.

Q3 Explain 3 marks Explain why a binary search needs fewer comparisons than a linear search on a large sorted array.
ReminderSay what one comparison achieves, and give the effect on the number of comparisons.
Each comparison with the middle item rules out half of the remaining items, because the array is sorted. So the number of items left halves each time, and the number of comparisons grows with log₂ of the size (e.g. 1 000 items need about 10). A linear search removes only one item per comparison, so it may need to check every item.
Common mistakeSaying binary search “is faster” without saying why. Name the halving.
Q4 Rewrite 6 marks Rewrite the recursive binary search as an iterative function using program code.
ReminderThe recursive calls become changes to Lower or Upper, inside a loop that runs while there is something left to search.
Function header with the array and value to find as parameters (the bounds set up inside). Lower and Upper initialised to the first and last index. Loop that continues while Upper >= Lower. Middle calculated inside the loop. If equal, the index is returned; if greater, Upper becomes Middle − 1; otherwise Lower becomes Middle + 1. Returns −1 after the loop if not found.

Q5 Discuss 4 marks Discuss whether a recursive or an iterative binary search is the better choice.
ReminderOne advantage and one disadvantage of each, then a judgement.
Recursive: short code that follows the idea directly (search a smaller range). Recursive: each call needs a stack frame, so it uses more memory, though only about log₂ n frames are needed. Iterative: no stack frames, so it uses less memory and has no risk of stack overflow. A judgement: for binary search the depth is small, so either works; the iterative version is slightly more efficient, the recursive version is often clearer.
Common mistakeSaying recursion is always slower or always uses too much memory. For binary search the stack depth is tiny.

Top tips

  • The array must be sorted. Say so in any binary search explanation.
  • Two base cases: found (return the index) and Upper < Lower (return −1).
  • Middle ← Lower + (Upper − Lower) DIV 2. Use integer division. Check that the middle is always between Lower and Upper.
  • Exclude the middle. The new bounds are Middle − 1 and Middle + 1, not Middle, because that item has been checked.
  • Use RETURN on the recursive call. RETURN RecursiveBinarySearch(…). Without it the answer never reaches the original caller.
  • Indexes, not the number of items. An array of 20 items has indexes 0 to 19, so the first call uses 0 and 19.
  • In a trace table the Return value is blank on the way down. The same index is returned all the way up.
  • Count with powers of 2. 7 items: 3 calls at most. 15: 4. 1 023: 10. Each doubling adds one call.
  • Handle “not found” in the main program. Test the returned value for −1 before outputting a position.
  • Say “halves the search space” when comparing with linear search.
