Hashing Algorithms

Coursebook: Chapter 13 · Data representation, section 13.2 File organisation and access

What a hashing algorithm does, MOD hash values, collisions and how they are resolved when storing and finding records; animations, a hash table sandbox and the real 9618 hashing questions from 2023 and 2024.

This page in five sentences

A hashing algorithm is a mathematical formula that is applied to a record's key field and calculates the address where the record is stored or should be found. The most common one is the modulus: divide the key by the number of locations and use the remainder. Because two different keys can give the same address, a collision can occur, and the system needs a collision resolution method, such as storing the record in the next free location (linear probing) or in an overflow area. To find a record the same hash is calculated, the location is read, and if the key there does not match the search continues in the same way. This is how random files give direct access to a record without reading the others.

1 · What a hashing algorithm does

StepStoring a recordFinding a record
1Take the record's key (e.g. account number 3003)Take the key being searched for
2Apply the hashing algorithm: 3003 MOD 5 = 3Apply the same algorithm: 3003 MOD 5 = 3
3Write the record at location 3Read location 3 and check the key matches

The same key always gives the same address, so a record can be stored and found without searching. MOD gives the remainder after integer division: 3003 MOD 5 = 3, 1029 MOD 5 = 4, 7630 MOD 5 = 0.

def Hash(Key, Size):    return Key % Size            # the remainder: always from 0 to Size - 1 print(Hash(3003, 5))             # 3print(Hash(1029, 5))             # 4print(Hash(7630, 5))             # 0

A good hashing algorithm is fast, always gives the same address for the same key, and spreads keys evenly over all locations so there are few collisions. Using a table size that is a prime number helps.

2 · Collisions

A collision occurs when two different keys give the same hash value, so the location the algorithm identifies is already in use. Two records cannot occupy the same address.

MethodWhen storingWhen finding
Linear probing (closed hashing)Start at the hashed location and go through the following locations, one after another, until the first free one, and store the record thereStart at the hashed location and search linearly onwards until the key matches. If an empty location is reached, the record is not in the file
Overflow area (open hashing)Store the record in the next free space in a separate overflow areaIf the key at the hashed location does not match, search the overflow area linearly until the matching key is found
ChainingEach location holds a reference to a collection (chain) of items; add the record to the chainSearch the chain at the hashed location
Exam wordingWhen asked what happens on a collision, say: the calculated location is already used for another record; the file is searched linearly from that point (or the overflow area is searched) for the next free space and the record is stored there; when finding, the search carries on linearly until the matching key is found, and if it is not found the record is not in the file.

3 · Hashing and the random file

A random file is opened with FOR RANDOM. The hash gives the location to SEEK, and then GETRECORD or PUTRECORD reads or writes the record. The pseudocode questions that do this are on the chapter 20 file processing page.

Location ← Hash(Customer.AccountNumber)SEEK AccountFile, LocationGETRECORD AccountFile, Customer

4 · Advantages and limits

  • Fast direct access: one calculation and (usually) one read, however large the file.
  • Records can be updated directly without rewriting the file.
  • Some locations are empty, so space is wasted, and collisions make access slower as the file fills up.
  • The records are not in key order, so a hash file is poor for reports that need an order.

5 · Common ways to lose marks

  • Saying a hash function "encrypts" the key. It calculates an address; it is not for secrecy.
  • Calculating MOD wrongly: the remainder after integer division, so 1029 MOD 5 is 4, not 205.
  • Describing a collision as an error in the file. It is two keys producing the same address.
  • For a collision, only saying "use another location". Say how: next free space linearly, or an overflow area.
  • Forgetting that finding a record also has to follow the same collision method.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A library catalogue

Each book's ID is turned into a shelf location by a hash. Looking up a book means calculating the hash and going to that shelf, instead of searching every shelf.

Exam use: hashing gives direct access using the key field.

A phone's contacts or a database index

Many databases use hash tables so a record can be found from its key in about one step, however many records there are.

Exam use: random files and hash tables share the same idea.

A hotel booking system

Booking references are hashed to locations in a large file. If two bookings map to the same place, the second is stored in the next free location, and a search follows the same path.

Exam use: collisions are resolved by linear probing or an overflow area.

Checking a downloaded file

A different kind of hash, a checksum, is calculated over a whole file. If the result differs from the published one, the file has changed.

Exam use: same word, different purpose: this hash checks integrity, not an address.

Passwords

Websites store a hash of your password, not the password. When you log in the hash of what you type is compared with the stored one.

Exam use: another use of hashing: here it is a one-way function, unlike the address calculation in this topic.

M/J 2023 · 9618/31, 33 · Q3 Complete / Describe 2 + 4 marks A hashing algorithm is used to calculate storage locations for records in a random access file. It calculates hash values by using the function modulus 3. The function modulus gives the remainder after integer division. For example, 1030 modulus 3 = 1, so the record key 1030 gives a hash value of 1. (a) Complete the table to show the hash values for the keys 1050 and 1025. (b) Describe what happens, in relation to the storage or retrieval of a record in the file, when the calculated hash value is a duplicate of a previously calculated hash value for a different record key.
Record key     Hash value
1030           1
1050           ...
1025           ...
Reminder(a) divide and keep the remainder. (b) a collision, then how a record is stored and how it is found.

(a) 1050 MOD 3 = 0 (1050 = 3 × 350) 1025 MOD 3 = 2 (1025 = 3 × 341 + 2)

Record key     Hash value
1030           1
1050           0
1025           2

(b) Up to four marks: A collision occurs when the record key does not match the stored record key which means the determined storage location has already been used for another record When storing: search the file linearly to find the next available storage space (closed hash), or the overflow area linearly (open hash) When finding: search the overflow area linearly, or search linearly from where you are, until the matching record key is found; if it is not found the record is not in the file

Common mistakeGiving a wrong remainder: 1050 is exactly divisible by 3, so the hash value is 0.

(b) The use of a hashing algorithm can result in the same storage location being identified for more than one record. Outline two methods of overcoming this issue.

(a) Up to three: A hashing algorithm is used in direct access methods on random and sequential files It is a mathematical formula used to perform a calculation applied to the key field of the record being searched or stored The result of the calculation gives the address where the record should be found or stored

(b) The record is stored in the next free memory space after the one identified by the hashing algorithm (linear progression) An overflow area is set up and the record is stored in the next free memory space in the overflow area

(a) Outline what is meant by the term collision in this context. (b) Explain how a collision can be dealt with when writing records to a random file.
Reminder(a) two keys, the same hash value, the location already in use. (b) any one method, with its steps.

(a) A collision is when the key fields of two records give the same hash value so the location identified may already be in use: two records cannot occupy the same address

(b) Up to three, from one method: A process of collision resolution is used: start at the original hashed storage space go through the following spaces in a linear fashion and store the data item in the first available slot (or: search the overflow area in the same way; or: each space holds a reference to a chain of items, and the item is stored in the first available space in the chain)

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Calculate 2 marks A random file uses Hash(Key) = Key MOD 11. Give the hash values for the keys 4719 and 5000.
ReminderDivide by 11, keep the remainder.

4719 MOD 11 = 0 (11 × 429 = 4719 exactly) 5000 MOD 11 = 6

Common mistakeUsing the quotient. Hash values are always remainders between 0 and 10.
Describe 3 marks Keys 1030 and 1050 are stored in a file using Hash(Key) = Key MOD 5. Both give 0. Describe what happens when 1050 is stored after 1030, and how 1050 is later found.
ReminderCollision, next free space, linear search.

Location 0 is already used by 1030, so there is a collision. 1050 is stored in the next free location after location 0 (linear probing). To find 1050 the hash is calculated, location 0 is read (key 1030, no match), and the search continues linearly until the key 1050 is found.

State 2 marks State two properties of a good hashing algorithm.
ReminderThink speed and spread.

It is quick to calculate and always gives the same value for the same key. It spreads the keys evenly over the locations so there are few collisions.

Explain 2 marks Explain why records in a hash (random) file cannot easily be produced in key order.
ReminderWhere do the records sit?

Records are stored at addresses calculated from their keys, not in key order. Many locations are empty, so producing an ordered list needs a separate sort.

Compare 3 marks Compare using the next free location with using an overflow area to resolve a collision.
ReminderWhere is the record stored; how is it found?

Next free location: the record goes in the following space in the main file, found by searching linearly on from the hashed location. Overflow area: the record goes in a separate area, found by searching that area when the hashed location holds a different key. Both need the same method used when storing and finding.

Top tips

  • MOD is the remainder. Divide, ignore the whole number, keep what is left over.
  • Same hash, same place. Storing and finding use the same algorithm and the same collision method.
  • Define a collision. Two different keys give the same hash value, so the location is already in use.
  • Give a method with its steps. Next free space, searching on linearly; or an overflow area searched linearly.
  • The hash gives an address, not an order. Records are not stored in key order.
  • Say 'key field'. The hashing algorithm is applied to the key field of the record.
