Interpreters and the Stages of Compilation

Coursebook: Chapter 16 · System software, section 16.2 Translation software

How an interpreter executes a program, and the four stages of compilation (lexical analysis, syntax analysis, code generation, optimisation); animations, a tokeniser lab and the real Paper 3 questions from 2021 to 2025.

This page in five sentences

Programs written in a high-level language have to be translated before the processor can run them. An interpreter translates and executes the source code one statement at a time, never producing a translated copy of the whole program; if it finds an error it reports it and stops, and it must translate every statement again each time the program runs, including every pass round a loop. A compiler translates the whole program into object code in one go, in four stages: lexical analysis (source code to tokens), syntax analysis (tokens checked against the grammar to give a parse tree), code generation (the parse tree to executable code) and optimisation (making the code use fewer resources). The executable can then be run as often as needed without the source code or the translator.

1 · Interpreter

An interpreter executes a program without producing a translated version of it.

  1. It takes the next statement of the source code and translates it.
  2. It checks the statement for errors.
  3. If there is no error the statement is executed at once.
  4. If an error is found it is reported and the interpreter halts.
  5. It carries on to the next statement.

Nothing is stored in executable form, so the translation is repeated every time the program is run, and repeated for each pass through a loop. Interpreters are good for developing and testing (an error is found as soon as that statement is reached, so the programmer can fix and re-run at once) but run more slowly than compiled code.

2 · The stages of compilation

Lexical analysis

The first stage. The source code is read and white space and comments are removed. The rest is broken into a series of tokens: keywords, identifiers, operators, constants and punctuation. Each token is categorised and assigned a type. Identifiers (variable and subroutine names) are stored in a symbol table. If the lexical analyser finds an invalid token it generates an error; acceptable output passes to the syntax analyser.

The line Total = Price * 2 + 5 becomes the tokens Total (identifier), = (operator), Price (identifier), *, 2 (constant), +, 5 (constant).

Syntax analysis

The second stage. The token stream from the lexical analyser is analysed (parsed) against the grammar of the language to detect errors: do the tokens conform to the rules of the language? Syntax errors are reported. The output is a parse tree (an abstract syntax tree), which shows the structure of the code, for example that in a + 2 * c the multiplication is done before the addition.

Code generation

The parse tree (or an intermediate representation) is converted into executable code: machine code or assembly for the target processor.

Optimisation

The code is improved so that it uses minimum resources: it identifies and removes redundant code, simplifies expressions and may reorder the code, so that storage size, memory use, power consumption, CPU time or execution time are minimised. For example, 2 * 60 * 60 can be worked out once during compilation as 7200, and an instruction whose result is never used can be deleted.

3 · Common ways to lose marks

  • Describing a compiler when the question asks about an interpreter. An interpreter produces no translated version.
  • Leaving out "one statement at a time", "checked for errors before execution" or "translated again every time".
  • Putting the stages in the wrong order: lexical, syntax, code generation, optimisation.
  • Writing that lexical analysis checks the grammar. That is syntax analysis; lexical analysis makes tokens and removes white space and comments.
  • Writing that optimisation makes the program "better" or "faster" only. It uses fewer resources: storage, memory, CPU time.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Python in a notebook

Python normally runs through an interpreter: you type a line, it runs at once, and an error appears when that line is reached. This makes it good for trying things out.

Exam use: an interpreter executes statement by statement.

A game you install

The game is distributed as an executable. The developer compiled it once, so you do not need the source code and the game starts without any translation.

Exam use: a compiler produces an executable.

The red wavy line in a code editor

The editor runs a quick lexical and syntax check as you type and marks tokens or structures that break the rules of the language.

Exam use: lexical and syntax analysis report errors.

A compiler making your program smaller

When you turn on optimisation the compiler removes code that does nothing and works out constant calculations in advance, so the program uses less memory and time.

Exam use: optimisation uses minimum resources.

A web page's JavaScript

The browser interprets (or compiles just in time) the script each time the page loads, because the source is delivered as text.

Exam use: interpreted code is translated every time it runs.

Top tips

  • Interpreter: one statement at a time. Check, execute, halt on error, repeat every run and every loop.
  • No translated version. That is the point of an interpreter.
  • Four stages in order. Lexical, syntax, code generation, optimisation.
  • Lexical: tokens. Remove white space and comments, create tokens and the symbol table.
  • Syntax: grammar and parse tree. Syntax errors reported.
  • Optimisation: minimum resources. Remove redundant code; less memory, storage, CPU time.
