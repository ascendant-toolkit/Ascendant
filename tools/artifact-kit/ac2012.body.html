Classes, objects, encapsulation, getters and setters, inheritance, polymorphism and containment; how to read, complete and design class diagrams; animations, labs and the real past paper questions on OOP.

This page in five sentences

In object-oriented programming (OOP) a program is built from objects, each created from a class that defines its properties (attributes) and methods. A constructor sets up a new object, and encapsulation keeps the properties private so they can only be read or changed through getters and setters. Inheritance lets a new class take the properties and methods of a parent class, and polymorphism lets the same method name behave differently in different classes. When one class holds objects of another, that is containment (aggregation). To solve a problem you decide the classes, their properties and their methods before writing any code; the next page turns the designs into working code.

2 · Why encapsulation?

If every part of a program can change an object's data directly, any bug or careless line can corrupt it. With private properties the only way in is through the methods, so the class can check values (a priority must be 1 to 5), a property can be made read-only by providing a getter but no setter, and the inside of the class can change without breaking the rest of the program. The mark scheme answer is short: so the attributes can only be accessed using the class's own methods.

3 · Class diagrams

A class diagram is a box in three parts: the class name, the properties with their data types, and the methods. Exams ask you to complete one from a description. The pattern is nearly always the same:

  • one property for each data item, with a sensible name and the right data type (STRING, INTEGER, DATE, BOOLEAN, REAL)
  • a constructor if the question says objects are created with their values set
  • a setter for each property that can change: SetPriority(Urgency : INTEGER), with a parameter and its data type
  • a getter for each property that has to be read: GetPriority(), with no parameter
  • names that match the property they work with (Priority, SetPriority, GetPriority)

4 · Designing classes to solve a problem

  1. Find the things the problem talks about (customers, vehicles, yarn). Each kind of thing is a class.
  2. List the data each one stores. Each item is a property with a data type.
  3. List what each one does: displays itself, changes its stock, moves. Each action is a method.
  4. Look for sharing. If several classes share properties and methods and one "is a" kind of the other, put the shared parts in a parent class (inheritance). If one thing "has" others inside it, use containment.
  5. Decide access. Make properties private and add getters and setters only where they are needed.
Is a, or has a?A Parrot is an Animal: inheritance. A Hand has Cards: containment. If you can put "is a" between the two names and it makes sense, it is inheritance.

6 · Common ways to lose marks

  • Defining encapsulation as "hiding things". Say the properties and methods are in one class and the data can only be reached through the class's own methods.
  • Mixing up class (the template) and object (an instance of it).
  • Writing a setter with no parameter, or a getter with one. A setter takes the new value; a getter takes nothing.
  • Giving a getter or setter a name that does not match its property.
  • Repeating the parent's properties in the child class diagram, or drawing the arrow the wrong way.
  • Describing polymorphism as "many classes". It is the same method name redefined, with different behaviour, in derived classes.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A school management system

Student, Teacher and Substitute can share a parent class Person with a name and a telephone number, and each adds its own data. Records are private and changed through setters, so a telephone number is always stored in the same format.

Exam use: inheritance for shared data, encapsulation for safe changes, setters that check values.

A video game

Every character has a position and a name, but a magic character also has spells and a bike character has a speed. They inherit from Character, and each overrides a method such as Move() to behave in its own way.

Exam use: polymorphism: one call to Move() on a list of characters does the right thing for each.

A card game

A Hand object contains five Card objects, and the game can ask each card for its number and colour through getters without ever touching the card's private data.

Exam use: containment (a Hand has Cards) and getters.

A bank account

Balance is private. You cannot set it to any number you like: Deposit() and Withdraw() are the only ways in, and Withdraw() refuses to go below the overdraft limit.

Exam use: encapsulation protects the data; methods enforce the rules.

A medical records system

An Appointment records the patient, doctor, treatments and medications. The date seen has a setter and a getter, but the patient number is set once and only read, so it has a getter but no setter.

Exam use: choose getters and setters to match what is allowed to change.

Distinguish 2 marks Distinguish between a class and an object.
ReminderTemplate against occurrence.

A class is a template that defines the properties and methods. An object is an instance of the class: one occurrence with its own values.

Explain 3 marks A class Vehicle has child classes Car and Lorry. Explain how inheritance helps the programmer.
ReminderWhat is written once, and where it is reused.

Properties and methods common to all vehicles are written once, in Vehicle. Car and Lorry reuse them, so less code is written and tested. Each child adds only what is different, or overrides a method, and a change to Vehicle reaches both.

Identify 2 marks A Garage class holds a list of Vehicle objects. State the OOP relationship and say why it is not inheritance.
ReminderHas a, or is a?

Containment (aggregation): a Garage has vehicles. A Garage is not a kind of Vehicle, so the 'is a' test of inheritance fails.

Describe 3 marks Class Shape has a method Area() returning 0. Circle and Rectangle each define their own Area(). Describe how this shows polymorphism.
ReminderSame name, different behaviour.

Circle and Rectangle both have a method called Area(). Each redefines (overrides) the method in the parent class. Calling Area() on a Circle or on a Rectangle runs the version for that class, giving different results.

Top tips

  • Use the exact definitions. Instance: an occurrence of an object. Inheritance: a new class takes the properties and methods of a parent class. Polymorphism: the same method is redefined in derived classes.
  • Setters take, getters give. SetX(NewValue : TYPE) has a parameter. GetX() has none and returns the value.
  • Match the names. Property Priority, setter SetPriority, getter GetPriority. The mark scheme checks that they match.
  • Read the data types from the text. A number with a leading zero or a unique ID is usually a STRING. A scale of 1 to 5 is an INTEGER.
  • Private is the default. If the question says attributes must be private, say so in the declaration, and say why: only reached by the class's own methods.
  • Draw inheritance arrows upward. Child to parent, and show only the new members.
