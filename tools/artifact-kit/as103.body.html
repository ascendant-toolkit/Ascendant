Opening files in READ, WRITE and APPEND mode, reading to the end of file, searching, the last three lines, copying and creating files, with animations, file labs and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

A text file stores data permanently as lines of text; a program must open it in a mode, read or write it, and close it. READ mode lets you read lines one at a time with READFILE until EOF() (end of file) is true; WRITE mode creates the file or overwrites everything in it; APPEND mode adds to the end and keeps the existing data. A file is a better store than an array when the data must survive after the computer is switched off, when it is more than an array can hold, or when another program must use it. A file can only hold text, so numbers and Booleans must be converted to strings before writing (and back after reading). Typical exam tasks: search a file for a value, output the last lines, copy and reformat lines, and create several files.

Why use a file instead of an array: data is saved after the computer is switched off and need not be re-entered; the number of values can be larger than a fixed array; the data can be used by another program.

2 · Common file algorithms

  • Search: open for READ; loop until EOF or the value is found; read a line; extract the field (MID, LEFT, RIGHT with the field lengths); compare; if found, output; close; if not found, say so after the loop.
  • Last three lines: keep three variables and shuffle them as each line is read: LineX ← LineY, LineY ← LineZ, LineZ ← ThisLine; after the loop output them in order.
  • Efficient search of a sorted file: the search can stop as soon as the current value read is greater than the value being searched for.
  • Copy and reformat: open the old file for READ and the new file for WRITE; read three lines; join them with a separator; write; repeat until EOF; close both.
  • Several files: a loop creates a name (root, a dot, a three-digit suffix padded with zeros) and opens each file for WRITE, writes a line and closes it.
PROCEDURE LastLines(ThisFile : STRING)   DECLARE ThisLine, LineX, LineY, LineZ : STRING   OPENFILE ThisFile FOR READ   LineY ← ""   LineZ ← ""   WHILE NOT EOF(ThisFile)      READFILE ThisFile, ThisLine      LineX ← LineY      LineY ← LineZ      LineZ ← ThisLine   ENDWHILE   CLOSEFILE ThisFile   OUTPUT LineX   OUTPUT LineY   OUTPUT LineZENDPROCEDURE

Common ways to lose marks

  • Not opening the file, not closing it, or opening it in the wrong mode (WRITE when the data must be kept).
  • Reading with no loop, or a loop with no EOF test.
  • Reading the file inside the loop after the end condition (read, then test again).
  • Writing a number without converting it to a string.
  • Searching the whole file when the question says the file is sorted and asks for efficiency.

Top tips

  • Open, loop, close. In READ, WRITE or APPEND.
  • Append keeps old data. Write overwrites.
  • Loop until EOF. And until found, if searching.
  • Extract fields with MID/LEFT/RIGHT. Use the field lengths.
  • Sorted file: stop early. When the line is greater.
  • Strings only. Convert numbers before writing.
