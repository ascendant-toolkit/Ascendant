Recursion

A subroutine that calls itself, over and over, until it reaches a case it can answer directly. It feels strange at first, so every call and every return is drawn out here, one step at a time: the call stack, the call tree, the winding down and the unwinding back, with the code highlighted alongside.

The big idea

Recursion solves a problem by solving a smaller version of the same problem. A recursive subroutine calls itself with a simpler input, and keeps going until the input is so simple that the answer is obvious. Then the answers travel back up and are combined.

Think of Russian dolls. To count the dolls, open one, and ask "how many dolls are inside?" That is the same question on a smaller doll. Eventually you reach the smallest doll with nothing inside. That is where it stops.

The three essentials

1 · Base case

The input where the answer is known without any further call. It stops the recursion. Also called the terminating condition.

IF n = 0 THEN
   RETURN 1

2 · General case

The subroutine calls itself with a smaller or simpler value, so every call moves closer to the base case.

RETURN n * Fact(n - 1)

3 · Unwinding

Once the base case returns, each waiting call receives its answer, finishes its calculation and returns. Anything written after the recursive call runs now.

Fact(0) → 1
Fact(1) → 1 × 1
Fact(2) → 2 × 1 ...
Two ways it goes wrongNo base case, or a base case that is never reached (for example counting up when it should count down): the calls never stop and the stack overflows. A base case that returns the wrong value (Fact returning 0) runs fine but gives a wrong answer.

Winding and unwinding

Take Fact(3). It cannot finish 3 × Fact(2) until Fact(2) answers, and so on. The calls wind down to the base case. Nothing has been multiplied yet. Then the answers unwind back up and the multiplications happen on the way.

How the computer does it: the call stack

A stack is a last in, first out structure. Every time a subroutine is called, the computer pushes a stack frame on it. The frame holds the parameters, the local variables and the return address (where to carry on when the call finishes). The top frame is the call being run. When a call returns, its frame is popped and the one beneath becomes the top again.

A recursive call is just an ordinary call that happens to be to the same subroutine. Each call gets its own frame with its own copy of n, which is why Fact(3) and Fact(2) do not interfere with each other. That is also why recursion uses a lot of memory: n calls means n frames.

Exam linkThis is the standard "how does a compiler implement recursion" answer: calls push frames (return address, parameters, locals) on the stack; the base case returns; frames are popped in reverse order as each call returns. Name the stack, the frame contents and LIFO.

How to trace a recursive function in an exam

  1. Write each call on its own row going down, with the value of the parameter. Keep going until you reach the base case.
  2. Mark the base case row and write what it returns.
  3. Work upwards. On each row below it, substitute the returned value into the waiting expression and write the result.
  4. Take the answer from the top row, the first call. Check any OUTPUT lines: those before the call print going down, those after it print going up.

Recursion or iteration?

Benefits of recursion

  • Short, clear code that mirrors the problem (trees, divide and conquer).
  • Often easier to write and to prove correct.
  • Natural for data that contains smaller copies of itself.

Drawbacks of recursion

  • Each call needs a stack frame, so it uses more memory.
  • Pushing and popping frames makes it slower than a loop.
  • Too deep, or no base case: stack overflow.
  • Harder to trace and debug.

Any recursive routine can be rewritten with a loop (and sometimes a stack of your own). The two versions below give the same answers.

Recursive

FUNCTION Fact(n) RETURNS INTEGER
   IF n = 0 THEN
      RETURN 1
   ELSE
      RETURN n * Fact(n - 1)
   ENDIF
ENDFUNCTION
def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)

Iterative

FUNCTION Fact(n) RETURNS INTEGER
   Result ← 1
   FOR i ← 2 TO n
      Result ← Result * i
   NEXT i
   RETURN Result
ENDFUNCTION
def fact(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

Descriptions are kept general. Use them as examples of ideas, not as exact descriptions of any company's software.

Searching folders on a computer

A folder holds files and other folders. To list everything, list the files, then repeat the same process inside each sub-folder. The base case is a folder with no sub-folders.

Exam use: a clear example of data that contains smaller copies of itself, so recursion is more natural than a loop.

Traversing a binary tree

In-order traversal: visit the left subtree, output the node, visit the right subtree. Each subtree is a smaller tree. The base case is an empty subtree (a null pointer).

Exam use: links 19.2 to 19.1.3. Work after the first call runs during unwinding, so the nodes come out in order.

Binary search and merge sort

Divide and conquer: halve the problem, solve the halves the same way, combine. Binary search needs one recursive call per level; merge sort needs two.

Exam use: explains why recursion suits algorithms that split the data into smaller copies.

Fractals and graphics

A snowflake or fern is drawn by drawing a shape that contains smaller copies of itself. The base case is "too small to draw".

Exam use: shows that the base case controls how deep the recursion goes.

Compilers checking brackets and maths

An expression like (2 + (3 × 4)) contains smaller expressions inside the brackets. Parsers handle this by calling themselves for each inner bracket.

Exam use: a real use of the call stack: each unfinished bracket waits, like a frame waiting for its inner call.

Route and maze solving

Try a path; at each junction call the same routine for each direction; if stuck, return and try another. Going back is the unwinding.

Exam use: depth-first search is naturally recursive and the call stack remembers where to back up to.

Calculating Fibonacci naively

Fib(40) written with two recursive calls takes noticeably long because it re-solves the same sub-problems billions of times. A loop does it in 40 steps.

Exam use: the standard example of a drawback: elegant but inefficient. Say "repeated calculation".

Infinite "Droste" effect

A picture that contains a smaller copy of itself, which contains a smaller copy, and so on. Without a smallest picture it never ends.

Exam use: a memorable way to explain why the base case is essential.

Past papers: theory

M/J 2023 · 31, 33 Q12(a) and M/J 2025 · 31 Q4(b) Describe 2 marks Describe what is meant by recursion.
ReminderBoth papers award the same marks. Two ideas: it calls itself, and it stops at a base case. “Unwinding” also earns the second mark in 2023.
A technique where a function or procedure is defined in terms of itself / calls itself (the general case). It does so until a terminating condition / base case is reached, where no further recursive call is made (then the calls unwind).
Common mistakeWriting “it repeats” or “it loops”. A loop repeats too; recursion is the self-call plus the base case.
O/N 2021 · 31, 32 · Q10(a), (b) State / Explain 3 + 3 marks (a) State three essential features of recursion. (b) Explain why a stack is a suitable ADT to implement recursion.
Reminder(a) is a list, no explanation. (b) needs LIFO, push on call, pop on return, and why that order matters.
(a) It must have a base case / stopping condition. It must have a general case that calls itself (the subroutine is defined in terms of itself). Each call changes its state, moving towards the base case; unwinding can occur once the base case is reached.
(b) A stack is a last in, first out structure. Each recursive call is pushed onto the stack, and is popped when the function ends. This allows backtracking / unwinding in the correct order.
Common mistakeSaying a queue would also work. It would give the calls back in the wrong order: the last call made must finish first.

(i) Write the function. (ii) The main program stores 0, 5, 1, 2, 5, 9, 9, 6, 5, 0 in a 1D array, calls RecursiveCount() with 0, 10 and the array, and outputs the return value. Write the main program.
ReminderThe algorithm is given in the question: follow it step by step. Each call passes the array without its first element and NumberElements − 1.

(i) Six marks: function header taking three parameters; checking for 0 elements and returning 0; comparing the first element to DataToFind; on a match, returning 1 + the recursive call; on no match, returning the recursive call without adding 1; every recursive call passes the array without the first element, NumberElements − 1 and DataToFind.

def RecursiveCount(DataToFind, ArrayCopy, NumberElements):
    if NumberElements > 0:
        NewArray = ArrayCopy[1:]
        if ArrayCopy[0] == DataToFind:
            return 1 + RecursiveCount(DataToFind, NewArray, NumberElements - 1)
        else:
            return RecursiveCount(DataToFind, NewArray, NumberElements - 1)
    else:
        return 0

(ii) Three marks: storing the correct data in an array; calling RecursiveCount() with the correct parameters; outputting the return value. The output is 2.

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check you can explain and trace recursion before attempting the real questions above.

Recall and explain

Q1 State 2 marks State two features of a recursive subroutine.
Reminder"State" needs short points, no explanation. The two essentials: a base case and a call to itself.
It calls itself (from within its own definition). It has a base case / stopping condition, where it returns without calling itself again.
Common mistakeWriting "it uses a loop" or "it repeats". Iteration repeats too; recursion is defined by the self-call.
Q2 Explain 3 marks Explain why every recursive subroutine needs a base case.
ReminderWhat the base case does, what happens without it, and the consequence for the stack.
The base case is the condition where the subroutine returns an answer without calling itself. Without it the subroutine would keep calling itself forever (infinite recursion). Each call adds a stack frame, so the stack would run out of memory and cause a stack overflow error.
Common mistakeSaying "the program would crash" without linking it to the stack. Name the stack and the frames.
Q3 Describe 4 marks Describe how a stack is used when a recursive function is executed.
ReminderThe four ideas: frame pushed on each call, what is stored in it, base case, popping in reverse order.
Each time the function is called, a stack frame is pushed onto the call stack. The frame stores the parameter values, local variables and the return address. Calls keep being pushed until the base case is reached, which returns without a further call. As each call finishes, its frame is popped (most recent first), the returned value is passed back and execution continues from the return address.
Common mistakeForgetting the return address, or describing a queue. It is last in, first out.
Q4 Explain 3 marks Explain what is meant by a stack overflow and how it can be caused by a recursive function.
ReminderDefine it, give the cause (base case), say why each call matters.
A stack overflow is an error when the call stack runs out of memory for more frames. It occurs if the base case is missing or can never be reached (e.g. the parameter moves away from the base value). Every recursive call pushes a new frame and none are popped, so the stack fills. (Very deep, but finite, recursion can also do this.)
Common mistakeConfusing it with "overflow" of a number (integer too large).
Q5 Give 4 marks Give two benefits and two drawbacks of using recursion instead of iteration.
ReminderTwo of each. Use the words memory, stack, readable, tree.
Benefits: The code is shorter and easier to read/write for problems that are naturally recursive (trees, divide and conquer). It is easier to see that the solution is correct, because it mirrors the definition of the problem.
Drawbacks: Each call uses stack memory, so it needs more memory than a loop and may cause a stack overflow. It is usually slower because of the overhead of pushing and popping frames (and is harder to trace/debug).
Common mistakeWriting "recursion is faster". It is almost never faster than the equivalent loop.
Q6 Describe 3 marks A recursive function has just reached its base case. Describe what happens next as the program unwinds.
ReminderReturn value, frame popped, caller resumes and completes its calculation.
The base case returns its value and its stack frame is removed (popped). Control passes back to the previous call, using the return address, which receives the value. That call completes its waiting calculation and returns in turn, so the calls finish in the reverse order that they were made.
Common mistakeSaying the calls "restart". They resume exactly where they paused.

Q9 Trace 3 marks What is output when Show(3) is called?

Q10 Trace 4 marks What value is returned by Gcd(48, 18)? Show each call. 
FUNCTION Gcd(a, b : INTEGER) RETURNS INTEGER
   IF b = 0 THEN
      RETURN a
   ELSE
      RETURN Gcd(b, a MOD b)
   ENDIF
ENDFUNCTION
ReminderEvaluate a MOD b for each call to get the next parameters. The answer is passed back unchanged.
Gcd(48, 18): 48 MOD 18 = 12, so call Gcd(18, 12)
Gcd(18, 12): 18 MOD 12 = 6, so call Gcd(12, 6)
Gcd(12, 6): 12 MOD 6 = 0, so call Gcd(6, 0), where b = 0 returns 6
Each earlier call returns 6 unchanged: the value returned is 6.
Common mistakeUsing a DIV b by mistake, or stopping at Gcd(12, 6) without reaching b = 0.
Q11 Trace 3 marks A function is shown. State the value returned by Mystery(472). 
FUNCTION Mystery(n : INTEGER) RETURNS INTEGER
   IF n = 0 THEN
      RETURN 0
   ELSE
      RETURN (n MOD 10) + Mystery(n DIV 10)
   ENDIF
ENDFUNCTION
ReminderMOD 10 gives the last digit; DIV 10 removes it.
Mystery(472) = 2 + Mystery(47); Mystery(47) = 7 + Mystery(4), and Mystery(4) = 4 + Mystery(0) = 4 + 0; so the value returned is 2 + 7 + 4 = 13 (the sum of the digits).
Common mistakeGiving 472 MOD 10 only. Follow the call all the way to Mystery(0).
Q12 Calculate 3 marks A recursive function Fib(n) returns n if n ≤ 1, otherwise Fib(n − 1) + Fib(n − 2). Calculate the total number of calls to Fib made when Fib(5) is called, counting the first call.
Remindercalls(n) = 1 + calls(n − 1) + calls(n − 2). Start with calls(0) = calls(1) = 1.
calls(0) = calls(1) = 1, so calls(2) = 3, calls(3) = 5, calls(4) = 9, and calls(5) = 1 + 9 + 5 = 15 calls.
Common mistakeCounting only the answer (5) or forgetting the base case calls.
Q13 Explain 2 marks Explain why the recursive Fib function in Q12 is inefficient for large values of n.
ReminderSay what is repeated, and what happens to the amount of work.
The same values (e.g. Fib(2), Fib(1)) are calculated again and again in different branches of the call tree. The number of calls roughly doubles as n increases, so it becomes very slow (exponential growth) and uses a lot of stack.
Common mistakeSaying "because it is recursive". Recursion alone is not the problem; the repeated calculation is.
Q14 Trace 4 marks The binary tree below has root 8, left child 4 (with children 2 and 6) and right child 12. The procedure is called with InOrder(Root). State the output and explain how the order is produced. 
PROCEDURE InOrder(Node)
   IF Node <> NULL THEN
      CALL InOrder(Node.Left)
      OUTPUT Node.Value
      CALL InOrder(Node.Right)
   ENDIF
ENDPROCEDURE
ReminderThe base case is a NULL node, which does nothing. The OUTPUT sits between the two calls.
Output: 2, 4, 6, 8, 12. The left subtree is fully visited (recursively) before the node itself is output. Then the node's value is output, then the right subtree is visited. The base case (Node = NULL) ends each branch; as calls return, the nodes appear in ascending order for a binary search tree.
Common mistakeOutputting 8 first (that is pre-order). Where the OUTPUT line sits decides the order.

Q20 Discuss 6 marks A program must list every file in a folder and in all of its sub-folders, to any depth. A programmer writes it recursively; a colleague says a loop would be better. Discuss which approach is more suitable.
ReminderTwo sides plus a judgement tied to the scenario. Use the words stack, base case, memory, depth.
Folders contain smaller folders of the same type, so the problem is naturally recursive. A recursive routine lists the files, then calls itself for each sub-folder; the base case is a folder with no sub-folders. The code is short and easy to read and to check. A loop would need its own stack or queue of folders still to visit, making the code longer and harder to follow. However, each recursive call uses stack memory; a very deeply nested folder structure could cause a stack overflow, where a loop would not. Judgement: folder depth is normally small, so recursion is more suitable here as clarity outweighs the small memory cost.
Common mistakeListing generic pros and cons without using the folder scenario, or not reaching a conclusion.

Top tips

  • Find the base case first. In any recursion question, locate the IF that stops the calls and say what it returns.
  • Trace downwards, then upwards. Write all the calls to the base case before calculating anything. Then fill in the return values from the bottom up.
  • Before the call = going down; after the call = coming up. Show(n) prints in opposite orders either side of the CALL.
  • Count the base case call. Fact(3) is four calls and four frames, not three.
  • Each call has its own parameters. Fact(3) and Fact(2) each hold their own n. Draw them separately.
  • The argument must move toward the base case. n − 1, DIV 10, a shorter string, a smaller range. If not, stack overflow.
  • Write RETURN before the recursive call in a function. A call without RETURN loses the answer.
  • Stack answers need four words: frame, return address, push/pop, last in first out.
  • Drawbacks: say memory and stack. "Slower" alone earns nothing.
  • Check Fibonacci-style code for repeated work. Two calls per frame means a branching tree and repeated calculations.
  • When writing code, copy the structure: header, base case, general case, ENDIF, ENDFUNCTION. Marks go to each part.
  • For converting to a loop: an accumulator replaces the waiting multiplication or addition.
