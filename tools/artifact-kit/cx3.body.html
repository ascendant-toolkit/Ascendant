IGCSE Computer Science · 0478 · Exam technique

Paper 2 Algorithms and Programming: Technique and Practice

How Paper 2 is built, the syllabus pseudocode, the standard methods, trace tables, finding errors, flowcharts, test data and short written answers, with fourteen real questions and what each mark was for.

This part in five sentences

Paper 2 is a 75-mark written paper in 1 hour 45 minutes on Topics 7 to 10, with about 60% of its marks for applying knowledge (AO2), and no calculator. Most of the marks outside the last question come from a few tasks that repeat every series: complete a trace table, find and fix errors, draw a flowchart, write short pseudocode, suggest test data and name checks. The syllabus publishes the pseudocode that the paper uses, and the examiner reports say that candidates who follow it exactly score the most, while answers written in program code earn no marks unless it is the 15-mark scenario question. Logic matters more than syntax, but precision matters: x > y is accepted and "x is greater than y" is not. Learn the standard patterns for counting, totalling, finding the largest and smallest, searching and sorting, because most algorithm marks are for initialising, looping, comparing and updating in the right places.

4 · The standard methods

The syllabus limits standard methods to linear search, bubble sort, totalling, counting and finding the maximum, minimum and average. In each, the marks are for the same four things: initialise, loop, compare or update, and output. The examiner report for Oct/Nov 2024 says the maximum and minimum variables must be initialised, and totals set to zero before they are used.

Counting and totalling

Total ← 0Count ← 0FOR Index ← 1 TO 50    IF Marks[Index] > 0      THEN        Total ← Total + Marks[Index]        Count ← Count + 1    ENDIFNEXT IndexAverage ← Total / Count

Largest and smallest

Largest ← Marks[1]Smallest ← Marks[1]FOR Index ← 2 TO 50    IF Marks[Index] > Largest      THEN        Largest ← Marks[Index]    ENDIF    IF Marks[Index] < Smallest      THEN        Smallest ← Marks[Index]    ENDIFNEXT Index

Linear search

Found ← FALSEIndex ← 1WHILE Found = FALSE AND Index <= 50 DO    IF Names[Index] = SearchName      THEN        Found ← TRUE      ELSE        Index ← Index + 1    ENDIFENDWHILE

Bubble sort with the two efficiency features

The Oct/Nov 2024 mark scheme gives the two features that make a bubble sort efficient: a flag that shows whether a swap was made, so the loop stops once the data is in order, and an inner loop whose limit reduces after each pass, so fewer comparisons are needed.

Limit ← 100Pass ← 1Swapped ← TRUEWHILE Swapped = TRUE AND Pass <= Limit - 1 DO    Swapped ← FALSE    FOR Counter ← 1 TO Limit - Pass        IF ItemList[Counter] > ItemList[Counter + 1]          THEN            Temp ← ItemList[Counter]            ItemList[Counter] ← ItemList[Counter + 1]            ItemList[Counter + 1] ← Temp            Swapped ← TRUE        ENDIF    NEXT Counter    Pass ← Pass + 1ENDWHILE

5 · Trace tables

The syllabus says a trace table records, at each step, the variables, the outputs and the user prompts. The examiner reports give three rules that cost marks every series:

  • Record every assignment. Each time a variable is given a value, the new value goes in its column.
  • No quotation marks on outputs. The output column shows what the user sees.
  • Stop when the stopping condition is met. Once the terminating value is processed, make no further entries, even if there is more input data.

6 · Finding and fixing errors

Two real questions show the pattern. In both, the answer is a line number and a correction. The Oct/Nov 2024 report on a flowchart question in paper 23 notes that many candidates identified the same error twice, so list each error once.

QuestionErrors the mark scheme acceptedThe type of error

Line 04: = should be <>
Line 14: OR should be AND
Line 19: WHILE should be UNTIL		Wrong variable name; wrong comparison; wrong logical operator; wrong loop keyword
Bubble sort (Oct/Nov 2024, paper 22, 5 errors)Line 02: loop counter declared STRING, should be INTEGER
Line 09: Temp ← TRUE should be Swapped ← TRUE
Line 10: OR should be AND

  1. Check the structure first. Every IF needs an ENDIF, every REPEAT an UNTIL, every FOR a NEXT.
  2. Check every variable name against the declarations.
  3. Check every condition and operator: comparisons, AND against OR, the stopping value.
  4. Run one small example through the algorithm to catch an index or initialisation error.
  5. Write each error once, with its line number and the corrected line.

7 · Flowcharts

Flowchart questions are marked with one mark for each of a short list of points. For a count-controlled totalling flowchart in Oct/Nov 2024 the list was: two labelled terminators, loop initialisation, incrementation and termination, input with a prompt, total initialised and added to, output with a message, and a fully correct chart with arrows, Yes/No labels and symbols. The examiner reports add that candidates lost marks for wrong symbols and for flow lines without arrows.

A real Oct/Nov 2024 question asked for two items of test data to test a limit of 80 for whole numbers, with a reason for each. The mark scheme: 80, the largest accepted number at the limit; and 81, the smallest rejected number. The report says many candidates named types of test data or gave any values. 9 · Short written answers in Paper 2

  • Purpose of an algorithm: say what it achieves with the input, not how it loops. "It multiplies the input by every whole number below it" earns the mark; "it loops" does not.
  • Program development life cycle: analysis, design, coding, testing. Analysis: abstraction (removing unnecessary detail), decomposition (inputs, processes, outputs, storage), identifying the problem and the requirements.
  • Design methods: structure diagram (a hierarchy showing a program broken into parts), flowchart (the ordered steps), pseudocode (what the program does in plain language). Each method named earns one mark and its description another.
  • Why store data in a file: it can be retrieved when needed, and storage is non-volatile. The report says candidates wrote about checking a password instead of why it is stored.
  • Meaningful identifiers: Marks, Counter, Total. Array is not meaningful. Maintainable code uses comments, procedures and functions, and white space.

10 · Common ways to lose marks

  • Program code in a pseudocode question.
  • Not initialising a total, a counter, or the largest and smallest.
  • Quotation marks in the output column of a trace table, or entries after the stopping value.
  • Wrong flowchart symbols, or lines with no arrows, or decisions with one exit labelled.
  • Naming a type of test data instead of giving values, or giving one value for boundary data.
  • Naming a validation check when verification is asked for.
  • Listing the same error twice in an error-finding question.
  • Vague descriptions of purpose such as "it counts" without saying what.

6 · Multiple choice

These come from the Principal Examiner Reports for Cambridge IGCSE Computer Science, which describe what candidates actually wrote. The wording is ours.

Program code in a pseudocode question

Oct/Nov 2024, papers 21 and 23: asked to write pseudocode, many candidates used program code or pseudocode that did not match the syllabus. The syllabus says solutions in program code are not awarded marks except in the 15-mark scenario question.

Exam use: any 'write pseudocode' question: use the syllabus keywords (OUTPUT, ←, ENDIF) and nothing else.

An array called Array

Oct/Nov 2024, papers 21 and 23: when asked for meaningful identifiers, many candidates used Array for the array, which is not meaningful. The mark scheme accepts names such as MyArray or Names.

Exam use: name things for what they hold: Marks, MemberTime, Total, Counter.

Quotation marks and extra rows in a trace table

Oct/Nov 2024, paper 21: quotation marks on outputs are incorrect, and once the stopping condition has been met no further entries should be made. In paper 23: each time a variable is assigned a value it must be recorded in the table.

Exam use: trace tables: record every assignment, write outputs as the user sees them, stop at the stopping value.

Naming validation when verification is asked

Oct/Nov 2024, paper 22: a significant number of candidates named validation checks such as range check or presence check when asked for a verification check. Visual check and double entry check were the accepted answers.

Exam use: check the word: validation, verification.

Test data without the detail

Oct/Nov 2024, paper 22: a significant number of candidates named types of test data or gave any values. The question asked for test data that tested the limit of 80, so boundary data was needed: 80 as the highest accepted and 81 as the first rejected.

Exam use: give the actual value, say if it is accepted or rejected, and give the reason.

The same error twice

Oct/Nov 2024, paper 23: many candidates identified the same error twice by swapping Yes and No on one decision box in a flowchart. The question had different errors to find.

Exam use: list each error once; if you have found the same error twice, look for another.

Wrong symbols and flow lines with no arrows

Oct/Nov 2024, paper 21: many candidates used incorrect flowchart symbols or did not complete flow lines with arrows. Flow lines should go to a terminator or a subroutine.

Exam use: flowcharts: use a terminator, a process, a decision and an input/output box, and put an arrowhead on every line.

Based on Oct/Nov 2024 · 0478/21 · Q6(a) [3] An incomplete algorithm counts the zero readings in an array and totals the other readings. Complete it.
DECLARE A[1:40] : INTEGERDECLARE C : INTEGERDECLARE Z : INTEGERDECLARE S : INTEGERS ← 0...............................FOR C ← 1 TO 40    IF A[C] ...............      THEN        Z ← Z + 1      ELSE        S ← S + A[C]    ENDIF...............................
What the mark scheme wants
  • One mark for each of three points: initialise the zero counter, Z ← 0, before the loop
  • The comparison that tests for a zero element: = 0
  • The loop closing statement: NEXT C
Plan

Check what is used before it is set. S is set to 0 on line 5, so Z must be set on the blank line. Check the IF line against the THEN and ELSE, and close the FOR with NEXT and the same variable.

Based on Oct/Nov 2024 · 0478/21 · Q6(c) [3] Meaningful identifiers have not been used in the algorithm above. Suggest meaningful identifiers for the array A, and for the variables C, Z and S.
What the mark scheme wants
  • One mark for a meaningful identifier for the array, such as Readings or MyArray
  • One mark for two meaningful identifiers for variables, two marks for all three, such as Index, ZeroCount, Total
  • 'Array' on its own was not accepted as meaningful
Plan

The name should say what the thing holds or does: Readings, Index, ZeroCount, Total. Use mixed case and no spaces, as in the syllabus.

Based on Oct/Nov 2024 · 0478/21 · Q9 [8] A program checks a quiz mark between 0 and 20 inclusive. Input stops when 99 is entered. (a) Identify four errors and correct each. (b) Give the range of marks accepted. (c) Complete the trace table for the corrected program using 7, 21, 0, 99, 5.
REPEAT    OUTPUT "Enter the mark "    INPUT Mrk    IF Mark = 99      THEN        IF Mark > 20          THEN OUTPUT "Too high"        ENDIF        IF Mark < 0          THEN OUTPUT "Too low"        ENDIF        IF Mark >= 0 OR Mark <= 20          THEN OUTPUT "Valid"        ENDIF    ENDIFWHILE Mark = 99
What the mark scheme wants
  • (a) Four errors, each with its correction: the variable is Mrk but everywhere else Mark; the IF should test Mark <> 99; the OR should be AND; the REPEAT must end with UNTIL Mark = 99, not WHILE
  • (b) Two marks: greater than or equal to 0, and less than or equal to 20
  • (c) One mark for each correct column, maximum two: Mark column 7, 21, 0, 99; output column Valid, Too high, Valid, with the prompt before each input; nothing after 99
Plan

Read for structure (REPEAT…UNTIL), then names, then operators. For the trace table, the final 5 is never read. Remember: no quotation marks on the outputs.

Based on Oct/Nov 2024 · 0478/22 · Q7 [8] An algorithm stops when −1 is entered. (a) Complete the trace table for the input data 4, 5, −1, 12, 3. (b) State the purpose of the algorithm. (c) Describe the problem if the value 0, 1 or less than −1 is input.
REPEAT    INPUT Number    IF Number <> -1      THEN        Product ← Number        FOR Step ← Number - 1 TO 1 STEP -1            Product ← Product * Step        NEXT Step        OUTPUT Product    ENDIFUNTIL Number = -1
Columns: Number, Step, Product, OUTPUT.
What the mark scheme wants
  • (a) Five marks: correct Number column; correct Step column; the Product column down to the first output; the rest of the Product column; the OUTPUT column
  • For 4: Product 4, then Step 3 → 12, Step 2 → 24, Step 1 → 24, OUTPUT 24. For 5: 5, then 20, 60, 120, 120, OUTPUT 120. Then −1; 12 and 3 are never read
  • (b) It multiplies the input by every whole number below it, down to 1 (the factorial)
  • (c) Two marks: the program would accept the value and enter the FOR loop; the counter would keep reducing and never reach 1, as it would already be less than 1, so the loop would be endless
Plan

Record the Product after every pass of the loop. Stop at −1. For (c), the mark scheme says the program accepts the value and enters the FOR loop, and that the counter never reaches 1.

Top tips

  • Use the syllabus pseudocode. OUTPUT, ←, ENDIF. No program code.
  • Initialise before the loop. Totals to 0, counters to 0, largest and smallest to the first value.
  • Trace every assignment. No quotation marks. Stop at the stopping value.
  • Check structure, names, operators. Then run one small example.
  • Label both exits. Yes and No, and an arrow on every line.
  • Test data needs a pair. Last accepted and first rejected.
  • Meaningful names. Marks, Counter, Total. Not Array.
