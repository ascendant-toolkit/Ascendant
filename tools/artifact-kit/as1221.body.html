Coursebook: Chapter 12 · Software development · section 12.2 Program design

Structure charts: modules, parameters, functions and procedures, selection and repetition, module headers from a chart and decomposition, with animations, labs and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

A structure chart shows how a program is divided into modules (procedures and functions) and how they relate: which module calls which, and what parameters pass between them. It is drawn as a hierarchy: the top module calls the modules below it. Arrows beside the lines show the parameters passed down to a module and the values passed up (returned) to the module that called it. A diamond shows selection (one of the lower modules is called) and a curved arrow shows repetition (the lower modules are called repeatedly, in order, left to right). Structure charts are produced in the design stage, from the problem broken down by decomposition.

1 · The notation

SymbolMeaning
RectangleA module (procedure or function) with its name
Line from a module to the one belowThe upper module calls the lower module
Arrow pointing down with an open circleA data parameter passed to the lower module
Arrow pointing upA value returned to the calling module: the lower module is a function
Arrow with a filled circleA flag (a Boolean value)
Arrow with a head at both endsA value passed in and passed back: a BYREF parameter
Diamond on the calling moduleSelection: one of the lower modules is called, chosen when the program runs
Curved arrow under the calling moduleRepetition: the lower modules are called repeatedly in order, left to right

A module with no upward arrow is a procedure; a module with an upward arrow is a function and its header ends with RETURNS and a type.

2 · Reading a chart to write headers

Analyse has one parameter coming down (Count): PROCEDURE Analyse(Count : INTEGER). Update has Key coming down and T1 coming back, so it is a function: FUNCTION Update(Key : STRING) RETURNS INTEGER. Sort has a two-headed arrow: PROCEDURE Sort(BYREF P2 : BOOLEAN). The curved arrow on Convert means it repeatedly calls Analyse, then Update, then Sort.

3 · Drawing a chart from headers

  1. Put the top (calling) module at the top and the modules it calls below it, in the order they are called.
  2. Join each pair with a line.
  3. For each parameter in a header, add a down arrow with an open circle (open circle for data, filled for a Boolean flag).
  4. For a FUNCTION add an up arrow for the returned type. For BYREF add an arrow with two heads.
  5. Add a diamond if one of the modules is called, or the curved arrow if they are called repeatedly.

4 · Why use a structure chart and decomposition

  • Breaking a complex problem into sub-problems (decomposition) makes it easier to understand and solve.
  • Smaller modules are easier to program, test and maintain.
  • Different modules can be given to different teams or programmers with different expertise and solved separately.
  • A structure chart shows the relationships and hierarchy, the parameters passed between modules, and whether each module is a function or a procedure.

Common ways to lose marks

  • Arrows in the wrong direction: down is a parameter passed to the lower module; up is a value returned.
  • Forgetting the up arrow for a function, or adding one for a procedure.
  • Showing selection when the question says the modules are called repeatedly (and the other way round).
  • Leaving out the data types in a header, or BYREF on a two-headed arrow.

Top tips

  • Down passes in, up returns. An up arrow means a function.
  • Two heads: BYREF. In and out.
  • Diamond or curve. Diamond: choose one. Curve: repeat all in order.
  • Name every module. In the explanations and on the chart.
  • Types in headers. Add the data type for every parameter.
  • Left to right. The order of the lower modules is the order they are called.
