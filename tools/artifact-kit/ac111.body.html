Binary Prefixes, Number Bases, BCD and Hexadecimal

Coursebook: Chapter 1 · Information representation, section 1.1 Data representation

Binary and decimal prefixes, converting between binary, denary and hexadecimal, Binary Coded Decimal, where BCD and hex are used, and eleven questions from the 2021 to 2026 papers.

This page in five sentences

Computers store everything in binary, and the syllabus expects you to move between binary, denary and hexadecimal and to describe Binary Coded Decimal (BCD). Sizes use two sets of prefixes: kilo, mega, giga, tera are powers of 10 and kibi, mebi, gibi, tebi are powers of 2, so a kibibyte is 1024 bytes and a kilobyte is 1000. Hexadecimal is a shorthand for binary because one hex digit stands for exactly four bits. BCD stores each denary digit in its own four bits, which makes it easy to display and exact for money. Most marks in this topic are for a conversion with the working shown, a one-line difference, or a justified use of BCD or hex.

1 · Binary and decimal prefixes

A decimal prefix steps up by 1000 (103) each time. A binary prefix steps up by 1024 (210) each time, because memory addresses are binary and 1024 is the power of 2 closest to 1000.

Decimal prefixBytesBinary prefixBytesGap
kilobyte (kB)1000 = 103kibibyte (KiB)1024 = 2102.4%
megabyte (MB)1 000 000 = 106mebibyte (MiB)1 048 576 = 2204.9%
gigabyte (GB)109gibibyte (GiB)1 073 741 824 = 2307.4%
terabyte (TB)1012tebibyte (TiB)24010.0%
  • The pairs to know: kibi and kilo, mebi and mega, gibi and giga, tebi and tera. The syllabus names exactly these four pairs.
  • Moving between units within one family multiplies or divides by the step: 3 kibibytes = 3 × 1024 = 3072 bytes, and 2 terabytes = 2 × 1000 = 2000 gigabytes. Do not mix families in one calculation.
  • Why the gap matters: storage makers advertise in decimal units while operating systems often report in binary units, so a 1 TB drive appears as about 931 GiB.
  • Bits and bytes: 1 byte = 8 bits, so a file of 1 kibibyte holds 8192 bits.
Exam tipA "difference between a kibibyte and a kilobyte" needs both values or both families: "kibibyte = 1024 bytes, kilobyte = 1000 bytes" or "kibi is a binary prefix, kilo is a denary prefix". Saying only "a kibibyte is bigger" is not enough.

2 · Number systems and place value

A number system is defined by its base: the number of different digits it uses. Each column is worth the base raised to a power.

SystemBaseDigitsColumn values (right to left)
Denary100 to 91, 10, 100, 1000
Binary20 and 11, 2, 4, 8, 16, 32, 64, 128
Hexadecimal160 to 9 then A to F (A=10, B=11, C=12, D=13, E=14, F=15)1, 16, 256, 4096

Binary to denary

Write the column values above the bits and add the values under each 1. For 10110110: 128 + 32 + 16 + 4 + 2 = 182.

Denary to binary

Work down the column values, writing 1 if the value fits into what is left and subtracting it, otherwise 0. For 241: 128 fits (113 left), 64 fits (49), 32 fits (17), 16 fits (1), 8, 4 and 2 do not, 1 fits. That gives 11110001. The Watch tab animates this.

Binary to hexadecimal and back

Split the binary number into groups of four bits from the right, then convert each group to one hex digit. 1111 0010 becomes F and 2, so 11110010 = F2. To go back, write each hex digit as four bits.

Denary to hexadecimal

Either convert to binary first and then group the bits, or divide by 16: 241 ÷ 16 = 15 remainder 1, so 241 = F1 (15 is F). For a number over 255 the binary route is safer: 558 = 0010 0010 1110 = 22E.

Hexadecimal to denary

Multiply each digit by its column value and add. F0 = 15 × 16 + 0 = 240. A04 = 10 × 256 + 0 × 16 + 4 = 2564. C0F = 12 × 256 + 0 + 15 = 3087.

3 · Binary Coded Decimal (BCD)

In BCD each denary digit is stored as its own 4-bit group. The number is not converted to a single binary value.

DenaryBCDPlain binary
9641001 0110 010011 1100 0100
871000 0111101 0111
270010 01111 1011
  • Encoding: take each digit, write it as four bits, and keep the digits in the same order. 964 is 9 (1001), 6 (0110), 4 (0100).
  • Decoding: split into groups of four from the left or right and read each group as a digit. 1000 0110 0101 = 8, 6, 5 = 865.
  • Only 0000 to 1001 are valid. The patterns 1010 to 1111 are never a BCD digit, so a nibble such as 1100 means the value is not BCD.
  • Same bits, different value: 0010 0111 is 39 as an unsigned binary integer but 27 as BCD. The question tells you which to use.
  • Cost: BCD uses more bits than plain binary for the same value (4 bits per digit), so it wastes some storage and arithmetic is more awkward.

4 · Where BCD and hexadecimal are used

Used forWhy that representation
BCD · financial and banking calculationsMoney uses decimal digits and exactly two decimal places. Many decimal fractions cannot be stored exactly in plain binary, so rounding errors build up. BCD keeps each digit exact.
BCD · calculators, digital clocks, seven-segment displaysA display shows one digit at a time, so each digit is already in its own group and conversion to the display is simple.
BCD · date and time in the PC's BIOS clockHours, minutes and days are read and shown as separate decimal digits, so conversion with denary is easier.
BCD · barcode systemsEach digit of a code is separate, and denary-to-BCD conversion is accurate and quick.
Hex · colour codes such as #FC238AThree pairs of hex digits give the red, green and blue values (0 to 255), which is far shorter than 24 binary digits.
Hex · memory addresses, machine code and memory dumpsOne hex digit is four bits, so addresses are short and easy to read and copy without mistakes.
Hex · MAC addresses, IPv6 addresses, error codesLong binary values are shown in a compact form that a person can check.

Hexadecimal does not make the computer work faster or take less memory: the computer still stores binary. It is for people, because it is shorter, easier to read and has fewer transcription errors than a long string of 1s and 0s.

5 · Common ways to lose marks

  • Treating BCD as plain binary: converting 87 to 1010111 instead of 1000 0111.
  • Mixing prefixes: using 1000 for a kibibyte or 1024 for a megabyte.
  • Reading hex letters as ordinary numbers, for example taking F as 6 instead of 15.
  • Dropping leading zeros in a BCD or fixed-width answer, so the groups no longer line up.
  • Justifying BCD with "it is faster". The accepted reasons are exact decimal digits, no accumulating errors, and easy conversion to a display.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

The missing gigabytes

A 1 TB drive holds 1 000 000 000 000 bytes. A computer that reports sizes in binary units divides by 240 and shows about 0.91 TiB, or roughly 931 GiB. Nothing is missing: the two sides use different prefixes.

Exam use: a 'why does the drive show less space' question: decimal prefix on the label, binary prefix in the reporting.

Web colours

A colour such as #FC238A is red FC (252), green 23 (35) and blue 8A (138). Three bytes give 16.7 million colours, and the six hex digits are much easier to type and compare than twenty-four bits.

Exam use: hex questions set in a graphics context: convert each pair separately.

Network addresses

A MAC address is 48 bits shown as twelve hex digits, such as 3C:22:FB:7A:10:E5. IPv6 addresses use hex too. Engineers read and copy them far more reliably than binary.

Exam use: justify hex: shorter, four bits per digit, fewer transcription errors.

Why the till does not use plain binary for pence

Decimal fractions such as 0.10 cannot be stored exactly in plain binary, so repeated additions drift. Financial software uses decimal digit encodings such as BCD so each penny is held exactly.

Exam use: BCD application and justification: exact decimal digits, no accumulating rounding error.

Seven-segment displays

A digital clock or calculator shows one digit at a time. Holding each digit in its own four bits means the display circuit can decode the digit directly, with no division by ten needed.

Exam use: second BCD justification: easier conversion between stored value and the display.

Top tips

  • Show the groups. Write the column values or the nibbles beside the answer. Working earns a mark even when the answer slips.
  • Match the prefix family. Compare kibi with kilo, mebi with mega, gibi with giga and tebi with tera. Never mix 1000 and 1024 in one step.
  • Check which rule the question names. The same eight bits can be unsigned binary, BCD or two's complement. Each gives a different denary value.
  • Use the full width. A 12-bit answer needs twelve bits with leading zeros; a BCD answer needs a full nibble for every digit.
  • Justify, do not just name. For BCD or hex, write the use and then the reason: 'financial calculations, because decimal digits are stored exactly'.
  • Hex is for people. The computer stores binary. Hex is shorter and easier to read and copy, with fewer errors.
