Compression: Lossy, Lossless and Run-Length Encoding

Coursebook: Chapter 1 · Information representation, section 1.3 Compression

Why files are compressed, lossy against lossless with a justified choice, run-length encoding step by step, how text, images and sound are compressed, and eleven questions from the 2021 to 2026 papers.

This page in five sentences

Compression makes a file smaller so that it takes up less storage space and can be transmitted in less time using less bandwidth. Lossless compression keeps all the data, so the original can be rebuilt exactly; lossy compression permanently removes data that is judged unimportant, which gives a much smaller file but cannot be undone. Run-length encoding (RLE) is the lossless method the syllabus names: a run of identical values is replaced by one copy of the value and a count. Text must be compressed losslessly, whereas photographs, music and streamed video can usually be compressed lossily because the loss is hard to notice. A good answer says what is removed or replaced, what the effect on the file is, and why that suits the situation.

1 · Why compress files?

  • Less storage: the file takes up less space on a drive or server, so more files can be kept.
  • Faster transmission: fewer bits to send, so the file is transmitted or downloaded in less time.
  • Less bandwidth: it uses less of the connection, which matters for people with a slow or limited connection.
  • Fits a limit: an email attachment or upload may have a maximum file size.
  • Less buffering: a streamed video or a real-time call keeps up with the connection.

Examples: photographs compressed before they are uploaded to a website; a sound file compressed before it is emailed; a text file compressed by an operating system utility; a video compressed before real-time streaming.

Exam tipRead the last words of the question. A benefit "for storing" the file is less space; a benefit "for transmitting" it is less time or bandwidth. Both are true of compression, but only one answers the question asked.

3 · Run-length encoding (RLE)

RLE finds runs: consecutive identical values. Each run is replaced with one copy of the value and the number of times it repeats.

OriginalRLESaved?
AAAABBBCC4A3B2C9 symbols to 6
BBBBBBBBBB (ten blue pixels)10B10 values to 2
EA F1 F1 F2 F2 F2 EA1EA 2F1 3F2 1EA7 values to 4 pairs
RGB (all different)1R1G1B3 symbols to 6: bigger
  • Lossless: decoding repeats each value its count, so the original is rebuilt exactly.
  • Works best with long runs: a logo, a diagram, a screenshot, a scanned page with large white areas, text with repeated characters.
  • May not shrink the file when there are few runs, as in a photograph where neighbouring pixels differ slightly. Each value then needs a count of 1 stored beside it, which adds data. The mark scheme example is red, green, blue becoming red 1, green 1, blue 1.
  • Bitmap: done row by row, or across the whole sequence of pixel codes. The first row of ten blue pixels is stored as blue and 10.
  • Sound: consecutive samples with the same value can be run-length encoded. Silence is a long run.

6 · Common ways to lose marks

  • Saying "lossy loses quality" without saying data is permanently removed and cannot be restored.
  • Saying "lossless makes the file the same size". It still reduces the size, by encoding the data more efficiently.
  • Writing that RLE "compresses repeated images". It compresses runs of identical consecutive values.
  • Giving a benefit that is not for the situation, such as faster transmission in a question about storing.
  • Suggesting lossy compression for a text file without noting that it would corrupt the text.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Photos on a website

A photograph from a phone can be several megabytes. Websites usually store a lossy version a tenth of that size. Pages load faster, and few visitors notice the difference on a screen.

Exam use: lossy for web photographs: smaller file, faster download, loss of detail not noticed.

Streaming video

Services send compressed video so that it keeps up with the viewer's connection. If the connection is slow the quality is reduced further. Without lossy compression, most connections could not carry a live video call.

Exam use: real-time streaming: lossy reduces bandwidth and buffering.

Zip files

A zip file combines files and compresses them losslessly. The files that come out are identical to the ones that went in, which is why zip is used for documents, spreadsheets and programs.

Exam use: lossless for text and program files: nothing may be lost.

Screenshots and logos

An image with big areas of one colour, such as a logo or a screenshot of a web page, has long runs of identical pixels. Run-length encoding shrinks it a lot without changing a pixel.

Exam use: RLE works on images with long runs of identical colours.

Why a photograph barely shrinks with RLE

Neighbouring pixels in a photograph are almost never identical, so each run has length 1 or 2. RLE then adds a count for almost every pixel and the file can be bigger. Photographs are compressed with lossy methods instead.

Exam use: RLE may not reduce a bitmap's size when there are few runs; the counts add data.

Based on May/June 2026 · 9618/13 · Q3(c)(i) [4] An animation's images and sound are compressed independently using lossless compression. Explain the different ways that lossless compression can be used for the images and for the sound file.
What the mark scheme wants
  • Images (max two): run-length encoding; store each colour and the number of times it appears consecutively.
  • Sound (max two): reduce the amplitude range to the values actually used, which reduces the sampling resolution without affecting the sound; or record the changes in amplitude instead of each amplitude, since each change needs fewer bits; RLE is accepted for sound but not for both parts.
Plan

Two different methods, one for each file type. Do not use RLE for both.

Technical knowledge (K)Applied to the context (A)

Images: run-length encoding stores each colour with the number of times it appears in a row. Sound: instead of storing every full amplitude, the change from one amplitude to the next is stored, and each change needs fewer bits than a whole new amplitude.

Top tips

  • Say what is removed. Lossy permanently removes data and the original cannot be rebuilt. Lossless keeps all the data.
  • Match the benefit to the question. Storage means less space. Transmission means less time and bandwidth.
  • Describe RLE fully. A run of identical values becomes one copy of the value and a count.
  • Use the example you are given. If the question shows a row of pixels, write its RLE code.
  • Justify one side. Pick lossy or lossless and keep every reason on that side.
  • RLE can make a file bigger. When there are few runs, each value is stored with a count of 1.
