Floating-point Numbers: Format and Conversion

Coursebook: Chapter 13 · Data representation, section 13.3 Floating-point numbers, representation and manipulation

The floating-point format with a two's complement mantissa and exponent, converting to and from denary with the working the exam awards marks for; animations, labs and every Paper 3 conversion question from 2021 to 2026.

This page in five sentences

A computer stores a real number in floating-point form as a mantissa (the digits) and an exponent (the power of 2 that scales them), both in two's complement, so the value is mantissa × 2exponent. The mantissa has an implied binary point after its first bit, so it is a value from −1 up to (but not including) +1, and the exponent says how many places to move the point right (positive) or left (negative). To convert a floating-point number to denary you read the exponent, move the binary point, and add up the place values, remembering the first bit of a negative mantissa has a negative place value. To convert a number to floating-point you convert it to binary, move the point to get a normalised mantissa, find the exponent, and for a negative number take the two's complement of the mantissa. The next page covers normalisation, accuracy and errors.

1 · The format

A floating-point number is stored in two parts, with a fixed number of bits for each, for example 10 bits for the mantissa and 6 for the exponent (16 bits in total):

Mantissa (10 bits)Exponent (6 bits)
1.011000111000111
  • The mantissa is a two's complement fraction. The binary point sits after the first bit: 1.011000111. The first bit has a place value of −1; the rest are ½, ¼, ⅛...
  • The exponent is a two's complement integer: 000111 is 7, 100001 is −31.
  • Value = mantissa × 2exponent. Multiplying by 27 moves the binary point 7 places to the right.
  • A positive mantissa starts 0 and a negative one starts 1.
Two's complement reminderThe first bit has a negative place value. In 8 bits, 10011011 is −128 + 16 + 8 + 2 + 1 = −101. To negate a number, invert every bit and add 1. So −(01100101) = 10011010 + 1 = 10011011.

2 · Floating-point to denary

  1. Exponent: convert the exponent from two's complement to denary.
  2. Move the point: write the mantissa with its point after the first bit, then move the point right by the exponent (left if the exponent is negative), adding zeros if you run out of bits.
  3. Evaluate: add up the place values. For a negative number the first (left-most) bit is negative: −2n.
StepMantissa 1011000111, exponent 000111
Exponent000111 = 7
Mantissa with its point1.011000111
Move the point 7 places right10110001.11
Place values−128 + 32 + 16 + 1 + 0.5 + 0.25
Value−78.25

A positive example: mantissa 0100111100, exponent 001001 = 9. The mantissa is 0.100111100; moving the point 9 places gives 100111100, which is 256 + 32 + 16 + 8 + 4 = 316. With a negative exponent the point moves left: exponent −2 turns 0.101 into 0.00101.

3 · Denary to floating-point

  1. Convert the number (ignore the sign) to binary, including any fraction.
  2. Normalise: move the binary point so the number is written 0.1... × 2n. The number of places moved is the exponent (positive if the point moved left, negative if it moved right).
  3. Write the mantissa: a 0 for the sign, then the digits, padding with zeros on the right to fill the mantissa.
  4. Negative numbers: take the two's complement of the mantissa (invert and add 1). The exponent stays the same.
  5. Write the exponent in two's complement using the bits available.
Step−7.25 in a 10-bit mantissa, 6-bit exponent
Binary7.25 = 111.01
Normalise0.11101 × 23, so the exponent is 3
Positive mantissa0111010000
Negative: invert, add 11000101111 + 1 = 1000110000
Exponent 3 in 6 bits000011
Answer1000110000 000011
Check yourselfConvert your answer back to denary. 1.000110000 × 23 = 1000.110000 = −8 + 0.5 + 0.25 = −7.25. A normalised negative mantissa always starts 10; a normalised positive one starts 01.

If the number has more significant bits than the mantissa can hold, the extra bits on the right are lost (truncated). The stored value is then only an approximation (see the next page).

from fractions import Fraction def to_float(x, mbits, ebits):    """normalised two's complement mantissa and exponent for x"""    mag, e = abs(Fraction(x)), 0    while mag >= 1: mag, e = mag / 2, e + 1    while mag < Fraction(1, 2): mag, e = mag * 2, e - 1    m = int(mag * 2 ** (mbits - 1))                  # truncate extra bits    if x < 0: m = (1 << mbits) - m                   # two's complement    return format(m, f"0{mbits}b"), format(e % (1 << ebits), f"0{ebits}b") print(to_float(-7.25, 10, 6))                        # ('1000110000', '000011')

4 · Setting out your answer

  • Show the conversion to binary, the movement of the binary point (the exponent), and the final mantissa and exponent. The mark scheme awards marks for the working.
  • Write the answer in the table the question gives: mantissa on the left, exponent on the right.
  • Count the bits: a 10-bit mantissa has exactly 10 digits and a 6-bit exponent exactly 6.

5 · Common ways to lose marks

  • Treating the mantissa as a whole number. The point is after the first bit.
  • Getting the exponent's direction wrong: moving the point right makes a positive exponent when converting to denary; moving it left to normalise a large number also makes a positive exponent.
  • For a negative number, forgetting to take the two's complement of the whole mantissa, or changing the exponent.
  • Not giving the first bit of a negative mantissa a negative place value when evaluating.
  • Writing a mantissa or exponent with the wrong number of bits.
  • Not saying the number is truncated (precision lost) when it does not fit in the mantissa.

Why computers use floating point

A scientific calculation may involve both the size of an atom and the distance to a star. Floating point stores a number as digits and a scale factor so the same number of bits can cover both huge and tiny values.

Exam use: floating point trades some precision for a very wide range.

A weather model

Temperatures, pressures and distances are real numbers with fractional parts. The model stores them in floating point and a small rounding at each step can add up over many steps.

Exam use: floating-point numbers are often approximations of the true value.

Graphics and games

Positions and colours of millions of points are real numbers. Graphics hardware is built to do floating-point arithmetic very fast.

Exam use: mantissa and exponent let one format store many magnitudes.

Money in a banking program

Money is often stored as a whole number of pence rather than a floating-point number, because some decimals such as 0.1 cannot be stored exactly in binary.

Exam use: not every decimal fraction can be stored exactly in binary floating point.

Scientific notation

Writing 6.02 × 1023 is the same idea in denary: a number (the mantissa) and a power of ten (the exponent). Floating point uses powers of 2.

Exam use: value = mantissa × 2exponent.

ReminderUse the positive mantissa for 5.5 and negate it.

ReminderA negative exponent moves the point left.

Value = 1/8 + 1/16 = 0.1875

ReminderAdd the two parts.

16 bits 2 bytes

Top tips

  • Write the working. Binary conversion, the movement of the point, the exponent, then the answer. The marks are for the working.
  • Mantissa starts 0 or 1. 0 positive, 1 negative. The point is after that first bit.
  • Exponent sign. Point moves right to evaluate: positive exponent. A small number needs a negative exponent.
  • Negatives: negate the mantissa only. Invert, add 1. The exponent is the same as for the positive number.
  • Fit the bits. Count the digits in each field. Extra digits on the right are lost.
  • Check by converting back. It takes a minute and catches most slips.
