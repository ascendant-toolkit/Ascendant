Data Manipulation Language (DML)

Coursebook: Chapter 8 · Databases · section 8.3 Data definition language (DDL) and data manipulation language (DML)

SELECT with WHERE, joins, GROUP BY, ORDER BY, COUNT, SUM and AVG, and INSERT, UPDATE and DELETE, with animations, a working SQL workbench and 23 real Paper 1 questions from 2021 to 2026.

This page in five sentences

Data Manipulation Language (DML) is the part of SQL that searches and changes the data in tables. SELECT fields FROM table WHERE condition returns the data that matches; add GROUP BY to group rows, ORDER BY ... DESC to sort, the functions COUNT, SUM and AVG to calculate, AS to name a result, LIKE for patterns, and a join (INNER JOIN ... ON, or two tables in FROM with the keys matched in WHERE) to use more than one table. INSERT INTO ... VALUES adds a record, UPDATE ... SET ... WHERE changes records and DELETE FROM ... WHERE removes them. The marks are one per clause: the right fields and function, the right tables, the join, the condition, the grouping and ordering. Write every statement exactly in the order SELECT, FROM, WHERE, GROUP BY, ORDER BY.

1 · SELECT

SELECT FirstName, LastNameFROM CUSTOMERWHERE Town = "Leeds"ORDER BY LastName; SELECT COUNT(CustomerID)FROM SHOP_ORDERWHERE CustomerID = "HJ231"; SELECT CustomerID, SUM(Quantity) AS TotalItemsFROM SHOP_ORDER INNER JOIN ORDER_ITEMON SHOP_ORDER.OrderNo = ORDER_ITEM.OrderNoGROUP BY CustomerIDORDER BY TotalItems DESC;
Clause or functionUse
SELECTThe fields to return (or an aggregate such as SUM(Quantity)); AS Name gives a result a title
FROMThe table (or tables) used
WHEREThe condition: =, <, >, <=, >=, <>, AND, OR, LIKE "CAN%" (or "CAN*"), BETWEEN, a Boolean such as Paid = FALSE
INNER JOIN t2 ON t1.key = t2.keyJoins two tables on the foreign key and primary key; alternatively list both tables in FROM and add WHERE t1.key = t2.key
GROUP BYOne result row per group, used with an aggregate (the grouped field must also be selected)
ORDER BY field [DESC]Sorts the results: ascending by default, DESC for descending
COUNT, SUM, AVGCount the records, add up values, or find the mean

When a field name appears in both tables, put the table name before it: SHOP_ORDER.OrderNo. A join is needed whenever the fields you want, or the condition, are in different tables.

2 · INSERT, UPDATE and DELETE

INSERT INTO CARVALUES ("123AA", "Tiger", "Lioness", 10500, "12BSTREET"); UPDATE CHARACTERSSET Level = 3, Money = 10000.00WHERE CharacterID = "0002"; DELETE FROM PLACEMENTWHERE Complete = TRUE;

The values in INSERT must be in the same order as the fields. UPDATE and DELETE need a WHERE clause, otherwise every record is changed or deleted.

Common ways to lose marks

  • Leaving out the join: selecting from two tables without matching the keys in WHERE or ON.
  • Using SUM when the question asks for a count (the number of records), or COUNT when it asks for a total.
  • Putting text in quotes and numbers not, and the Boolean unquoted (TRUE).
  • Forgetting GROUP BY when the question says "each" (each customer, each show).
  • Using OR where the question means AND, or AND between two values of the same field.

Top tips

  • One mark per clause. SELECT, FROM, join, WHERE, GROUP BY, ORDER BY.
  • 'Each' means GROUP BY. Select the grouped field too.
  • Number: COUNT. Total: SUM. Mean: AVG. Check the wording.
  • Join through the keys. INNER JOIN ... ON, or match in WHERE.
  • Quote text, not numbers. TRUE is not quoted.
  • UPDATE and DELETE need WHERE. Or every record changes.
