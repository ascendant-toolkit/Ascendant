Abstraction and Decomposition

Coursebook: Chapter 9 · Algorithm design and problem-solving · section 9.1 Computational thinking skills

Abstraction as filtering out unnecessary information, decomposition into sub-problems and modules, and how to answer the scenario questions, with animations, labs and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

Abstraction is the process of filtering out information that is not necessary for the task and keeping only what is needed, which makes the problem easier to design, implement and solve; an abstract model of a car hire system keeps car and customer IDs, dates and cost, but not the car's colour or the customer's favourite music. Decomposition is breaking down a problem into sub-problems (smaller parts or steps) so each can be understood and solved, which leads to the idea of program modules (procedures and functions), each of which can be tested separately or given to a different team. In the exam, abstraction questions ask what data to store and what processes (operations) are needed; decomposition questions give a scenario and ask for named sub-modules with their use. Name each module like a function (GetOverdueLoan()) and say what it does in the scenario. Never answer with general statements only: the marks are for scenario-specific modules and data.

1 · Abstraction

  • Definition: filtering out (removing) information or data that is not necessary for the task, and keeping only what is needed.
  • Advantage: makes the solution easier to design, implement and solve.
  • Abstract model for car hire: data stored each time a car is hired: car ID or registration; customer ID or name; start date of hire; return date or number of days; cost of hire. Not stored: the car's colour, the customer's hobbies.
  • Operations (processes) for the data: input customer details, input car details, create or start a hire, return a car or end a hire, check or change the car's status, cancel a hire, process payment or calculate hire cost.

When asked which items a new module needs, choose each item and justify it from the scenario: the mobile phone number is needed to send the text message; the name to personalise it; the exercise interest to decide whether the member is interested.

2 · Decomposition

  • Definition: breaking down a problem or task into sub-problems (smaller parts or steps), in order to understand or solve it more easily, leading to the idea of a program made of modules that can be assigned to teams.
  • Benefits: each module is easier to code, test and debug; different programmers can work on different modules; modules can be reused.
  • Types of module: a procedure does a task; a function returns a value.

Example: a program that emails students with an overdue book is decomposed into GetOverdueLoan() (identifies an overdue book), IdentifyStudent() (identifies the student), GetStudentEmail(), CreateEmail() and SendEmail().

Common ways to lose marks

  • Describing decomposition without saying "sub-problems" and "modules".
  • Describing abstraction as "hiding detail from the user". It filters out unnecessary information so the problem is easier to solve.
  • Giving modules that are not specific to the scenario, such as "input" and "output".
  • Naming a module with no use. Give the name and say what it does.
  • Listing items that are not needed for the task, or repeating the same item twice (hire date and hire date).

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A map

A tube map filters out streets and distances and keeps stations and connections: an abstract model for planning a journey.

Exam use: abstraction.

Building a school app

Timetable, attendance and messages are built by different teams as separate modules, then joined: decomposition.

Exam use: decomposition.

A game character

A game keeps position, health and score for a character, not the hair colour of the player: only the data the game logic needs.

Exam use: abstraction.

Cooking a big meal

You split it into starter, main, pudding and plan each separately: breaking a problem into sub-problems.

Exam use: decomposition.

A bank app

Login, balance, transfer and statement are separate modules; the transfer module returns success or failure: a function.

Exam use: modules and functions.

Top tips

  • Abstraction: filter out. Keep only what the task needs.
  • Decomposition: break into sub-problems. Leads to modules.
  • Module: name and use. Both marks, with the scenario.
  • Justify each item from the scenario. Mobile number: to send the text.
  • Function returns a value. Procedure does not.
  • Mention the scenario. Max 2 if you do not.
