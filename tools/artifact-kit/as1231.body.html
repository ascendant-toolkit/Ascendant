Errors and Testing

Coursebook: Chapter 12 · Software development · section 12.3 Program testing and maintenance

Syntax, logic and run-time errors, test data and test plans, walkthroughs, white-box, black-box, stub and integration testing and alpha, beta and acceptance testing, with animations, labs and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

There are three kinds of error. A syntax error breaks the rules of the language, so the program will not run or compile. A logic error means the program runs but gives wrong results, because the algorithm is wrong. A run-time error happens while the program runs, when it is asked to do something impossible (divide by zero, an index outside an array, or an endless loop that makes it stop responding). Testing is planned with a test plan: test data of the right types (normal, abnormal, boundary) with the expected result for each. Testing is done at different levels and by different people: walkthroughs, white-box and black-box testing, stub and integration testing, and finally alpha, beta and acceptance testing.

1 · Types of error

ErrorWhen foundDescriptionExample
SyntaxWhen the program is translatedThe program breaks the rules or grammar of the language: it will not compile or runA misspelt keyword, a missing bracket, NEXT where ENDWHILE is needed, using & to join an integer
LogicWhen running, from wrong outputThe program runs but does not do what was intended: an error in the algorithm or the designThe wrong arithmetic operator, the wrong loop count, a condition that is the wrong way round
Run-timeWhile runningThe program performs an illegal operation and may crash or freezeDivide by zero, a value outside the range of an array index, an endless loop

A program that is "free of syntax errors" obeys the rules of the language and will run (compile or be interpreted), but may still contain logic or run-time errors.

2 · Test data and the test plan

  • Normal data is valid and typical: 153 for a range 150 to 155.
  • Abnormal (erroneous) data should be rejected: a value outside the range, or the wrong type.
  • Boundary (extreme) data lies at the edge of the range: the smallest and largest accepted values (150, 155) and the values just outside them (149, 156).
  • A test plan lists each test with its data, an explanation and the expected result, written before testing.

For a range 24 to 37 inclusive a thorough plan has normal data (30), the boundaries (24, 25, 36, 37) and the values just outside (23, 38) and clearly invalid values (12, 99).

3 · Methods of testing

  • Dry run / walkthrough: going through the program a line at a time with test data, recording the variables in a trace table; an error shows when a variable or output has an unexpected value. The design (the algorithm or code) and a test plan (inputs and expected outputs) are needed first, so that all paths through the program can be tested.
  • White-box testing: the tester knows the code and chooses data to make every path through it run (for the bonus pay: one test for each row of the table).
  • Black-box testing: the tester checks inputs against expected outputs without looking at the code.
  • Stub testing: the unfinished modules are replaced by simple modules (stubs) that return a known value or output a message to show they were called, so the rest can be tested.
  • Integration testing: modules that work alone are combined and tested together.
  • Using an IDE: breakpoints, single-stepping and watching variables find errors (see section 5.2.2).

4 · Final stages of testing

  • Alpha testing: done in-house by the developers or the company's own testers before the software is released.
  • Beta testing: carried out by a small group of potential users, who check it works in the real world, find errors and feed back problems and suggestions; these are addressed before the program is sold or released to everyone.
  • Acceptance testing: the customer tests the whole system on their own hardware, and if the tests are passed the customer accepts the system.

Common ways to lose marks

  • Testing only normal data. A plan needs abnormal and boundary data too.
  • Omitting the expected result, or giving an expected result that does not match the rule.
  • Describing beta testing as done by the developers (that is alpha).
  • Calling a freeze a logic error: a program that stops responding has a run-time error.

Top tips

  • Three error names. Syntax: rules. Logic: wrong result. Run-time: crashes or freezes.
  • Three data types. Normal, abnormal and boundary, each with the expected result.
  • Both ends of the range. The edge values and the values just outside.
  • Alpha in-house. Beta by users, acceptance by the customer.
  • Walkthrough needs a plan. Trace table, test data, expected output.
  • Stubs return something. A known value, or a message that it was called.
