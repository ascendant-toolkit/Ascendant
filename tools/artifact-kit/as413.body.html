The Fetch-Execute Cycle and Interrupts

Coursebook: Chapter 4 · Processor fundamentals · section 4.1 Central Processing Unit architecture

The fetch-execute cycle in register transfer notation, a step-through simulator, and how interrupts are detected and handled with the stack and ISR, with animations, labs and the real Paper 1 questions from 2021 to 2026.

This page in five sentences

The CPU repeats the fetch-execute (F-E) cycle for every instruction: fetch it from main memory using the PC, MAR, MDR and CIR, then decode and execute it. In register transfer notation (RTN) the fetch is: MAR ← [PC], PC ← [PC] + 1, MDR ← [[MAR]], CIR ← [MDR]. An interrupt is a signal from a device or a process seeking the attention of the processor. At the end of each cycle the processor checks for an interrupt; if its priority is higher than the current process, the processor stores the registers on the stack, calls the interrupt service routine (ISR), then restores the registers and carries on. Interrupts come from hardware (key pressed, power failure, printer out of paper, buffer full) or from software (division by zero, stack overflow, invalid memory access).

1 · Register transfer notation

Square brackets mean "the contents of"; the arrow means "is copied to". [[MAR]] means the contents of the memory location whose address is held in the MAR.

StepRTNMeaning
1MAR ← [PC]The contents of the PC (the address of the next instruction) are copied to the MAR
2PC ← [PC] + 1The address in the PC is incremented, ready for the next instruction
3MDR ← [[MAR]]The data at the address held in the MAR is copied to the MDR (via the data bus; the address bus carries the MAR)
4CIR ← [MDR]The contents of the MDR (the instruction) are copied into the CIR

The same order is accepted if steps 1 and 2 are done together. The PC is incremented, never decremented, and step 3 uses the contents of the address in the MAR, not the MAR itself. After step 4 the CU decodes the instruction in the CIR and the processor executes it (for example the ALU adds a number to the ACC).

2 · Interrupts

Purpose: an interrupt sends a signal from a device or process seeking the attention of the processor, so that urgent events can be dealt with without the processor constantly polling.

Hardware interruptSoftware interrupt
Buffer full; printer out of paper; a key pressed; power failure; a device finished transferring dataDivision by zero (a run-time error); an attempt to access an invalid memory location; array index out of bounds; stack overflow; a program requesting a device

Detected: at the end (or start) of each fetch-execute cycle, after the execute stage has finished, the processor checks the interrupt register. Handled:

  1. An interrupt flag is raised in the interrupt register.
  2. The priority of the interrupt is checked. If it is lower than the current process, the F-E cycle simply continues.
  3. If it is higher, the state of the current process is saved: the contents of the registers are stored on the stack.
  4. The source and type of interrupt is identified, and the appropriate interrupt service routine (ISR) (its address is loaded into the PC) is called.
  5. When the ISR has finished, the processor checks again for further interrupts of higher priority.
  6. If none, the registers are restored from the stack and the interrupted process continues with the next F-E cycle.

Common ways to lose marks

  • Writing PC ← [PC] − 1 or leaving out the double brackets in MDR ← [[MAR]].
  • Explaining the interrupt with no mention of priority, the stack, or the ISR.
  • Saying the processor stops everything: it only changes to the ISR if the priority is higher than the current process.
  • Saying the registers are "deleted" or "saved on the hard disk". They are stored on the stack.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Typing while a video plays

Each key press is an interrupt: the CPU pauses the video work briefly, runs the keyboard routine, then returns to the video.

Exam use: hardware interrupt, ISR, back to the process.

A game crashing with 'stack overflow'

A program that calls itself too deeply uses up the stack and raises a software interrupt, which the OS handles.

Exam use: software interrupt.

Unplugging the power

The power failure interrupt has the highest priority: the processor can save critical data before everything stops.

Exam use: priority.

An app 'not responding'

The CPU still runs the fetch-execute cycle millions of times a second; the app is waiting for data and the OS handles other work in between.

Exam use: the cycle never stops.

Why saving the registers matters

When you return from a notification, your program carries on exactly where it was because its registers were stored and restored.

Exam use: stack.

Top tips

  • Fetch in four steps. MAR←[PC]; PC←[PC]+1; MDR←[[MAR]]; CIR←[MDR].
  • Increment, not decrement. And double brackets for MDR.
  • Check at the end of the cycle. After execute, before the next fetch.
  • Priority first. Lower: carry on. Higher: handle it.
  • Stack, ISR, restore. The three nouns of every interrupt answer.
  • Hardware or software. Devices against errors in a program.
