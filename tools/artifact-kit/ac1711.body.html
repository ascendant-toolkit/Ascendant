Symmetric and Asymmetric Encryption

Coursebook: Chapter 17 · Security, section 17.1 Encryption, encryption protocols and digital certificates

Plain text and cipher text, symmetric and asymmetric key cryptography, and sending private and verified messages with public and private keys; animations, a toy key-pair lab and the real Paper 3 questions from 2022 to 2026.

This page in five sentences

Encryption turns plain text into cipher text that is meaningless to anyone who intercepts it, using an encryption algorithm and a key; decryption reverses it. With symmetric key cryptography the sender and receiver use the same secret key to encrypt and decrypt, which is quick but the key has to be shared safely (the key distribution problem). With asymmetric key cryptography there is a matched pair of keys: a public key that anyone can have and a private key kept secret, and what one key encrypts only the other can decrypt. To send a private message you encrypt with the receiver's public key and only their private key can decrypt it; to send a verified message you encrypt with your private key and anyone can use your public key to prove it came from you.

1 · Words to know

TermMeaning
Plain textThe original, readable data before encryption.
Cipher textThe text produced from plain text by an encryption algorithm.
EncryptionScrambling data so it is meaningless if intercepted.
KeyA value used by the algorithm to encrypt or decrypt.
Public keyOne key of a matched pair; it can be obtained and used by anyone to send encrypted messages (or to decrypt a sender's digital signature).
Private keyThe other key of the pair: secret, never transmitted, and used to decrypt data that was encrypted with its matching public key.

Why use key cryptography: to ensure the message is authentic (came from a trusted source), that only the intended receiver can understand it, and that it has not been altered in transit; and for non-repudiation (neither side can deny the transmission).

2 · Symmetric key cryptography

One key is used for both encryption and decryption. A simple example is a Caesar cipher with a shift of 3: HELLO becomes KHOOR, and shifting back by 3 decrypts it. (Real algorithms are far stronger but work the same way.)

  • Benefit: a simple process that can be carried out quickly; keys are usually shorter (128 or 256 bits).
  • Drawback: the key must be shared with the receiver first. Sending it over the network risks it being intercepted: the key distribution problem. If it is compromised, all messages are.

3 · Asymmetric key cryptography

Each user (or organisation) has a matched pair of keys made by an algorithm. One key encrypts and the other key decrypts. The public key can be shared openly; the private key never leaves its owner. This solves the key distribution problem, because no secret ever has to be sent.

  • Benefit: better security; keys do not need to be exchanged secretly; it allows verification of the sender.
  • Drawback: much more complex and so slower; the keys must be much longer (for example 2048 bits against 128 or 256) to give the same security.

4 · Sending a private message

  1. The receiver's computer uses an algorithm to generate a matched pair of keys.
  2. The receiver makes the public key available (sends it, or publishes it on a website).
  3. The sender encrypts the plain text with the receiver's public key to give cipher text, and sends it.
  4. The receiver decrypts the cipher text with their private key. Only that key can do it.

5 · Sending a verified message to the public

  1. The organisation generates a matched pair of keys and makes its public key available (for example on its website).
  2. It encrypts the message with its private key and sends it to the group.
  3. Anyone receiving it can decrypt it with the organisation's public key.
  4. It could only have been produced with the private key, so the sender is verified (non-repudiation). Anyone can read the message, so it is not private.
RememberPrivate message: encrypt with the receiver's public key. Verified message: encrypt with your own private key. In both cases the other key of the pair decrypts.

6 · Common ways to lose marks

  • Encrypting a private message with your own public key. Use the receiver's public key.
  • Saying the private key is sent to the receiver. It is never transmitted.
  • Describing symmetric encryption as having "two keys" or asymmetric as "one key".
  • Forgetting the order of the steps: keys generated, public key made available, message encrypted, sent, decrypted.
  • Writing "the key is hidden" without saying which key and who holds it.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

The padlock in your browser

When you log in to a website your browser and the server set up encryption so your password cannot be read on the way. Asymmetric keys start the exchange; a faster symmetric key carries the data.

Exam use: both types of cryptography are used together.

Messaging apps with end-to-end encryption

Each person has a key pair. Your phone encrypts a message with the other person's public key, so only their private key, which never leaves their phone, can read it.

Exam use: encrypt with the receiver's public key.

Wi-Fi passwords

Everyone on a home network shares one passphrase. That is symmetric: the same key must be given to every device, which is the key distribution problem in a small way.

Exam use: symmetric keys have to be shared.

Software updates that prove who made them

The publisher signs the update with its private key. Your computer checks it with the publisher's public key, so it knows the update is genuine.

Exam use: encrypt with the private key to verify the sender.

A safe with a letterbox

Anyone can post a letter in through the slot (the public key), but only the owner has the key to open the safe (the private key).

Exam use: the public key encrypts; only the private key decrypts.

Top tips

  • Private message: receiver's public key. Only the receiver's private key can decrypt it.
  • Verified message: your private key. Anyone can check it with your public key.
  • The private key is never sent. It stays with its owner.
  • Symmetric: one key. Fast and simple, but the key must be shared.
  • Asymmetric: a pair. More secure, slower, longer keys.
  • Order of steps matters. Generate keys, share public key, encrypt, send, decrypt.
