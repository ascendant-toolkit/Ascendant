IDE Features: Presentation and Debugging

Coursebook: Chapter 5 · System software · section 5.2 Language translators

The presentation and debugging features of an Integrated Development Environment, with a debugger simulator, labs and the real Paper 1 questions from 2021 to 2026.

This page in five sentences

An Integrated Development Environment (IDE) brings together the tools a programmer needs to write, translate, test and debug a program in one application. Its features fall into two groups. Presentation and writing features make the code easier to read and write: colour coding (syntax highlighting), prettyprint (automatic formatting), auto-indentation, expand and collapse code blocks, auto-complete and context-sensitive prompts, auto-correct and dynamic syntax checks. Debugging features help to find logic and run-time errors: single stepping, breakpoints, and the report window (variable watch window). A good answer names the feature and says what it does, linked to the situation.

1 · Presentation and writing features

FeatureWhat it does
Colour coding (syntax highlighting)Shows keywords, variables, strings and comments in different colours so the structure is easy to see
Prettyprint (auto-formatting)Automatically lays out the code in a standard style
Auto-indentationIndents code as the user types so the structure is clear and it is more readable
Expand and collapse code blocksSections of code that belong to the same block can be expanded to see the content or collapsed so the overall structure is seen
Auto-complete / context-sensitive promptsAs the code is being written, the options to complete the statement are shown or completed automatically
Auto-correctFixes common mistakes as the code is typed
Dynamic syntax checksHighlights or underlines statements that do not meet the rules of the language as the code is entered

2 · Debugging features

FeatureWhat it doesHow the programmer uses it
Single steppingExecutes one line of the program and then stopsRuns the code one line at a time and checks the variable contents and program flow
BreakpointStops the program running at a set lineRuns the code up to a set line, then checks the status (values of variables) or tests a sub-section
Report window / variable watch windowShows the contents of variables and data structuresViews how and when the data changes as each line runs

A trace table is the same idea on paper: it records the value of each variable after every line, and the watch window does it automatically.

3 · Choosing the feature

  • The program must stop at a particular line to check a value: a breakpoint (the technical term for the position at which the program stops).
  • To see the effect of each statement: single stepping.
  • To see how a variable changes over time: the report (watch) window.
  • To make the code easier to read: prettyprint, colour coding, auto-indentation, expand/collapse.

Common ways to lose marks

  • Naming a debugging feature when the question asks for a presentation feature (or the other way round).
  • Describing "debugging" as "check for errors". Say how: one line at a time, stop at a line, view variables.
  • Describing single stepping and a breakpoint in the same way. Stepping runs one line then stops; a breakpoint stops at a set line.
  • Describing colour coding as "making the code look nice". Say it shows keywords and structure so the code is easier to read.
  • Describing the feature without saying how the student uses it when the question asks how they can use it.

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A red squiggle under code

The editor checks the syntax as you type, so you fix a missing bracket before you run anything.

Exam use: dynamic syntax check.

Finding why a total is wrong

Set a breakpoint, run to it, then step one line at a time and watch the total change until it goes wrong.

Exam use: breakpoint, single stepping, watch window.

Reading someone else's code

Colour coding and collapsing the functions you do not need makes a long program much easier to follow.

Exam use: presentation features.

Typing a function name

The editor suggests the rest of the name and its parameters, so you make fewer typing mistakes.

Exam use: auto-complete and context-sensitive prompts.

A team agreeing a style

Prettyprint formats everyone's code the same way, so it is easy to read each other's work.

Exam use: prettyprint.

Top tips

  • Name it, then what it does. Two marks for each feature.
  • Presentation or debugging? Check which the question wants.
  • Stepping: one line. Breakpoint: a set line.
  • Report window: variables. Shows how they change.
  • 'How can the programmer use it?' Say what the programmer does with it.
  • Dynamic: as you type. Syntax checks and prompts.
