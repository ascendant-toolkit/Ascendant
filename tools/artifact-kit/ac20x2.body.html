Why and When to Use Exception Handling

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

The three reasons, the situations where try and except is the right tool and where an IF is better, and why checking first is not always enough; pseudocode and Python side by side, with step-by-step animations.

This page in five sentences

Exception handling is a process that responds to an unwanted or unexpected event while a program is running, so the program does not stop unexpectedly. There are three reasons to use it: to trap runtime errors, to prevent the program halting, and to show a meaningful message (or recover) instead of a system error. Use it where the problem comes from outside the program's control and cannot be ruled out in advance, such as opening a file, reading a file, or converting what a user typed. For a value that has to be in a range, or a choice from a known set, an ordinary IF check (validation) is the right tool. The two work together: validation checks the data is sensible, and exception handling catches what is still able to go wrong.

2 · The same input, handled

The user types ten instead of 10. The conversion cannot be done, but the program responds and carries on.

Python

try:    Age = int(input("Enter your age: "))    print("Next year you will be", Age + 1)except ValueError:    print("Please enter a whole number")print("Finished")

Pseudocode (exam style)

TRY   INPUT Age   OUTPUT "Next year you will be ", Age + 1EXCEPT   OUTPUT "Please enter a whole number"ENDTRYOUTPUT "Finished"

3 · When to use it, and when to use an IF

Use exception handling forUse an ordinary IF check for
Opening, reading and writing filesA value that must be in a range, such as IF Age < 0 THEN
Converting typed input: int(input())A list index you can test: IF Index < len(List)
Network, printer or disk problemsA menu choice from a known set
Anything that depends on something outside the programLogic errors in your own algorithm, which are fixed in the code, not caught

4 · Using both: ask until the input is valid

int() can fail, so it goes inside a try. Whether the age is sensible is a range check, so it is an IF.

Python

Valid = Falsewhile not Valid:    try:        Age = int(input("Enter your age: "))        if Age < 0 or Age > 120:            print("Age must be between 0 and 120")        else:            Valid = True    except ValueError:        print("Please enter a whole number")

Pseudocode (exam style)

Valid <- FALSEWHILE NOT Valid   TRY      INPUT Age      IF Age < 0 OR Age > 120 THEN         OUTPUT "Age must be between 0 and 120"      ELSE         Valid <- TRUE      ENDIF   EXCEPT      OUTPUT "Please enter a whole number"   ENDTRYENDWHILE

5 · Why checking first is not always enough

A program can test that a file exists with an IF and still fail: the file may be deleted, locked or damaged between the check and the open, or the read may fail part-way through. A try block responds whenever the problem happens.

6 · Common ways to lose marks

  • Giving only an example. "Reasons" needs the reasons: trap errors, stop the halt, meaningful message.
  • Describing validation (an IF) as exception handling.
  • Saying exception handling "fixes" a bug. It responds to an unexpected event; a logic error still has to be fixed in the code.
  • Writing a try block with no message or action in the except.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A web form that asks for a quantity

If a customer types ten instead of 10, the conversion would normally crash the page. The code catches the error and shows 'Please enter a whole number'.

Exam use: meaningful message instead of a system error.

A spreadsheet opening a missing file

When a linked file has been moved the program says it cannot find the file and offers to browse for it, instead of closing.

Exam use: the program carries on after the problem.

A game saving to a full disk

The save fails. The game reports it and keeps running, so the player does not lose progress held in memory.

Exam use: stops the program halting; protects the data.

A banking program with a range check

An account balance that must not be negative is checked with an IF before it is saved. This is not an exception: the program already has the value and can test it.

Exam use: validation uses IF, not try.

An app that loses its connection

A download stops when the Wi-Fi drops. The app catches the connection error, tells the user and lets them retry.

Exam use: failure outside the program's control, reported rather than crashing.

Top tips

  • Give the reasons. Trap errors, prevent halting, meaningful message. An example alone is not enough.
  • Say 'unexpected'. Exception handling responds to unexpected events while the program runs.
  • Use try for the outside world. Files, typed input, devices, networks.
  • Use IF for known values. Ranges and menus are validation.
  • Always add a response. An except block needs a message or action.
  • Name how to avoid termination. A try ... except block, or an error message.
