RISC, CISC, Pipelining and Interrupts

Coursebook: Chapter 15 · Hardware and virtual machines, section 15.1 Processors, parallel processing and virtual machines

RISC and CISC processors compared, five-stage pipelining with pipeline tables, interrupt handling and how pipelining affects it; animations, a pipeline calculator and the real Paper 3 questions from 2022 to 2024.

This page in five sentences

A RISC (Reduced Instruction Set Computer) processor has a small set of simple, fixed-length instructions, each normally completing in one clock cycle, with many general-purpose registers and a hardwired control unit, so it suits pipelining. A CISC (Complex Instruction Set Computer) processor has a large set of complex, variable-length instructions, many addressing modes, few registers and a programmable (micro-coded) control unit, and an instruction may take several clock cycles. Pipelining splits the fetch-execute cycle into stages and overlaps the stages of different instructions so a new instruction can finish every clock cycle, which raises instruction throughput. When an interrupt arrives the processor stops the current program, saves the register contents on the stack, runs an interrupt service routine, then restores the registers and carries on. Pipelining makes interrupts harder to handle because several instructions are in progress at once.

2 · Pipelining

The fetch-execute cycle for one instruction is divided into stages. In a typical five-stage pipeline: IF instruction fetch, ID instruction decode, OF operand fetch, IE instruction execute, WB write back the result. Each stage uses a different part of the processor (and its own registers), so the stages of different instructions can happen at the same time.

  • Each stage takes one clock cycle.
  • No two instructions can be in the same stage in the same clock cycle.
  • While one instruction is being decoded, the next is being fetched, and so on.

Six instructions through a five-stage pipeline take 10 clock cycles (5 for the first, then one more for each of the other 5), instead of 30 without pipelining:

The benefit is increased CPU instruction throughput: the number of instructions completed per unit of time goes up, although each single instruction still needs all five cycles. Pipelining works best for RISC because the instructions are the same length and each stage takes one cycle.

3 · Interrupt handling

An interrupt is a signal that tells the processor something needs attention (an input, a timer, an error). The processor checks for interrupts at the end of each fetch-execute cycle.

  1. The processor detects the interrupt at the start or end of a fetch-execute cycle.
  2. The current program is temporarily stopped and the contents of the registers (including the program counter) are stored on the stack.
  3. The processor runs the interrupt service routine (ISR).
  4. When the ISR finishes, the registers are restored from the stack and the original program carries on from where it stopped.

Interrupts and pipelining

With a pipeline, several instructions are in progress when an interrupt arrives, so there is added complexity. Usually the instructions currently in the pipeline are discarded (except the one at the last stage, which is allowed to finish), the interrupt handler is run, and when the interrupt has been serviced the processor restarts with the next instruction in the sequence.

4 · Common ways to lose marks

  • Writing "RISC is faster". Give the reason: simple single-cycle instructions that pipeline well.
  • Mixing the features: many registers is RISC; many instruction formats and addressing modes is CISC.
  • Describing pipelining as "doing two things at once" without the stages of different instructions overlapping.
  • Forgetting to store the register contents on the stack in interrupt handling, or to restore them afterwards.
  • In a pipeline table, starting instruction 2 in the same cycle as instruction 1, or putting two instructions in one stage in the same cycle.
  • Saying CISC is "slower" without the reason: instructions need several cycles and are harder to pipeline.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Phones and tablets

Most phone and tablet chips use a RISC design: simple instructions that are quick to carry out, using little power. That helps battery life.

Exam use: RISC: fewer transistors, simple single-cycle instructions, low power.

Desktop and laptop processors

Traditional PC processors have a very large instruction set built up over the years and break complex instructions into smaller internal steps.

Exam use: CISC: a large instruction set with complex, variable-length instructions.

A pipelined assembly line

Like a car factory, one stage of a pipeline is working on each car at once. Each car still takes the whole time, but a finished car leaves every cycle.

Exam use: pipelining raises throughput, not the time for one instruction.

Pressing a key while a program runs

The keyboard sends an interrupt. The processor saves where it was, runs the routine that reads the key, then picks the program up again.

Exam use: interrupt handling uses the stack to save and restore the registers.

A branch in a program

If a program jumps, the instructions already fetched into the pipeline may be the wrong ones and have to be discarded, which costs time.

Exam use: pipelines add complexity when the sequence of instructions changes.

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Explain 3 marks Explain why RISC processors are well suited to pipelining.
ReminderThink about instruction length and cycles.

RISC instructions are all the same (fixed) length and have few formats, so each can be fetched and decoded in a predictable way. Most instructions take a single clock cycle, so each pipeline stage takes one cycle. So the stages of different instructions can overlap without waiting.

Calculate 3 marks A program of 20 instructions runs on a five-stage pipeline with one clock cycle per stage. How many clock cycles does it need with and without pipelining?
Reminder5 + (n − 1) against 5n.

Without pipelining: 20 × 5 = 100 cycles With pipelining: 5 + 19 = 24 cycles A speed-up of about 4.2 times

State 2 marks State two reasons why CISC processors are harder to pipeline than RISC.
ReminderLength and cycles.

Instructions have variable lengths and many formats, so decoding takes different times. Instructions need different numbers of clock cycles, so the stages do not line up.

Describe 3 marks A key is pressed while a program is running. Describe what the processor does with the registers.
ReminderStack, ISR, restore.

It stops the current program at the end of the fetch-execute cycle and stores the register contents on the stack. It runs the interrupt service routine to deal with the key press. It then restores the register contents from the stack and continues the program.

Distinguish 2 marks Distinguish between the control units of RISC and CISC processors.
ReminderHow they are built.

A RISC control unit is hardwired. A CISC control unit is usually programmable (micro-programmed), so complex instructions are broken into micro-operations.

Top tips

  • Give both sides of a difference. 'RISC has many registers whereas CISC has few.'
  • RISC: reduced and simple. Small set, fixed length, one cycle, many registers, hardwired, pipelining.
  • CISC: complex. Large set, variable length, many cycles, few registers, programmable control unit.
  • Pipeline tables: staircase. Instruction n starts in cycle n. n instructions take n + 4 cycles for five stages.
  • Interrupts: stack. Save the registers on the stack, run the ISR, restore them.
  • Pipelining and interrupts: the pipeline is full. Several instructions are in progress, so most are discarded and the processor restarts at the next instruction.
