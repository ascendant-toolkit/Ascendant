Data Types and Primary Keys

Suitable data types for database fields, and the purpose of a primary key.

The big idea

Every field has a data type that fits what it stores, and every table needs a primary key: a field that is unique for each record so it can be found exactly.

9.2 Data types and primary keys

Data types in a database

Each field has a data type that says what kind of data it can hold. Choosing the right type allows the database to validate input, sort correctly, do calculations and use the right amount of storage.

Data typeStoresExamples
Text / alphanumericLetters, digits and symbols in any mixName, address, telephone number, postcode, product code
CharacterA single characterM or F, a grade (A, B, C), Y or N
BooleanOnly two values: TRUE or FALSE (yes or no)InStock, IsMember, PaidTrip
IntegerA whole numberQuantity, Year group, Age, number of siblings
RealA number with a fractional partPrice, height in metres, weight
Date/timeA date, a time, or bothDate of birth, appointment time
Telephone numbers are textYou never do arithmetic on a telephone number, and it may start with 0, which an integer would drop. The same goes for postcodes and IDs that contain letters. If you do not calculate with it, it is usually text.

Choosing a suitable type

  • Counted things (quantity, age in years) are integer; measured or money values (height, price) are real.
  • A yes/no fact is Boolean.
  • One letter is character; several characters are text.
  • Dates and times use date/time, so they can be sorted and compared.

Primary key

A primary key is a field whose value is unique for every record. It identifies exactly one record. A good primary key:

  • is unique: no two records have the same value;
  • is never empty;
  • does not need to change.
StudentID ★NameYearDateOfBirth
1001Sam Lee1015/03/2010
1002Ana Cho1015/03/2010
1003Sam Lee902/11/2011

StudentID is a suitable primary key because every value is different. Name is not: there are two students called Sam Lee. DateOfBirth is not: two students share a birthday. Year is not: students share a year.

Typical primary keys are ID numbers that the database creates or checks (student number, product code, passport number, vehicle registration).

Why use a primary key?

  • It lets you find, update or delete exactly one record.
  • It prevents duplicate records, because a repeated key is rejected.
  • It makes searching faster and is the basis of links between tables in larger databases.

Q1 State 3 marks A hotel database stores the room number, the price per night and whether the room has a sea view. State a suitable data type for each field.
ReminderInteger, real, Boolean.
Room number: integer (or text) Price per night: real Sea view: Boolean
Common mistakeChoosing text for everything.
Q2 Explain 2 marks A telephone number is stored in a database. Explain why the data type should be text and not integer.
ReminderNo arithmetic, leading zero.
A telephone number can start with 0, which an integer would remove (or include symbols such as + and spaces). You do not calculate with telephone numbers, so a numeric type is not needed.
Common mistakeSaying "because it is long".
Q3 State 3 marks Give a suitable data type for (a) a student's date of birth, (b) the first letter of a grade, (c) the weight of a parcel in kilograms.
ReminderDate/time, character, real.
(a) Date/time (b) Character (c) Real
Common mistakeUsing integer for a weight that can have decimals.
Q4 Explain 2 marks Explain what is meant by a primary key.
ReminderUnique identifier.
A field in a table whose value is unique for every record (so it identifies one record).
Common mistakeSaying it is the "most important field".
Q5 Identify 2 marks A table stores Surname, FirstName, DateOfBirth and StudentNumber. Identify the best primary key and explain why.
ReminderUnique for every student.
StudentNumber It is unique for each student, whereas names and birth dates can be shared by several students.
Common mistakeChoosing Surname: many people share a surname.
Q6 Explain 2 marks Explain why a Name field is not suitable as a primary key.
ReminderDuplicates.
Two (or more) records could have the same name. A primary key must be unique for each record.
Common mistakeSaying names are "too long".
Q7 Describe 3 marks Describe two benefits of using a primary key in a database table.
ReminderFind, avoid duplicates, search.
It identifies exactly one record, so the right record can be found, updated or deleted. It prevents two records from being entered with the same key (duplicates). It makes searching faster.
Common mistakeWriting about passwords or security.

Top tips

  • Six data types: text/alphanumeric, character, Boolean, integer, real, date/time.
  • If you will not calculate with it, it is text (phone numbers, postcodes).
  • Whole numbers are integer, decimals are real, yes/no is Boolean.
  • A primary key is unique for every record and never empty.
  • Choose an ID field as the key, not a name or a date of birth.
