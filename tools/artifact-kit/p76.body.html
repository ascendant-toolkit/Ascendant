Trace Tables, Errors and Writing Algorithms

Completing trace tables, finding and correcting errors in algorithms, and writing precise algorithms in pseudocode.

The big idea

A trace table shows what an algorithm does, line by line, which makes errors easy to spot. Writing a good algorithm needs precision, correct starting values and the right loop and decision structure.

7.6 Trace tables, finding errors and writing algorithms

Trace tables

A trace table records what happens when an algorithm is dry-run (worked through by hand, without a computer). There is a column for each variable, plus columns for outputs and for user inputs or prompts. Work through the algorithm line by line and write a new value in the column each time a variable changes.

With the inputs 3, 8, 2, 5 the trace table starts like this (a new row each time a value changes):

TotalCountNumberOUTPUT
0
1
3
3
2
8
11
... and so on until OUTPUT 18
  • List the variables in the order they first appear.
  • Only write a value in the row where it changes; leave other cells empty.
  • For a loop, check the condition every time; the last check is the one that fails.
  • Use the test data given. If none is given, choose some.

Finding errors in an algorithm

To find an error, trace the algorithm with test data and compare the output with what is expected. Look for the line where the values first go wrong. Typical errors:

ErrorExampleCorrection
Wrong loop limit (off by one)FOR Count ← 1 TO 4 to add 1 to 5FOR Count ← 1 TO 5
Wrong starting valueTotal ← 1 before adding upTotal ← 0
Wrong operatorIF Mark > 50 when 50 should passIF Mark >= 50
Loop never endsWHILE with no update to the variableAdd Index ← Index + 1 inside the loop
Output in the wrong placeOUTPUT Total inside the loopMove it after the loop
Wrong variableTotal ← Total + Count instead of NumberUse the correct variable

Writing and amending algorithms

  1. Read the question carefully. What are the inputs, processes and outputs?
  2. Decide the variables and their starting values (Total ← 0, Count ← 0, Max ← first item).
  3. Choose the structure: a FOR loop if you know how many times, WHILE or REPEAT if it depends on a condition, IF for a decision.
  4. Write precise pseudocode (or code), with meaningful names and comments if you wish.
  5. Trace it with a small example to check it.

Example: input 20 marks, then output how many are 50 or more and the highest mark.

PrecisionUse INPUT, OUTPUT, ←, and comparisons such as >=. Do not write English instructions such as "add one to the count". You may answer in pseudocode, a programming language or a flowchart unless the question says which.

Debugging in a real project

Programmers use a debugger to step through code line by line and watch the values of variables change, which is a trace table done by the computer.

Exam use: why tracing finds errors: you see where a variable first goes wrong.

A bank interest calculator

If the loop runs one year too few, the final balance is wrong. Tracing with 1 year then 2 years shows the loop limit is off.

Exam use: an "off by one" loop limit error.

A game score

A bug that forgets to set the score back to 0 at the start of a new game carries over the old score.

Exam use: a wrong starting value.

An app that freezes

A loop that waits for a condition that never becomes true leaves the program stuck.

Exam use: a loop that never ends: no update inside the loop.

A recipe with a mistake

"Bake for 4 hours" instead of 40 minutes. Reading the steps with an example finds the error.

Exam use: check an algorithm by working through it with real values.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 Complete 4 marks The algorithm below is used with the inputs 4 and 9. Complete the trace table and state the output.
INPUT A
INPUT B
Total ← A + B
Average ← Total / 2
OUTPUT Average
ReminderA column for each variable. New value when it changes.
A = 4 B = 9 Total = 13 Average = 6.5 and OUTPUT 6.5
Common mistakeWriting the final answer only. A trace table needs each variable's values.
Q2 Complete 4 marks Complete a trace table for this algorithm and state the output.
Number ← 345
Sum ← 0
WHILE Number > 0 DO
   Digit ← MOD(Number, 10)
   Sum ← Sum + Digit
   Number ← DIV(Number, 10)
ENDWHILE
OUTPUT Sum
ReminderMOD gives the remainder, DIV the quotient. Check Number > 0 each time.
Digit 5, Sum 5, Number 34 Digit 4, Sum 9, Number 3 Digit 3, Sum 12, Number 0 (then the loop condition fails) OUTPUT 12
Common mistakeMissing the last check: when Number is 0, the loop stops.
Q3 Identify 2 marks The algorithm below should output the total of the numbers 1 to 5 (15). It outputs 10. Identify the error and correct it.
Total ← 0
FOR Count ← 1 TO 4
   Total ← Total + Count
NEXT Count
OUTPUT Total
ReminderTrace it: which Count values are added?
Error: the loop stops at 4, so 5 is never added. Correction: FOR Count ← 1 TO 5
Common mistakeChanging the output line. The error is in the loop limit.
Q4 Identify 3 marks Two errors stop this algorithm finding the smallest of 10 marks in Marks[1:10]. Identify and correct them.
Min ← 0
FOR Index ← 1 TO 10
   IF Marks[Index] > Min
     THEN Min ← Marks[Index]
   ENDIF
NEXT Index
OUTPUT Min
ReminderMin starts as the first item. Which operator finds a smaller value?
Error 1: Min starts at 0 (so nothing can be smaller). Correction: Min ← Marks[1] Error 2: the operator is >, which finds the largest. Correction: IF Marks[Index] < Min (Either correction on its own earns its own mark; credit for naming both errors.)
Common mistakeFixing only one. Trace with a small list to see both.
Q5 Write 6 marks Write an algorithm that inputs 20 marks, then outputs how many are 50 or more and the highest mark.
ReminderInitialise, loop 20 times, input, count, max, output after the loop.
Count ← 0 and Max ← 0 (or the first mark) before the loop A loop that repeats 20 times (FOR Index ← 1 TO 20) INPUT Mark inside the loop IF Mark >= 50 THEN Count ← Count + 1 IF Mark > Max THEN Max ← Mark OUTPUT Count and OUTPUT Max after the loop
Common mistakePutting OUTPUT inside the loop, or starting Count at 1.
Q6 Write 4 marks Write an algorithm that asks the user to enter a score from 0 to 10 and keeps asking until a valid score is entered.
ReminderA loop with a range check.
INPUT Score before checking (or inside a REPEAT loop) A loop that repeats while the score is invalid (Score < 0 OR Score > 10) An error message is output for an invalid score The loop ends when 0 <= Score <= 10
Common mistakeUsing AND instead of OR for the invalid condition.
Q7 Explain 2 marks Explain how a trace table helps to find errors in an algorithm.
ReminderValues, expected results.
It records the value of each variable as the algorithm is dry-run. The actual output or values can be compared with the expected results to find the line where the error occurs.
Common mistakeSaying it "runs the program". It is done by hand.
Q8 Explain 2 marks A student writes: Add 1 to the count. Explain why this is not suitable in an exam answer and rewrite it correctly.
ReminderPrecision.
Algorithms need precise code-like statements, not English instructions. Count ← Count + 1
Common mistakeRewriting with different words instead of using ← and the variable.

Top tips

  • Trace table: a column for each variable, plus OUTPUT and any prompts.
  • Write a value only where it changes.
  • Check a loop's condition every time, including the final failing check.
  • To find an error, trace with test data and see where the values go wrong.
  • Common errors: loop limit, starting value, operator, no update in a loop, OUTPUT in the wrong place.
  • Write precise pseudocode: INPUT, OUTPUT, ←, >=.
