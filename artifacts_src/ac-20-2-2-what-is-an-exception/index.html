What an Exception Is and What Causes It

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

Defining an exception, what happens when one is not handled, the three causes with Python examples, and how an exception differs from a syntax or logic error; pseudocode and Python side by side, with step-by-step animations.

This page in five sentences

An exception is an unexpected event that happens while a program is running and disrupts its normal flow of instructions. If nothing responds to it, the program halts at that line and the remaining statements never run. Exceptions have three common causes: programming errors (dividing by zero, using an index that does not exist), user errors (typing text where a number is needed, giving a file name that does not exist) and hardware failure (a disk crash, a printer or network connection lost). An exception is different from a syntax error, which is found before the program runs, and from a logic error, where the program runs but gives wrong results. Python gives each exception a name, such as ZeroDivisionError, and prints it with the line where it happened.

1 · What happens with no handling

This program divides 100 by a number the user types. The user types 0.

Python

Number = int(input("Enter a number: "))Result = 100 / Numberprint(Result)print("Finished")

Pseudocode (exam style)

INPUT NumberResult <- 100 / NumberOUTPUT ResultOUTPUT "Finished"

The first line works. The second line cannot be carried out, so an exception is raised and the program halts there. Result is never output and Finished is never printed. The user sees a system message instead.

4 · Reading the error message

Traceback (most recent call last):  File "prog.py", line 2, in <module>    Result = 100 / NumberZeroDivisionError: division by zero

The last line is the exception and its reason. The line above shows the statement that caused it, and the line before that gives the line number.

6 · Common ways to lose marks

  • Defining an exception as just "an error". Say it is an unexpected event during execution that disrupts the normal flow and can make the program halt.
  • Giving a cause that is not one of the three, such as "the program is slow".
  • Giving two examples of the same cause when two different causes are asked for.
  • Describing a syntax error or a logic error as an exception.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A web form quantity box

A customer types ten instead of 10. Converting it to a number fails, which is a user error causing a ValueError.

Exam use: user error: text where a number is expected.

A spreadsheet with a moved file

A linked file has been renamed. Opening it fails because it no longer exists under that name.

Exam use: user error: wrong or missing file name.

A game saving to a full disk

There is no space left, so the write fails. The program did nothing wrong; the device could not cope.

Exam use: hardware or system failure.

An average of no values

A program divides a total by the number of transactions. On a quiet day there are none, so it divides by zero.

Exam use: programming error: a case the code did not allow for.

A lost network connection

A download stops when the Wi-Fi drops. The program cannot prevent this.

Exam use: failure outside the program's control.

Top tips

  • Say 'unexpected'. An exception is an unexpected event during execution, not just an error.
  • Say what it does. It disrupts the normal flow and may make the program halt.
  • Give causes in three groups. Programming error, user error, hardware failure.
  • Different causes. If two causes are asked for, pick from two different groups.
  • Name an example with each. Divide by zero; wrong file name; disk crash.
  • Don't mix them up. Syntax errors are found before running; logic errors do not stop the program.
