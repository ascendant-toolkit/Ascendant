Recursion in Action: The Fibonacci Sequence

The classic example of a function that calls itself twice. See the call stack and the call tree grow, fill in the trace table from the past paper, count the calls, and find out why the simple recursive version is slow.

The sequence

The Fibonacci sequence starts 0, 1 and then every number is the sum of the two before it: 0, 1, 1, 2, 3, 5, 8, 13, 21, … Counting from position 0, Fib(0) = 0, Fib(1) = 1, Fib(2) = 1, Fib(3) = 2, Fib(4) = 3, Fib(5) = 5.

That definition refers to itself: Fib(n) is Fib(n − 1) + Fib(n − 2). It is a natural fit for recursion, and it appeared in 9618 Paper 3 (M/J 2023) as a trace table question.

Two base cases, two calls

Base cases

Fib(0) = 0 · Fib(1) = 1

The two starting values are known, so no further call is made. In the paper’s code both are handled by one test, Number <= 1, which returns Number itself.

General case

Fib(n) = Fib(n − 1) + Fib(n − 2)

For any larger n, call the function twice, with n − 1 and n − 2, and add the answers. Both arguments are smaller, so each call moves towards a base case.

Why two base cases?Fib(2) calls Fib(1) and Fib(0). If only Fib(1) were a base case, Fib(0) would call Fib(−1) and Fib(−2), and the calls would never stop.

The function, line by line

This is the function from the past paper. Switch between Pseudocode and Python.

  1. Header. One parameter, Number, and it RETURNS an INTEGER.
  2. IF Number <= 1. Covers both base cases. Result ← Number gives 0 for Fib(0) and 1 for Fib(1).
  3. The recursive line. Fib(Number - 1) + Fib(Number - 2) makes two calls. The addition waits until both have returned.
  4. RETURN Result. Both branches finish here, so every call hands back its answer.

Double recursion

Compound interest and factorial call themselves once, so the calls form a single chain. Fibonacci calls itself twice, so the calls form a tree. The first call (Fib(Number - 1)) is followed all the way down and back before the second call (Fib(Number - 2)) even starts. The stack only ever holds one branch: it is as deep as n, even though the tree has many more calls.

The cost of the simple version

Look at the tree for Fib(5) in the Watch tab: Fib(3) is worked out twice, Fib(2) three times, and Fib(1) five times. Nothing is remembered, so the same sub-problems are repeated. The number of calls roughly multiplies by 1.6 each time n goes up by 1.

The same job with a loop

An iterative version keeps the last two values and moves along, doing about n steps and using no stack.

Recursive

FUNCTION Fib(Number : INTEGER) RETURNS INTEGER
   IF Number <= 1 THEN
      RETURN Number
   ELSE
      RETURN Fib(Number - 1) + Fib(Number - 2)
   ENDIF
ENDFUNCTION
def fib(number):
    if number <= 1:
        return number
    return fib(number - 1) + fib(number - 2)

Iterative

FUNCTION Fib(Number : INTEGER) RETURNS INTEGER
   Previous ← 0
   Current ← 1
   FOR i ← 2 TO Number
      Next ← Previous + Current
      Previous ← Current
      Current ← Next
   NEXT i
   IF Number = 0 THEN
      RETURN 0
   ENDIF
   RETURN Current
ENDFUNCTION
def fib(number):
    previous, current = 0, 1
    for i in range(2, number + 1):
        previous, current = current, previous + current
    return 0 if number == 0 else current
Fibonacci is a good function to learn recursion on, and a poor one to use recursively in a real program. The recursive version is shorter and matches the definition; the loop is far faster.

Quick quiz

Flashcards

General descriptions of where the idea appears. Numbers are illustrative only.

Breeding rabbits

Fibonacci described an idealised rabbit population: each pair needs a month to mature, then produces a new pair every month. The number of pairs each month is the number two months ago plus the number last month, which is exactly the definition.

Exam use: a clear example of a problem defined in terms of two smaller versions of itself.

Climbing stairs

If you can climb one or two stairs at a time, the number of ways to reach step n is the number of ways to reach step n − 1 plus step n − 2. The answers follow the Fibonacci numbers.

Exam use: shows that the same code shape solves counting problems, not only “maths” sequences.

Spirals in plants

The number of spirals in some pine cones, sunflower heads and pineapples are often Fibonacci numbers. The link is a result of how growth packs new seeds efficiently, not a program running in the plant.

Exam use: interesting context, but not needed in an answer.

Other problems that split in two

Searching a game tree, exploring a maze with a choice of two turns, and many divide-and-conquer algorithms call themselves two or more times, just like Fib. The call tree is the same kind of picture.

Exam use: a good answer to “give an example of an application that could use recursion”, together with the reason: the problem splits into smaller copies of itself.

Why real programs avoid the simple version

Because the same values are recomputed, the plain recursive Fib takes far longer than a loop as n grows. Programmers either use a loop or store results already worked out (called memoisation) so each value is calculated once. Memoisation is beyond the 9618 syllabus, but it explains why repeated calls are the weakness.

Exam use: supports a “discuss the drawbacks of recursion” answer: repeated work, more memory for the stack, possible stack overflow.

Q3 Explain 3 marks Explain why the recursive version of Fib() is slow for large values of Number.
ReminderSay what is repeated, and what that does to the number of calls.
Each call (except the base cases) makes two further calls. The same values are calculated many times (e.g. Fib(2) is worked out again in each branch), because nothing is remembered. The total number of calls roughly multiplies each time Number increases (exponential growth), so far more calls are made than a loop would need.
Common mistakeJust writing “recursion is slow”. Name the repeated calculations.
Q4 Rewrite 5 marks Rewrite the function Fib() as an iterative function, using program code.
ReminderStarting values replace the base cases. The repeating step goes in a loop. Keep two variables for the previous two values.
Function header with one parameter, returning an integer. Two variables initialised to the starting values (0 and 1). A loop that runs the correct number of times (Number − 1 passes from 2 up to Number). Inside the loop, the new value is the sum of the two previous ones and the variables are updated in the right order. Returns the correct value (including the case Number = 0 or 1). 
def fib(number):
    previous, current = 0, 1
    for i in range(2, number + 1):
        previous, current = current, previous + current
    return 0 if number == 0 else current
Common mistakeUpdating previous before current has used it, so one value is lost. Python’s two-value assignment avoids this; in pseudocode use a temporary variable.

Top tips

  • Two base cases. Fib(0) = 0 and Fib(1) = 1. Both appear in a trace table, so don’t leave out Fib(0).
  • Go down the left branch first. Fib(Number - 1) is called and finished completely before Fib(Number - 2) is started.
  • In the Result column write the sum going down (Fib(4) + Fib(3)) and the numbers going up (3 + 2). The Return value column stays blank until a call returns.
  • Count the calls with a tree. Fib(3) is 5 calls, Fib(4) is 9, Fib(5) is 15. Each is the previous two plus 1.
  • The stack is only as deep as n. Fib(5) never has more than 5 frames, even though there are 15 calls in all.
  • For drawbacks, name the repeated work. The same values are recalculated, so the number of calls grows very quickly. Also: more memory for stack frames and a risk of stack overflow.
  • Converting to a loop: the base-case values become the starting values of two variables, and the sum goes in the loop.
  • Say “frame”, “return address”, “push” and “pop” in any stack answer.
