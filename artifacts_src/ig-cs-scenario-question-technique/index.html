IGCSE Computer Science · 0478 · Exam technique

The 15-Mark Scenario Question: How Each Band Is Reached

How the last question of Paper 2 is marked, what the AO2 and AO3 bands look like in a real program, a 30-minute plan, the techniques scenarios keep asking for, and six practice scenarios.

This part in five sentences

The last question of Paper 2 is a 15-mark unseen scenario in which you write a program, and the syllabus says to spend about 30 minutes on it. It is marked in two bands: AO2 out of 9 for the programming techniques and the data structures you choose, and AO3 out of 6 for comments, identifiers, logical order and accuracy, so a program that does everything the scenario asks, with the structures it names and clear comments, can earn all 15. Each series gives a list of requirements and the names of the arrays and variables to use, and the mark scheme is a checklist of those requirements, so the strongest answers follow the scenario line by line. The examiner reports repeat the same advice every year: read to the end, use the given arrays as they are described, do not waste time declaring what you are told is already declared, comment every part, and put a message with every input and output. The band you reach depends on how much of the checklist your program meets, so plan the requirements first and write the program in that order.

4 · How to reach each band

The descriptors are about what your program contains. This table turns them into what to check in your own answer.

The two bands move together, because a program that meets all the requirements with the right structures usually shows the habits that AO3 rewards. The lab in the Explore tab turns this table into a checklist for estimating where an answer sits. It is a teaching model, not an official mark.

5 · The 30-minute plan

  1. Read (3 minutes). Read to the end. Underline the array and variable names, the numbers (60 riders, under 900 seconds) and the closing instructions.
  2. Checklist (2 minutes). Write one line in the margin for each bullet, with the technique: input twice (loop, comparison), sort both arrays (nested loops), top three (output), store names (selection, counting, second array), output the count.
  3. Write (20 minutes). One requirement at a time, in order, with a comment above each part and a message with each input and output.
  4. Check (5 minutes). Tick each bullet against the code. Look for initialisation, loop limits, whether both arrays move together, and whether every output has a message.

6 · The techniques that scenarios keep asking for

Validate a number in a loop

REPEAT    OUTPUT "Enter the number of rooms (3 to 20)"    INPUT Number    IF Number < 3 OR Number > 20      THEN        OUTPUT "The number must be between 3 and 20, please try again"    ENDIFUNTIL Number >= 3 AND Number <= 20

The May/June 2023 report notes that some candidates validated with a single IF statement, which allows only one attempt at entering a correct value. A loop allows as many as needed.

Enter a value twice and compare (verification)

REPEAT    OUTPUT "Enter the time"    INPUT FirstEntry    OUTPUT "Enter the time again"    INPUT SecondEntry    IF FirstEntry <> SecondEntry      THEN        OUTPUT "The times do not match, please try again"    ENDIFUNTIL FirstEntry = SecondEntry

Sort two arrays together

When two arrays hold related data at the same index, every swap must move both. The Oct/Nov 2024 report notes some candidates used only one loop, and some used the min/max method once instead of the three times needed. Use the bubble sort from the previous review and swap the names as well as the times.

Store the items that meet a rule in another array

BadgeCount ← 0FOR Index ← 1 TO 60    IF RiderTime[Index] < 900      THEN        BadgeCount ← BadgeCount + 1        BadgeName[BadgeCount] ← RiderName[Index]    ENDIFNEXT Index

The second array has its own counter. Using Index there would leave gaps in the array. The report for the club scenario says candidates identified the right members but did not store their names in the array given.

Nested loops for a 2D array

FOR Row ← 1 TO 7    FOR Reading ← 1 TO 4        OUTPUT "Enter the temperature for day ", Row, " reading ", Reading        INPUT Temperature[Row, Reading]    NEXT ReadingNEXT Row

Round, total, find the largest, find the smallest

TotalArea ← 0Largest ← 0Smallest ← 100000FOR Index ← 1 TO Number    TotalArea ← TotalArea + Area[Index]    IF Area[Index] > Largest      THEN        Largest ← Area[Index]    ENDIF    IF Area[Index] < Smallest      THEN        Smallest ← Area[Index]    ENDIFNEXT IndexAverageArea ← ROUND(TotalArea / Number, 2)

The Oct/Nov 2024 report for the rooms scenario says variables that need initialising must be initialised: a smallest value starting at 0 would never be replaced, and a total used before it is set gives the wrong answer.

7 · One scenario, three answers, three bands

This scenario is our own, built on the pattern of a real running club question. Below are three different answers to it and the band each would be given against the published descriptors. These are our own illustrations, not examiner scripts, and an examiner decides the real mark.

Scenario. A cycling club has 60 riders who each ride a 5-kilometre time trial. The riders' names are stored in the one-dimensional (1D) array RiderName[]. Each rider's time, in seconds, is stored in the 1D array RiderTime[]. A rider's data is at the same index in both arrays. The club gives rosettes to the riders with the three fastest times and a badge to every rider who finishes in under 900 seconds.

Write a program that: allows each rider's time to be input twice and checks that the two inputs match; sorts RiderTime[] and RiderName[] into ascending order of time; outputs the names and times of the three fastest riders, labelled First, Second and Third; stores the names of all riders who earn a badge in the array BadgeName[]; and outputs the number of badges needed. Use pseudocode or program code and add comments. You do not need to declare any arrays or variables. All inputs and outputs must have suitable messages. [15]

Answer A: AO2 about 2 of 9, AO3 about 1 of 6

INPUT TimeIF Time < 900  THEN    OUTPUT "Badge"ENDIFOUTPUT Time

It uses input, selection and output, so some technique is present (AO2 band 1 to 3). It stores one value in a variable and not the arrays in the scenario. There is no loop, so only one rider is handled. No comments (AO3 band 1 to 2). It attempts one requirement: the badge test.

Answer B: AO2 about 5 of 9, AO3 about 2 to 3 of 6

// input the timesFOR Index ← 1 TO 60    OUTPUT "Enter the time for ", RiderName[Index]    INPUT RiderTime[Index]NEXT Index// sort the timesFOR Index ← 1 TO 59    IF RiderTime[Index] > RiderTime[Index + 1]      THEN        Temp ← RiderTime[Index]        RiderTime[Index] ← RiderTime[Index + 1]        RiderTime[Index + 1] ← Temp    ENDIFNEXT IndexOUTPUT "First ", RiderName[1], RiderTime[1]OUTPUT "Second ", RiderName[2], RiderTime[2]OUTPUT "Third ", RiderName[3], RiderTime[3]Count ← 0FOR Index ← 1 TO 60    IF RiderTime[Index] < 900      THEN        Count ← Count + 1    ENDIFNEXT IndexOUTPUT Count

It uses the given arrays with loops, selection and counting: more than one technique applied to the scenario, and some of the data stored in the structures given (AO2 band 4 to 6). It is not in the top band because requirements are missing or wrong: the times are entered once, not twice with a comparison; the sort makes one pass; the names do not move with the times, so a rider can be given another rider's time; and the badge names are not stored in BadgeName[]. It has some comments and mostly sensible names, but parts are inaccurate and fewer than most of the requirements are fully met, so AO3 sits on the border between band 1 to 2 and band 3 to 4. The last output has no message.

Answer C: AO2 about 9 of 9, AO3 about 6 of 6

// input each rider's time twice and check that the inputs matchFOR Index ← 1 TO 60    REPEAT        OUTPUT "Enter the time in seconds for ", RiderName[Index]        INPUT FirstEntry        OUTPUT "Enter the time again to confirm"        INPUT SecondEntry        IF FirstEntry <> SecondEntry          THEN            OUTPUT "The two times do not match, please try again"        ENDIF    UNTIL FirstEntry = SecondEntry    RiderTime[Index] ← FirstEntryNEXT Index// bubble sort into ascending order of time, swapping name and time togetherLast ← 60REPEAT    Swapped ← FALSE    FOR Index ← 1 TO Last - 1        IF RiderTime[Index] > RiderTime[Index + 1]          THEN            TempTime ← RiderTime[Index]            RiderTime[Index] ← RiderTime[Index + 1]            RiderTime[Index + 1] ← TempTime            TempName ← RiderName[Index]            RiderName[Index] ← RiderName[Index + 1]            RiderName[Index + 1] ← TempName            Swapped ← TRUE        ENDIF    NEXT Index    Last ← Last - 1UNTIL Swapped = FALSE OR Last = 1// output the three fastest ridersOUTPUT "First: ", RiderName[1], " with a time of ", RiderTime[1], " seconds"OUTPUT "Second: ", RiderName[2], " with a time of ", RiderTime[2], " seconds"OUTPUT "Third: ", RiderName[3], " with a time of ", RiderTime[3], " seconds"// store the names of the riders who earn a badge and count themBadgeCount ← 0FOR Index ← 1 TO 60    IF RiderTime[Index] < 900      THEN        BadgeCount ← BadgeCount + 1        BadgeName[BadgeCount] ← RiderName[Index]    ENDIFNEXT IndexOUTPUT "Number of badges needed: ", BadgeCount

Every bullet has a matching block: a verification loop with the two inputs compared, a bubble sort with nested iteration that moves both arrays, the top three output with labels, the names stored in BadgeName[] with their own counter, and the count output. All the data the scenario requires is stored in the structures it names (AO2 band 7 to 9). Every part has a comment, the names say what they hold, the order is logical and the program does everything asked (AO3 band 5 to 6). It does not declare the arrays, because the scenario says that is unnecessary.

6 · Multiple choice

These come from the Principal Examiner Reports for Cambridge IGCSE Computer Science, which describe what candidates actually wrote. The wording is ours.

Data for one member, not all

Oct/Nov 2024, paper 21 (a running club): most candidates attempted the input requirement but did not use the arrays in the question. Most entered the data for one member, not the 200 stated, and many did not use an index or a loop to input all the times.

Exam use: read the numbers in the scenario and make the loop limits match them.

Declaring what was already declared

Oct/Nov 2024, paper 22 (house rooms): many candidates spent time declaring arrays and variables when the question said it was not necessary. Marks are given for covering the requirements, so the time is better spent there.

Exam use: read the closing instructions before writing anything.

The maximum that never changed

Oct/Nov 2024, paper 22: finding the largest and smallest room needs a maximum and a minimum that are initialised sensibly, and totals must be set before they are used. Initialisation still has to be shown.

Exam use: start the smallest at a large number or at the first item.

The top team but not the points

May/June 2024, paper 21 (a league): some candidates found only the index of the team with the highest points, not the points themselves, and most wrote nothing for a tie for first place.

Exam use: ask what the requirement says to output, and what could go wrong with the data.

Only the seats booked

Oct/Nov 2023, paper 21 (theatre seats): requirement 1 was not attempted well because candidates did not use a nested loop or the 2D array, and requirement 3 was met by only a few because the output only stated the seats booked, not whether any were available.

Exam use: use the array structure as described and output what the requirement asks.

A single attempt at validating

May/June 2023, paper 21 (weekly temperatures): a few candidates used an IF statement for validation, which allows one attempt. A loop within the loops was the strongest approach. Many calculated and converted correctly but did not round.

Exam use: validation needs a loop; read each requirement for rounding.

What the strongest answers did

Every series, the reports say the strongest candidates matched the requirements closely, used the data structures as the scenario described them, commented each part, and gave a message for every input and output.

Exam use: the closing instructions in the scenario are marking instructions.

Based on Oct/Nov 2024 · 0478/21 · Q11 [15] A cycling club has 60 riders who each ride a 5-kilometre time trial. The riders' names are stored in the one-dimensional (1D) array RiderName[]. Each rider's time, in seconds, is stored in the 1D array RiderTime[]. A rider's data is at the same index in both arrays. The club gives rosettes to the riders with the three fastest times and a badge to every rider who finishes in under 900 seconds. Write a program that allows each time to be input twice and checks that the inputs match; sorts both arrays into ascending order of time; outputs the three fastest riders as First, Second and Third; stores the names of riders who earn a badge in BadgeName[]; outputs the number of badges needed. Use comments and give every input and output a message. You do not need to declare any arrays or variables.
What the mark scheme wants
  • AO2 maximum 9, AO3 maximum 6. Data structures required, named as given: RiderName[], RiderTime[], BadgeName[]
  • R1 input and verify the times (input, iteration)
  • R2 sort both arrays in ascending order of time and output the top three (nested iteration, sorting, selection, output)
  • R3 store the names of the riders who get a badge and output the number (iteration, selection, counting, output)
  • AO2 top band: every requirement covered by an appropriate technique and all the data stored in appropriate structures
  • AO3 top band: fully commented, meaningful identifiers, logical order, accurate, all requirements
Plan

Checklist: loop of 60; two inputs and a comparison in a REPEAT; bubble sort moving both arrays; three labelled outputs; BadgeName[] with its own counter; a message with the count. The full model answer is in the Learn tab.

Based on Oct/Nov 2024 · 0478/22 · Q12 [15] A garden centre stores the names of up to 12 flower beds in the 1D array BedName[] and the length, width and area of each bed in the 2D array BedSize[]. The variable NumberOfBeds holds the number of beds, which must be at least 2 and no more than 12. Write a program that: inputs and validates the number of beds; inputs each bed's name, length and width in metres; calculates and stores the area, rounded to 2 decimal places; calculates the total area and the average area, rounded to 2 decimal places; finds the largest and smallest beds by area; outputs every bed's name, dimensions and area; and outputs the names of the largest and smallest beds, the total area and the average. Use comments and messages. You do not need to declare any arrays or variables.
What the mark scheme wants
  • Structures: a 1D array for the names, a 2D array for the dimensions and area, and a variable for the number
  • R1 input and store the number of beds, the names and the dimensions, with validation of the number (input with prompts, nested iteration, variables, 1D and 2D arrays, validation)
  • R2 calculate and store the areas, the total and the average, rounded; find the smallest and largest (calculation, totalling, rounding, maximum and minimum, iteration)
  • R3 output the results, including the contents of the arrays and the calculated data (iteration, output)
  • The report: variables for the maximum and minimum and the total need initialising; declaring arrays was not required
Plan

Checklist: validate NumberOfBeds in a REPEAT loop; FOR loop to input; ROUND(Length * Width, 2); total with TotalArea ← 0; Largest and Smallest set before the loop; output loop; final outputs with messages.

Based on Oct/Nov 2023 · 0478/21 · Q10 [15] A cinema hall has 8 rows of 15 seats. The 2D Boolean array Seat[1:8, 1:15] holds FALSE for a seat that is free and TRUE for a seat that is booked. A customer can book from 1 to 5 seats at a time, and seats are given in order from those free. Write a program that: counts and outputs the number of free seats; inputs and validates the number of seats the customer wants; checks whether enough free seats are left and outputs suitable messages; and books the seats if there are enough. You do not need to declare any arrays or variables.
What the mark scheme wants
  • Structures: a 2D array for the seats (Boolean) and variables for the counters and the number wanted
  • R1 find the number of seats available and output it (searching, nested iteration, output)
  • R2 input and validate the number of seats (input, iteration, selection)
  • R3 check whether seats are available (selection, assignment, output with appropriate messages)
  • The report: many did not use a nested loop or the 2D array; the output often stated only the seats booked, not whether any were available
Plan

Checklist: nested FOR loops over Row and Column counting FALSE values; REPEAT loop validating 1 to 5; IF free seats >= wanted; a loop that sets the next free seats to TRUE; separate messages for 'not enough seats' and for a booking made.

Based on May/June 2024 · 0478/21 · Q10 [15] A hockey league has 8 teams. The array TeamName[] holds the names. For each team the program must input the number of games played, wins, draws and losses, and check that wins + draws + losses equals the games played. A win scores 3 points, a draw 1 and a loss 0. Write a program that stores the data, calculates each team's points in the array Points[], finds the highest number of points, and outputs the name of every team with the highest number of points. Use comments and messages.
What the mark scheme wants
  • Based on the report for May/June 2024 paper 21: the best responses validated the games played against the wins, draws and losses
  • Calculation of points for each team (iteration, arithmetic)
  • Find the highest points, and not only the index of the team
  • Output the team or teams with the highest points: a second loop that outputs every team whose points equal the highest, to cover a tie
Plan

Checklist: loop over 8 teams with a validation loop; Points[Index] ← Wins * 3 + Draws; Highest set from the first team; a second loop for the output, using IF Points[Index] = Highest.

Based on May/June 2023 · 0478/21 · Q11 [15] A weather station records four temperature readings in degrees Celsius on each of 7 days. They are stored in the 2D array Temperature[1:7, 1:4]. Write a program that inputs all the readings with validation (between −20 and 45), calculates the average for each day and for the whole week, and outputs each average in degrees Fahrenheit rounded to 1 decimal place (Fahrenheit = Celsius × 9 / 5 + 32). Use comments and messages.
What the mark scheme wants
  • Based on the report for May/June 2023 paper 21: requirement 1 was well attempted by most candidates with a nested loop and the 2D array stated
  • A few validated with a loop within the loops; a few validated with an IF that allowed one attempt only
  • Requirements 2 and 3 were fairly well attempted, but many calculated the averages and converted correctly and did not round the answer

Based on Feb/March 2025 · 0478/22 · Q10 [15] A sports club stores its members' codes in the 1D array MemberCode[] and their first and last names in the 2D array MemberName[]. The variable NewCode holds a new code. Write a program that shows a menu with three options: 1 add a new member; 2 display all members' names and codes; 3 end the program. To add a member, input the new code, the first name and the last name, and check that the code has exactly 6 characters and has not been used before. Use comments and messages. You do not need to declare any arrays or variables.
What the mark scheme wants
  • Based on the report for Feb/March 2025: the scenario required a menu with three options, a check that the code had six characters and had not been used before, a list of all members and an option to end
  • Stronger responses closely matched the requirements and used all the data structures as described: a 1D array for the codes, a 2D array for the names, a variable for the new code
  • Use LENGTH for the length check; a loop through the existing codes for the uniqueness check; a REPEAT loop for the menu
Plan

Top tips

  • Read to the end first. Names, numbers and the closing instructions.
  • Turn each bullet into a checklist line. One technique for each.
  • Use the names given. In the way they are described.
  • Do not declare what is declared. Initialise what needs initialising.
  • Comment each part. And a message with every input and output.
  • Both arrays move together. Swap names as well as times.
  • Check against the list. Tick every bullet in the last five minutes.
