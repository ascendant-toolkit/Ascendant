try, except, else and finally in Python

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

How a try block, except blocks, else and finally run and in what order, with named exceptions and the exam pseudocode form; pseudocode and Python side by side, with line-by-line animations.

This page in five sentences

A try block holds the statements that might cause an exception. If one does, the rest of the block is skipped and Python looks for an except block that matches the exception, runs it, and then carries on with the statement after the whole structure. If nothing goes wrong the except blocks are skipped. You can name the exception (except ValueError:), give several except blocks for different exceptions, or use a bare except: that catches any. An else block runs only when there was no exception, and a finally block runs whether or not there was one, which makes it the place to tidy up. The exam pseudocode form is TRY ... EXCEPT ... FINALLY ... ENDTRY.

1 · The basic structure

Python

try:    Number = int(input("Enter a number: "))    Result = 100 / Number    print(Result)except ZeroDivisionError:    print("Cannot divide by zero")finally:    print("Done")

Pseudocode (exam style)

TRY   INPUT Number   Result <- 100 / Number   OUTPUT ResultEXCEPT   OUTPUT "Cannot divide by zero"FINALLY   OUTPUT "Done"ENDTRY

Exam pseudocode has one EXCEPT block for every kind of exception. The named exceptions and else below are Python only.

2 · What runs, in order

BlockWhen it runs
tryAlways starts. Stops at the first statement that raises an exception; the rest of the block is skipped
exceptOnly if an exception was raised and it matches. The first matching block runs; the others are skipped
elseOnly if the try block finished with no exception
finallyAlways, last, whether or not there was an exception

3 · Naming the exception

Different problems often need different responses, so there can be several except blocks.

try:    Number = int(input("Enter a number: "))    Result = 100 / Numberexcept ValueError:                    # the text was not a whole number    print("Not a whole number")except ZeroDivisionError:             # the number was 0    print("Cannot divide by zero")else:                                 # no exception at all    print("Result is", Result)
FormCatches
except ValueError:Only that exception. Anything else still halts the program
except (ValueError, TypeError):Either of those two
except IOError:Problems opening or reading a file (FileNotFoundError is one)
except:Every exception. Accepted in the exam; less precise
try:    Age = int(input("Enter your age: "))except ValueError as Problem:    print("Problem:", Problem)        # Problem holds the reason Python gave

4 · finally: tidying up

With input 0 the output is Cannot divide by zero then Done. With input 4 it is 25.0 then Done. The finally block runs both times. It even runs when an exception is not caught by any except: Python runs it, then halts.

5 · Common ways to lose marks

  • try with no except (or finally). It is a syntax error.
  • An except block that does nothing, or has no message.
  • Putting statements that can fail outside the try.
  • Naming the wrong exception, such as except IOError for a ValueError. It does not match, so the program halts.
  • Writing the colon or the indentation wrongly: every block ends with : and its lines are indented.
  • Thinking else and finally are the same. else only runs if there was no exception.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A form with two kinds of bad input

A calculator page gives one message for text that is not a number and a different one for a division by zero, because the two need different advice.

Exam use: several except blocks for different exceptions.

A report that always closes its file

A program writes a report and must release the file whatever happens, so the closing is in finally, not at the end of the try block.

Exam use: finally: runs with or without an exception.

A save that confirms only when it worked

A message 'Saved' is shown only if no problem happened, and an error message otherwise.

Exam use: else: for the no-exception path.

A catch-all in a launcher

A launcher wraps starting each program in try and a general except, so one failing program never closes the launcher.

Exam use: a bare except catching everything.

A hospital system closing a connection

Whether a record was read or the read failed, the database connection is closed at the end so it is not left open.

Exam use: finally for cleanup.

Top tips

  • try needs except. A try with no except or finally is a syntax error.
  • Risky lines go inside. Everything that can fail belongs in the try block.
  • Always a message. An except with no action earns nothing.
  • Match the exception. ValueError for bad text, IOError for files. Or use a bare except.
  • else is the no-exception block. finally runs whatever happens.
  • Colons and indents. Each block ends with : and is indented.
