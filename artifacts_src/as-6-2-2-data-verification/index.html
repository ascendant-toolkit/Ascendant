Data Verification

Coursebook: Chapter 6 · Security, privacy and data integrity · section 6.2 Data integrity

Visual check, double entry, parity byte and block checks and the checksum, how each detects errors and where it is used, with animations, parity labs and the real Paper 1 and Paper 2 questions from 2021 to 2026.

This page in five sentences

Data verification checks that data entered or transferred is the same as the original; it does not check that the original was right. During data entry two methods are used: a visual check (a person compares the entered data with the original) and double entry (the data is entered twice and the computer compares them). During data transfer the methods are the parity byte check, the parity block check and the checksum. A parity bit is added so that the number of 1s in each byte is odd or even as agreed (7 bits of data plus one parity bit); the receiver recounts and an unexpected parity means an error. A parity block check adds parity in both directions so the position of a single wrong bit can be found; a checksum is calculated from the data, sent with it, recalculated by the receiver and compared.

MethodHow it works

Double entryThe data is entered twice (by the same or by different people) and the computer compares the two entries; if they differ there is an error

2 · Verification during data transfer

Parity byte check

Sender and receiver agree on odd or even parity. The data is split into groups (7 bits), the 1s in each group are counted and a parity bit is appended so the whole byte has an even (or odd) number of 1s. The receiver counts the 1s: if a byte with an odd number of 1s arrives when even parity is used, there is an error. Example, even parity: 0101110 has four 1s, so the parity bit is 0, giving 01011100. 101010 has three 1s, so with even parity the parity bit is 1 (giving 1010101).

Parity block check

Bytes are grouped in a grid. Parity is calculated for each row (the parity bit) and for each column (the bits of the extra parity byte, sent with the data). When received, the rows and columns are recounted; the row with the wrong parity and the column with the wrong parity locate the single bit that is wrong, so it can be corrected.

Checksum

A calculation is made from the data and the result (the checksum) is transmitted with the data. The receiver repeats the calculation on the data received and compares it with the checksum received. If the two are different there is an error; if they match no error has been detected.

3 · Verification against validation

Verification checks the data is the same as the original (or as sent). Validation checks the data is reasonable and in the right format. Neither proves the original data is accurate.

Common ways to lose marks

  • Writing that verification "checks the data is correct". It checks that it matches the original or the data sent.
  • Describing double entry as "typing it again". The computer compares the two entries.
  • Describing the checksum without the steps: calculate, send with the data, recalculate, compare.
  • Counting the parity bit in the wrong way: with even parity the total number of 1s including the parity bit must be even.
  • Saying a parity check can correct an error. A parity byte check only detects; a parity block check can locate a single wrong bit.

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Typing a password twice

A sign-up form makes you type your new password twice and refuses if they differ: double entry.

Exam use: verification at data entry.

Downloading a file

Many download pages give a checksum; your computer recalculates it on the downloaded file and compares to be sure it arrived unchanged.

Exam use: checksum.

Memory and network errors

A parity bit on each byte catches a single flipped bit caused by noise on a line.

Exam use: parity byte check.

A teacher reading marks back

After typing marks from a paper register, the teacher reads the screen against the paper: a visual check.

Exam use: visual check.

Barcode scanning

A second scan of the same barcode and comparison guards against misreads.

Exam use: comparing to the original.

M/J 2025 · 9618/23 · Q5 Write 8 marks A module Parity() takes a string BitString representing a binary value. It concatenates '0' to the end if BitString contains an even number of 1s, or '1' if it contains an odd number, and returns the modified value. ReminderCount the 1s; MOD 2; append the character.

One answer:

FUNCTION Parity(BitString : STRING) RETURNS STRING   DECLARE Index, Count : INTEGER   Count ← 0   FOR Index ← 1 TO LENGTH(BitString)      IF MID(BitString, Index, 1) = '1' THEN         Count ← Count + 1      ENDIF   NEXT Index   IF Count MOD 2 = 1 THEN      BitString ← BitString & '1'   ELSE      BitString ← BitString & '0'   ENDIF   RETURN BitStringENDFUNCTION

Function heading, ending, STRING parameter and STRING return type Loop for the length of BitString Extract the current character in the loop Compare it to '1' or '0' Increment a count that was initialised Check if there is an even or odd number of 1s Append '1' or '0' as appropriate Return the amended BitString

Common mistakeAppending the parity before the count is complete, or returning only the parity character.

Top tips

  • Verification: same as the original. Not 'correct'.
  • Entry: visual check, double entry. Transfer: parity, checksum.
  • Parity: odd or even, 7 bits plus 1. Count the 1s including the parity bit.
  • Block: row and column. They cross at the wrong bit.
  • Checksum: four steps. Calculate, send, recalculate, compare.
  • Double entry: the computer compares. Say who compares.
