Interrupts

Signals that make the processor pause, how they are serviced, and how buffers and interrupts keep printing and streaming smooth.

The big idea

An interrupt is a signal sent from a device or from software to the microprocessor. It makes the processor temporarily stop what it is doing so it can deal with the interrupt. Interrupts let a computer do many tasks, or have several windows open, at the same time.

4.1.4 Interrupts

What causes an interrupt?

Timing signal

A clock or timer signal, for example when a time slice ends.

Input/output process

A disk drive or printer needs more data.

Hardware fault

For example, a paper jam in the printer.

User interaction

The user presses a key or keys, such as Ctrl-Alt-Break.

Software error

An .exe file cannot be found, two processes try to use the same memory location, or a division by zero is attempted.

When the signal arrives, the computer must identify the type of interrupt and its priority. The processor either carries on with its current task, or stops to service the device or program that caused the interrupt.

How an interrupt is serviced

  1. Save the status of the current task: the contents of the program counter (PC) and other registers.
  2. Load the start address of the interrupt service routine (ISR) into the PC, and run the ISR.
  3. When the interrupt has been fully serviced, restore the saved registers.
  4. The interrupted task carries on from where it stopped.

Buffers

A buffer is an area of memory that stores data temporarily. Buffers and interrupts are often used together.

Streaming a video

Data arrives from the internet at a different speed from the one the media player needs. The buffer must be filled faster than the player empties it, otherwise the movie keeps freezing.

Printing a document

Printing takes far longer than sending the data. The data goes to the printer buffer, and the processor carries on with other tasks. When the buffer is empty, an interrupt asks for more data. The current task is suspended while it is serviced.

Without buffers and interrupts the processor would sit idle waiting for the printer.

Extension: interrupts in the fetch-execute cycle (A Level)

Not needed for IGCSE.

The CPU has an interrupt register. If a bit in it changes (for example 0000 0000 becomes 0000 1000 after a disk fault), the register is checked at the next fetch-execute cycle. If the interrupt is enabled and has a high enough priority, the CPU stores its registers, passes control to the interrupt handler (ISR), and when it has finished, resets the register and restores the registers.
