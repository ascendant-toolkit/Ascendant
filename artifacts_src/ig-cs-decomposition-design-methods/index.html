Decomposition and Design Methods

Sub-systems, inputs, processes, outputs and storage, structure diagrams, flowcharts, pseudocode, and explaining the purpose of an algorithm.

The big idea

A big problem is decomposed into sub-systems. Design tools such as structure diagrams, flowcharts and pseudocode plan the solution before any code is written.

7.2 Decomposition and design methods

Sub-systems

Every computer system is made of sub-systems, and each sub-system is made of smaller sub-systems. A car park system, for example, contains a ticket machine, a barrier, a payment kiosk and a display; the ticket machine in turn has a button, a printer and a processor. Decomposition is the process of breaking a problem down like this into its component parts.

Inputs, processes, outputs and storage

A useful way to decompose a problem is to ask four questions about it:

Inputs

What data goes in? (buttons pressed, values typed, readings from sensors)

Processes

What must be done to the data? (calculate, compare, sort, search)

Outputs

What must come out? (a ticket, a message, a sound, a signal to a motor)

Storage

What data must be kept? (a file or database of records, such as tickets issued)

Example, a car park ticket machine: input: driver presses the button, coins inserted. Process: record the entry time, calculate the fee. Output: print a ticket, show the fee, give change. Storage: a log of tickets and payments.

Structure diagrams

A structure diagram shows the problem as a hierarchy of boxes. The whole problem is the top box, which is split into sub-problems, each split again until every box is a task small enough to code. It shows what the parts are and how they fit together, not the order of steps.

Flowcharts

A flowchart shows the steps and decisions of an algorithm using standard shapes joined by arrows. These are the symbols used in the exam:

SymbolNameMeaning
TerminatorThe Start and Stop of the flowchart
ProcessSomething being done, such as a calculation or assignment
Input / OutputData being input or output
DecisionA Yes/No (True/False) question with two exits
SubroutineA call to a separate procedure or function with its own flowchart
Flow lineAn arrow: control passes from one shape to the next
  • A flowchart has one Start and (usually) one Stop.
  • A decision shape has two exits, labelled Yes/No or True/False.
  • A loop is drawn by an arrow that goes back to an earlier step.

Pseudocode

Pseudocode describes an algorithm in structured, code-like English. It does not belong to any one language. The Cambridge style uses upper-case keywords, the ← arrow for assignment, and four-space indentation.

Explaining the purpose of an algorithm

Questions may give an algorithm and ask for its purpose. State what it does overall (in one sentence), then describe the processes it uses. Try the algorithm with a small example (a trace) to see what comes out. Do not just copy the code line by line.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 Explain 3 marks A computer system is built from sub-systems. Explain what is meant by decomposing a problem.
ReminderBreak down, repeatedly, for a reason.
Breaking a problem (or system) down into smaller parts (sub-problems). Each part can be broken down again into smaller sub-parts until each is easy to solve. Each part can be solved and tested separately.
Common mistakeWriting "making it simpler" without saying it is split into parts.
Q2 State 4 marks A school library system lets students borrow and return books. State one example for each of inputs, processes, outputs and storage.
ReminderFour short examples.
Input: student ID scanned (or book barcode scanned) Process: check if the book is available (or calculate the due date) Output: a receipt printed (or a message on the screen) Storage: a file or database of books and loans
Common mistakeGiving the same kind of answer twice. Each must be a different part.
Q3 Describe 2 marks Describe what a structure diagram shows.
ReminderHierarchy of parts.
The parts (sub-problems) that make up a problem arranged in a hierarchy from the whole problem down to the smallest tasks.
Common mistakeDescribing the order of steps. That is a flowchart, not a structure diagram.
Q4 Identify 3 marks Name the flowchart symbol used for (a) Start, (b) a Yes/No question, (c) INPUT Age.
ReminderThree symbol names.
Terminator Decision Input/output (parallelogram)
Common mistakeCalling the decision a "question box". Use decision.
Q5 Explain 3 marks Explain the purpose of the algorithm below.
Total ← 0
FOR Count ← 1 TO 10
   INPUT Number
   Total ← Total + Number
NEXT Count
Average ← Total / 10
OUTPUT Average
ReminderOverall purpose first, then the processes.
Purpose: to input ten numbers and output their average. A loop repeats ten times, inputting a number each time and adding it to a running total. The total is divided by 10 to find the average, which is output.
Common mistakeCopying the code in words line by line. State the overall purpose too.
Q6 Explain 2 marks A student writes IF Mark is greater than 50 in pseudocode. Explain why this is not acceptable and write it correctly.
ReminderPseudocode must be precise.
Pseudocode needs precise, code-like statements, not English phrases. Correct: IF Mark > 50
Common mistakeRewriting it in words again. Use the symbols > < >= <= = <>.

Top tips

  • Decompose with four questions: inputs, processes, outputs, storage.
  • Structure diagram = the parts. Flowchart = the steps.
  • Flowchart shapes: terminator, process, input/output, decision (two exits), subroutine, flow line.
  • Pseudocode must be precise: use ←, =, <, >, not English phrases.
  • For "purpose" questions: say what it does overall, then describe the processes.
