Dijkstra's and A* Algorithms

Coursebook: Chapter 18 · Artificial Intelligence, section 18.1 Artificial Intelligence

Dijkstra's shortest-path algorithm and the A* algorithm worked through on the graphs from the past papers, and how they differ; animations, search labs and the real Paper 3 questions from 2021 to 2026.

This page in five sentences

Dijkstra's algorithm finds the shortest path from a start node to every other node in a weighted graph: it sets the start to 0 and all other nodes to ∞, repeatedly visits the unvisited node with the smallest distance, and updates its neighbours if the route through it is shorter. The A* algorithm finds the best path between two nodes, start and goal, and is faster because it uses a heuristic (an estimate of the distance still to go) to try the most promising nodes first, instead of exploring all routes. A* chooses the node with the lowest f = g + h, where g is the cost so far and h is the heuristic. Dijkstra's algorithm always finds the shortest path; A* may not if its heuristic is inaccurate. You will not be asked to write these algorithms, but you must be able to work them through on a graph.

1 · Purpose

Both algorithms perform a search on a graph to find a path between points. They are used in satnavs, route planners, game character movement and robot navigation, to find the optimal, shortest or most cost-effective route based on distance, cost or time.

2 · Dijkstra's algorithm

  1. Initialise: give the start node distance 0 and every other node ∞.
  2. Choose the unvisited node with the smallest distance and mark it visited (its distance is now final).
  3. For each unvisited neighbour, work out distance of this node + weight of the edge. If it is less than the neighbour's current value, replace it (and note the route).
  4. Repeat from step 2 until every node is visited (or the destination is visited).
  5. Read the final distances, and follow the recorded routes back to get each path.

3 · The A* algorithm

A* is used to find a path from a start node to a goal node. Every node has a heuristic h: an estimate of the cost from that node to the goal (for a map, the straight-line distance). For each node A* keeps:

  • g: the cost of the route from the start to the node found so far;
  • h: the heuristic, the estimated cost from the node to the goal;
  • f = g + h: the estimated total cost of a route through this node.
  1. Put the start node in the table with g = 0 and its h.
  2. Choose the node with the lowest f that has not been expanded.
  3. For each neighbour, work out g (the current node's g plus the edge weight), look up h, and write the row: start node, destination node, g, h and f. Only note a neighbour again if this route to it is cheaper than one already found.
  4. Stop when the goal is the node with the lowest f. The final path is found by following back through the nodes you came from.

5 · Common ways to lose marks

  • Not showing the working: ∞ for unvisited nodes, updated values, and which nodes are visited.
  • Choosing the node with the smallest edge weight instead of the smallest total distance from the start.
  • In A*, choosing the lowest g or lowest h instead of the lowest f = g + h.
  • Saying that A* "always finds the shortest path". It depends on the heuristic.
  • Giving only one route to each node. Show a second route where there is one, to show you compared them.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Finding the quickest way home

A route planner models the roads as a graph and runs a shortest-path search. A* is popular because the straight-line distance to your destination gives a good heuristic.

Exam use: A* uses a heuristic to search less.

Characters in a game

A character that has to walk from one side of a level to a door uses A* on a grid or map of locations, so it takes a sensible route round walls.

Exam use: path-finding for one start and one goal.

Internet routing

Routing protocols use shortest-path algorithms like Dijkstra's to decide the cheapest route across a network of routers.

Exam use: Dijkstra's finds the shortest path to every node.

A robot vacuum

It builds a map of your rooms as a graph and plans the route to cover them and get back to its charger.

Exam use: weights can be distance or energy.

Emergency vehicles

A planner can weight edges by travel time that includes traffic, so the quickest route changes through the day.

Exam use: weights are costs such as time.

Top tips

  • Dijkstra: start 0, others ∞. Write it down; it earns the working marks.
  • Visit the smallest distance. Then update neighbours: distance + weight, if smaller.
  • Show two routes. Compare them for at least one node.
  • A*: lowest f = g + h. Not the lowest g or h.
  • Dijkstra: all nodes, always shortest. A*: one goal, heuristic, may not be shortest.
  • Check the path. Add the weights of your final path.
