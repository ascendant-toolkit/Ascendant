Data Definition Language (DDL)

Coursebook: Chapter 8 · Databases · section 8.3 Data definition language (DDL) and data manipulation language (DML)

CREATE DATABASE, CREATE TABLE with data types, constraints and keys, and ALTER TABLE, with animations, a working SQL lab and the real Paper 1 questions from 2021 to 2026.

This page in five sentences

Data Definition Language (DDL) is the part of SQL that defines a database and its tables, rather than the data in them: CREATE DATABASE, CREATE TABLE and ALTER TABLE (to add a field or a key). In CREATE TABLE you give each field a name and a data type (CHAR, VARCHAR, BOOLEAN, INTEGER, REAL, DATE, TIME), optional constraints such as NOT NULL, then the PRIMARY KEY and any FOREIGN KEY ... REFERENCES. Choose the data type from the sample data: text IDs with letters are VARCHAR or CHAR(n), whole numbers INTEGER, money REAL, yes/no BOOLEAN. Exam questions ask you to write a statement, complete one, or find and correct errors, each mark for a specific feature.

1 · The statements

CREATE DATABASE SHOP; CREATE TABLE CUSTOMER(CustomerID VARCHAR(5) NOT NULL,FirstName VARCHAR(20),LastName VARCHAR(20),DateOfBirth DATE,PRIMARY KEY (CustomerID)); CREATE TABLE SHOP_ORDER(OrderNo INTEGER NOT NULL,CustomerID VARCHAR(5),OrderDate DATE,PRIMARY KEY (OrderNo),FOREIGN KEY (CustomerID) REFERENCES CUSTOMER(CustomerID)); ALTER TABLE SHOP_ORDERADD Paid BOOLEAN; ALTER TABLE SHOP_ORDERADD FOREIGN KEY (CustomerID) REFERENCES CUSTOMER(CustomerID);
PartWhat it does
CREATE DATABASE name;Defines a new database with that name
CREATE TABLE name( ... );Creates a table: opening and closing brackets, fields separated by commas
field typeGives each field its data type (the length goes in brackets for CHAR and VARCHAR)
NOT NULLA constraint: a value must be entered
PRIMARY KEY (field)Sets the primary key; a composite key lists both fields, PRIMARY KEY (A, B)
FOREIGN KEY (field) REFERENCES table(field)Links the field to the primary key of another table
ALTER TABLE name ADD field type;Adds a new field to an existing table (add several with commas); also used to add a foreign key

Common ways to lose marks

  • Forgetting the commas between fields, or the closing bracket and semicolon.
  • Using INTEGER for an ID that contains letters or leading zeros.
  • Writing PRIMARY KEY CharacterID without brackets, or FOREIGN KEY with no REFERENCES table and field.
  • Using CREATE DATA BASE or NONULL (spelling errors the paper plants as 'find the error' questions).
  • Using INSERT for a new field. A new field is added with ALTER TABLE ... ADD.

Building a new app's database

Before any data goes in, the developer writes CREATE TABLE statements for each entity, choosing field types and keys.

Exam use: DDL defines the structure.

Adding a feature later

A shop wants to record whether a toy has been returned: ALTER TABLE adds a Returned field without losing existing records.

Exam use: ALTER TABLE ... ADD.

Why IDs are text

A customer number like 000123 must keep its leading zeros, so it is stored as text, not a number.

Exam use: VARCHAR for codes.

Linking orders to customers

FOREIGN KEY (CustomerID) REFERENCES CUSTOMER(CustomerID) stops an order being created for a customer that does not exist.

Exam use: foreign key constraint.

Creating the database itself

Before tables exist the database is created once with CREATE DATABASE.

Exam use: CREATE DATABASE.

Top tips

  • CREATE TABLE: brackets, commas, semicolon. Check the end of every line.
  • Pick types from the sample data. Letters or leading zeros: VARCHAR.
  • PRIMARY KEY (field). Composite: both fields.
  • FOREIGN KEY ... REFERENCES table(field). Name the table and the field.
  • New field: ALTER TABLE ... ADD. Not INSERT.
  • Spell the keywords. CREATE DATABASE, NOT NULL.
