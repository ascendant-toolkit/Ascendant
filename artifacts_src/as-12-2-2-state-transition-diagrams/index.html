State-Transition Diagrams

Coursebook: Chapter 12 · Software development · section 12.2 Program design

State-transition diagrams: states, inputs, outputs, loops and halting states, reading a diagram into a table and drawing one from a table, with animations, simulators and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

A state-transition diagram shows how a system moves between states when something happens. Each state is a circle, the start is a filled dot with an arrow, and a final (halting) state is drawn as a double circle. An arrow between states is a transition, labelled with the input or event that causes it and, after a bar, any output: Low level detected | Activate pump. An arrow that leaves a state and returns to it is a loop (the input does not change the state). The same information can be written as a state-transition table with columns for current state, input, output and next state.

1 · The notation

  • X (the dot and arrow into S1) is the start: the label that replaces X is "Start".
  • S1 to S2: input "Low level detected", output "Activate pump". S1 to S3: input "Normal level detected", no output.
  • S2 loops on "Low level detected" (no output) and moves to S3 on "Normal level detected" with the output "Deactivate pump".
  • S3 is the final (halting) state: it has the double circle and no transitions out.

Counting: three transitions result in a different state (S1 to S2, S1 to S3, S2 to S3); two have an associated output. If the current state is S1 and "Low level detected" happens four times, the first moves to S2 and produces one output; the other three loop on S2 and produce nothing: 1 output, current state S2.

2 · Reading a diagram as a table

Start in S1. Follow each input: the table is built one row at a time, using the next state of the previous row as the current state.

  1. Draw one circle for every state in the table, and mark the start.
  2. For each row draw an arrow from the current state to the next state, labelled input | output (only the input if the output is "none").
  3. A row where the current state equals the next state is a loop.
  4. Tick off the rows as you draw them: eight rows, eight arrows.

4 · Using a diagram to design

A state-transition diagram documents an algorithm in the design stage: the states, the events that cause the change, and the outputs. Identify the states of the system (standby mode, on mode, alarm sounding) and the events (movement detected, wrong password entered repeatedly, battery too low).

Common ways to lose marks

  • Writing an output for a transition that has none (use "none"), or taking the output from the wrong arrow.
  • Using the wrong current state: each row starts in the previous row's next state.
  • Counting loops as changes of state, or leaving them out of a diagram you draw.
  • Drawing an arrow in the wrong direction: it starts at the current state and ends at the next state.

A traffic light

The states are red, red-amber, green and amber; a timer is the event that moves from one to the next.

Exam use: states and events.

A vending machine

It waits for coins, then a choice, then dispenses; pressing cancel returns the coins and goes back to waiting.

Exam use: transitions with outputs.

A door alarm

Standby, armed and alarm sounding are states; entering the password, opening a door or waiting are the events.

Exam use: design with states.

Games and characters

A character is idle, walking, jumping or falling, and the buttons and the ground are the inputs that change its state.

Top tips

  • Chain the rows. Next state of one row is the current state of the next.
  • Write none. When a transition has no output.
  • Loops count. Draw them and write their labels; they are not changes of state.
  • Start and final. Dot with an arrow; double circle.
  • One arrow per row. Tick the table off as you draw.
  • Arrow direction. From the current state to the next state.
