HTTP, FTP, SMTP, POP3, IMAP and BitTorrent Compared

Coursebook: Chapter 14 · Communication and internet technologies, section 14.1 Protocols

Tell the six application layer protocols apart: what each is for, push against pull, client and server against peer to peer, and POP3 against IMAP; a decision path, side-by-side comparison and practice.

This page in five sentences

The six protocols in 14.1.4 are easy to mix up, so this page puts them side by side and gives you questions to ask that separate them. First, is it email? If it is, SMTP sends, while POP3 and IMAP receive: POP3 downloads the message to one device and normally removes it from the server, IMAP leaves it on the server so every device stays in sync. If it is not email, HTTP(S) transfers web pages, FTP transfers files to and from a server, and BitTorrent shares a file peer to peer in pieces with no central server holding it. All six belong to the Application layer. Use the decision path and the confusions table below, then test yourself.

2 · A decision path

  1. Is it email? If yes: is it sending? Use SMTP. Is it receiving? Does the mail need to stay on the server, and be read from several devices? IMAP. Is it downloaded to one device and removed from the server? POP3.
  2. Is it a web page in a browser? HTTP(S).
  3. Is it a file moved to or from a server? FTP.
  4. Is it a large file shared among many users with no central server holding it? BitTorrent.

4 · BitTorrent words

  • A peer is a user sharing and downloading pieces; the swarm is all the peers sharing one file.
  • A seed has the whole file and shares it. A tracker holds data about the peers in the swarm.
  • The file is split into pieces; each peer collects pieces from several others and passes on the ones it has.

5 · Push protocols and pull protocols

The difference is which side starts the transfer.

PushPull
Who startsThe sender, as soon as it has something to sendThe receiving client, when it asks the server
Email exampleSMTP: client to mail server, and server to serverPOP3 and IMAP: your client collects from your mail server
Why it is usedMail servers are always on, so mail can be delivered at onceYour phone or laptop may be off or offline, so the server holds the mail until it asks

How a pull client keeps checking

The mail server does not need to know where your device is. Your email client checks the server again and again, for example every 5 minutes. This is called polling.

  1. A timer in the email client runs out, or the user presses refresh.
  2. The client connects to the mail server and logs in with the user name and password.
  3. The client asks what is in the mailbox.
  4. If there is new mail, the client retrieves it. POP3 downloads it and normally deletes the server copy; IMAP synchronises and leaves it there.
  5. The client disconnects (or, with IMAP, may stay connected), waits, and checks again.

A message that arrives just after a check waits on the server until the next one. A short interval means less delay but more checks, most of which find nothing. Many IMAP clients can also stay connected and be told of new mail by the server, using an extension called IDLE.

6 · MIME: sending photos and files by email

SMTP was designed to carry plain 7-bit ASCII text. A photo, a PDF or a sound file is binary data, and many languages need characters outside ASCII. MIME (Multipurpose Internet Mail Extensions) solves this by describing each part of a message and turning it into text that can travel safely. MIME is not a transfer protocol: SMTP still sends the message, and POP3 or IMAP still retrieves it.

  1. Compose. You type a message and attach a photo.
  2. Describe. The email client adds headers: MIME-Version, and a Content-Type for each part, such as text/plain or image/jpeg. A message with several parts is multipart/mixed, with a boundary string marking where each part starts.
  3. Encode. Binary parts are converted into text, usually with Base64. The Content-Transfer-Encoding header records the method.
  4. Send. SMTP carries the whole message, which is now all text, to the recipient's mail server.
  5. Retrieve. The recipient's client pulls it with POP3 or IMAP.
  6. Decode. The client reads the headers, splits the message at the boundaries, decodes each part back to the original bytes and opens it with a suitable program.
From: teacher@example.com
To: student@example.com
Subject: Trip photo
MIME-Version: 1.0
Content-Type: multipart/mixed; boundary="PART"

--PART
Content-Type: text/plain; charset="utf-8"

Here is the photo.

--PART
Content-Type: image/jpeg
Content-Disposition: attachment; filename="trip.jpg"
Content-Transfer-Encoding: base64

/9j/4AAQSkZJRgABAQAAAQABAAD...
--PART--

Base64 in one example

Base64 takes 3 bytes (24 bits), cuts them into 4 groups of 6 bits and writes each group as one of 64 safe characters. The data therefore grows by about a third.

8 · Common ways to lose marks

  • Naming SMTP for receiving email, or POP3 for sending it.
  • Writing that IMAP "downloads" the email. It leaves the message on the server.
  • Describing BitTorrent as "downloading from a server". There is no central server holding the file.
  • Saying HTTP is "for the internet". Be specific: it transfers web pages (hypertext documents).
  • Describing which layer the protocols belong to wrongly. All six are Application layer protocols.

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A school reports portal

Parents open a link and see their child's report in a browser. The page and the login form travel by HTTPS, which keeps the details secure.

Exam use: HTTP(S) transfers web pages; the S means secure.

Uploading a website

A designer uses an FTP program to send the website's files to the hosting company's server, and later downloads them again to make changes.

Exam use: FTP sends and receives files over a network, in either direction.

A phone and a laptop, one inbox

An email read on the phone is shown as read on the laptop. Both are using IMAP to look at the same copy on the mail server.

Exam use: IMAP leaves the mail on the server and keeps every device in sync.

An old desktop mail program

A program set to use POP3 collects the mail onto the computer and removes it from the server. Another device would not see those messages.

Exam use: POP3 downloads the message and normally removes it from the server.

Sharing a large file

A game developer shares a large file via BitTorrent so thousands of users download pieces from each other, which stops one server from being overloaded.

Exam use: BitTorrent is peer to peer: no central server holds the file; users share pieces.

BitTorrent and the Application layer

M/J 2024 · 9618/32 · Q2(c) Explain 3 marks Explain the meaning of the phrase: BitTorrent protocol provides peer-to-peer file sharing.
ReminderMany users, directly, no central server, equal status.

Any three: BitTorrent allows the sharing of files between thousands of users connected together over the internet It allows more users to share files with each other than would be the case with a simple peer-to-peer network Users share files directly with each other: their computers act as peers No web server / central device is used: all users are of equal status

O/N 2025 · 9618/32 · Q3(b) Describe 4 marks Describe how files are shared using the BitTorrent protocol.
ReminderTorrent file, pieces, tracker and swarm, peers become sources, seeds.

Any four: Files are shared over a peer-to-peer network A small torrent (descriptor) file with metadata about the file is created by a peer The whole file must initially be on at least one peer The file is broken into equal-sized pieces Other peers obtain the torrent file and connect to a tracker, which holds data about all the computers in the swarm Each peer downloads parts of the file from other peers until it has the whole file As each peer receives a piece it becomes a source for that piece A peer that has the complete file and shares it is a seed

Common mistakeDescribing a central server that holds the file. In BitTorrent the tracker only holds data about the peers; the pieces come from the peers.
O/N 2024 · 9618/32 · Q5(b) Explain 3 marks Explain the purpose and function of the Application Layer in the TCP/IP protocol suite.
ReminderUser interface, the programs that exchange data, protocols.

Any three: The Application layer provides access to all the programs that exchange data / interacts directly with the user used by, for example, web browsers and server software It communicates with, and enables data transfer to and from, the Transport layer / allows applications to access the services of the other TCP/IP layers It defines the protocols that any application uses to exchange data

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Identify 1 mark Name the protocol used by an email client to send a message to a mail server.
ReminderSending: SMTP.

SMTP (Simple Mail Transfer Protocol)

Describe 3 marks A user reads the same email on a phone, a tablet and a laptop. Name the protocol and describe how it makes this possible.
ReminderName it, then say where the message lives.

IMAP The email is kept on the mail server and not removed from it. Each device shows the server's copy, so all stay in sync.

Distinguish 2 marks Explain one difference between POP3 and IMAP.
ReminderWhere is the message afterwards?

POP3 downloads the message to the device and normally removes it from the server. IMAP leaves it on the server and keeps all the user's devices in sync.

Describe 3 marks Describe how BitTorrent allows a large file to be shared among many users.
ReminderPieces, peers, no central server.

The file is split into pieces. Users (peers) download pieces from several other peers at once and share the pieces they have, forming a swarm. No central server holds the file; a tracker holds data about the peers.

Explain 2 marks A web designer needs to upload 200 files to a web host. Name the most suitable protocol and give one reason.
ReminderWhich protocol is for files?

FTP It is designed for sending and receiving files over a network, so many files can be transferred to the server.

Identify 2 marks State the layer of the TCP/IP suite to which all six protocols HTTP, FTP, SMTP, POP3, IMAP and BitTorrent belong.
ReminderThe one the user's programs use.

The Application layer

Describe 3 marks An email client uses a pull protocol. Describe how it finds out that a new email has arrived.
ReminderWho starts, how often, and what happens to the message.

The email client connects to the mail server at set intervals (or when the user refreshes). It asks the server whether there are new messages in the mailbox. If there are, it retrieves them using POP3 or IMAP; until then they wait on the server.

Common mistakeSaying the server pushes each email to the user's device. With POP3 the client has to ask.
Explain 4 marks Explain how a photo can be sent by email using SMTP, which was designed for text.
ReminderDescribe, encode, send, decode.

MIME headers state the type of each part of the message. The binary photo is encoded as text, for example with Base64. SMTP sends the message, which now contains only text. The receiving client uses the headers to decode the text back into the photo.

Common mistakeCalling MIME the protocol that sends the email. SMTP sends it; MIME describes and encodes the content.

Top tips

  • Sending or receiving? SMTP sends. POP3 and IMAP receive. Say which in your answer.
  • Where does the mail end up? POP3: on the device, removed from the server. IMAP: stays on the server, every device in sync.
  • Is there a central server? HTTP and FTP: yes, a server. BitTorrent: no, peers share pieces.
  • Be specific about HTTP. It transfers web pages (hypertext documents). The S means secure.
  • All six are Application layer protocols. They are what programs use to exchange data.
