Algorithms, Flowcharts and Identifier Tables

Coursebook: Chapter 9 · Algorithm design and problem-solving · section 9.2 Algorithms

Algorithms, identifier tables with data types, the assignment, selection and iteration constructs, and drawing and reading program flowcharts, with animations, labs and the real Paper 2 questions from 2021 to 2026.

This page in five sentences

An algorithm is a sequence of steps that describes how to solve a problem. During design it can be written as numbered steps in words, drawn as a program flowchart, or written in pseudocode; a table called an identifier table lists every variable with a meaningful name, its data type, an explanation (purpose) and an example value. Every algorithm is built from three constructs: assignment (store a value in a variable), selection (choose with IF or CASE) and iteration (repeat with FOR, WHILE or REPEAT). A flowchart uses a terminator (START and END), a parallelogram for input and output, a rectangle for a process (assignment), a diamond for a decision with YES and NO exits, and a rectangle with double sides for a call to a subroutine; arrows show the flow. Exam questions ask you to complete an identifier table, tick the constructs in some pseudocode, draw a flowchart from a description, or turn a flowchart into pseudocode.

1 · Identifier tables

An identifier table is produced in the design stage and documents the variables to simplify program maintenance.

Choose a meaningful name (a name such as Temp or X does not say what the variable is used for, which is not good practice) and a data type from the example value: text in quotes STRING, a single character in single quotes CHAR, whole numbers INTEGER, numbers with a decimal point REAL, TRUE or FALSE BOOLEAN, a date DATE. An identifier table also holds the purpose, an example value, the number of elements of an array or length of a string, the value of constants and the scope (local or global).

Iteration (repetition)FOR Index ← 1 TO 10 ... NEXT Index; WHILE condition DO ... ENDWHILE (test first); REPEAT ... UNTIL condition (test last)

One line can contain more than one construct: REPEAT INPUT Value UNTIL Sales[4] > Value is both iteration and input; an IF with an assignment inside is selection and assignment; a FOR whose body calls a procedure is iteration and a subroutine call.

3 · Program flowcharts

Draw START, then the steps in order. A decision has two exits labelled YES and NO. A loop is drawn by an arrow that returns to an earlier box. A call to a function is shown as a call box or inside a decision. Variable declarations are not required. Example: input integers until zero is entered; sum and count the positive values and the negative values; output the two sums and two counts.

The same idea for "input integers until a negative value; count how many times IsPrime() returns TRUE":

Marks go for: initialising the counters before the loop; the input inside the loop; the loop test and exit; the correct calculations; and the output after the loop.

4 · Reading a flowchart as pseudocode

Work from START. Each decision with a loop-back becomes a WHILE (test first) or REPEAT loop; a decision with two forward paths becomes IF ... ELSE ... ENDIF; the call box becomes CALL.

Common ways to lose marks

  • Writing a variable called X or Temp in an identifier table: the name must say what it holds.
  • Using INTEGER for a decimal value or STRING for a date.
  • Initialising a counter inside the loop (it resets every time).
  • Using a diamond for an assignment or a rectangle for a decision.
  • Forgetting the YES and NO labels on a decision, or leaving a decision with only one exit.

Naming variables

A team reading `Total` knows what it means; `T1` forces them to look it up. That is why identifier tables ask for meaningful names.

Top tips

  • Meaningful names. Not X or Temp.
  • Type from the example value. Quotes: STRING. Decimal: REAL.
  • Initialise before the loop. Input inside it.
  • Decision: diamond, YES and NO. Input/output: parallelogram.
  • A line can hold several constructs. Tick every one.
  • WHILE: test first. REPEAT: test last. Name the loop type.
