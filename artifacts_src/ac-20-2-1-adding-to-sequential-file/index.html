Adding a Record to a Sequential File

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

Why a sequential file is rebuilt rather than appended to, and the copy-and-insert algorithm with its three cases; pseudocode and Python side by side, with a line-by-line animation.

This page in five sentences

A sequential file keeps its records in order of a key field, so a new record cannot simply be added to the end: it has to go in its key position. A text file cannot have a line pushed in the middle, so the program makes a new version of the file. It reads the old file one record at a time and copies each to a new file, and when it reaches the first record whose key is larger than the new key it writes the new record first. If no record is larger, the new record is written after the loop, at the end. Finally the old file is deleted and the new file renamed to take its place.

1 · Why not just append?

Appending 130 to a file that holds 101, 115, 142, 160 gives 101, 115, 142, 160, 130. The file is no longer in key order, so it is no longer sequential: a search that stops when it passes the key would now give wrong answers. The record has to be placed between 115 and 142.

2 · The record format used on this page

Each record is one line, as on the previous page. The key is the first three characters: every StudentID has exactly 3 digits, so the key can be cut out with LEFT(Line, 3) in pseudocode, or Line.split(",")[0] in Python.

101,Ana,58115,Bo,66142,Cy,71160,Di,49

3 · The algorithm

The new record is NewLine and its key is NewKey. Placed remembers whether the new record has been written yet, so it is written only once.

Python

import osNewKey = 130NewLine = "130,Dev,64\n"Placed = False Old = open("Students.txt", "r")New = open("NewStudents.txt", "w")for Line in Old:    Key = int(Line.split(",")[0])    if not Placed and Key > NewKey:        New.write(NewLine)        Placed = True    New.write(Line)if not Placed:    New.write(NewLine)Old.close()New.close()os.replace("NewStudents.txt", "Students.txt")

Pseudocode (exam style)

NewKey <- 130NewLine <- "130,Dev,64"Placed <- FALSE OPENFILE "Students.txt" FOR READOPENFILE "NewStudents.txt" FOR WRITEWHILE NOT EOF("Students.txt")   READFILE "Students.txt", Line   Key <- STR_TO_NUM(LEFT(Line, 3))   IF NOT Placed AND Key > NewKey THEN      WRITEFILE "NewStudents.txt", NewLine      Placed <- TRUE   ENDIF   WRITEFILE "NewStudents.txt", LineENDWHILEIF NOT Placed THEN   WRITEFILE "NewStudents.txt", NewLineENDIFCLOSEFILE "Students.txt"CLOSEFILE "NewStudents.txt"// delete Students.txt, then rename NewStudents.txt to Students.txt
Two files are open at onceThe old file is opened FOR READ and the new file FOR WRITE. Both must be closed before the old one is replaced. Python's os.replace() does the delete and rename in one step.

4 · What each part does

PartJob
Key > NewKeyTrue at the first record that should come after the new one. Records with a smaller key are copied untouched
PlacedStops the new record being written again at every later record
New.write(Line)Copies the record just read. It runs every time round the loop, after any insertion
IF NOT Placed after the loopCatches the case where the new key is larger than every key in the file
Replace the fileThe new version becomes the file the program uses from now on

5 · The three cases

New keyWhere it is writtenWhich line does it
Smaller than the first key (100)Before the first recordThe IF inside the loop, on the very first record
Between two keys (130)Between themThe IF inside the loop, at the first larger key
Larger than every key (200)After the last recordThe IF NOT Placed after the loop

6 · The same pattern changes and deletes records

Copy every record to a new file, but leave out the record to delete, or write a changed version of it instead. For a small file, an alternative is to read the records into an array, insert the new record in the right position, and write the whole array back with FOR WRITE.

7 · Common ways to lose marks

  • Appending the record. That breaks the key order.
  • Opening the same file for reading and writing at once. The update is done through a second file.
  • Writing the new record every time the key is larger. Placed must stop it after the first.
  • Forgetting the check after the loop, so a record with the largest key is lost.
  • Leaving out the copy of the record just read, so existing records disappear.
  • Forgetting to close both files before replacing the old one.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A payroll master file

Employees are kept in employee number order. When someone joins, the program copies the old file to a new one and writes the new employee at the right place, so the file is still in order for the next payroll run.

Exam use: sequential update by copying to a new file.

Overnight batch processing

The day's changes are collected in a transaction file, sorted by key, and merged with the master file in a single pass from top to bottom to produce a new master file.

Exam use: sequential files suit batch processing: one pass, old file in, new file out.

A bank statement run

At the end of the month every account is read in account order and a line is written for each to a new file. The old file is kept as a backup until the new one is checked.

Exam use: the old and new version both exist during the update.

Why a search can stop early

A library file is in order of book number. A search for number 5120 can stop as soon as it reads 5121, because 5120 would have come before it.

Exam use: a sequential search stops when the key has been passed.

Top tips

  • Never append. A new record goes in its key position, so the file is rebuilt.
  • Two files. READ the old, WRITE the new, then replace the old with the new.
  • Use a flag. Placed stops the new record being written more than once.
  • Cover the end case. IF NOT Placed after the loop handles the largest key.
  • Copy what you read. Every old record is written, after any insertion.
  • Say 'a new version of the file'. This phrase earns the mark in descriptions.
