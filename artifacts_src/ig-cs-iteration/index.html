Iteration

Repeating instructions with FOR, WHILE and REPEAT ... UNTIL loops.

The big idea

Iteration repeats a block of code. A FOR loop repeats a set number of times. WHILE and REPEAT loops repeat until a condition says stop.

8.1.4 Iteration

Iteration means repeating a set of instructions. The repeated lines are called a loop. Loops save you from writing the same lines again and again, and let a program repeat something an unknown number of times.

FOR: count-controlled

Use a FOR loop when you know how many times to repeat. A loop counter changes by itself each time, from the start value up to the end value. STEP changes the size of the jump.

Python's range()In Python, range(1, 5) goes 1, 2, 3, 4. It stops before the end value. Pseudocode's 1 TO 4 includes 4, so the Python end value is one more. For a step use range(0, 11, 2).

WHILE: condition tested first

A WHILE loop repeats while a condition is TRUE, and tests it before each repeat. If the condition is FALSE at the start, the body never runs. Something inside the loop must change the condition, or it will never stop.

REPEAT ... UNTIL: condition tested last

A REPEAT loop runs the body, then tests the condition at the end. It repeats until the condition becomes TRUE, so the body always runs at least once. That suits asking for input again until it is valid.

Python has no REPEATPython has no post-condition loop. The usual way is while True: with a break when the condition is met.

Infinite loopsA loop whose condition never changes runs forever. In a WHILE loop, always check that something inside it moves the condition towards FALSE (for example Number ← Number - 1).

A loop can also sit inside another loop. This is called a nested loop: the inner loop runs completely for each repeat of the outer loop.

A playlist on repeat

The player runs through each song in turn until it gets to the end of the playlist.

Exam use: a FOR loop, because the number of songs is known.

A PIN prompt

The ATM asks for your PIN again until it is right, or the card is blocked.

Exam use: REPEAT ... UNTIL: you must be asked at least once, and then until the PIN is valid.

A game loop

While the player still has lives, the game keeps running frames. When lives reach 0 the game stops.

Exam use: a WHILE loop, tested before each repeat.

Q1 State 2 marks State the difference between a count-controlled loop and a condition-controlled loop.
ReminderOne repeats a set number of times. The other repeats until something is true.
Count-controlled: repeats a set number of times (known in advance), for example FOR Condition-controlled: repeats while / until a condition is met (the number of repeats may not be known), for example WHILE or REPEAT.
Common mistakeSaying a FOR loop "has a condition". It has a counter, not a test of a condition.
Q2 Write 3 marks Write pseudocode to output the numbers 1 to 20.
ReminderFOR, a counter, an output.
FOR Count ← 1 TO 20 OUTPUT Count inside the loop NEXT Count
FOR Count ← 1 TO 20    OUTPUT CountNEXT Count
Common mistakeUsing 1 TO 19 or 0 TO 20. Check the first and last values.
Q3 Complete 4 marks Complete the trace table for the code, and state the output.
Number ← 3WHILE Number > 0 DO    OUTPUT Number    Number ← Number - 1ENDWHILEOUTPUT "Go!"
ReminderTest the condition each time, before the body.
Number: 3, 2, 1, 0 Output: 3 2 1 Condition is FALSE when Number is 0, so the loop stops then "Go!" is output after the loop
Common mistakeOutputting 0. When Number is 0 the condition 0 > 0 is FALSE, so the body does not run.
Q4 Write 4 marks Write pseudocode to keep asking for a password until the user types "open". Output "Welcome" when it is right.
ReminderIt must ask at least once, so REPEAT ... UNTIL fits.
REPEAT INPUT Password inside the loop UNTIL Password = "open" OUTPUT "Welcome" after the loop
REPEAT    INPUT PasswordUNTIL Password = "open"OUTPUT "Welcome"
Common mistakeWriting UNTIL Password <> "open". UNTIL stops the loop when the condition is TRUE.
Q5 State 2 marks State which type of loop always runs its body at least once, and explain why.
ReminderThink about where the condition is tested.
REPEAT ... UNTIL (post-condition loop) because the condition is tested at the end, after the body has run once.
Common mistakeChoosing WHILE. A WHILE loop tests first, so it may never run.
Q6 Rewrite 3 marks Rewrite the WHILE loop as a REPEAT ... UNTIL loop that gives the same output.
Number ← 1WHILE Number <= 5 DO    OUTPUT Number    Number ← Number + 1ENDWHILE
ReminderReverse the condition: WHILE continues while TRUE, UNTIL stops when TRUE.
REPEAT in place of WHILE ... DO and UNTIL in place of ENDWHILE Condition reversed: UNTIL Number > 5 (or >= 6) Body unchanged: OUTPUT Number and Number ← Number + 1
Number ← 1REPEAT    OUTPUT Number    Number ← Number + 1UNTIL Number > 5
Common mistakeCopying the WHILE condition into UNTIL. Reverse it (<= becomes >).
Q7 Write 3 marks Write pseudocode to input 10 numbers and output each one doubled.
ReminderA FOR loop with the INPUT inside it.
FOR Count ← 1 TO 10 ... NEXT Count INPUT Number inside the loop OUTPUT Number * 2 inside the loop
FOR Count ← 1 TO 10    INPUT Number    OUTPUT Number * 2NEXT Count
Common mistakePutting INPUT before the loop, so only one number is read.
Q8 Write 5 marks Write pseudocode to input 20 marks. For each mark, output "Pass" if it is 50 or more, otherwise "Fail".
ReminderA loop around a selection.
FOR Count ← 1 TO 20 INPUT Mark inside the loop IF Mark >= 50 THEN OUTPUT "Pass" ELSE OUTPUT "Fail" ENDIF and NEXT Count in the right places (ENDIF inside the loop)
FOR Count ← 1 TO 20    INPUT Mark    IF Mark >= 50      THEN        OUTPUT "Pass"      ELSE        OUTPUT "Fail"    ENDIFNEXT Count
Common mistakePutting NEXT Count inside the IF, which breaks the structure.
Q9 Explain 2 marks The code below never stops. Explain why, and how to fix it.
Number ← 5WHILE Number > 0 DO    OUTPUT NumberENDWHILE
ReminderDoes anything inside the loop change Number?
Number is never changed, so Number > 0 is always TRUE (infinite loop) Fix: add Number ← Number - 1 inside the loop.
Common mistakeSaying the condition is wrong. The condition is fine. Nothing makes it become FALSE.

Top tips

  • FOR when you know how many times. WHILE and REPEAT when you do not.
  • WHILE tests first and may never run. REPEAT tests last and always runs at least once.
  • WHILE repeats while TRUE. REPEAT stops when TRUE. Reverse the condition when you convert.
  • Check the first and last value of a FOR loop. 1 TO 10 runs 10 times.
  • Something inside a WHILE loop must change the condition, or it runs forever.
  • Python's range(1, 11) gives 1 to 10. The end value is not included.
