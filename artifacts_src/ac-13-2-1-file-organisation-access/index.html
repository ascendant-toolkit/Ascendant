File Organisation and Access

Coursebook: Chapter 13 · Data representation, section 13.2 File organisation and access

Serial, sequential and random file organisation, sequential and direct access, how a record is found in each, choosing a method for a problem; animations, a search simulator and the real 9618 questions from 2021 to 2026.

This page in five sentences

File organisation is how the records are arranged in a file: serial files hold records in the order they were added, sequential files hold them in order of a key field, and random files place each record at a location worked out from its key. File access is how a program finds a record: sequential access reads the records one after another from the start, and direct access jumps straight to a record without reading the others. Serial and sequential files are normally accessed sequentially; random files are accessed directly, and a sequential file can be accessed directly if it has an index. You choose a method by thinking about how the file is used: adding, searching, updating and processing in bulk. The pseudocode commands that do this are on the chapter 20 file processing page.

Typical usesLogs, temporary transaction files, backups, batch processing, bills and payrollMaster files processed in batches, ordered payroll or bill filesDatabases, booking systems, operating system file management
  • In both serial and sequential files the records are stored one after the other and have to be accessed one after the other.
  • In a sequential file the position depends on the key. In a serial file it depends only on when the record was added.
  • A random file can have empty locations, and its key is turned into a location by a hashing algorithm (next page).

2 · The two methods of access

Sequential access

Start at the beginning of the file and check each record in turn (linearly) until the record is found, the end of the file is reached, or (in a sequential file) the key of the current record is greater than the key you are looking for.

OrganisationHow sequential access finds record K
SerialCheck every record from the start until K is found or all have been checked. It cannot stop early, because the file is not in key order
SequentialCheck records in key order until K is found, or the key of the current record is larger than K, which means K is not in the file

Direct access

A record is found without reading the other records, using its key field to work out where it is.

OrganisationHow direct access finds record K
SequentialAn index of all the key fields is kept. The index is searched for the key, and gives the address in the file of the record, which is then read directly
RandomA hashing algorithm is applied to the key to calculate the address; the record is read from there. If it is not there, a collision method (such as a linear search from that point) is used
Which method?A record referenced by a unique address on a disk-type medium: direct access. A bank storing its records in ascending order of account number and processing them all: sequential access.

3 · Choosing an organisation

If the program mostly...UseBecause
Adds records as they arrive and processes everything later (logs, backups, a payroll run)SerialAppending is fast and no ordering is needed
Processes every record in key order in a batchSequentialOrdered records suit report and merge jobs, and a search can stop early
Looks up one record at a time, quickly, in a very large file (bookings, accounts)RandomDirect access avoids reading the other records

4 · In code

Text files (serial and sequential) are read with READFILE in a loop until EOF. Random files use SEEK and GETRECORD or PUTRECORD.

# sequential access to a sequential (key-ordered) text filedef Find(Key):    File = open("Accounts.txt", "r")    for Line in File:        Record = int(Line.strip())        if Record == Key:            File.close()            return True              # found        if Record > Key:            break                    # passed the key: not in the file    File.close()    return False

5 · Common ways to lose marks

  • Describing a serial file as "in order". It is in the order the records were added (chronological); a sequential file is in key order.
  • Saying random means "stored anywhere at random". A random file uses the key to calculate where a record goes.
  • Forgetting that sequential access starts at the beginning of the file.
  • For a sequential file, not saying the search can stop when the key has been exceeded.
  • For direct access on a sequential file, leaving out the index; on a random file, leaving out the hashing algorithm.
  • Writing a definition of the organisation when the question asks for an example of where it is used (the mark scheme says not to allow that).

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A data-logging file

A weather station adds a reading every minute to a file. The readings are stored in the order they were taken and processed at the end of the day, so a serial file fits.

Exam use: serial: chronological order, new records appended to the end.

A payroll run

Every employee's pay is calculated once a month by reading the employee file from start to finish, in order of employee number. A sequential file is processed in a batch.

Exam use: sequential: ordered by a key; accessed one after another.

An airline booking system

Seat records are fetched and updated in a moment by flight and seat number, among millions of records. The key is turned into a location, and the record is read directly.

Exam use: random organisation with direct access using a hashing algorithm.

A bank's overnight batch

Account records stored in ascending order of account number are matched against the day's transactions, which are in the same order, in one pass.

Exam use: sequential access suits batch processing of an ordered file.

A backup

A backup copies every file from the start to the end in one go, without needing any ordering or fast lookup.

Exam use: serial files are good for simple storage that is read in full.

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Distinguish 2 marks Distinguish between a serial file and a sequential file.
ReminderOrder of the records.

A serial file stores records in the order they were added (chronological), with new records appended to the end. A sequential file stores records in order of a key field, with new records inserted in the correct position.

Explain 3 marks Explain why a random file is better than a serial file for a booking system with millions of records.
ReminderHow a record is found.

In a serial file records must be read one after the other from the start until the one wanted is found. In a random file a hashing algorithm turns the key into the address of the record. The record is read directly without reading the others, so access is much faster.

State 2 marks A sequential file holds the keys 5, 12, 20, 33, 47, 60. A program searches it for 25. State the keys read and why the search stops.
ReminderStop when the current key exceeds the target.

5, 12, 20 and 33 are read the search stops at 33 because it is greater than 25, so 25 is not in the file

Common mistakeReading to the end of the file. A sequential file lets the search stop once the key is passed.
Outline 2 marks Outline how a new record is added to a sequential file.
ReminderWhy can it not simply be appended?

The file cannot just be appended to, because the records must stay in key order. A new version of the file is created, with the new record written in the correct position.

Choose 3 marks For each situation, name the file organisation and access method: (a) a log of every sensor reading, processed at the end of the day; (b) a flight booking record fetched by booking reference.
ReminderSerial or random; sequential or direct.

(a) serial organisation with sequential access (read from the start to the end) (b) random organisation with direct access

Top tips

  • Serial is chronological; sequential is key order. Keep these apart. Both are read one record after another.
  • Start at the beginning. Sequential access always begins at the start of the file.
  • Mention the stopping condition. Found, end of file, or (sequential) key exceeded.
  • Direct access needs a tool. An index for a sequential file; a hashing algorithm for a random file.
  • An example is not a definition. When the question asks where it is used, name a use such as batch processing or a booking system.
  • Match the method to the use. Whole-file batch: sequential access. One record quickly: direct access.
