Recursion in Action: Lists and Strings, One Item at a Time

Deal with the first item, then let a recursive call deal with the rest. This is the pattern behind the most common Paper 4 recursion questions: totalling an array, counting a value, counting vowels in a string, and rewriting a loop as a recursive function.

The pattern

An array, a queue or a string is a list of items. Any job done by looping over a list can be described like this: handle the first item, then do the same job on the rest of the list. “The rest of the list” is a smaller list, so the job calls itself on it.

When there is nothing left, the job is finished. That is the base case, and the answer it gives is the starting value of the running total: 0 for a sum or a count.

From loop to recursion

Past papers ask you to rewrite a loop-based function as a recursive one, or to write a recursive function from a description. Each part of the loop has a matching part in the recursive version.

In the loop versionIn the recursive version
Running total starts at 0The base case returns 0 (nothing left to add)
Loop stops when the data runs outThe base case test: the index has gone past the last item
Loop body: use the current itemThe general case: use Items[Index]…
Index moves on by 1 each pass…and call again with Index + 1
Total ← Total + itemRETURN item + (the call for the rest)

Example 1: total of an array

Indexes start at 0 here. Index says which item is being handled; everything from Index onward is “the rest”.

  1. Base case: Index > Last. There is no item at this index, so there is nothing to add. Return 0.
  2. General case. Add the current item, Numbers[Index], to the total for the rest, which is Total(Numbers, Index + 1, Last). The index moves towards the end each call.
  3. The addition waits. As in compound interest, the + cannot be done until the call below has returned. The calls wind down to the end of the list, and the additions happen as they unwind.

Example 2: counting items that match

Now a call may or may not add 1. If the current item matches, return 1 plus the count for the rest; if not, return the count for the rest unchanged. This is O/N 2025 Paper 4 (counting how many times a value is in an array).

Example 3: strings

A string is a list of characters, so the same shape works. Counting vowels (O/N 2023, Paper 4): look at the current character, add 1 if it is a vowel, and call again for the rest of the string. The base case is when the index reaches the length of the string. IsVowel here stands for a test that the character is a, e, i, o or u.

Two ways to say “the rest”Some questions pass a moving index, as here. Others pass a smaller copy of the data each time (a string with its first character removed, or an array with its first element dropped, plus a count of the elements left). Both work. The base case is then an empty string or zero elements.

Cost

A list of n items makes n + 1 calls (one for each item, plus the base case) and the stack gets n + 1 frames deep. A loop does the same work with no stack. For a very long list the recursive version could overflow the stack, so real programs would normally use a loop for this job. In an exam, recursion is used to show you can write and trace it.

Flashcards

General descriptions of where the same pattern appears. Numbers are illustrative only.

Adding up a till roll

Adding up a list of prices is “this price plus the total of the others”. That is the Total function, and the empty list totals 0.

Exam use: a plain example of a recursive sum, with a base case that returns 0.

Counting words or characters

Counting how many times a letter appears in a text, or how many words contain a given letter, follows the counting pattern: match adds 1, non-match adds nothing.

Exam use: the counting function from O/N 2025, and the vowels function from O/N 2023.

Checking a palindrome

A word reads the same both ways if its first and last letters match and the word between them is also a palindrome. Each call strips a letter from both ends. A word with 0 or 1 letters is the base case.

Exam use: a good “write a recursive function” practice question using the same “smaller copy of the data” idea.

Reversing a string

The reverse of a word is the reverse of everything after its first letter, followed by the first letter. The empty string reverses to itself.

Exam use: shows recursion where the work is done on the way back up, since the first letter is added last.

Processing a queue or stack

Totalling the items in a queue, as in O/N 2022, walks along the queue from one end. A linked list is processed the same way: handle the node, then follow the pointer to the rest.

Exam use: links recursion to the ADTs in 19.1.

Why real programs often use a loop

For a list of a million items the recursive version would need a million frames and could overflow the stack. A loop does the same job in constant memory. Recursion earns its place when the problem splits into several smaller problems, as with trees.

Exam use: supports a “when is recursion beneficial?” answer: it is clearer for self-similar structures, not faster for flat lists.

FUNCTION IterativeOutput(Start : INTEGER) RETURNS INTEGER
   DECLARE Total : INTEGER
   Total ← 0
   FOR Count ← Start - 1 TO HeadPointer STEP -1
      Total ← Total + Queue[Count]
   NEXT Count
   RETURN Total
ENDFUNCTION
ReminderA loop with a running total becomes: base case at the end of the data, then “this item + the recursive call for the rest”.

Six marks: function header taking a parameter; check whether at the start of the queue; return the last value in the queue; otherwise add the value to the result of the recursive call; recursive call with the pointer reduced by 1; return the final total.

def RecursiveOutput(Start):
    if Start == 0:
        return Queue[Start]
    else:
        return Queue[Start] + RecursiveOutput(Start - 1)

print(RecursiveOutput(TailPointer - 1))

The call passes TailPointer - 1, the position of the last item, so the recursion works from the tail back to the head at position 0.

FUNCTION IterativeVowels(Value : STRING) RETURNS INTEGER

   DECLARE LengthString : INTEGER
   DECLARE FirstCharacter : CHAR
   Total ← 0

ENDFUNCTION
ReminderBase case: empty string returns 0. General case: look at the first character, then recurse on the rest of the string.

Six marks: a recursive call; function header taking a string, returning an integer; base case: length is 0, return 0; extract the first character and check whether it is a vowel; vowel: return 1 + the recursive call on the string with one fewer character; not a vowel: return the recursive call with one fewer character.

def recursive_vowels(value):
    if len(value) == 0:
        return 0
    if value[0] in "aeiou":
        return 1 + recursive_vowels(value[1:])
    return recursive_vowels(value[1:])

As program code (Python):

def RecursiveValue(Number, ToFind):
    if Number == 0:
        return 0
    else:
        if ToFind % Number == 0:
            return Number + RecursiveValue(Number - 1, ToFind)
        else:
            return RecursiveValue(Number - 1, ToFind)

print(RecursiveValue(50, 50))

One mark for each of the five gaps, one for the recursive calls both accurate and in the right places, one for the rest of the function with nothing extra. RecursiveValue(50, 50) returns 93, the total of the factors 1 + 2 + 5 + 10 + 25 + 50.

def count_item(numbers, index, last, target):

Top tips

  • Base case = nothing left. It returns the starting value: 0 for a sum or count.
  • Each call handles one item, then calls itself for the rest with the index moved on by 1 (or the data made one item smaller).
  • Always move towards the base case. A recursive call that repeats the same Index never stops.
  • Counting has two branches. A match returns 1 + the call; a non-match returns the call alone. Both need a RETURN.
  • Rewriting a loop: counter → parameter, starting total → base case, loop body → general case.
  • Check the first index. The call from the main program must start where the loop started (0 or 1, or the head pointer).
  • In a trace table, write the waiting sum going down and the numbers coming up. The base case row has a Return value; calls above it do not until unwinding.
  • n items → n + 1 calls and n + 1 frames. The extra one is the base case.
  • Strings: check whether the question uses MID with a start position of 0 or 1, and whether it passes an index or a shorter string.
  • Procedures return nothing. A recursive PROCEDURE has no return column and no unwinding work, unless something is done after the call.
