File Processing: Text, Serial, Sequential and Random Files

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

Opening, reading, writing and closing text files; serial, sequential and random files; SEEK, GETRECORD and PUTRECORD; Python for Paper 4; animations, labs and the real Paper 3 and Paper 4 file questions.

This page in five sentences

A program's variables disappear when it ends, so data that must last is stored in a file on secondary storage. To use a file you open it in a mode (read, write, append, or random), read or write one record or line at a time, and then close it. A text file is processed from the start in order: serial files hold records in the order they were added and sequential files hold them in key order, so both are read one record after another until the end of the file. A random file lets the program jump straight to a record: SEEK moves to a position, then GETRECORD reads it or PUTRECORD writes it. Paper 3 asks you to complete this pseudocode; Paper 4 asks you to read and write files in Python.

Always closeEvery file that is opened must be closed, in an appropriate place (after the loop, not inside it). Closing a written file makes sure the data is actually saved. Python's with open(...) as f: closes it for you; the mark scheme accepts it.

2 · Reading a text file into an array

Each line of a text file is one string. Convert it to the type you need (int(Line)), and remove the newline with strip() if you will compare or split it.

DataArray = []                                   # 25 elements of type integerDataFile = open("Data.txt", "r")for Line in DataFile:                            # one pass for each line, until the end of file    DataArray.append(int(Line))DataFile.close()

When a record is spread over several lines, read the lines in the order they were written, or keep the fields on one line and split them:

File = open("HighScore.txt", "r")for x in range(0, 10):    FileData[x][0] = File.readline()[:3]        # line 1: three-character player name    FileData[x][1] = File.readline().strip()    # line 2: the scoreFile.close() # a record on one line, fields separated by spaces:   "Aria True 12 3"Parts = Line.strip().split(" ")                 # ["Aria", "True", "12", "3"]

4 · Serial, sequential and random files

FileHow records are storedHow you find a recordAdding a record
SerialIn the order they were added, with no ordering on a keyRead from the start until found (or to the end to process all)Append to the end
SequentialIn order of a key fieldRead in order; can stop once the key has been passedWrite a new file, inserting the record in the right place
RandomAt an address calculated from the key (position, or a hash)Go straight to the address with SEEK, then GETRECORDSEEK to the address, then PUTRECORD

For a serial or sequential file the program loops: open, repeat READFILE until EOF, close. Processing a file means doing something to each record in that loop (copying, totalling, searching). To delete or change a record in a text file, write every record to a new file, changing or leaving out the one required.

OPENFILE "ActiveFile.txt" FOR READOPENFILE "ArchiveFile.txt" FOR WRITEWHILE NOT EOF("ActiveFile.txt")   READFILE "ActiveFile.txt", Account   IF Account = "" THEN      WRITEFILE "ArchiveFile.txt", "Account not present"   ELSE      WRITEFILE "ArchiveFile.txt", Account   ENDIFENDWHILECLOSEFILE "ActiveFile.txt"CLOSEFILE "ArchiveFile.txt"

5 · Random files: SEEK, GETRECORD and PUTRECORD

A random file is opened with FOR RANDOM. Each record has the same size, so the program can work out where record number n starts and jump there.

CommandWhat it does
OPENFILE "Stock.dat" FOR RANDOMOpens the file for reading and writing at any position
SEEK "Stock.dat", LocationMoves the file pointer to the record at that location
GETRECORD "Stock.dat", ItemReads the record at the pointer into the variable
PUTRECORD "Stock.dat", ItemWrites the variable as the record at the pointer
OPENFILE "StockList.dat" FOR RANDOMOUTPUT "Enter a location between 1 and 500: "INPUT LocationSEEK "StockList.dat", Location        // always SEEK before GETRECORD or PUTRECORDGETRECORD "StockList.dat", ItemIF Item = "" THEN   OUTPUT "This record is missing."ELSE   OUTPUT "The item in stock is ", ItemENDIFCLOSEFILE "StockList.dat"

The location is often calculated from the key with a hash function (for example the account number MOD the number of slots), so a record can be found without searching: Location ← Hash(Customer.AccountNumber), SEEK AccountFile, Location, GETRECORD AccountFile, Customer. A random file has empty locations, which is why a record that reads back as "" means "nothing stored here".

TaskPattern
Read a record at a known placeOPEN RANDOM, SEEK, GETRECORD, CLOSE
Store a record at a known placeOPEN RANDOM, SEEK, PUTRECORD, CLOSE
Find the first empty slotloop: SEEK, GETRECORD, if empty then PUTRECORD and stop, else add 1 to the location
Copy records from one file to anotherFOR each position: SEEK, GETRECORD from the first file, SEEK, PUTRECORD in the second

6 · Common ways to lose marks

  • Forgetting CLOSEFILE, or closing inside the loop, or before the last read.
  • Using FOR WRITE when the data must be added to what is already there (that is APPEND), or FOR READ on a file you also write to.
  • Leaving out SEEK before GETRECORD or PUTRECORD in a random file.
  • Not converting what was read: a line is a string. Use int() before adding or comparing as numbers.
  • Not removing the newline, so the data never equals what it should.
  • Writing a number without str(), or forgetting the new line, so everything ends up on one line.
  • Looping a fixed number of times when the question says "until the end of the file".
  • In Paper 4, forgetting the exception handling mark for opening or reading the file (see the next page).

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A high score table

A game saves the top ten names and scores in a text file when it closes and reads them back when it starts. Writing replaces the old file with the new table.

Exam use: WRITE overwrites the file; read it back in the same order it was written.

A log of events

A server adds one line to a log every time something happens. The program opens the file in append mode so earlier lines are never lost.

Exam use: APPEND adds to the end of an existing file.

A bank's account file

Millions of account records are stored in a random file. The account number is turned into a location by a hash function, so one record can be fetched without reading the rest.

Exam use: random access: SEEK to the location and GETRECORD.

A payroll run

A program reads each employee's hours from a file, line by line, calculates pay and writes a payslip line to a new file. It stops at the end of the file.

Exam use: serial processing: read until EOF, process, write, close.

Backing up a file

A copy of every record is written one at a time from the live file to a stored file. Anything that is blank is replaced with a standard message.

Exam use: copying with SEEK, GETRECORD and PUTRECORD for random files, or READFILE and WRITEFILE for text.

Sequential The new record cannot just be added to the end: the file must be rewritten (copied) with the record inserted in the correct position.

Top tips

  • Match the file to the command. Text files: READFILE and WRITEFILE. Random files: SEEK with GETRECORD and PUTRECORD.
  • Open once, close once. OPENFILE before the loop, CLOSEFILE after it. Close every file you opened.
  • SEEK first. In a random file, SEEK to the position before every GETRECORD and PUTRECORD.
  • Pick the right mode. READ to read. WRITE replaces. APPEND adds. RANDOM to jump about.
  • Check what the loop depends on. 'Until the end of the file' is EOF. A set number of records is a FOR loop.
  • Convert what you read. Lines are strings: int(Line), and strip() the newline.
  • Convert what you write. write() takes a string: str(value) + "\n".
