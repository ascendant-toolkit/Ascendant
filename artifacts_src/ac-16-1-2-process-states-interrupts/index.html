Process States and Interrupt Handling

Coursebook: Chapter 16 · System software, section 16.1 Purposes of an operating system

Processes, the running, ready and blocked states and the changes between them, and how the kernel handles interrupts for low-level scheduling; animations, labs and the real Paper 3 questions from 2023 to 2025.

This page in five sentences

A process is a program that is being executed, together with its data and the values in the registers. A process is always in one of three states: running (using the CPU), ready (able to run and waiting for the CPU) or blocked (waiting for an input or output operation or some other event). A running process moves to ready when its time slice runs out or a higher-priority process pre-empts it, and to blocked when it must wait for I/O; a blocked process becomes ready when the event it waited for has happened. The kernel acts as the interrupt handler: it saves the state of the running process, uses an interrupt table to find the right routine, runs it, then restores the state. This is how low-level scheduling reacts to events such as a timer or a finished disk transfer.

1 · Processes and multi-tasking

A program is a set of instructions stored on disk. A process is a program that has been loaded and is being run. With multi-tasking there may be many processes at once but, on a processor with one core, only one can be using the CPU at any instant. The OS keeps a record of each process (its state, the program counter, the register contents, its priority) so that a process can be stopped and later carry on exactly where it left off.

2 · The three process states

StateMeaningExample
RunningThe CPU has been allocated and the process is being executed.A word processor is checking spelling.
ReadyThe process could run and is waiting in the ready queue for a slice of CPU time.A music player waiting its turn, or one that was pre-empted by a higher-priority process.
BlockedThe process is waiting for an I/O operation or other event to be completed, so it cannot run even if the CPU is free.A program waiting for the user to type, or for a file to load from disk.

Changing state

  • Ready → running: the scheduler picks the process and gives it the CPU.
  • Running → ready: the process's time slice has expired (round robin), a higher-priority process arrives in the ready queue and pre-empts it, or an interrupt arrives and the running process is pre-empted. The process is not waiting for anything: it could run again at once.
  • Running → blocked: the process needs input or output that will take time, so it waits for the event.
  • Blocked → ready: the event has happened (the I/O is complete); the process joins the ready queue. It never goes straight from blocked to running.

3 · Interrupts and the kernel

An interrupt is a signal to the processor that something needs attention at once: a timer, a key press, a disk finishing a transfer, a hardware fault. The kernel acts as the interrupt handler:

  1. The kernel receives a signal when the interrupt is generated.
  2. It checks the priority of the interrupt against the process that is running. If the interrupt has higher priority the system enters kernel mode.
  3. It saves the state of the interrupted process (the contents of the registers, including the program counter) on the kernel stack.
  4. It consults the interrupt dispatch table (also called the interrupt vector table, IVT, or interrupt descriptor table, IDT), which maps each interrupt to its interrupt service routine (ISR), and runs that routine.
  5. When the ISR has finished the kernel restores the state of the process, which carries on, or the scheduler picks another process.

Interrupts and low-level scheduling

The low-level scheduler (dispatcher) is the part of the OS that moves processes between the ready and running states. It is driven by interrupts: a timer interrupt marks the end of a time slice, an I/O interrupt tells the OS that a blocked process can become ready, and a priority interrupt can pre-empt the running process. Handling the interrupts by priority ensures that critical events are dealt with without delay.

4 · Common ways to lose marks

  • Saying a process goes from blocked straight to running. It goes to ready first and waits for the scheduler.
  • Describing "ready" as waiting for input. That is blocked; ready means able to run, waiting for the CPU.
  • Describing what the interrupt is for, instead of what the kernel does: receive the signal, check priority, save the state, look up the ISR, restore the state.
  • Forgetting that the state of the interrupted process has to be saved and restored.
  • Giving only "time ran out" for running to ready. Other valid reasons: a higher-priority process arrives, or an interrupt pre-empts it.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A download that stalls

A program waiting for data from the network is blocked. It does not use the CPU while it waits, so other programs run faster.

Exam use: blocked means waiting for an event.

Typing while a video plays

Each key press is an interrupt. The kernel saves the video player's state, passes the key to the editor, then lets the video carry on.

Exam use: the kernel saves and restores state around an interrupt.

The spinning wheel

A program that stops responding is usually waiting for an event that never arrives, so it stays blocked.

Exam use: a blocked process cannot run until its event happens.

Fire alarm in a building

The fire alarm interrupts everything. Work stops, people follow the alarm routine, and normal work resumes afterwards. The higher-priority event wins.

Exam use: interrupts are handled by priority.

A queue at a till

People waiting in the queue are ready; the one being served is running; a person who has gone to find the price of something is blocked until they come back.

Exam use: ready, running and blocked.

Top tips

  • Three states. Running, ready, blocked. Use those words.
  • Ready can run; blocked cannot. Ready is waiting for the CPU. Blocked is waiting for an event.
  • Blocked goes to ready. Never straight to running.
  • Running to ready: three causes. Time slice ends, higher priority arrives, interrupt.
  • Interrupt handling by the kernel. Signal, priority check, save state, table lookup, ISR, restore.
  • Name the table. Interrupt dispatch / vector table (IDT or IVT).
