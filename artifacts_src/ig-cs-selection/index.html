Selection

Making decisions in a program: IF, IF ... ELSE, nested IF and CASE OF.

Definition: selection

Selection is when a program chooses between routes, using a condition that is TRUE or FALSE. A full definition has three parts:

1
A choice between two (or more) routes
Different lines of code could run.
2
Based on a condition
A test, such as Battery < 20.
3
Resulting in TRUE or FALSE
TRUE runs one route. FALSE runs another route, or skips it.

Weak definitions: what is missing?

These would not earn full marks. Which of the three parts is each one missing, or getting wrong?

✗
"Selection is when the user chooses an option."
Missing: it is the program that chooses, and there is no condition or TRUE/FALSE (parts 2 and 3).
✗
"Selection is when a program makes a decision."
Missing: it never says the decision is based on a condition that is TRUE or FALSE (parts 2 and 3).
✗
"Selection is when a program repeats lines until a condition is met."
Wrong: that is iteration (a loop). Selection does not repeat anything.

Example

Battery ← 15IF Battery < 20  THEN    OUTPUT "Low battery"  ELSE    OUTPUT "Battery OK"ENDIF

Only one route runs each time.

8.1.4 Selection

Selection lets a program choose what to do. It tests a condition. A condition is something that is either TRUE or FALSE, such as Mark >= 50. The result decides which lines run.

IF ... THEN ... ENDIF

The simplest form. The lines inside run only if the condition is TRUE. If it is FALSE the program carries on after ENDIF.

IF ... THEN ... ELSE ... ENDIF

Two routes. One runs if the condition is TRUE, the other (ELSE) if it is FALSE. Exactly one of them runs.

Nested IF

An IF placed inside another IF handles three or more outcomes. The tests run from the top. The first one that is TRUE wins, so the order of the tests matters.

Order of the testsIf you test Mark >= 50 first, then a mark of 85 matches straight away and the test for 70 is never reached. Test the hardest condition first.

CASE OF

When one variable is compared with several fixed values, CASE OF is tidier than a pile of nested IFs. OTHERWISE catches anything that did not match.

Q1 Define 2 marks Define the term selection.
ReminderThree parts: a choice between routes, based on a condition, resulting in TRUE or FALSE.
A choice between two (or more) routes / sets of instructions based on a condition where the condition is evaluated as TRUE or FALSE (and this decides which route runs)

Common mistakeWriting "the program makes a decision" with no condition, or describing a loop (repeating) instead.
Q2 Label 5 marks Give the correct label for each one (A to E).
INPUT ScoreA IF  B Score >= 50  THEN    C OUTPUT "Pass"  ELSE    D OUTPUT "Fail"E ENDIF
ReminderThe TRUE route is the code after THEN. The FALSE route is the code after ELSE.
A: IF keyword (starts the selection)
B: condition (Score >= 50)
C: TRUE route (runs if the condition is TRUE)
D: FALSE route (runs if the condition is FALSE)
E: ENDIF keyword (ends the selection)
Common mistakeLabelling C or D as "the output" or "the value". They are whole routes (blocks of code), not values. Also mixing up TRUE and FALSE: the route after THEN is TRUE, after ELSE is FALSE.
Q3 State 1 mark State the purpose of the ELSE part of an IF statement.
ReminderWhat happens when the condition is FALSE?
It contains the instructions that are run when the condition is FALSE (the alternative route).
Common mistakeSaying it runs after the THEN part. It runs instead of it.
Q4 Write 4 marks Write pseudocode to input a person's age and output "Adult" if the age is 18 or over, otherwise output "Child".
ReminderOne test, two routes.
INPUT Age IF Age >= 18 THEN OUTPUT "Adult" in the THEN part, and ELSE with OUTPUT "Child" ENDIF at the end
INPUT AgeIF Age >= 18  THEN    OUTPUT "Adult"  ELSE    OUTPUT "Child"ENDIF
Common mistakeUsing > 18, which leaves out the age 18 itself. "18 or over" needs >=.
Q5 Complete 3 marks The code is run three times, with inputs 85, 60 and 30. State the output each time.
INPUT MarkIF Mark >= 70  THEN    OUTPUT "Grade A"  ELSE    IF Mark >= 50      THEN        OUTPUT "Grade B"      ELSE        OUTPUT "Grade C"    ENDIFENDIF
ReminderFollow the tests from the top. The first TRUE condition wins.
85: Grade A 60: Grade B 30: Grade C
Common mistakeGiving both Grade A and Grade B for 85. Only one branch runs.
Q6 Write 4 marks A game menu has options 1 Start, 2 Load and 3 Exit. Write pseudocode using CASE OF to input a choice and output the name of the option. Output "Invalid" for any other number.
ReminderCASE OF, one line per value, OTHERWISE for the rest.
INPUT Choice CASE OF Choice 1, 2 and 3 each with the correct OUTPUT OTHERWISE with OUTPUT "Invalid" and ENDCASE
INPUT ChoiceCASE OF Choice  1 : OUTPUT "Start"  2 : OUTPUT "Load"  3 : OUTPUT "Exit"  OTHERWISE OUTPUT "Invalid"ENDCASE
Common mistakeForgetting ENDCASE, or putting a condition such as Choice > 3 on the OTHERWISE line.
Q7 Explain 3 marks The code below should output Distinction for 70 or over. Explain why a mark of 85 gives the wrong output, and how to correct it.
IF Mark >= 50  THEN    OUTPUT "Merit"  ELSE    IF Mark >= 70      THEN        OUTPUT "Distinction"    ENDIFENDIF
ReminderWhich test does 85 match first?
85 is >= 50, so the first test is TRUE so "Merit" is output and the test for 70 is never reached Fix: test Mark >= 70 first (swap the order of the two tests).
Common mistakeSaying the tests are wrong. The tests are fine, it is the order that is wrong.
Q8 Write 5 marks Write pseudocode to input a temperature. Output "Too cold" if it is below 10, "Just right" if it is 10 to 25 inclusive, and "Too hot" if it is above 25.
ReminderThree outcomes: use a nested IF. Test one end first, then the other.
INPUT Temperature IF Temperature < 10 THEN OUTPUT "Too cold" ELSE with a second IF Temperature <= 25 (or > 25) correct outputs "Just right" and "Too hot" in the right branches all IFs closed with ENDIF
INPUT TemperatureIF Temperature < 10  THEN    OUTPUT "Too cold"  ELSE    IF Temperature <= 25      THEN        OUTPUT "Just right"      ELSE        OUTPUT "Too hot"    ENDIFENDIF
Common mistakeUsing < 25 or > 10, which gets the boundary values 25 and 10 wrong.
Q9 Describe 2 marks Describe when a programmer would use CASE OF instead of a nested IF.
ReminderThink about what is being compared.
When one variable (the same value) is being compared against several fixed values for example a menu choice; it is shorter and easier to read than many nested IFs.
Common mistakeSaying CASE OF can test ranges such as Mark >= 50. It matches fixed values.
Q10 Write 6 marks A cinema charges $5 per ticket for under 12s and $10 per ticket for everyone else. Write pseudocode to input an age and the number of tickets wanted, then output the total cost.
ReminderSelection chooses the price. Sequence does the rest.
INPUT Age and INPUT Tickets IF Age < 12 THEN Price ← 5 ELSE Price ← 10 and ENDIF Total ← Price * Tickets, after the selection OUTPUT Total
INPUT AgeINPUT TicketsIF Age < 12  THEN    Price ← 5  ELSE    Price ← 10ENDIFTotal ← Price * TicketsOUTPUT Total
Common mistakeWorking out Total inside the THEN part only, so over-12s never get a total.

Top tips

  • A condition is TRUE or FALSE. The result decides which lines run.
  • IF ... ELSE runs exactly one branch. Never both.
  • With nested IFs the first TRUE test wins. Put the most specific test first.
  • Check the boundary. "18 or over" is >= 18. "Over 18" is > 18.
  • Close every IF with ENDIF and every CASE with ENDCASE.
  • Pseudocode compares with =, Python with ==. Python also needs a colon and indentation.
