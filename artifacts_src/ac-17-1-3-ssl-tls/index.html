SSL and TLS

Coursebook: Chapter 17 · Security, section 17.1 Encryption, encryption protocols and digital certificates

The purpose of SSL and TLS, the handshake between client and server, the handshake and record protocols, and when to use them; animations, labs and the real Paper 3 questions from 2021 and 2025.

This page in five sentences

Secure Sockets Layer (SSL) and its successor Transport Layer Security (TLS) are protocols that give security over the internet: they encrypt the data, let the two parties identify and authenticate each other, and keep the communication confidential and unaltered. They are used in client-server communication, for example between a browser and a web server (HTTPS). A connection starts with a handshake: the client asks for the server's digital certificate, checks it and obtains the server's public key, the encryption algorithms are agreed, and symmetric session keys are generated. After that, the record protocol uses those keys to encrypt and send the data safely.

1 · Purpose of SSL/TLS

  • To provide communications security over the internet or a network: security and privacy.
  • To provide encryption of the data sent.
  • To let the two parties identify and authenticate each other (client and server).
  • To let them communicate with confidentiality and integrity: nobody can read it and nobody can change it unnoticed.

SSL is the older name. TLS is the modern version, and people often write SSL/TLS for both.

2 · How a secure session starts (client-server)

  1. An SSL/TLS connection is initiated by an application, which becomes the client. The application that receives the connection is the server.
  2. Every new session begins with a handshake, as defined by the SSL/TLS protocols.
  3. The client requests the digital certificate from the server (the server sends it).
  4. The client verifies the server's certificate with the certificate authority that issued it, and obtains the server's public key from it.
  5. The encryption algorithms are agreed, and a symmetric session key is generated, with the help of the public key so that it can be shared safely.
  6. A secure session is established. Data is now encrypted with the fast symmetric session key.

Notice that both kinds of cryptography are used: the asymmetric keys and the certificate set up trust and share the key, then symmetric encryption carries the data quickly.

3 · The two protocols that make up TLS

ProtocolPurpose
Handshake protocolEstablishes a secure and reliable connection between the two devices: the client and server authenticate each other and agree the encryption algorithms and keys.
Record protocolProvides a secure and reliable way to send and receive data over the network: it encrypts and authenticates the data exchanged between client and server, protecting its integrity and authenticity, and deals with the format of the data transmission.

4 · When to use SSL/TLS

  • When sending authentication data: passwords and session cookies.
  • When transmitting data that must be protected from modification on its way to or from a server, for example a user's input or results from the server.
  • When transmitting data classified as non-public: card details, personal data, private messages, online banking and shopping.

It is not needed for public information that anyone can read and nobody gains by changing, such as a public timetable page (although many sites use it anyway).

5 · Common ways to lose marks

  • Writing that SSL/TLS "stops hackers". Name the functions: encryption, authentication, confidentiality and integrity.
  • Leaving out the digital certificate and the public key in the handshake.
  • Saying the session uses the asymmetric keys for all the data. The agreed keys for the session are symmetric.
  • Describing the two protocols without names: handshake protocol and record protocol, each with its own purpose.
  • Giving examples that are too vague, such as "the internet". Say what is sent: passwords, payment details, personal data.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

The padlock and https://

When a web address starts with https the browser and the site have used TLS. The padlock means the site's certificate was checked and the data is encrypted.

Exam use: SSL/TLS is used between browser (client) and web server.

Online banking and shopping

Card numbers and passwords are sent over a TLS connection so that a person on the same Wi-Fi cannot read or change them.

Exam use: non-public data needs protecting.

Logging in

The password is sent inside the encrypted session. A session cookie that proves you are logged in is protected in the same way.

Exam use: authentication data such as passwords and session cookies.

Secure email

Mail servers use TLS between each other and your mail app, so messages are not readable on the way.

Exam use: TLS is used by many protocols, not just the web.

A warning page about a certificate

If the server's certificate cannot be verified, the browser warns you because it cannot be sure it is talking to the real site.

Exam use: the client verifies the server's certificate.

Top tips

  • Functions: encrypt, authenticate, confidential, integrity. Learn all four.
  • Handshake first. Client, certificate, verify, public key, algorithms, session keys.
  • Client and server. The application that starts the connection is the client.
  • Two protocols. Handshake protocol and record protocol.
  • Symmetric session keys. Fast encryption for the data after the handshake.
  • Examples: passwords, cookies, non-public data. Be specific.
