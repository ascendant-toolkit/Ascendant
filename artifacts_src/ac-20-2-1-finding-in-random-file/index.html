Finding a Record in a Random File

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

Direct access with a hash, following a collision chain, knowing when a record is not in the file, and searching by a field that is not the key; pseudocode and Python side by side, with a line-by-line animation.

This page in five sentences

A random file lets a program go straight to a record instead of reading the ones before it. To find a record by its key, the program calculates the location with the same hash function that stored it, uses SEEK to move there, and GETRECORD to read it. It then compares the key of the record it read with the key it wants: if they match, the record is found. If the location holds a different record the wanted one may have been moved on by a collision, so the program checks the next locations, and gives up at an empty location or after every location has been tried. To find a record by a field that is not the key, such as a name, the hash cannot help, so every location is read in turn until the value is found.

import structclass TAccount:    def __init__(self, AccountNumber=0, Name=""):        self.AccountNumber = AccountNumber        self.Name = Name Layout = "<i20s"RecSize = struct.calcsize(Layout)     # 24 bytes per record def GetRecord(File):    Num, Name = struct.unpack(Layout, File.read(RecSize))    return TAccount(Num, Name.decode().rstrip("\x00")) def Hash(Key):    return Key % 7

2 · Direct access: one SEEK, one GETRECORD

When the question does not mention collisions, finding a record is four steps: calculate the location, SEEK, GETRECORD, use the record. This is how the exam questions on random files are written.

Python

File = open("Accounts.dat", "rb")Location = Hash(SearchKey)File.seek(Location * RecSize)Current = GetRecord(File)if Current.AccountNumber == SearchKey:    print(Current.AccountNumber, Current.Name)else:    print("Not found")File.close()

Pseudocode (exam style)

OPENFILE "Accounts.dat" FOR RANDOMLocation <- Hash(SearchKey)SEEK "Accounts.dat", LocationGETRECORD "Accounts.dat", CurrentIF Current.AccountNumber = SearchKey THEN   OUTPUT Current.AccountNumber, Current.NameELSE   OUTPUT "Not found"ENDIFCLOSEFILE "Accounts.dat"

The comparison matters. Searching for 17 gives location 3, but location 3 holds account 10. Without the IF the program would output the wrong customer.

3 · The record may have been moved: follow the chain

Searching for 24 starts at location 3 and finds account 10, so it is not there. It looks at 4, then 5, then 6 and finds 24. The search follows the same steps the insert took. It stops when the key is found, when it reaches an empty location (a record with this key would have been stored there, so it is not in the file), or when it has looked at every location.

Python

File = open("Accounts.dat", "rb")Location = Hash(SearchKey)Count = 0Found = Falsewhile True:    File.seek(Location * RecSize)    Rec = GetRecord(File)    if Rec.AccountNumber == SearchKey:        Found = True    else:        Location = (Location + 1) % 7        Count = Count + 1    if Found or Rec.AccountNumber == 0 or Count == 7:        breakFile.close()if Found:    print(Rec.AccountNumber, Rec.Name)else:    print("Not found")

Pseudocode (exam style)

OPENFILE "Accounts.dat" FOR RANDOMLocation <- Hash(SearchKey)Count <- 0Found <- FALSEREPEAT   SEEK "Accounts.dat", Location   GETRECORD "Accounts.dat", Rec   IF Rec.AccountNumber = SearchKey THEN      Found <- TRUE   ELSE      Location <- (Location + 1) MOD 7      Count <- Count + 1   ENDIFUNTIL Found OR Rec.AccountNumber = 0 OR Count = 7CLOSEFILE "Accounts.dat"IF Found THEN   OUTPUT Rec.AccountNumber, Rec.NameELSE   OUTPUT "Not found"ENDIF

4 · Finding a record by a field that is not the key

The hash function turns an account number into a location. It cannot turn a name into one, because the records were not placed by name. So the program starts at location 0 and reads every location until the name matches or the file ends. A flag stops the loop as soon as the record is found.

Python

File = open("Accounts.dat", "rb")Location = 0Found = Falsewhile not Found and Location < 7:    File.seek(Location * RecSize)    Rec = GetRecord(File)    if Rec.Name == SearchName:        Found = True    else:        Location = Location + 1File.close()if Found:    print(Rec.AccountNumber, Rec.Name)else:    print("Customer does not exist.")

Pseudocode (exam style)

OPENFILE "Accounts.dat" FOR RANDOMLocation <- 0Found <- FALSEWHILE NOT Found AND Location <= 6   SEEK "Accounts.dat", Location   GETRECORD "Accounts.dat", Rec   IF Rec.Name = SearchName THEN      Found <- TRUE   ELSE      Location <- Location + 1   ENDIFENDWHILECLOSEFILE "Accounts.dat"IF Found THEN   OUTPUT Rec.AccountNumber, Rec.NameELSE   OUTPUT "Customer does not exist."ENDIF

6 · Common ways to lose marks

  • Leaving out SEEK, so GETRECORD reads wherever the pointer was.
  • Not comparing the key of the record read with the key wanted.
  • Using READFILE on a random file. Random files use GETRECORD.
  • Using the hash to search for a name. The hash is for the key field only.
  • A loop that never ends because it does not stop at an empty location, at the end of the file or when the record is found.
  • Forgetting the message when the record is not found.
  • Not closing the file.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

An ATM looking up an account

When a card is inserted the account number is turned into a location and the record is fetched directly. The customer is not left waiting while millions of other records are read.

Exam use: direct access: hash the key, SEEK, GETRECORD.

A school office searching by surname

The student file is organised by student ID, so searching by surname means the system has to read record after record until the name is found, which is slower than searching by ID.

Exam use: the hash cannot be used on a field that is not the key.

A stock check

A warehouse program asks for a location and reads that one record. An empty record means the shelf is empty, and the program shows a message instead of an item.

Exam use: SEEK, GETRECORD, then test the record for empty.

A missing record

A customer quotes an account number that was never opened. The program reaches an empty location and reports that the account does not exist, without reading the whole file.

Exam use: an empty location ends the search: the record is not stored.

Top tips

  • SEEK before GETRECORD. Every time, for every location you read.
  • Open FOR RANDOM. Not READ or APPEND.
  • Compare the key. The record at the hashed location may belong to a different key.
  • Know when to stop. Record found, empty location, or every location tried. A flag or Count makes the loop end.
  • Hash is for the key only. To find a name, read every location from the start.
  • Say what happens if it is missing. Output a message such as "Not found".
