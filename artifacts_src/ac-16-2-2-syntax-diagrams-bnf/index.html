Syntax Diagrams and BNF

Coursebook: Chapter 16 · System software, section 16.2 Translation software

How to read and draw syntax diagrams and write Backus-Naur Form, including recursion for repetition; animations, a string checker and the real Paper 3 questions from 2021 to 2025.

This page in five sentences

The grammar of a programming language, the rules for how its statements can be written, can be shown as syntax diagrams or in Backus-Naur Form (BNF). A syntax diagram follows arrows from left to right: rectangles are names of other rules, rounded boxes are characters that appear exactly as written, a choice is a set of parallel routes, and a loop back lets something repeat. In BNF each rule has the form <name> ::= definition, where | means "or", names are in angle brackets, and repetition is written with recursion, a rule that uses its own name. The two notations describe the same thing, so you must be able to turn a diagram into BNF and back, and to decide whether a string is valid. Syntax analysis uses these rules to check a program.

1 · Syntax diagrams

Start at the arrow on the left, follow the lines to the arrow on the right, and write down each box you pass through. A string is valid if it can be made by some route.

  • Rounded box: a terminal, a symbol that appears as it is, such as a digit or an operator.
  • Rectangle: a non-terminal, the name of another rule that is defined by its own diagram.
  • Choice: parallel routes; take exactly one.
  • Loop back: the route can return to an earlier point, so the part inside the loop can be used one or more times.
  • Bypass: a line that goes straight past a box, so the box is optional.

Turning a diagram into BNF

  • A choice becomes alternatives joined by |: for a symbol diagram that offers $, %, &, @ or #, <symbol> ::= $ | % | & | @ | #.
  • A sequence is written side by side: a number that is an odd digit followed by an optional odd or even digit is built from <odd> then the rest.
  • An optional part becomes two alternatives, one with it and one without: <number> ::= <odd> | <odd><even> | <odd><odd>.
  • A repeat (a loop) is written with recursion, so that the rule is defined using itself: one or more letters is <word> ::= <letter> | <word><letter> (or <letter><word>). The first alternative ends the repetition; the second adds one more.

Worked example (O/N 2021, Paper 31)

A password is a character followed by one or more digits or capital letters.

The loop needs a helper rule <code>, one or more digits or capital letters:

<password> ::= <character><code>
<code> ::= <digit> | <capital_letter> | <digit><code> | <capital_letter><code>

A valid password is $A9E3. Names with a space, such as capital letter, are written with an underscore in BNF.

3 · Drawing a syntax diagram from a description

  1. Put the elements in order, as rectangles (or rounded boxes for fixed characters).
  2. Add a choice where the description says "or".
  3. Add a loop back where it says "one or more" or "can be repeated".
  4. Add a bypass where it says "optional" or "zero or one".
  5. Label the diagram with its name, and put arrows on every line, including one at the start and one at the end.

4 · Common ways to lose marks

  • Forgetting the angle brackets round names, or writing = or := instead of ::=.
  • Writing a repeat as the name followed by "..." or "*". BNF has no repeat symbol; use recursion.
  • Making a rule that can never end: the recursive rule needs a non-recursive alternative.
  • Giving the reason a string is invalid without referring to the diagram: the first character must be a letter, the symbol must come after the digits, ? is not an allowed symbol.
  • In a drawn diagram, missing the arrows, the label, or the loop, or adding extra boxes.

Checking a program's grammar

The syntax-analysis stage of a compiler uses the grammar of the language, often written in BNF, to decide whether a line of code is allowed.

Exam use: BNF defines the rules a parser applies.

Forms that reject your input

A website that says a postcode or password is invalid is applying a grammar like these diagrams: letters first, then digits, with only certain symbols allowed.

Exam use: validity is a pattern of allowed characters.

Rules for a username

'One or more letters followed by at most two digits' is exactly a loop on letter and an optional digit in a syntax diagram.

Exam use: loops and bypasses express repetition and options.

Language reference manuals

Languages such as Python and SQL publish their grammar in BNF-like notation so that anyone can build a tool that understands them.

Exam use: BNF is a standard way to define a language.

Top tips

  • Follow the arrows. A string is valid only if some route through the diagram makes it.
  • Give the reason. Begins with a digit, symbol before digits, a character that is not allowed, too many digits.
  • ::= and |. BNF: ::= means is defined as, | means or.
  • Repeat = recursion. <word> ::= <letter> | <word><letter>.
  • Optional = two alternatives. One with the part, one without.
  • Diagram: name, arrows, boxes. Label it, put arrows on every line, add loops and bypasses carefully.
