Declarative Programming: Facts, Rules and Goals

Coursebook: Chapter 20 · Further programming, section 20.1 Programming paradigms

Facts, rules, goals and variables in a logic language; adding facts from a description, giving the result of a goal, and writing rules with AND and NOT; animations, a goal engine you can query, and every declarative question from the 2021 to 2026 Paper 3 papers.

This page in five sentences

Declarative programming tells the computer what is true and what answer is wanted, not how to find it. A program is a set of facts (things that are true) and rules (things that are true if other things are true), which together form a knowledge base. You run it by asking a goal (a query): the system searches the facts and rules and returns every answer that satisfies it. Names that start with a lower-case letter are constants; names that start with a capital letter are variables that the system fills in. In the exam you write extra facts from a description, say what a goal returns, and write a rule or a goal using AND and NOT.

Declarative languages are logic programming (facts, rules and goals, such as Prolog) or functional programming (the program is built by applying functions to arguments). The exam uses the logic style.

2 · Facts

A fact is a predicate with arguments in brackets and a full stop. The meaning of each argument depends on its position, and you decide the order, so be consistent.

FactMeaning
type(leopard, wild).A leopard is a type of wild cat
hair(lion, short).A lion has short hair
customer(petrov).Petrov is a customer
owns(projector, petrov).Petrov owns a projector (device first, owner second)

One-argument facts such as customer(petrov). say that something is a member of a kind. They matter: rules use them to say what kind of thing a variable can be.

Adding facts from a description"Betty is a customer who owns a large TV and wants a Blu-ray player." This needs one fact for each statement: customer(betty). owns(large_tv, betty). wants(bluray_player, betty). Use the exact constants already in the knowledge base (large_tv, bluray_player), the same argument order, and lower case. A brand-new person or item also needs its "is a" fact (customer(betty).), and the mark scheme counts it.

3 · Goals and variables

A goal asks a question. Put a variable (capital first letter) where you want the answer. The system tries every fact with the same predicate, keeps the ones that match, and returns all the values the variable can take, in the order of the facts.

GoalReturns
hair(Cat, medium)Cat = leopard, cheetah, savannah
type(Pet, domestic)Pet = persian
hair(lion, short)true (no variable: a yes/no question)
hair(Cat, purple)false (nothing matches)

A goal can have several conditions joined with , (AND). The same variable in two conditions links them: it must take one value that satisfies both.

spots(WildSpotty, yes), type(WildSpotty, wild)

spots(_, yes): leopard, cheetah, savannah
type(_, wild): leopard, lion, cheetah
Both:          leopard, cheetah

4 · Rules

A rule says that something is true if other conditions are true. It has a head (what is being defined), the word IF, and a body of conditions joined with AND (or a comma), and NOT for "is not true".

may_buy_device(D, A)
   IF device(D) AND customer(A) AND NOT owns(D, A).

may_buy_device(D, A) IF device(D), customer(A), NOT owns(D, A).    // same rule

Read it as: D may be available for A to buy if D is a device and A is a customer and A does not own D. The three marks for the conditions come from device(D), customer(A) and owns(D, A), and a fourth for correct operators and punctuation.

  • List one condition for each "is a" in the sentence, then the extra condition.
  • Put NOT before the condition that must fail, and put the "is a" conditions first, so the variables are filled in before NOT is tested.
  • The mark scheme accepts , for AND and, for SWISH Prolog, \+ for NOT. It does not accept extra lines of code.
Exam notationProlog
father(X, Y) IF male(X) AND parent(X, Y).father(X, Y) :- male(X), parent(X, Y).
NOT owns(D, A)\+ owns(D, A)

5 · How the system answers

  1. Take the first condition and look through the facts for matches. Each match fills the variables.
  2. For each match, test the next condition using the values already filled in.
  3. A NOT condition succeeds only if the fact is not found.
  4. Every way of satisfying all the conditions is an answer. If none exists the answer is false.

6 · Common ways to lose marks

  • Writing a constant with a capital letter (Betty) or a variable with a lower-case one. Capital means variable.
  • Leaving out the "is a" fact for a new person or item, or the full stop at the end of a fact.
  • Changing the argument order from the one in the knowledge base.
  • In a rule, forgetting a condition (for example customer(A)), or putting NOT on the wrong one.
  • Listing results in the goal answer that do not match, or leaving some out. Check every fact with that predicate.
  • Adding extra lines or text to a rule or goal that asks for a single line.
  • Describing declarative as "no loops". Say it states what is wanted using facts and rules, and the system works out how.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

An expert system

A medical or car-repair helper holds facts about symptoms and rules such as 'the fault may be the battery if the lights are dim and the engine does not turn'. The user states what they see and the system reasons its way to answers.

Exam use: declarative systems are used where knowledge is a set of facts and rules and the answer is found by search.

A family tree

Facts say who is a parent of whom. A rule defines grandparent as a parent of a parent, and the same rule answers for any family without a loop being written.

Exam use: rules built from other rules and facts: describe the relationship once.

A database query

SQL is also declarative: SELECT name FROM Cat WHERE type = 'domestic' says what rows are wanted, not how to scan the table.

Exam use: like a goal, it states the result wanted and the system works out how.

A timetable or planning tool

Facts say which teachers can teach which subjects and which rooms are free. A rule defines when a lesson may be placed. The system tries combinations to find one that satisfies every rule.

Exam use: searching for answers that satisfy all conditions at once.

A shop recommendation rule

may_buy(Device, Customer) IF device(Device) AND customer(Customer) AND NOT owns(Device, Customer) finds everything a customer does not already own.

Exam use: NOT is used for 'does not already have' conditions.

Top tips

  • Match the knowledge base. Use the same predicate names, argument order and constants. Copy a similar fact and change the values.
  • One fact per statement. Count the things the description says, and write a fact for each, including the 'is a' fact for anything new.
  • Capital means variable. betty is a constant; Betty is a variable. Never capitalise a constant.
  • Results come in order. List the answers in the order the facts appear, and check every fact with that predicate.
  • Rules: one condition per 'is a'. device(D) AND customer(A) AND the extra condition. NOT only on the one that must fail.
  • Reuse the variable to link. The same variable name in two conditions makes them apply to the same thing.
  • Do not add extra lines. A one-line rule or goal gets no mark for extra code.
