Data Entry Errors v Data Transmission Errors

Two different kinds of mistake need two different kinds of check. One happens when a person types or scans a code. The other happens when the data travels. Learn when each happens, which checks guard against it, and why one can never do the other's job.

The big idea

Ask when the error happened. A data entry error happens before the data is sent: a person types, or a scanner reads, the wrong thing. A data transmission error happens while the data is travelling: the data was right when it left. The check you choose depends on the answer, because the two kinds of check ask different questions.

1 · The two questions

Entry check asks

"Is this number valid?" It looks at the code itself and tests whether the digits follow the rule that real codes follow. It needs no copy of the original, because the rule is built into the number.

Transmission check asks

"Is this exactly what was sent?" It compares what arrived with something worked out from what left. It does not care whether the data made sense in the first place.

4 · How a check digit works

The textbook method (ISBN-13 style) gives each digit a weighting of 1 and 3 in turn, adds the results, and chooses the final digit so that the total is a multiple of 10.

code 5307?     digits     5   3   0   7
               weights    1   3   1   3
               products   5 + 9 + 0 + 21 = 35
35 ÷ 10 leaves 5, so check digit = 10 − 5 = 5
full code: 53075

To check a typed code, apply the weights to all five digits (the check digit has weight 1). A valid code gives a total that is a multiple of 10. For 50375: 5 + 0 + 3 + 21 + 5 = 34, which is not, so the mistake is caught.

Not every error is caughtA check digit finds most typing mistakes, not all. Two digits that differ by 5, swapped in positions with weights 1 and 3, can leave the total unchanged. You can hunt for one in the Explore tab.

5 · How a CRC works (transmission)

The sender counts the 1-bits in the packet's payload and stores the total, as hex, in the trailer. The receiver counts again and compares. A packet with 5 one-bits has trailer 05. If the receiver counts 6, it does not match, so it asks for the packet again.

The key contrastA mistyped number that is sent perfectly passes every transmission check, because it arrived exactly as it was sent. And a check digit says nothing about whether bits were damaged in transit. Each check only guards its own part of the journey, so real systems use both.
Validation and verificationIn Chapter 7.5 you meet validation (the computer tests the data is reasonable) and verification (checking data was copied correctly). A check digit is one of the validation checks. Everything on this page about check digits applies there too.

7 · Multiple choice

Descriptions are kept general. Real systems use more advanced calculations, but the ideas are the ones in the textbook.

The supermarket till

A scanner can misread a barcode. The last digit is a check digit, so a misread fails the check and the till beeps for a re-scan instead of charging for the wrong item. That is a data entry check. Nothing has been sent anywhere yet.

Exam use: a scanner is a source of data entry errors. Name the check digit and the solution (re-scan).

Typing a card number into a website

Card numbers end in a check digit. Many sites test it as soon as you stop typing, so a slip is flagged before the form is submitted.

Exam use: shows an entry check running on the user's own device before the data is transmitted.

Downloading a file

The file is split into packets, each with a check value. A damaged packet fails its check and only that packet is requested again. A packet that never arrives is requested after a timeout.

Exam use: a transmission check (CRC), with a negative acknowledgement for corruption and a timeout for loss.

Typing an ISBN to order a book

The shop checks the last digit of the ISBN. A swapped pair usually fails, so you are asked to look again. Once the order is sent, a different set of checks protects the data in transit.

Exam use: a good example for questions that ask for a check at each stage. Entry: check digit. Transmission: checksum or CRC with ARQ.

A video call

Live calls cannot wait for a re-send, so a damaged or lost packet often just becomes a glitch. Speed matters more than a perfect picture.

Exam use: re-sending costs time, so it is not always the best fix for a transmission error.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each highlighted phrase earns one mark; the number shows which mark point it is.

Q1 State 2 marks State one error check used when data is entered and one used when data is transmitted.
ReminderOne method per mark. Match each to the right stage.
Data entry: a check digit. Data transmission: any one of parity check / checksum / echo check / CRC / ARQ.
Common mistakeWriting "validation" or "verification" for the entry mark. Those are headings from Chapter 7.5; here the named method is the check digit.
Q2 Identify 3 marks For each error, state whether it is a data entry error or a data transmission error. (a) The code 3140 is typed as 3410. (b) A packet is lost on the way to the receiver. (c) Interference changes a 1 to a 0.
ReminderAsk: did it happen before sending or while travelling?
(a) Data entry error (a transposition). (b) Data transmission error (lost data). (c) Data transmission error (corrupted data).
Common mistakeCalling any wrong data a "transmission error". If a person caused it, it is data entry.
Q3 Calculate 3 marks A check digit is added to the code 4821. Each digit is multiplied by 1 or 3 in turn, starting with 1, the products are added and the check digit makes the total a multiple of 10. Work out the check digit.
ReminderShow the products. Method marks are available even if the arithmetic slips.
4×1 + 8×3 + 2×1 + 1×3 = 4 + 24 + 2 + 3 = 33
33 ÷ 10 leaves 3, so check digit = 10 − 3 = 7
Weights applied: 4, 24, 2, 3. Total 33. Check digit 7 (so the code is 48217).
Common mistakeWriting the check digit as 3 (the remainder). The digit is what must be added to reach the next multiple of 10.
Q4 Explain 3 marks A clerk types the code 48271. The system rejects it. Use the check-digit rule from Q3 to explain why.
ReminderApply the weights to all five digits, including the last.
4×1 + 8×3 + 2×1 + 7×3 + 1×1 = 4 + 24 + 2 + 21 + 1 = 52
The system recalculates using the weightings 1 and 3. The total is 52. 52 is not a multiple of 10, so the code is invalid (a transposition of 1 and 7 in 48217) and the clerk is asked to enter it again.
Common mistakeLeaving the check digit out of the total. The final digit is part of the sum.
Q5 Explain 4 marks A school uses a check digit when staff type student ID numbers, and a checksum when it sends the records to the local authority. Explain why each check is used where it is.
ReminderTwo reasons, one for each place. Say what each check compares.
Typing mistakes are made by people before the data is sent. A check digit tests whether the ID number is valid, so a mistyped ID is caught and re-entered. The records can be damaged while travelling, for example by interference. A checksum is recalculated by the receiver and compared with the one sent; a mismatch means the data changed in transit and it is sent again.
Common mistakeSaying the checksum would also catch the typing mistake. It would pass it, because the wrong ID arrives exactly as sent.
Q6 Describe 3 marks Describe how a cyclic redundancy check (CRC) detects an error in a packet.
ReminderSender, then receiver, then the decision.
The sender counts the 1-bits in the payload and stores the total (in hex) in the trailer. The receiver counts the 1-bits in the payload it receives. If the two totals differ, an error has been detected and the packet is requested again.
Common mistakeForgetting that the trailer travels with the packet. The receiver has something to compare with.
Q7 Suggest 4 marks Customers type a booking reference into a cinema's app. The app then sends the booking to the cinema's server. Suggest a suitable error check for each stage and give a reason for each.
ReminderMatch entry to entry and transmission to transmission. One check and one reason for each.
Typing the reference: a check digit. It is recalculated as the reference is entered, so a mistyped digit is found and the customer is asked to type it again. Sending the booking: a checksum (or CRC) with ARQ. The server recalculates the value and compares it with the one sent; if they differ, it asks for the booking to be sent again.
Common mistakeSuggesting a parity bit for the typed reference. Parity checks bits in transit, not typed codes.
Q8 Discuss 4 marks A student says: "If the data passes the checksum when it is received, it must be correct." Discuss whether the student is right.
ReminderGive a point for, a point against, and a conclusion. Use an example.
The student is partly right: a matching checksum shows the data received is the same as the data sent. But the checksum only compares with what was sent, so it cannot show the data was correct to begin with. For example, a code mistyped as 50375 instead of 53075 is sent and received perfectly, so the checksum matches. Data entry errors need a separate check, such as a check digit, before the data is sent.
Common mistakeWriting only "yes" or only "no". A discuss question rewards both sides.
Q9 Compare 4 marks Compare the use of a check digit with the use of an echo check.
ReminderPut both methods in each point. Use "whereas" and "both".
Both are used to detect errors, and in both the user or sender has to put the data right again if an error is found. A check digit is used for data entry errors, whereas an echo check is used for data transmission errors. A check digit is worked out from the digits of the code and sends no extra data, whereas an echo check sends a copy of all the data back. An echo check cannot tell whether the error happened on the way there or the way back, whereas a check digit tests the code as typed.
Common mistakeDescribing each method on its own. Link them in every point.

Top tips

  • Start with "when". Before or during sending? That one question picks the check.
  • Check digit = data entry. Parity, checksum, CRC, echo check and ARQ = transmission. Never swap them.
  • Transmission checks compare with what was sent. They cannot tell if the data was right to begin with.
  • Check digits catch most typing mistakes, not all. Do not say they catch every one.
  • In calculations, include the check digit in the total when you are checking a code, and leave it out when you are working it out.
  • Detect is not correct. The fix is to re-enter (entry) or to re-send (transmission).
  • Say what is compared. A check digit tests the number; a CRC compares counts of 1-bits.
  • Do not say a check "prevents" errors. It finds them after they happen.
