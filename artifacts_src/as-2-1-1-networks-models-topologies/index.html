Networks, Network Models and Topologies

Coursebook: Chapter 2 · Communication · section 2.1 Networks including the internet

LANs and WANs, client-server and peer-to-peer models, thin and thick clients, and bus, star, mesh and hybrid topologies; animations, a cable-failure lab and the real Paper 1 questions from 2021 to 2025.

This page in five sentences

A network is a group of computers and devices connected so they can share data and resources. A LAN covers a small area (a building) on equipment the owner controls, and a WAN covers a large area (cities or countries) using external, shared infrastructure. In a client-server network one or more servers provide services and manage the network for clients, while in a peer-to-peer network every computer has equal status and shares its own resources. A thin client leaves almost all processing to the server; a thick client does most of its own processing and storage. The way devices are connected is the topology: bus, star, mesh or a hybrid of them, each with its own cost, speed and fault tolerance.

1 · LAN and WAN

LAN (local area network)WAN (wide area network)
AreaSmall geographical area: a building or siteLarge geographical area: between cities or countries
InfrastructurePrivately owned, dedicated hardware; no leased lines neededOften external or public infrastructure, non-dedicated hardware
ConnectionsWired or wireless; usually physical linksOften virtual, over leased or public links
SpeedHigher data transfer rateLower data transfer rate
SecurityEasier to protectHarder to protect

Benefits of connecting computers in a LAN: sharing files and data, sharing resources such as printers and software, communication between devices, and central management of security and backups. The internet is the biggest WAN.

2 · Client-server and peer-to-peer

  • Client-server: one or more servers store the files, run services and manage security and backup; the clients request services from them. The server performs the tasks asked of it and sends the results back.
  • Peer-to-peer: all computers are of equal status. Each shares its own files and resources and is responsible for its own security. There is no central server.
Client-serverPeer-to-peer
BenefitsCentral management of security, backup and software; easier to control access; reliable and scalableCheap and simple to set up; no dedicated server or administrator; no single point of failure
DrawbacksExpensive to buy and maintain a server; if the server fails the clients lose the service; a network manager is neededNo central security: only as secure as the weakest computer, each at risk from viruses on the others; no central backup; slower when others use your computer; files only available while that computer is on
SuitsA school, company or bank with many users and sensitive dataA few friends or a small home network sharing files

Thin client and thick client

  • Thin client: depends on the server for processing and storage. It only sends requests and displays the results. Cheap, easy to manage and secure, but useless if the server or network is down.
  • Thick client: does most of its own processing, with software and data installed locally. It works without the server for much of the time, but the clients cost more and each needs updating.

3 · Topologies

Bus

All devices share one backbone cable. Data goes along it and each device looks at the address. Cheap and simple, but only one device can transmit at a time, so there are collisions; a break in the backbone stops everything.

Star

Every device connects directly to a central switch. Packets go from the sender to the switch, which checks the destination address and forwards them only to the intended receiver. Fewer collisions, easy to add devices and find faults; if one cable fails only that device is lost, but if the switch fails everything is.

Mesh

Each device is connected to at least one other, often several. There are multiple routes, so a failed link can be avoided and nodes act as relays. Very reliable and secure, but expensive: a full mesh of n devices needs n(n − 1) ÷ 2 links.

Hybrid

A combination of topologies, for example stars joined by a bus backbone. Used in larger networks where different areas have different needs.

To justify a topology for a situation, give a reason tied to the situation: a classroom of 20 computers on a switch suits a star (a fault stays local, higher performance, easy to add computers); a few buildings that must stay connected if a cable is cut suit a mesh.

4 · Common ways to lose marks

  • Writing "it is bigger" for a WAN. Say the geographical area, the use of public or leased infrastructure and the lower data rate.
  • Drawing a star topology with devices connected to each other. In a star every device connects only to the switch (or server).
  • Describing a thick client as a computer with a bigger screen. It is about where the processing and storage are.
  • Giving drawbacks of peer-to-peer as "slow" with no reason. Say no central security or backup, or that files are only available while that computer is on.
  • Saying a mesh is "better" with nothing more. Say multiple routes, so a failed line is avoided.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Your home Wi-Fi

Your phone, laptop and TV connect to one router. That is a star: every device talks to the router, not to each other directly.

Exam use: star topology around a central device.

A school computer room

Every computer connects to a switch, and the switch connects to the server. If one cable fails, only one computer is lost.

Exam use: star, with the server managing logins and files.

Chromebooks and web apps

A Chromebook does little itself and relies on web services. That is close to a thin client.

Exam use: thin clients rely on the server.

Sharing a file between friends' laptops

Two laptops on the same Wi-Fi can share a folder directly. Each is both giving and receiving: a small peer-to-peer network.

Exam use: peers have equal status.

The internet

Millions of networks joined by many routes: if one link is cut, data finds another way. That is the idea of a mesh at a huge scale.

Exam use: multiple routes give reliability.

M/J 2021 · 9618/11/13 · Q4(a)(b) Describe 2 + 4 marks Melinda and her friends set up a peer-to-peer network between their computers to share data. (a) Describe the key features of a peer-to-peer network. (b) Describe two drawbacks to Melinda and her friends of using a peer-to-peer network.
Reminder(a) Equal status, shared resources, own security. (b) Two drawbacks, each with a reason.

(a) Any two: All computers are of equal status Each computer provides access to resources and data (data is distributed) Computers can communicate and share resources Each computer is responsible for its own security

(b) Two drawbacks, a mark each plus up to one expansion each (max 2 per drawback): Reduced security: there is no central management of security so it is only as secure as the weakest computer, and each is at risk from viruses from the others No central management of backup so if the data on one computer is not backed up it is lost to all of them Other drawbacks accepted: no central management of files or software (inconsistent versions); computers respond slowly while others use them; computers must all be switched on to share files.

Common mistakeGiving a drawback such as 'it is slower' with no reason. Say why: other computers are using it, or files are not available when a computer is off.

2. Review questions

Written for practice and revision, not taken from past papers. Use them to check your understanding before attempting the real questions above.

Explain 2 marks Explain why a thin client cannot be used when the server is switched off.
ReminderWhere is the processing?

A thin client depends on the server for processing and storage It only sends requests and displays results, so without the server it can do nothing

Explain 3 marks A small business has six computers. Explain whether client-server or peer-to-peer is the better choice if they handle customers' bank details.
ReminderThink about security and backup.

Client-server A server centrally manages security (access rights, antivirus) and backups Peer-to-peer would leave each computer responsible for its own security, so the weakest computer puts the data at risk

Describe 2 marks Describe one disadvantage of a bus topology.
ReminderShared cable.

All devices share one backbone cable, so only one can transmit at a time and collisions occur If the backbone breaks the whole network (or part of it) fails (one of these with its explanation)

Explain 3 marks A hospital has three buildings that must always stay connected. Explain why a mesh topology could suit it.
ReminderMultiple routes.

Each building is connected to at least one other, with several routes If one link fails data can go another way So the network is reliable (but it costs more cable)

Distinguish 2 marks Distinguish between a LAN and a WAN.
ReminderArea and ownership.

A LAN covers a small area, usually in one building, on privately owned equipment A WAN covers a large area, such as between cities, using external or leased links

Top tips

  • Star: everything to the switch. Never connect devices to each other.
  • LAN: small, private. WAN: large, shared. Give the area and who owns the infrastructure.
  • Peer-to-peer: equal status. No central security or backup.
  • Thin client: server does the work. Thick client does its own processing.
  • Mesh: multiple routes. Reliable but costly.
  • Justify with the situation. Link the topology or model to the people and data in the question.
