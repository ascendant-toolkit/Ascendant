Operating Systems: Purposes and Resources

Coursebook: Chapter 16 · System software, section 16.1 Purposes of an operating system

What an operating system does: managing resources, multi-tasking, the user interface and device drivers hiding the hardware, and the kernel; animations, labs and the real Paper 3 questions from 2021 to 2025.

This page in five sentences

An operating system (OS) is the system software that manages the hardware and provides a platform on which application programs run. It manages the resources of the computer (processor time, main memory, input and output devices and storage) and shares them between the programs that want them. It maximises the use of those resources by multi-tasking, scheduling processes, and using virtual memory so the processor is kept busy and memory is used well. It hides the complexity of the hardware from the user with a user interface, device drivers and a file system, so that the user clicks an icon instead of writing code that deals with memory addresses and buses. At the centre is the kernel, which handles interrupts and starts and stops processes.

1 · What the OS manages

ResourceWhat the OS does
Processor (CPU)Decides which process runs next and for how long (scheduling), so the CPU is rarely idle.
Main memoryGives each process the memory it needs, keeps processes apart, and uses virtual memory when RAM is short.
Input and output devicesControls keyboards, screens and printers through device drivers; queues requests.
Secondary storage and filesOrganises files in folders, tracks where each file is stored, and controls access.
Users and securityLogs users in, sets permissions, and stops one process changing another's data.

2 · Maximising the use of resources

  • Multi-tasking means running more than one process at the same time, or appearing to. The processor is shared by giving each process a short time slice in turn, so many tasks make progress instead of one task having to finish before the next starts. While one process waits for a slow input or output device, the CPU runs another.
  • Scheduling chooses which process gets the CPU. Good scheduling keeps the CPU busy all the time, gives all processes fair access, and lets high-priority jobs finish first (16.1.3).
  • Memory management shares RAM between processes, and uses virtual memory (part of the disk) so that more programs can be open than fit in RAM at once (16.1.4).
  • The OS also monitors the state of every process so that tasks do not clash over the same resource.

3 · Hiding the complexity of the hardware

The hardware is complicated: buses, memory addresses, controllers, disk sectors. The OS hides this by abstraction, so the user and the application program only see simple things.

  • The user interface (a graphical user interface with windows, icons, menus and a pointer, or a command-line interface) lets the user control the computer in an intuitive way, by clicking an icon rather than writing code that handles memory locations and hardware. Different interfaces also give appropriate access to users with different needs.
  • Device drivers are small programs that translate the OS's general instructions into the commands a particular printer, disk or screen understands. Applications ask the OS to print; the driver deals with the printer.
  • The file system lets the user work with named files and folders; the OS keeps track of the sectors on the disk.
  • The application layer idea: the user only sees the top layer, and the lower layers' details are hidden.

4 · The kernel

The kernel is the central part of the OS, loaded first and kept in memory. It runs in a privileged (kernel) mode with full access to the hardware. It starts, stops and switches processes, manages memory, and acts as the interrupt handler (16.1.2): when an interrupt arrives, the kernel saves the state of the current process, runs the right routine and restores the state afterwards.

5 · Common ways to lose marks

  • Saying the OS "runs the computer" with no detail. Name a resource and what is done with it.
  • Describing a user interface only as "easy to use". Say that it hides the complexity of the hardware, with an example such as clicking an icon instead of writing code.
  • Describing multi-tasking as "doing two things at exactly the same time" on one processor. It appears to run several processes by sharing the processor.
  • Mixing up multi-tasking (the aim) and scheduling (how the OS decides which process to run).
  • Writing "paging" when the question asks about virtual memory: virtual memory is the idea, paging is one way to do it.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

Having many windows open

You can listen to music, type a document and download a file at once. The OS gives each a tiny slice of the processor many times a second, so they all seem to run together.

Exam use: multi-tasking with time slices.

Plugging in a new printer

The computer asks for or installs a driver. After that every program can print without knowing anything about this printer's commands.

Exam use: device drivers hide the details of the hardware.

Dragging a file to the bin

You never type the disk sector numbers. The OS finds, moves or frees the data for you.

Exam use: a user interface hides hardware complexity.

Phone running out of memory

When many apps are open, the OS moves apps that are not in use out of RAM and brings them back when you return to them.

Exam use: memory management shares RAM between processes.

Different accounts on a shared computer

Each user sees only their own files and settings. The OS controls who may open what.

Exam use: the OS manages users and security.

Terms: multi-tasking, paging, interrupt handling, scheduling, virtual memory. Descriptions: (A) using secondary storage to simulate additional main memory; (B) managing the processes running on the CPU; (C) managing the execution of many programs that appear to run at the same time; (D) locating non-contiguous blocks of data and relocating them; (E) transferring control to another routine when a service is required; (F) reading and writing same-size blocks of data from and to secondary storage when required.
ReminderOne description is a distractor.

Multi-tasking → C Paging → F Interrupt handling → E Scheduling → B Virtual memory → A

Description D is not used: it describes defragmentation, which is utility software, not one of these OS terms.

Common mistakeJoining paging to A. Paging is the reading and writing of fixed-size blocks (pages); virtual memory is the idea of using storage as extra memory.

ReminderThe core.

Top tips

  • Name the resource. Processor, memory, devices, files: say what the OS does with each.
  • User interface: hides hardware. Benefit plus an example such as clicking an icon.
  • Multi-tasking: appears at the same time. The processor is shared; more tasks complete.
  • Two marks: name and describe. A way to hide the hardware needs both.
  • Do not mix terms. Virtual memory is the idea, paging is the method, scheduling chooses the process.
  • Kernel. The core: loads first, handles interrupts, controls processes.
