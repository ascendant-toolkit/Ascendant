Adding a Record to a Random File

Coursebook: Chapter 20 · Further programming, section 20.2 File processing and exception handling

Hashing a key to a location, SEEK and PUTRECORD, handling a collision with the next free location, and detecting a full file; pseudocode and Python side by side, with a line-by-line animation.

This page in five sentences

A random file is a file of equal-sized records, each at a numbered location, and the program can jump straight to any location with SEEK. To add a record, a hash function turns its key into a location (here Key MOD 7), the program uses SEEK to move there, and PUTRECORD writes the record. If another record is already at that location, that is a collision, so the program checks the next location (wrapping round at the end) until it finds an empty one. If it comes back to where it started, the file is full. An empty location holds a record whose key is 0, which is how the program recognises it.

1 · The file and its locations

This page uses a file Accounts.dat with 7 locations, numbered 0 to 6. Each record is a TAccount. The file is created with every location holding a blank record, so there is something at every location to read. (PutRecord is defined in the next section.)

Python

import struct class TAccount:    def __init__(self, AccountNumber=0, Name=""):        self.AccountNumber = AccountNumber        self.Name = Name File = open("Accounts.dat", "wb")for Location in range(7):    PutRecord(File, TAccount())      # blank recordFile.close()

Pseudocode (exam style)

TYPE TAccount   DECLARE AccountNumber : INTEGER   DECLARE Name : STRINGENDTYPE DECLARE Blank : TAccountBlank.AccountNumber <- 0Blank.Name <- ""OPENFILE "Accounts.dat" FOR RANDOMFOR Location <- 0 TO 6   SEEK "Accounts.dat", Location   PUTRECORD "Accounts.dat", BlankNEXT LocationCLOSEFILE "Accounts.dat"

2 · SEEK, GETRECORD and PUTRECORD in Python

Python has no commands with these names, so this page builds them from seek(), read() and write(). Every record is stored as exactly the same number of bytes, so location n starts at byte n × RecSize.

import structLayout = "<i20s"                      # a 4-byte integer then 20 bytes of textRecSize = struct.calcsize(Layout)     # 24 bytes per record def PutRecord(File, Rec):    File.write(struct.pack(Layout, Rec.AccountNumber, Rec.Name.encode())) def GetRecord(File):    Num, Name = struct.unpack(Layout, File.read(RecSize))    return TAccount(Num, Name.decode().rstrip("\x00")) def Hash(Key):    return Key % 7

3 · The hash function

It must give the same location every time for the same key, and a valid location (0 to 6). MOD does both: the remainder after dividing by 7 is always 0 to 6.

Python

def Hash(Key):    return Key % 7 Hash(24)    # 3Hash(16)    # 2

Pseudocode (exam style)

FUNCTION Hash(Key : INTEGER) RETURNS INTEGER   RETURN Key MOD 7ENDFUNCTION Hash(24)    // 3Hash(16)    // 2

4 · Storing a record at its hashed location

When the question does not mention collisions, this is the whole answer: calculate the location, SEEK, PUTRECORD.

Python

File = open("Accounts.dat", "r+b")Location = Hash(NewAccount.AccountNumber)File.seek(Location * RecSize)PutRecord(File, NewAccount)File.close()

Pseudocode (exam style)

OPENFILE "Accounts.dat" FOR RANDOMLocation <- Hash(NewAccount.AccountNumber)SEEK "Accounts.dat", LocationPUTRECORD "Accounts.dat", NewAccountCLOSEFILE "Accounts.dat"
The dangerPUTRECORD writes over whatever is at that location. If another account is already there, it is lost. That is why a safe version reads the location first.

5 · Collisions: the next free location

Two keys can hash to the same location: 24 and 10 both give 3. Read the location first. If it is empty (AccountNumber = 0) store the record. If not, move to the next location, wrapping from 6 back to 0 with MOD 7. This method is called linear probing. Start remembers where the search began, so if the program gets all the way round the file is full.

Python

File = open("Accounts.dat", "r+b")Stored = FalseLocation = Hash(NewAccount.AccountNumber)Start = Locationwhile True:    File.seek(Location * RecSize)    Current = GetRecord(File)    if Current.AccountNumber == 0:        File.seek(Location * RecSize)        PutRecord(File, NewAccount)        Stored = True    else:        Location = (Location + 1) % 7    if Stored or Location == Start:        breakFile.close()if not Stored:    print("File full")

Pseudocode (exam style)

OPENFILE "Accounts.dat" FOR RANDOMStored <- FALSELocation <- Hash(NewAccount.AccountNumber)Start <- LocationREPEAT   SEEK "Accounts.dat", Location   GETRECORD "Accounts.dat", Current   IF Current.AccountNumber = 0 THEN      PUTRECORD "Accounts.dat", NewAccount      Stored <- TRUE   ELSE      Location <- (Location + 1) MOD 7   ENDIFUNTIL Stored OR Location = StartIF NOT Stored THEN   OUTPUT "File full"ENDIFCLOSEFILE "Accounts.dat"
Why the second seek in Python?In Python, reading a record moves the file position on to the next location, so the program seeks back before it writes. The exam mark scheme (M/J 2025, Paper 33, Question 11) writes with PUTRECORD straight after GETRECORD with no second SEEK, so in exam pseudocode the pointer stays at the location that was sought.

6 · Common ways to lose marks

  • Leaving out SEEK. PUTRECORD writes wherever the pointer already is.
  • Using READFILE or WRITEFILE on a random file. Random files use GETRECORD and PUTRECORD.
  • Opening FOR APPEND or FOR WRITE instead of FOR RANDOM.
  • Storing straight at the hashed location without checking whether it is already used.
  • Adding 1 to the location without MOD, so it runs off the end of the file.
  • Not stopping when the file is full, so the loop never ends.
  • Not closing the file.

5 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

School lockers

A locker is assigned as student ID MOD number of lockers. If that locker is already taken, the student is given the next free one, wrapping round to the start after the last. That is the same method as linear probing.

Exam use: hash for the first choice, next location on a collision.

A bank's account file

Millions of records are stored at locations worked out from the account number. A new account is written straight to its location without reading any other record, which is why a random file is fast to add to.

Exam use: direct access: SEEK to the calculated location, then PUTRECORD.

A hotel booking system

Each booking reference is turned into a location in the booking file. When two references give the same location the system looks at the following locations until it finds an empty one.

Exam use: collisions are handled by checking the next location.

A full file

A small random file used as a cache has 500 slots. When all are taken the program has to report that it is full or throw an old record away; it must never overwrite a record by accident.

Exam use: the Start check stops the loop and the program reports the file is full.

Top tips

  • Always SEEK first. SEEK to the location before every GETRECORD or PUTRECORD.
  • Open FOR RANDOM. APPEND and WRITE are for text files.
  • Hash first. Location comes from the key, not from a loop, unless there is a collision.
  • Check before you write. PUTRECORD overwrites. Read the location and test that it is empty.
  • Wrap round with MOD. (Location + 1) MOD 7 never leaves the file.
  • Say what empty means. A blank record, such as AccountNumber 0 or an empty string.
