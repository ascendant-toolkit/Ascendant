Maintainable Programs

Meaningful identifiers, comments, procedures and functions: code that people can read and change.

The big idea

A program is maintainable when another person can understand it and change it safely. Good names, useful comments and well-chosen procedures and functions make that possible.

8.1.8 Maintainable programs

Programs are read far more often than they are written. They get fixed, improved and changed, often by someone who did not write them. A maintainable program is easy to read, understand and change without breaking it.

1 · Meaningful identifiers

An identifier is the name given to a variable, constant, array, procedure or function. A meaningful identifier says what the thing holds or does.

Used forPoorMeaningful
VariablexTotalMarks
ConstantnMaxStudents
Arraylist1StudentName
Procedurep1DisplayMenu
FunctionfCalculateAverage
Naming rulesStart with a letter. No spaces (join words as TotalMarks or total_marks). Do not use a keyword such as OUTPUT or FOR. Be consistent.

2 · Comments

A comment is a note for the human reader that the computer ignores. Pseudocode comments start with //, Python comments with #. A useful comment explains the purpose of a section or why something is done.

3 · Procedures and functions

Splitting a program into procedures and functions gives small parts that each do one job. Each can be read and tested on its own, and a repeated job is changed in one place.

Constants and layout also help

A constant names a value that does not change while the program runs. To change it you edit one line, and it cannot be altered by accident. Indentation and blank lines show the structure.

5 · Multiple choice

Descriptions are kept general. Check current details before quoting specifics.

A tax rate changes

A government changes a sales tax. A shop system that stores the rate in one constant needs one edit.

Exam use: constants: change a value in one place, with less chance of missing one.

A new team member

A programmer joins a project and has to fix a fault in code written years earlier.

Exam use: meaningful identifiers and comments let someone else understand the code.

A school system upgrade

Only the way report grades are calculated changes. It lives in its own function.

Exam use: subroutines: one part can be changed and tested without rewriting the rest.

Shared libraries

Teams publish routines with clear names and notes so that others can call them correctly.

Exam use: meaningful routine names and commenting support reuse.

Q8 Write 6 marks A cinema charges 12 for a ticket. Write maintainable pseudocode with a function that takes the number of tickets and returns the cost, taking 5 off when more than 4 are bought. Input the number and output the cost.
ReminderUse constants, clear names and a comment.
constant for the ticket price (and/or discount) function with a meaningful name, one parameter and RETURNS cost calculated as number × price IF more than 4, subtract 5, then RETURN the cost INPUT, function call and OUTPUT a relevant comment and meaningful identifiers throughout
CONSTANT TicketPrice ← 12CONSTANT GroupDiscount ← 5 // Returns the cost, with a discount for more than 4 ticketsFUNCTION TicketCost(Tickets : INTEGER) RETURNS INTEGER    DECLARE Cost : INTEGER    Cost ← Tickets * TicketPrice    IF Tickets > 4      THEN        Cost ← Cost - GroupDiscount    ENDIF    RETURN CostENDFUNCTION INPUT NumberOfTicketsOUTPUT TicketCost(NumberOfTickets)
Common mistakeUsing >= 4. "More than 4" means > 4.

Top tips

  • The three to remember: meaningful identifiers, comments, procedures and functions.
  • Explain, do not just list: add "so that..." to each feature.
  • In "write an algorithm" questions, use meaningful names and the names given in the question exactly.
  • Comments say why or what a section is for, not a copy of the line.
  • Constants are for values that stay the same while the program runs.
  • Maintainability is about people reading and changing code, not about speed.
