User-defined Types: Records, Sets and Classes

Coursebook: Chapter 13 · Data representation, section 13.1 User-defined data types

Composite types: records with dot notation, sets and their operations, classes; how to choose the right data type for each field; animations, labs and the real 9618 declaration questions from 2021 to 2026.

This page in five sentences

A composite user-defined type is built from other types and holds more than one value under a single identifier. A record groups fields of different types (a pet's name, age and gender), written between TYPE and ENDTYPE with a DECLARE for each field, and you reach a field with dot notation. A set is an unordered collection of unique values of one type, which supports union, intersection and difference. A class bundles fields with the methods that act on them, and its instances are objects. The skill the exam tests is to choose and design the right type: pick the fields, give each the most appropriate data type, and reuse an enumerated type where the values come from a fixed list.

1 · Records

A record holds the data about one thing, one field for each item. The fields can have different types, including an enumerated type you have declared earlier.

TYPE Aircraft = (C300, C350, D242, E757, X380)      // an enumerated type used below TYPE Flight   DECLARE FlightNumber : STRING   DECLARE Destination : STRING   DECLARE DepartureDate : DATE   DECLARE AircraftType : Aircraft                  // a field whose type is the enumerated typeENDTYPE DECLARE Flight1 : Flight                            // a variable that holds one recordFlight1.FlightNumber ← "XA782"                      // dot notation: variable.fieldFlight1.Destination ← "Cambridge"Flight1.DepartureDate ← 12/12/2022Flight1.AircraftType ← C350                         // an enumerated value, no quotation marks
  • A declaration of the type only describes it. DECLARE Flight1 : Flight creates the variable.
  • Each field is assigned separately with variable.field.
  • Strings go in double quotation marks, characters in single quotation marks, dates are written as given, and enumerated values have no quotation marks.
  • For many records use an array: DECLARE Flights : ARRAY[1:50] OF Flight and Flights[3].Gate ← "N03".
  • A type can be changed. To make a field's values come from a fixed list, declare an enumerated type and replace that field's declaration: DECLARE Gate : GateID. A range can also be stated: DECLARE NumberOfCopies : 1 .. 10.
from dataclasses import dataclassfrom datetime import date @dataclassclass Flight:                           # Python's closest equivalent of a record    FlightNumber: str    Destination: str    DepartureDate: date    AircraftType: str Flight1 = Flight("XA782", "Cambridge", date(2022, 12, 12), "C350")print(Flight1.Destination)

3 · Set types

A set is a composite type for a collection of values that are all of one data type. The elements are unordered, there are no duplicates, and set operations such as union and intersection can be applied. The declaration gives the type of the members; DEFINE then gives a variable its values.

TYPE Numbers = SET OF INTEGERDEFINE EvenNumbers (2, 4, 6, 8, 10, 12) : Numbers TYPE SymbolSet = SET OF CHARDEFINE Operators ('+', '-', '*', '/', '^') : SymbolSet

4 · Class / object as a composite type

A class is a composite type that holds fields and the methods that work on them. Each object made from it is an instance. Unlike a record, a class can keep its data private and be extended by inheritance. This is covered fully in the OOP pages of chapter 20.

5 · Defining a composite type

A composite type refers to at least one other data type in its definition; it holds several values under a single identifier. The data types can be primitive or user-defined. An example answer is: a record, a set, or a class/object.

6 · Common ways to lose marks

  • Leaving out ENDTYPE, or DECLARE on a field.
  • Using a STRING for a number that is used in calculations, or an INTEGER for a telephone number or an identity code.
  • Not using the enumerated type that the question tells you to use for a field.
  • Forgetting to declare a variable of the record type before assigning to it, or writing the field name without the variable name.
  • Quotation marks round an enumerated value, or no quotation marks round a string.
  • Describing a set as "an ordered list". It is unordered, with no repeats.
  • For a set: leaving out SET OF, DEFINE, the values in brackets, or the : type at the end.

6 · Multiple choice

Examples are explained in general terms. Check current details before quoting them in an exam answer.

A school's student records

Each student is a record with name, date of birth, form, a Boolean for permission to go on trips, and a field of type Subject for the favourite subject. An array holds the whole year group.

Exam use: records group different types of data for one item; arrays hold many records.

Airport departures board

Each flight is a record: flight number, destination, date, gate and airline. The gate is an enumerated type because only certain gates exist.

Exam use: a record with an enumerated field.

Followers and common interests

A social network can treat each person's interests as a set. The intersection of two people's sets shows what they have in common and the union shows everything either likes.

Exam use: set operations: union and intersection.

A game character

A Character has a name, position and strength together with methods to move and fight. It is made as a class so each character is an object with its own data.

Exam use: a class is a composite type with methods.

A video library

A video record has an identity code (STRING), title, year (INTEGER), purchase date (DATE), format and running time. The format is chosen from a fixed list, so it is a good enumerated type.

Exam use: choose the most appropriate type for each field.

Distinguish 2 marks Distinguish between a record and a set.
ReminderThink about types, order and duplicates.

A record holds fields of different data types for one item, each accessed by name. A set holds unordered, unique values that all have the same data type, and supports union and intersection.

Explain 3 marks A programmer stores a person's date of birth in a STRING field, and their telephone number in an INTEGER field. Explain why a different choice would be better for each.
ReminderWhat can be done with a DATE; what is lost in an integer.

A DATE field can be compared and used in calculations such as age, which a string cannot. A telephone number may start with 0, which an INTEGER drops. The telephone number is not used in arithmetic, so a STRING is the appropriate type.

Top tips

  • Check every field's type. Text and codes: STRING. Whole numbers: INTEGER. Fractions: REAL. Yes or no: BOOLEAN. Dates: DATE. Fixed lists: enumerated.
  • Telephone numbers and codes are STRINGs. They are not used in calculations, and may start with 0 or hold letters.
  • TYPE ... ENDTYPE, DECLARE on each line. One mark for the frame, then marks for the fields.
  • Declare the variable first. DECLARE Pet1 : Pet, then assign each field as Pet1.Field.
  • Use the type you are told to use. If the question says use the enumerated type, a STRING field loses the mark.
  • Sets: SET OF, DEFINE, values, type. Four things in two statements.
