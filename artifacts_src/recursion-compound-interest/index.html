Recursion in Action: Compound Interest and Its Trace Table

One small recursive function, followed all the way through: what each call does, how the call stack grows and shrinks, how the trace table is filled in row by row, and every past-paper question that tests the same skills. Includes a check of the coursebook’s Table 19.29.

The problem

Put 100 in an account that pays 5% a year, and leave the interest in. After one year there is 100 × 1.05 = 105. After two years there is 105 × 1.05 = 110.25. After three years, 110.25 × 1.05 = 115.7625. This is compound interest: each year’s interest is earned on the previous year’s total, which already includes earlier interest.

Spot the recursion. The amount after n years is the amount after n − 1 years, multiplied by 1.05. And the amount after 0 years is just the principal. A problem defined in terms of a smaller copy of itself is exactly what recursion is for.

The two cases

Base case

total₀ = principal

When years = 0 no interest has been added. The answer is known, so no further call is made.

General case

totalₙ = totalₙ₋₁ × rate

Any other number of years: find the total for one year fewer, then multiply by the rate. This is the recursive call.

rate is a multiplier5% interest is passed as 1.05, not 5 and not 0.05. 1.05 means “100% of what you had, plus 5% more”. For 8% pass 1.08; for 3.5% pass 1.035.

The function, line by line

This is the pseudocode from the coursebook (Table 19.28 gives the two cases), written so the trace matches the table’s RETURN column. Switch between Pseudocode and Python.

  1. Header. Three parameters: the starting principal, the growth factor rate and the number of years. It RETURNS a REAL, the final amount.
  2. IF years = 0. The base case test. If true, total ← principal and the calls stop.
  3. The recursive line. compoundInt(principal, rate, years - 1) asks the same question for one year fewer, then * rate adds this year’s growth. years - 1 is what moves each call towards the base case.
  4. RETURN total. Both branches finish here, so every call hands its answer back to whoever called it.

Why the multiplying waits. In compoundInt(100, 1.05, 3), the final * rate cannot be worked out until compoundInt(100, 1.05, 2) has an answer, which needs compoundInt(100, 1.05, 1), which needs the base case. So the calls wind down to years = 0, and then the multiplications happen one by one as the calls unwind. The principal stays at 100 in every call.

Reading a trace table

This is the same trace table layout that the exam uses (Call number, Function call, a column for each parameter or variable, then the return value). For compoundInt(100, 1.05, 3):

Amber row: the base case. Green rows: unwinding. The “cont” rows are the same call carrying on after the call beneath it returned (the exam mark schemes write these as the call number in brackets). In the exam, the total column is often written as the calculation, like 100 * 1.05, with the value in RETURN.

  1. Go down first. One row per call until the base case, with the years value counting down.
  2. Mark the base case row and write its return value. Only now do you have a number.
  3. Work back up. Each “cont” row takes the value just returned and finishes its own calculation.
  4. The answer is the last row, the original call: 115.7625 (115.76 to 2 decimal places).

A check of coursebook Table 19.29

The printed trace mixes two versions of the functionThe code in the coursebook passes principal * rate into the recursive call. The printed trace table, however, (1) shows the principal as 105 in calls 2, 3 and 4 when the code would give 105, 110.25 and 115.7625, and (2) has a RETURN column that climbs 100, 105, 110.25, 115.76, which would not happen with that code (every call would return 115.76).

The two columns come from different versions. Both give 115.7625, and both are valid recursion, but they work differently:

This page uses Version A, because it matches the two cases in Table 19.28 and the table’s RETURN column. Version B is shown alongside it in the Watch tab, so you can compare the two traces row by row. Version B is a form of tail recursion: nothing is left to do after the call, so nothing waits. The syllabus does not name it, but it is a good talking point.

The same job with a loop

FUNCTION compoundIntLoop(principal, rate : REAL, years : INTEGER) RETURNS REAL
   total ← principal
   FOR count ← 1 TO years
      total ← total * rate
   NEXT count
   RETURN total
ENDFUNCTION

The loop variable total plays the role that the waiting calls played in recursion. For this particular job the loop (or simply principal * rate ^ years) is simpler and uses no stack. Compound interest is taught recursively because the idea is easy to see, not because it is the best tool. Exam questions may ask you to convert between the two.

Quick quiz

Flashcards

General descriptions of how the same idea appears elsewhere. Numbers are illustrative only.

A savings account over time

If a balance earns 5% a year and the interest stays in the account, the balance after n years is the balance after n − 1 years × 1.05. That sentence is the whole recursive function.

Exam use: a clear example of a problem defined in terms of a smaller version of itself, with a natural base case (year 0 = the principal).

A loan or credit-card balance

A balance that grows by a percentage each month follows the same pattern, so the debt can grow faster and faster if nothing is paid off. Understanding it as repeated multiplication helps show why.

Exam use: a different context for the same function; only rate and the meaning of the numbers change.

Prices and inflation

If prices rise 3% a year, an item costing 20 would cost 20 × 1.03 next year, 20 × 1.03 × 1.03 the year after, and so on. The rate argument would be 1.03.

Exam use: shows that the growth factor is 1 + the percentage as a decimal.

Population and bacteria growth

A population that grows by a fixed percentage each period can be modelled by the same function. If the population shrinks by 10% each period, the rate is 0.9.

Exam use: a rate below 1 gives decay, with the same code and the same trace.

Depreciation of equipment

A machine that loses 20% of its value each year is worth 0.8 × the previous year’s value. Recursion with rate = 0.8 gives its value after n years.

Exam use: another example where the base case is the starting value.

Why real programs would use a loop here

For compound interest, a loop or the formula principal × rate ^ years is quicker, uses no stack and has no stack overflow risk. Recursion is better kept for problems that split into smaller copies, such as trees and divide and conquer.

Exam use: the standard evaluation point: recursion may be easier to read, but it uses more memory (a frame per call) and can be slower than iteration.

Past papers: theory

M/J 2023 · 31, 33 Q12(a) and M/J 2025 · 31 Q4(b) Describe 2 marks Describe what is meant by recursion.
ReminderBoth papers award the same marks. Two ideas: it calls itself, and it stops at a base case. “Unwinding” also earns the second mark in 2023.
A technique where a function or procedure is defined in terms of itself / calls itself (the general case). It does so until a terminating condition / base case is reached, where no further recursive call is made (then the calls unwind).
Common mistakeWriting “it repeats” or “it loops”. A loop repeats too; recursion is the self-call plus the base case.
O/N 2021 · 31, 32 · Q10(a), (b) State / Explain 3 + 3 marks (a) State three essential features of recursion. (b) Explain why a stack is a suitable ADT to implement recursion.
Reminder(a) is a list, no explanation. (b) needs LIFO, push on call, pop on return, and why that order matters.
(a) It must have a base case / stopping condition. It must have a general case that calls itself (the subroutine is defined in terms of itself). Each call changes its state, moving towards the base case; unwinding can occur once the base case is reached.
(b) A stack is a last in, first out structure. Each recursive call is pushed onto the stack, and is popped when the function ends. This allows backtracking / unwinding in the correct order.
Common mistakeSaying a queue would also work. It would give the calls back in the wrong order: the last call made must finish first.
O/N 2023 · 9618/32 · Q9(c) Explain 4 marks Explain how a compiler makes use of a stack when translating recursive programming code.
ReminderSay what goes on the stack, when it goes on, when it comes off. For compoundInt: four frames at the deepest point.
The compiler produces object code to use a stack for the calls. Return addresses and the values of local variables / parameters are pushed onto the stack with each recursive call (winding). They are popped off after the base case is reached, one by one in reverse order (unwinding).
Common mistakeDescribing what the program does without saying what the compiler generates. Name the return address and the pushing and popping.

Feature: the problem naturally breaks down into smaller versions of itself. Example: calculating compound interest (also accepted: factorial, Fibonacci or another mathematical series, tree traversal, evaluating RPN expressions).

O/N 2025 · 9618/32 · Q12(b) Explain 3 marks Explain the reasons why a stack is used when a recursive algorithm is executed.
ReminderLIFO, what is pushed on each call, and the pop order when unwinding. Four mark points are available; the maximum is 3.
A stack stores data in last in, first out (LIFO) order. Each time a recursive algorithm calls itself, data is pushed onto the stack. When the base case is reached and the algorithm starts to unwind, data is popped off the stack in the reverse order to which it was pushed.
Common mistakeDescribing how a stack works without linking it to the calls. Say what is pushed (return address, parameters) and when it is popped.

It is beneficial for problems that can be broken down into smaller, repetitive problems of the same kind. Especially problems with many possible branches, or too complex for an iterative approach. Example: solving a mathematical series (such as compound interest or Fibonacci), tree traversal, sorting.

(e) Six marks: function header taking four parameters, written recursively; calculating the middle value; comparing the middle value to the data and returning the index if equal; if the middle is greater, recursive call with Middle − 1 as the upper bound; if the middle is less, recursive call with Middle + 1 as the lower bound; checking if not found and returning −1.

def RecursiveBinarySearch(DataArray, Lower, Upper, DataToFind):
    if Upper >= Lower:
        Middle = Lower + (Upper - Lower) // 2
        if DataArray[Middle] == DataToFind:
            return Middle
        elif DataArray[Middle] > DataToFind:
            return RecursiveBinarySearch(DataArray, Lower, Middle - 1, DataToFind)
        else:
            return RecursiveBinarySearch(DataArray, Middle + 1, Upper, DataToFind)
    else:
        return -1

Describe 4 marks Describe how the call stack is used when compoundInt(100, 1.05, 3) is run.
ReminderUse the numbers: four frames at the deepest point, each holding principal, rate and years.
Each call pushes a stack frame holding its parameters (principal, rate, years), local variable total and the return address. Four frames are pushed (years = 3, 2, 1, 0) before the base case is reached. The base case returns 100 and its frame is popped. Each earlier frame is then popped in reverse order, multiplying the value returned to it by 1.05 to give 105, 110.25 and finally 115.7625.

Discuss 4 marks A programmer says compound interest should be calculated with a loop, not recursion. Discuss whether this could be a better choice.
ReminderGive a point for each side, apply it to this function, and make a judgement.
Recursion could use more memory, because every call needs a stack frame, so a long period could risk a stack overflow. A loop is likely to be quicker, as there is no overhead from pushing and popping frames. Recursion may be easier to read here, since the code closely mirrors the definition: the total for n years is the total for n − 1 years × rate. Overall, a loop is likely to be the better choice for this simple repeated calculation, although recursion may be worth using where the problem splits into smaller copies, as in a tree.

Top tips

  • Find the base case first. Here it is years = 0, and it returns the principal.
  • Go down, then back up. Write every call down to the base case before calculating anything. Only the base case has a number at that point.
  • Count the base case call. compoundInt(100, 1.05, 3) is four calls and four frames, and a trace table with 7 rows.
  • Check which version you are tracing. Principal fixed and RETURN climbing means × rate on the way up. Principal climbing and RETURN flat means principal * rate passed down.
  • In the total column, write the calculation going down (like Fib(4) + Fib(3) or 100 * 1.05) and the value going up. The exam wants the Result column to show both stages.
  • Rate is 1.05, not 5%. It is a multiplier. If a question gives “3% interest”, the argument is 1.03.
  • The argument must move towards the base case. years - 1. If it moved away, there would be a stack overflow.
  • Don’t fill RETURN on winding rows. Those calls have not finished.
  • Procedures return nothing. A trace for a recursive PROCEDURE (like Delete) has no return column and no unwinding work.
  • Converting to iteration: the starting value becomes the initial value of a variable, and the repeating step goes in a loop.
  • Say “frame”, “return address”, “push”, “pop” and “last in, first out” in any stack answer.
  • For drawbacks, name the stack. More memory, risk of stack overflow, overhead of calls. “Slower” alone earns nothing.
