This page in five sentences

Stepwise refinement is increasing the level of detail of an algorithm by breaking each step into smaller steps, repeatedly, until the steps can be directly translated into lines of code. An algorithm can be refined and written in structured English: numbered steps in plain words that name the variables, the loops and the decisions, but contain no pseudocode statements. A good description mentions the same things the mark scheme looks for: open the file (in the right mode) and close it, initialise a variable or index before the loop, a loop with its end condition, the input or read inside the loop, the test and its action, and the increment. The constructs you must identify are sequence (steps in order), selection and iteration. You must also be able to turn a program flowchart into pseudocode, step by step, or complete a flowchart from words.

1 · Stepwise refinement

Start with the problem in one line, then rewrite each step in more detail. Example: copy the lines of a file into an array refines to:

  1. Open the file for reading (and close it afterwards).
  2. Set an index variable to 1 before the loop.
  3. Repeat until the end of the file is reached:
    1. read one line from the file into a string variable;
    2. store that line in the array at the index;
    3. add 1 to the index.
  4. Close the file.

Each line is now simple enough to become one pseudocode statement. The construct needed apart from sequence is iteration (a conditional loop, repeating until the end of the file), and a selection statement tests the value returned by the EOF function or whether an element is blank.

2 · Writing an algorithm in structured English

  • Use numbered steps and indent the steps inside a loop.
  • Name the variables the question gives (MyChar, MyCount).
  • For files: say open, the mode (read, write or append if the file already has data you must keep), and close.
  • Do not write pseudocode statements such as WHILE or ←; use words.

Example answer for "input numbers until zero, then output the sum of the positive and the sum of the negative numbers": (1) set the two sums to zero; (2) prompt for and input a number; (3) if it is greater than zero add it to the positive sum, if it is less than zero add it to the negative sum; (4) repeat from step 2 if the number was not zero; (5) output the two sums.

3 · From a flowchart to pseudocode

Take the flowchart in order. The two boxes before a loop become initialisations. A decision whose YES branch returns to the decision itself is a WHILE loop with the decision as its condition. After the loop, a decision with two exits is an IF. A call box is CALL.

Pseudocode for the flowchart (O/N 2021)

Count ← 1Flag ← FALSEWHILE Flag = FALSE AND Count <= 5   CALL ReBoot()   Count ← Count + 1   Flag ← Check()ENDWHILEIF Flag = FALSE THEN   CALL Alert(27)ENDIF

4 · From words to a flowchart

Count pairs of values input until A has been greater than B ten times, then output the number of pairs:

Marks: initialise both counts; increment Tries for every pair input; compare A > B and increment Count if true; test for Count = 10 (the decision must have YES and NO labels); output Tries when it is, otherwise loop.

Common ways to lose marks

  • Writing pseudocode when the question says "do not include pseudocode statements".
  • Forgetting to open or close the file, or using write mode when data must be kept (append).
  • Not initialising the index or counter before the loop.
  • Leaving out the end condition of the loop (until end of file, until the value is zero).
  • Not incrementing the index inside the loop.

Top tips

  • Open, initialise, loop, close. The skeleton of a file algorithm.
  • End condition of the loop. End of file, zero, count reached.
  • Append keeps old data. Write overwrites.
  • No pseudocode when told not to. Use words.
  • Increment the index. Inside the loop.
  • Count your points. One mark each; check you have enough.
